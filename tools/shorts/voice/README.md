# ナレーションの声を作る（Fish Audio の画面から）

ショートのナレーションを、Fish Audio の声（いまは **Holiday Twist**、#908）で1文ずつ作り、
聞き取り直して原稿どおりに読めているかを確かめ、書き出し（`tools/shorts/render/`）に渡せる形に揃える。

| ファイル | どこで動く | 何をするか |
| --- | --- | --- |
| `fish_web.py` | EC2（`~/cdp/` に `cdp.py` と並べる） | ログイン済みの Chrome（`~/cdp-fish`）で1文ずつ作り、mp3 と記録（`attempts.jsonl`）を書く |
| `asr_check.py` | EC2（venv の faster-whisper） | 作った声を全部聞き取り直して `asr.json` を書く |
| `collect.py` | 手元 | 1文1ファイルに揃え、48kHz モノラル wav・長さ・音量を出し、原稿と聞き取りを比べて `lines.json` を書く |

この紙の `~` は、EC2 の ubuntu のホーム（SSM のコマンドは root で走るので、道具の中では `EC2_HOME` から組む）。

API の鍵は使わない（あやとの決定、#908）。画面が自分で送る要求の**返事を CDP で読む**だけで、
Cookie や `authorization` の値には触らない。

## 1. 先に知っておく数（2026-10-15 に実測）

| 項目 | 値 | どう確かめたか |
| --- | --- | --- |
| プランと量 | **Plus（月払い・2026-10-28 から。#1044）**: 毎月 250,000 クレジット・毎月28日に戻る。前の無料プランは毎月 8,000（1本 900〜1,200 なので月に約7本で尽きた） | チームの画面（`/app/team/`）の「残りクレジット」・`wallet/<team>/package` の `balance` |
| **1回に送れる量** | **UTF-8 で 500 バイト**（日本語だけなら約166字） | 入力欄の右下「63 / 500 文字」が UTF-8 のバイト数と一致 |
| **1回に使うクレジット** | **送った字の UTF-8 バイト数そのもの**（秒数ではない） | タスクの `credit_count`: 63バイト→63、132バイト→132、234バイト→234 |
| 1回で何本できるか | **2本**（「追加料金なしで2パターン」）。クレジットが付くのは片方だけ | `POST /task` が2本出て、片方の `credit_count` が 0 |
| 1本にかかる時間 | 3〜10秒 | タスクの `created_at` → `finished_at` |

8,000 クレジットで「7分」は、日本語のナレーションが**1秒あたり約18バイト**（速度 1.1）だから。
**秒数で予算を立てると読み違える。** 予算は `--budget-credits` で、クレジット（＝バイト）で決める。
2026-10-15 の3本（北マケドニアの回）は、A 690（38.4秒）・B 771（40.5秒）・C 561（32.9秒）、合わせて 2,022 クレジット。
かなに直すとバイトは増える（「280」は3バイト、「にひゃくはちじゅう」は27バイト）。

## 2. かなに直す決まり（`caption` と `tts_text`）

1文ごとに字を2つ持つ。

- `caption`: 原稿の字そのまま。字幕に出す
- `tts_text`: 声に渡す字。**読み違えそうなところだけ**かなに直す。**言う中身は `caption` と同じ。語を足さない**

| 直すもの | 例 | なぜ |
| --- | --- | --- |
| 数と単位・助数詞 | 280レク→にひゃくはちじゅうレク、約550円→約ごひゃくごじゅうえん、1席→いっせき、4時間→よじかん、20分→にじゅっぷん | 数字は中国語読み・英語読み・桁の取り違えが起きやすい |
| 「あと」＋かなの数 | あと25分→**あと、**にじゅうごふん | かなだけ続けると「あとに・じゅうごふん」と切られうる。足してよいのは読点だけ |
| 英字・記号 | 1A→いちエー、2番→にばん | 英字は英語読みになる |
| 読みが割れる漢字 | 空いてる→あいてる（すいてる）、鶏→とり（にわとり）、入り→いり（はいり）、行き→ゆき、中→なか、屋→や、車内→しゃない | 文脈で決まる読みは外れることがある |
| そのままでよいもの | プーレ・スタバ・マクド・ケバブ・ミニバン（カタカナ） | カタカナはそのまま読まれる |

迷ったら直す。直したかどうかは聞き取り（4）で確かめる。
実際に使った組は `lines/yk-by7R7iPA_p1.json`（三人称・27文）と `lines/yk-by7R7iPA_p3.json`（関西弁の一人称・71文。
2回目で直した文は1回目の字を `tts_text_1` に残してある）。次の動画もこの形（`key`・`plan`・`n`・`caption`・`tts_text`・`bytes`）で作る。

2026-10-15 の27文は、この決まりで直した字のまま、**1回目で全部が聞き取りと合った**（数・1A・プーレ・スタバ・マクドも）。
ただし Holiday Twist は「1A」「プーレ」をそのままでも読めたかは試していない（直さずに作った文が無い）。

## 3. 作る（EC2）

前提: fish の Chrome（`~/cdp-fish`）が fish.audio にログインしている。**切れていたら、列 `fish` の札を取って
`fish_login.py` で入り直す**（「Googleで続行」→ kosaka.ayato@gmail.com。パスワードが要らない所はこちらで押す。あやと 2026-10-28 #1044）。
**`up("fish", reseed=True)` で複製し直さない**——`~/cdp-fish` には TikTok の下書き（約564MB）があり、消える。
最初に作るときだけ `up("fish")` が既定のプロファイルから複製する（`ec2-chrome` スキル 3）。**あやとがリモートデスクトップで操作中は複製しない**
（EC2 の `/usr/local/sbin/desktop-input idle` の数が 300000（5分）以上になってから。xprintidle はこちらの Chrome が
動画を止めるだけで0に戻るので、それでは見ない。`ec2-chrome` スキル 2）。

```bash
E=.claude/skills/ec2-chrome/ec2.py
python3 $E put tools/shorts/voice/fish_web.py ~/cdp/fish_web.py
python3 $E put lines_in.json ~/voice/<動画>-lines_in.json      # [{"key": "A/01", "tts_text": "…"}, …]
```

EC2 で（長いので `nohup` で裏に回す。道具が列 `fish` の札を自分の pid で取る。ほかの人が fish の Chrome を持っていれば——
TikTok の投稿も同じ Chrome——空くまで待つ。札は道具が終われば消える。`ec2-chrome` 2.5。前は鍵 `~/locks/fish-voice` を1文ごとに触っていた）:

```sh
cd ~/cdp && python3 fish_web.py backup                       # あやとの下書きを写す・残りのクレジットを見る
python3 fish_web.py state --model <声のID>                               # ログイン・モデル・速度だけ見る（作らない）
nohup python3 fish_web.py gen --model <声のID> --lines ~/voice/<動画>-lines_in.json \
  --out ~/voice/out/<動画> --budget-credits 4500 > ~/voice/gen.log 2>&1 &
```

- 済んだ文は飛ばすので、止まっても同じ指示をもう一度流せば続きから
- 押しても要求が出なかったとき（窓が邪魔をしたなど）は、タブを作り直して1回だけ押し直す。
  そのときの画面は `err_<文>_<時刻>.jpg` に残る。2026-10-15 と 10-16 の2回とも、原因は開いた直後に出る
  **アップグレードの窓**（「期間限定：初年度50%オフ」「Plus（年払い）にアップグレード」）だった。
  **窓の中は何も押さない。** タブを作り直すと出ずに押せた
- **設定は触らない。** 2026-10-15 のアカウントは「Fish Audio S2.1 Pro・速度 1.1・ボリューム 0・ラウドネス正規化 オン・
  テキスト正規化 オフ」（あやとの下書きに入っていたまま）。各テイクの `settings`・`task_params` に残る
- **画面の「速度」では声は速くならない**（2026-10-18 に `gen --speed 1.3` で B の3行を作って確かめた。詰めた長さの合計は
  1.1 の 12.32秒に対して 12.31秒。聞き取りは6本とも原稿の語どおりで、「たかっ」の促音が落ちて聞こえるのは 1.1 のときと同じ）。速度は生成の要求（`POST /task` の本文）に乗らず、
  下書きの `audio_settings.prosody.speed` に残るだけ。画面の幅は 0.7〜1.3。速さは書き出しの倍率で決める
  （`tools/shorts/render/style.json` の `narration.max_tempo`）。`gen --speed` は試し用に残す（終わると元の値に戻す。
  途中で切れたら `fish_web.py speed --model <声> --value 1.1` と `restore --backup <写し>` で戻す）
- **入力欄はあやとの下書きと同じもの**（`GET/PUT api.fish.audio/tts-draft` でサーバーに保存される）。
  作る前に `fish_web.py backup` で下書きの返事（`GET /tts-draft`）を写しておき（EC2 の `~/voice/private/`、
  権限 700、git に入れない。`?modelId=` を付けずに開くので話者は替わらない）、
  終わったら `fish_web.py restore --backup <写し>` で戻す（下書きの話者の ID で開き直してから字を入れるので、声も字も戻る）。
  戻し終えた写しは消す（アカウントの情報が入っている）
- `state` と `gen` の最初に出る `credits_balance` が残りのクレジット（画面が読む `wallet/<team>/package` の返事）

## 4. 聞き取り直す（EC2）

数・名前の読み違いは、聞いてみないと分からない。faster-whisper で聞き取り直す。

```sh
python3 -m venv ~/voice/asr-venv          # 要るなら apt-get install python3.12-venv
~/voice/asr-venv/bin/pip install faster-whisper
~/voice/asr-venv/bin/python ~/cdp/asr_check.py ~/voice/out/<動画> \
  ~/voice/out/<動画>/asr.json --model <int8 の large-v3-turbo の置き場> --pack 26
# 合わなかった文だけ、1本ずつ聞き直す（--pack を付けない）
~/voice/asr-venv/bin/python ~/cdp/asr_check.py <同じ> <同じ> --model <同じ> --only A/04_a1_t1,B/03
```

- **t3.medium（メモリ 4GB）では `large-v3-turbo`（float16 の 1.6GB）を int8 で読み込む途中で落ちる**（Killed。
  あやとの Chrome が開いていると空きが 1.3GB しか無い）。int8 に変換済みの ct2
  （`Zoont/faster-whisper-large-v3-turbo-int8-ct2`、0.8GB）なら 12秒で読み込めた
- int8 でも、**`~/cdp-fish` の Chrome を開いたままだと読み込みで落ちる**（Killed）。聞き取りの前に `down("fish")` で閉じる
- faster-whisper 1.2.1 の音声の読み込みは、PyAV 19 では `metadata_errors` の引数で落ちる（`av<15` は wheel が無くビルドで落ちた）。
  `asr_check.py` は PyAV で自分で開いて配列を渡している（EC2 に ffmpeg は無い）
- 2 vCPU で1本あたり約30秒（数秒の音声でも 30秒の窓ぶん計算する）。27文×2テイクで約27分かかった。
  **`--pack 26` で、無音1.2秒をはさんで26秒ぶんまで1つの窓に詰めて聞き**、単語の時刻で文に割り戻す。
  同じ22本で 660秒 → 138秒、22本とも1本ずつ聞いたときと同じ文に割り戻せた（2026-10-16）。
  境目で取り違えた文は「合わない」に出るので、その文だけ `--only` で1本ずつ聞き直す。`nohup` で裏に回す
- **詰めるときの落とし穴（2026-10-16 に踏んだ）:** 同じ文の2テイクを隣に並べると、Whisper は2回目を繰り返しとみなして
  1回ぶんしか書かない（142本中17本が空）。残った1回がどちらの音から来たか分からないので、**片方が読み違えていても
  「合っている」に化けうる。** いまの `asr_check.py` はテイク1を全部並べてからテイク2を並べる。
  それでも**数・名前の入った文と、選ぶテイクは1本ずつ聞き直してから合否を決める**（10-16 は 50本を聞き直した）
- 1本ずつ聞いても、かなの数が助詞と切れて聞こえることがある。「出発にじゅうごふん前」は2テイクとも「出発に15分前」、
  「ひとはこでにひゃくえん」は「人は小手に100円」と聞き取られた。**漢数字にすると数のまとまりで読まれて直った**
  （「出発二十五分前」「ひと箱で二百円」）。かなにするのは、数の前が助詞と紛れないときだけにする
- **原稿を手がかり（`initial_prompt`）に渡さない。** 聞き取りが原稿に寄って、読み違いが「合っている」に化ける

## 5. 揃える（手元）

```bash
# 音声と記録を1つに固めて持ち帰る（1ファイルずつ get するより速い）
python3 $E run <(echo 'cd ~/voice/out && tar czf ~/voice/<動画>.tgz <動画>') 120
python3 $E get ~/voice/<動画>.tgz <手元>/raw.tgz
python3 tools/shorts/voice/collect.py --lines lines_in.json --attempts raw/attempts.jsonl --asr raw/asr.json \
  --raw raw --out <書き出し先>
```

- **投稿が済んだ回の声は、EC2 から消してよい**（あやと 2026-10-22 #1013「投稿完了したら素材は捨てて良い」。EC2 のディスクは 29G しかない）。
  消すのは素材だけ: `~/voice/out/<動画>`・`~/voice/<動画>.tgz`・`~/voice/<動画>-lines_in.json`。
  `~/voice/asr-venv`・書き起こしのモデル・`~/voice/private/`・`*.log` は残す。差し替えで同じ声が要るときは、
  書き出しの入力の置き場（`tools/shorts/render/remote.py` の CAS）から sha256 で取り戻せる（フランス A v3 で通した）
- 1文に2本（以上）あるテイクのうち、**聞き取りが原稿と合うもの**を選ぶ（同じなら新しい試し・テイク1）。
  人が聞いて選び直すときは `--pick A/04=2.1`（試し2のテイク1）
- 比べるのは字ではなく**読み**（Open JTalk でカタカナにして比べる）。「鶏／とり」「25分／にじゅうごふん」を同じとみなすため。
  同音の書き分け（「鳥」と「とり」）は読みで一致するが、辞書の癖で外れることがある（「1A」はイチアンペア）ので、
  最後の合否は `match` の中身を読んで決める。誤検出と確かめたものは `--accept A/09=理由` で合格にする
  （自動の判定は `match_auto` に残る）
- `lines.json` に、字幕・声に渡した字・ファイル・長さ（ffprobe）・試した回数・聞き取り・合否・音量（EBU R128）が入る
- **音量は測るだけで揃えない。** 揃えるのは書き出しの仕事（ここで触ると二重に掛かる）
- **問いの語尾が上がっているかを測る**（要るもの: `pip install praat-parselmouth`）。字幕が「？」で終わる文（「！？」も）は、
  テイクごとに Praat の既定（75〜600Hz）でピッチを取り、声の出ている最後のフレームを終わりとして
  「最後の0.2秒の中央値 − その前0.2〜0.6秒の中央値」を半音で出す（`rise_st`・`intonation_rise_st`）。
  +1 半音より上がっていなければ `intonation_flag`。読みの照合が同じテイクどうしなら、上がっているほうを選ぶ
  （半音の整数に丸めて比べ、測りの揺れでテイクを替えない）。末尾のきしみ声（文の中央値の0.65倍より低い最後のフレーム）は
  落としてから測る。落とさないと「揚げるん！？」が 430Hz まで上がってから最後に 77Hz へ落ちて −4.9 に出た。
  オクターブの取り違えで ±12 前後に振れることがあるので、数は目安。**印の付いた文から先に人が聞く**
- 「！？」は感嘆として読まれて下がりやすい。2026-10-16 は「ポテト入り！？」を「ポテトいり？」にして +5.2 に直った。
  一方「対面払い！？」「運転手？それとも機械？」は「？」だけ・「？？」・「〜？」・「……」を試しても +2 に届かなかった
  （いちばん上がって +1.9）。書き方だけで上げられない文があるので、2回で上がらなければ元のテイクのまま人に渡す
- 聞き取りでは「平板に読んだ」「問いを平叙で読んだ」は分からない。代わりに**長さで怪しい文に印を付ける**:
  頭とお尻の無音を除いた喋りの秒数で読み（カナ）の数を割り、同じ回の中央値の 0.7倍より遅い・1.4倍より速い、
  または途中の無音が1秒を超える文を `duration_flag` に出す。印の付いた文は人が聞く

## 6. 直す

`match` が `no` の文だけ、`tts_text` を直して作り直す。**1文2回まで**（2回目もまだ違うときだけ3回目）。

```sh
python3 fish_web.py gen ... --only A/04,B/03 --attempt-limit 2
```

`--only` を付けると、済んでいても作り直す。予算（`--budget-credits`）は同じ出力先の記録ぜんぶで数える。
