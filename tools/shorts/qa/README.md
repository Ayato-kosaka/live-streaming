# ショートの品質チェック（出す前に機械で全部見る）

書き出した mp4 を、媒体に出してよい形かどうか、13の検査で測る。各検査は
**pass / fail / needs-human / not-checkable** と、**測った数字と線**を返す。
「通った」だけを返さない（何を何件見て通ったかを、いつも並べて出す）。

```bash
python3 tools/shorts/qa/check.py out.mp4 out.work --json qa.json --md qa.md
#   out.work は render.py の --work（plan.json・字の絵・音の束）。無くても回るが、
#   束や時間割が要る検査は not-checkable になる（「無かったので通した」にはしない）
#   --plate no_text.mp4  字を重ねずに書いた同じ動画（あれば字の置き場を画素の差でも測る）
#   --crops DIR          人に見せる切り抜き（顔・透かし）の置き場。既定は out.qa/
#   --only / --skip      検査を絞る（, 区切り）
```

終了コード: **0** 全部 pass / **1** fail がある / **2** 動画が読めない /
**3** fail は無いが needs-human か not-checkable が残っている（人が見るまで出さない）。

`render/verify.py` とは役目が違う。あちらは「書き出しの道具が指示書どおりに書けているか」
（合成素材のカット位置の照合・2本のバイト一致）、こちらは「できあがりが出してよい形か」。

## 検査と線（なぜその線か）

| id | 見るもの | fail の線 | なぜ |
| --- | --- | --- | --- |
| `container` | 形式 | 1080x1920 でない／fps が 29.97〜30 でない／**60秒以上**／h264・yuv420p・aac でない／音が 44.1・48kHz の 2ch でない／moov が mdat の後ろ（faststart でない）／音と絵の長さが 0.1秒超違う／コマ数が時間割と違う | 媒体がそのまま縦型として扱う形。60秒未満はあやとの決め。faststart でないと全部落とすまで再生が始まらない |
| `loudness` | 積分ラウドネス・トゥルーピーク | **-14 LUFS ±1.5** を外れる／**-1.0 dBTP** を越える | YouTube は再生時に、だいたい -14 LUFS より大きいものを下げ、小さいものは上げない（広く測られている振る舞い。この箱から YouTube に届かないので自分では確かめていない）。小さく作ると前後より小さく鳴る。AAC にすると山が 0.5〜1dB 上に出るので、ピークは -1 dBTP 以下 |
| `voice_vs_bgm` | ナレーションの間の、声と BGM の差（行ごと） | どれかの行で **12dB 未満** | 様式の設計値は 18dB（声 -16、BGM -22 を 12 下げて -34）。12 を切るのは BGM が設計から 6dB（音圧2倍）以上上がったとき |
| `subtitle_sync` | 声の出だしと字幕の出だし | **±1コマ**を越えてずれる／声があるのに字幕が無い／声が終わる 3コマより前に字幕が消える（次の字幕も無いのに） | あやとの決め。声の出だしは束（stem_narration.f32）から、字幕は書き出したコマの画素から測る |
| `text_dup` | 強調の字（テロップ）の言い直し | 強調の字の **6割以上**が、同じときに出ている字幕のページ（めくれたら全部）かタイトルと共通の **4字以上**の並びで覆える（4字未満の強調はまるごと入っていたら）／はじめの3秒に、タイトル・強調・字幕の3つに同じ **3字以上**の並び | 強調の字は「ナレーションにもタイトルにも無いことを足すときだけ」（`production.md` の 2）。1本目は強調の半分が言い直しで、0秒目に「25分」が3回並んだ。字は `plan.json` の `overlays[].text` から読む |
| `safe_area` | タイトル・テロップ・字幕の置き場 | 安全領域（`style.json` の `safe`: 上360・下1248・左120・右960、y≥840 では右888）を出る／出ているはずのコマに見つからない／時間割と違う場所にある／タイトルが無い | YouTube と TikTok の画面の部品に隠れない範囲（`render/README.md` の「安全領域」） |
| `watermark` | 配信の「PRISM Live」 | 型との似ている度合い **0.55 以上**（0.40〜0.55 は needs-human） | 下の表の実測。透かしを残したまま投稿しない |
| `faces` | ぼかしていない顔 | 1件でもあれば **needs-human**（顔の切り抜きと時刻を出す） | 配信者本人かどうかは機械が決めない |
| `black` | 真っ黒なコマ | 字の外の 98% が黒いコマが **3コマ（0.1秒）以上**続く。1〜2コマは needs-human | 目に見える黒。1〜2コマはつなぎの瞬きかもしれない |
| `frozen` | 止まったコマ | 隣と同じコマが **1.5秒を超えて**続く（真っ黒の間は black が言うので数えない） | あやとの決め |
| `silence` | 無音 | 声も BGM も無い間（束で測る）、または仕上がりがほぼ無音（-50dBFS 未満）の間が **1.5秒を超える** | あやとの決め |
| `clipping` | 音割れ | 仕上がりが 0dBFS に 3サンプル以上張り付く／ナレーションの元の音声に平らな頂点（同じ値の最大が 4サンプル以上） | 自然な声が同じ最大値を 4サンプル続けることは 48kHz ではまず無い |
| `original_audio` | 元の配信の音の漏れ | 元音声がナレーションより **18dB 以上**小さくない | 書き出しは元の音を既定で消し、カットに `audio_db` を書いたときだけ入れる（本人の一言を残すとき）。18 を切るのは、残す音を下げ忘れたとき |

### 測りかたの要点

- **音の束（stem_*.f32）と仕上がりの音を、最小二乗で当てる。** 仕上がり ≒ a·声 + b·BGM (+ c·元音声)。
  ずれ（サンプル）は相互相関で出す（ffmpeg が AAC の頭の詰め物を外すので、ふつうは 0）。
  最後に音量を足しても a, b が同じだけ動くだけなので、声と BGM の差は a/b で直して測る。
  束が仕上がりと似ていない（相関 0.5 未満・a が 0.25〜4 倍の外）なら、**別の動画の work** とみなして束を使わない
- **元音声の束（stem_source.f32）があれば、それで測る。** 無ければ「仕上がり − a·声 − b·BGM」の残りを、
  **ナレーションから 0.5秒以上離れた所で**測る。声の間はリミッターと AAC の誤差が声の -20dB ほど
  残る（例の指示書で -37dBFS）ので使えない。声の無い所の誤差は -63dBFS ほどで、元音声（-44dBFS）がよく見える
- **2ch を ffmpeg に 1ch へ混ぜさせない。** 左右を足して √2 倍にするので +3dB に読める
  （`render/verify.py` の mix_rms がそれで 3dB 高く出ていたので、あわせて直した）
- **字幕の出だし**: 字の絵（PNG）の不透明な画素だけで、コマとの差の平均を取る。出ていれば H.264 の誤差
  （3〜9）、出ていなければ地との差（40 以上）。25 を線にした。声の出だしは、その行のいちばん大きい所から
  -30dB を越えた最初のサンプル（**後ろ向きの 2.5ms 移動 RMS**。前向きだと 1コマ早く読めた）
- **安全領域**は2つの測りかたを持つ。(1) 時間割の字の絵を、出ているはずのコマで探して実際の位置を出す
  （時間割の位置に無ければ全体を探す）。(2) 字なしの書き出し（plate）があれば、コマどうしを引いて
  字の画素を出す。(2) は時間割に載っていない重ね物も拾う
- **透かし**: 型（`assets/prism_live.png`）を、書き出しのコマを型の縮尺まで縮めて当てる。倍率は
  0.85〜2.7倍を 7% 刻み＋いちばん良い倍率のまわりを 1% 刻み。**明るさの段差を消してから（高域だけで）当てる**。
  **一色の地は測らない**（窓の中の揺れが型の 0.15 倍未満の所）。正規化相互相関は分母が 0 に近いと
  OpenCV が 1.0 を返すことがあり、書き出し担当の素材（testsrc の青い帯）で「17/68 コマに透かし・1.0」と出た
- **顔**: 4.3コマ/秒、540x960 に縮めて探す（いちばん小さい顔は書き出しで 48px）。正面の型と横顔の型（左右）。
  Haar の誤検出（字・模様）を、箱の真ん中 60% の肌色の割合 0.25 未満で捨てる。ぼかしの判定は、
  箱を 64px に縮めたラプラシアンの分散が 30 未満、かつまわりの輪の 0.25 倍未満
- **同じ画素のコマに、重い検出を2度かけない**（`common.frame_memo`。selftest で効く）

### 実測（2026-10-15）

透かしの型と線（`make_logo_template.py` で、yk-by7R7iPA の取り込み 13区間のうち 8区間・688コマの
中央値から型を作り、**残りの区間**と別の配信で当てた）:

| | コマ | 似ている度合い |
| --- | --- | --- |
| 残った透かし（型に使っていない区間、cover 1.5倍） | 132 | いちばん低い 0.885 |
| 残った透かし（さらに 1.25倍寄せ） | 132 | いちばん低い 0.916 |
| 残った透かし（別の配信 hk の静止画） | 32 | いちばん低い 0.703 |
| 残った透かし（合成素材の色の帯の上） | 8 | 0.780 |
| 消した（下 7% を切り落として cover） | 132 | いちばん高い 0.274（平らな地の守りを入れる前は 0.434） |
| 消した（描き埋め） | 132 | いちばん高い 0.273 |
| 合成素材（透かし無し） | 8 | いちばん高い 0.258 |

高域を引かずに当てると、色の帯の上の透かしが 0.505、別の配信で 0.472 まで落ち、消したコマ（0.443）と
分けられなかった。

顔（取り込みの 272コマに Haar を当てた 133件を目で分けた）: 本物の顔（配信者・通りすがり6人）は
肌色の割合が全部 0.78 以上、0.25 未満は全部 壁・看板・服・地面だった。0.25 以上に残る誤検出は
食べ物（ハンバーガーの絵・ピザ）と砂色の壁で、これは needs-human として人に回る。

書き出しの素の音量: 例の指示書（`render/example.edit.json`）で **-17.2 LUFS / -0.8 dBTP**、
selftest の素材で -15.1 LUFS / -1.2 dBTP。**いまの render.py の出力は loudness で落ちることがある**
（最後の音量合わせの段が無い）。

### 字の重なり（text_dup）の実測（2026-10-16）

人が見た6本の yt 版（A・B・C）の時間割で、言い直しは A 6・B 5・C 6（3つ並びを含む）。直したあとの A・B は 0。

| 強調の字 | 同時の字幕 | 覆える割合 | 判定 |
| --- | --- | --- | --- |
| 出発まで あと25分 | 国際バスの出発まで／あと25分 | 100%（＋3つ並び「25分」） | 落とす |
| クッキー1袋 約200円 | スーパーは／クッキー1袋で ＋ 約200円 | 100%（2ページにまたがる） | 落とす |
| 運賃 40レク（約80円） | 運賃は40レク／約80円らしい | 78% | 落とす |
| 車内の係の人から 紙の切符 | 車内の係の人に渡して／紙の切符をもらう | 83% | 落とす |
| 「今から揚げんの？」（本人の声） | なのにポテトは／これから揚げるらしい | 57%（「から揚げ」だけ） | 通す |
| アルバニア → 北マケドニア（地図） | ここはアルバニア ほか | 45% | 通す |
| Pulë ＝ 鶏（訳） | アルバニア語で／鶏のこと ほか | 0% | 通す |
| 予定の時間を過ぎた | 予定の時間は／もう過ぎた | 56% | **通してしまう**（「過ぎた」が3字） |
| 「ビッグマックのソースみたい」 | 本人いわく、ソースは／ビッグマックの味 | 54% | **通してしまう** |

最後の2つは、2つの間の共通を3字から数えれば落とせる（89%・77%）が、「でした」「ている」のような偶然の3字で
短い強調が落ちるようになるので、4字のままにしてある。人の目の検査（帯の絵）で拾う。

## 人の目の検査の帯（strips.py）

```bash
python3 tools/shorts/qa/strips.py out.mp4 out.work [--out PREFIX]   # PREFIX.jpg（1枚）と PREFIX.json
```

`production.md` の 3 で見る帯を1枚にまとめる: はじめの帯（0・0.5・1・2・3・4.5秒）と、ナレーションの行ごとの
1秒刻みの帯（時刻と字幕つき）。**弱い画の見当**に赤い枠を付ける——字の箱を除いた画の「大きな形の量」
（1/4 の画をさらに 1/8 にして、辺の強さ 20 を越える画素の割合 `e8`）の2秒の窓の中央値が **0.835 未満**の間が
**2秒以上**続き、主役の顔（字なしの書き出しで探す）が無い所。**合否ではない（needs-human の手がかり）**。

人が判定した4区間での値（4コマ/秒）:

| 区間 | 人の判定 | e8（各コマ） | 窓の中央値 | 印が付いたコマ |
| --- | --- | --- | --- | --- |
| B 10.8〜13.2秒 何も無いカウンター | 弱い | 0.799〜0.834 | 0.801〜0.843 | 9/10（頭の 10.8秒だけ、前の通路の窓に引かれて付かない） |
| C 15〜24秒 歩道 | 弱い | 0.683〜0.792 | 0.704〜0.741 | 36/36 |
| A 0.5〜3秒 回る肉の串 | 強い | 0.832〜0.885 | 0.849〜0.869 | 0/10 |
| B 5.8〜9秒 スーパーの棚 | 強い | 0.919〜0.952 | 0.888〜0.947 | 0/13 |

細かさ（ラプラシアンの分散・そのままの辺の量）では分けられなかった（歩道のレンガが串より「細かい」）。
線と強い側（串の 0.849）の間は 0.014 しかない。ほかに印が付くのは、暗い車内（0.5〜0.65）・字だけの暗い
メニュー（0.62）・道路を写した区間（C のほとんど）。自撮りで話す顔（0.73〜0.80）は、字なしの書き出しが
あれば顔で外れる（無いと、顔に字が掛かって Haar が見つけず、印が付く）。

## 弱いところ（確かめていないこと）

- **顔**: Haar は横顔・小さな顔（書き出しで 48px 未満）・青や緑の照明の下の顔（肌色に入らない）を見逃す。
  YuNet（OpenCV の顔検出 CNN。opencv_zoo の `face_detection_yunet_2023mar.onnx`）を `models/` に置けば自動で使うが、
  この箱のプロキシが github と huggingface からの取得を断るので**まだ一度も回していない**。
  Actions なら取れるので、書き出しのワークフローで取ってから回すのが次の手
- **OpenCV 5 には Haar が無い。** `opencv-python-headless<5` を入れる（4.12.0.88 で確かめた）
- **透かしの型は1つの配信（yk）から作った。** 別の配信（hk）の静止画 32枚でも 0.70 以上で当たったが、
  PRISM Live の版で透かしの形が変われば型を作り直す（`make_logo_template.py`）
- **止まったコマの線（0.5）**は合成素材でしか決めていない（止めたコマ 0.0〜0.1、動くコマ 3 以上）。
  三脚で動かない景色は、実物で測っていない
- **黒の線**は、夜道で街灯や看板が 2% は光る、という見込み。実物の夜の区間で測っていない
- **loudness の -14 LUFS** は YouTube の広く知られた振る舞いに合わせた線で、TikTok の基準は確かめていない

## selftest（落ちるときに落ちるか）

2本（壊し方の表は `drill.py` の頭）。**全部の PR で走る Selftests からは外してある**
（`python/selftest_runner.py` の `SKIP`、理由は「遅い」）。ショートを触った PR・master への push
（`tools/shorts/**` が変わったとき）で `.github/workflows/shorts_selftest.yml` が名指しで回す。
島の直しの PR まで、毎回4〜5分と ffmpeg の取り付けを待たせないため:

```bash
python3 tools/shorts/qa/qa_selftest.py         # 音・字（ずれ・置き場）・形式の壊し方（clean＋8通り）
python3 tools/shorts/qa/qa_video_selftest.py   # 絵・長さの壊し方（clean＋6通り）
python3 tools/shorts/qa/drill.py all --keep DIR  # 両方を1回で。作った動画と報告を残す
```

壊れていない1本は 13本とも pass、壊した1本ごとに**壊したところを見る検査だけ**が落ちることを当てる。
あわせて分母（顔が見たコマ・字幕が測った行…）が 0 でないこと、ぼかした顔が「検出されたうえで
ぼかし済み」と判定されること、透かしの「一色の地は測らない」守りを外すと化けて守りがあれば化けないこと
（1コマで当てる。動画の一色の箱では化けを再現できなかった）、`render/verify.py` の字幕の出入りの照合が
同じ clean で通ることも見る。

要るもの: ffmpeg（libx264・libass）、numpy・Pillow、`opencv-python-headless<5`、書体
（`render/fetch_fonts.sh` か、無ければ箱の書体を同じ名前で置く）。どれかが無ければ **2**（数えるものが無い）。
この箱（4コア・ほかの作業で load 7 前後）で、runner から 166秒と 154秒（1本の上限は 5分）。
