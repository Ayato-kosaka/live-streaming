# ショートの品質チェック（出す前に機械で全部見る）

書き出した mp4 を、媒体に出してよい形かどうか、16の検査で測る。各検査は
**pass / fail / needs-human / not-checkable** と、**測った数字と線**を返す。
「通った」だけを返さない（何を何件見て通ったかを、いつも並べて出す）。

```bash
python3 tools/shorts/qa/check.py out.mp4 out.work --json qa.json --md qa.md
#   out.work は render.py の --work（plan.json・字の絵・音の束）。無くても回るが、
#   束や時間割が要る検査は not-checkable になる（「無かったので通した」にはしない）
#   --plate no_text.mp4  字を重ねずに書いた同じ動画（あれば字の置き場を画素の差でも測る）
#   --crops DIR          人に見せる切り抜き（顔・透かし）の置き場。既定は out.qa/
#   --only / --skip      検査を絞る（, 区切り）
```

終了コード: **0** 全部 pass / **1** fail がある / **2** 動画が読めない /
**3** fail は無いが needs-human か not-checkable が残っている（人が見るまで出さない）。

`render/verify.py` とは役目が違う。あちらは「書き出しの道具が指示書どおりに書けているか」
（合成素材のカット位置の照合・2本のバイト一致）、こちらは「できあがりが出してよい形か」。

### 測りかたの要点

- **音の束（stem_*.f32）と仕上がりの音を、最小二乗で当てる。** 仕上がり ≒ a·声 + b·BGM (+ c·元音声)。
  ずれ（サンプル）は相互相関で出す（ffmpeg が AAC の頭の詰め物を外すので、ふつうは 0）。
  最後に音量を足しても a, b が同じだけ動くだけなので、声と BGM の差は a/b で直して測る。
  束が仕上がりと似ていない（相関 0.5 未満・a が 0.25〜4 倍の外）なら、**別の動画の work** とみなして束を使わない
- **元音声の束（stem_source.f32）があれば、それで測る。** 無ければ「仕上がり − a·声 − b·BGM」の残りを、
  **ナレーションから 0.5秒以上離れた所で**測る。声の間はリミッターと AAC の誤差が声の -20dB ほど
  残る（例の指示書で -37dBFS）ので使えない。声の無い所の誤差は -63dBFS ほどで、元音声（-44dBFS）がよく見える
- **2ch を ffmpeg に 1ch へ混ぜさせない。** 左右を足して √2 倍にするので +3dB に読める
  （`render/verify.py` の mix_rms がそれで 3dB 高く出ていたので、あわせて直した）
- **字幕の出だし**: 字の絵（PNG）の不透明な画素だけで、コマとの差の平均を取る。出ていれば H.264 の誤差
  （3〜9）、出ていなければ地との差（40 以上）。25 を線にした。声の出だしは、その行のいちばん大きい所から
  -30dB を越えた最初のサンプル（**後ろ向きの 2.5ms 移動 RMS**。前向きだと 1コマ早く読めた）
- **安全領域**は2つの測りかたを持つ。(1) 時間割の字の絵を、出ているはずのコマで探して実際の位置を出す
  （時間割の位置に無ければ全体を探す）。(2) 字なしの書き出し（plate）があれば、コマどうしを引いて
  字の画素を出す。(2) は時間割に載っていない重ね物も拾う
- **透かし**: 型（`assets/prism_live.png`）を、書き出しのコマを型の縮尺まで縮めて当てる。倍率は
  0.85〜2.7倍を 7% 刻み＋いちばん良い倍率のまわりを 1% 刻み。**明るさの段差を消してから（高域だけで）当てる**。
  **一色の地は測らない**（窓の中の揺れが型の 0.15 倍未満の所）。正規化相互相関は分母が 0 に近いと
  OpenCV が 1.0 を返すことがあり、書き出し担当の素材（testsrc の青い帯）で「17/68 コマに透かし・1.0」と出た
- **顔**: 4.3コマ/秒、540x960 に縮めて探す（いちばん小さい顔は書き出しで 48px）。
  見つけ役は YuNet（OpenCV の顔検出 CNN）。重みは環境変数 `SHORTS_QA_YUNET`（最優先）→ `qa/models/` →
  書き出しの道具の `render/models/`（`fetch_fonts.sh` が sha256 を確かめて落とす）の順に探す。どこにも無いときだけ
  Haar（正面の型と横顔の型（左右））に落ちる。Haar に落ちると顔でないものを顔と数えやすく、v3 の B では
  字と顔の検査が7行の嘘の不合格を出した。手元で回す前に `fetch_fonts.sh` を回しておく。どちらを使ったかは
  `thresholds.detector` に出る。
  誤検出（字・模様）を、箱の真ん中 60% の肌色の割合 0.25 未満で捨てる。ぼかしの判定は、
  箱を 64px に縮めたラプラシアンの分散が 30 未満、かつまわりの輪の 0.25 倍未満
- **字と顔**: 顔は**字なしの書き出し**（`work/no_text.mp4`）で探す。字を重ねた版で探すと、字が顔を隠して
  見つからず、被っているものほど通る。字が出ているコマぜんぶ（前後 4コマも）を 540x960 で探し、肌色と
  ぼかしの判定は `faces` と同じ。**1〜4コマだけ出る箱は顔として数えない**（隣のコマで IoU 0.3 以上の箱を
  つなぎ、5つ以上つながったものだけが顔。`facetrack.py`）。yk-by7R7iPA の p3 で、手を顔と間違えた箱が3コマ、パンを顔と間違えた箱が
  1コマと 2コマ、ぼかした人の体・バスの車輪が 1〜2コマずつ出た。配信者本人は数十コマ続く。
  見つけ役（YuNet の重みの探しかたと、無いときの Haar）は顔の検査と同じ
- **書き出しも同じものを読む。** 書き出しの顔よけ（`render/render.py` の `avoid_faces`）は、肌色・ぼかしの式を
  `faces.py` から、つなぎかたを `facetrack.py` から読む（写さない）。チェックより緩い線で先に避けるので、
  チェックが顔と数える箱は書き出しも避けている。片方だけ線を変えると、避けなかった箱で落ちる
- **同じ画素のコマに、重い検出を2度かけない**（`common.frame_memo`。selftest で効く）
- **元素材に戻る**（`source_stutter`・`shot_reuse`）: 時間割（`plan.json` の `cuts`）は、カットごとに元素材の置き場
  （`path`）・元のコマ（`in` / `out`）・出来上がりの頭（`at`）・使った範囲（`crop`）を持っている。配信の何秒目かは、
  取り込みの clips の置き場にある `index.json`（`video` と区間ごとの `start`）から出す（`common.segments`）
- **カクつき**: 隣のコマとの差（白黒の全画素の平均）を、前後 15コマの差の 90 パーセンタイル（そのあたりの動き）と比べ、
  その 15% 未満を「同じ絵の繰り返し」と数える。そのあたりの動きが 1.0 未満の所は止まった画として数えない。
  ffmpeg の mpdecimate は使わない（下の実測。繰り返しの半分を見逃し、写真を 97% と数える）。
  区間を選ぶ前に素材を1秒ずつ測る道具は `python3 tools/shorts/qa/stutter.py clip.mp4 [--from 秒] [--to 秒]`
- **使い回し**: カットの 2割・5割・8割の3コマを、字なしの書き出し（無ければ仕上がりから字の箱を除いて）で比べる。
  見た目の近さは HSV（色相12×彩度4×明度4）の分布の重なり、ほぼ同じ絵は pHash（63ビット）。束ねるのは
  (1) 同じ配信の同じ瞬間（1秒以内）で見た目が近い (2) 同じ素材のファイルか同じ配信の 10秒以内で見た目が近い
  (3) pHash の違いが 10ビット以内、のどれか。**本人が大きく写る画どうし**（ぼかしていない顔が画面の高さの 1割以上）は
  (1) でしか束ねない（自撮りで話す画は、同じ場所でも毎回ちがう表情と身ぶり）。顔は、色で束ねそうな組にだけ探す

透かしの型と線（`make_logo_template.py` で、yk-by7R7iPA の取り込み 13区間のうち 8区間・688コマの
中央値から型を作り、**残りの区間**と別の配信で当てた）:

| --- | --- | --- |
| 残った透かし（型に使っていない区間、cover 1.5倍） | 132 | いちばん低い 0.885 |
| 残った透かし（さらに 1.25倍寄せ） | 132 | いちばん低い 0.916 |
| 残った透かし（別の配信 hk の静止画） | 32 | いちばん低い 0.703 |
| 残った透かし（合成素材の色の帯の上） | 8 | 0.780 |
| 消した（下 7% を切り落として cover） | 132 | いちばん高い 0.274（平らな地の守りを入れる前は 0.434） |
| 消した（描き埋め） | 132 | いちばん高い 0.273 |
| 合成素材（透かし無し） | 8 | いちばん高い 0.258 |

高域を引かずに当てると、色の帯の上の透かしが 0.505、別の配信で 0.472 まで落ち、消したコマ（0.443）と
分けられなかった。

顔（取り込みの 272コマに Haar を当てた 133件を目で分けた）: 本物の顔（配信者・通りすがり6人）は
肌色の割合が全部 0.78 以上、0.25 未満は全部 壁・看板・服・地面だった。0.25 以上に残る誤検出は
食べ物（ハンバーガーの絵・ピザ）と砂色の壁で、これは needs-human として人に回る。

書き出しの素の音量: 例の指示書（`render/example.edit.json`）で **-17.2 LUFS / -0.8 dBTP**、
selftest の素材で -15.1 LUFS / -1.2 dBTP。**いまの render.py の出力は loudness で落ちることがある**
（最後の音量合わせの段が無い）。

### 字の重なり（text_dup）の実測（2026-10-16）

人が見た6本の yt 版（A・B・C）の時間割で、言い直しは A 6・B 5・C 6（3つ並びを含む）。直したあとの A・B は 0。

| 強調の字 | 同時の字幕 | 覆える割合 | 判定 |
| --- | --- | --- | --- |
| 出発まで あと25分 | 国際バスの出発まで／あと25分 | 100%（＋3つ並び「25分」） | 落とす |
| クッキー1袋 約200円 | スーパーは／クッキー1袋で ＋ 約200円 | 100%（2ページにまたがる） | 落とす |
| 運賃 40レク（約80円） | 運賃は40レク／約80円らしい | 78% | 落とす |
| 車内の係の人から 紙の切符 | 車内の係の人に渡して／紙の切符をもらう | 83% | 落とす |
| 「今から揚げんの？」（本人の声） | なのにポテトは／これから揚げるらしい | 57%（「から揚げ」だけ） | 通す |
| アルバニア → 北マケドニア（地図） | ここはアルバニア ほか | 45% | 通す |
| Pulë ＝ 鶏（訳） | アルバニア語で／鶏のこと ほか | 0% | 通す |
| 予定の時間を過ぎた | 予定の時間は／もう過ぎた | 56% | **通してしまう**（「過ぎた」が3字） |
| 「ビッグマックのソースみたい」 | 本人いわく、ソースは／ビッグマックの味 | 54% | **通してしまう** |

最後の2つは、2つの間の共通を3字から数えれば落とせる（89%・77%）が、「でした」「ている」のような偶然の3字で
短い強調が落ちるようになるので、4字のままにしてある。人の目の検査（帯の絵）で拾う。

  （90 パーセンタイル）を 0.08〜0.25 / 80〜97 に動かしても、カクカクの区間は 65% を下回らず、出したものは 59% を超えなかった
- **mpdecimate（hi=64*4:lo=64*2:frac=0.33）との違い**: 同じ区間で、カクカクが 21〜46%、出したもの 0〜10%、写真 96〜99%。
  並びは合うが、繰り返しのコマ（符号化し直して 8x8 の塊の差が 140〜600 残る）の半分を hi=256 で「違う」と読む。
  写真（止まった画）とカクつきも分けない
- **使い回しの線 25%・3回**: 出したものの最大（22%・3回）と p2（31%・4回）の間。見た目の近さ 0.6 は、p2 のベッドの
  6カットが互いに 0.55〜0.96（つながりで1つになる）、同じ素材の別の物（コンロとフライパン、宿の部屋の引きと寄り）が
  0.57 以下だったことから。pHash の 10 は、同じ区間を使い直したカットが 0〜8、別の絵が 12 以上（三脚で同じ所を写した
  別の時刻が 12、同じ一覧の別の切り抜きが 14）
- **本人の画を外さないと分けられなかった。** 外さずに数えると、yk B のケバブを持った自撮り（6カット）が 21%・4回、
  Hc の三脚の画（同じ場所の8カット）が束になり、p2 のベッドと同じ形になった。顔の高さは、本人の画が 0.13〜0.50、
  通りがかり（ぼかしたもの・小さいもの）が 0.02〜0.06
- **同じ場面を「同じファイル」で切った理由**: 時間（同じ配信の何秒以内）で切ると、p2 のベッドを1つにするには
  67秒の幅が要り、yk C のバス停の通りは別の素材のファイルどうしが 79秒離れているだけで、つながると 27%・5回（線越え）に
  なった。隙間は 12秒しか無い。取り込みの clips は、企画が頼んだ時刻のまわりを1本ずつ切ったもので、1本が配信の
  続いた1場面になっている（p2 のベッドは全部 `01_0-04-55_0-07-10.mp4` の中）。別のファイルどうしは 10秒以内だけ同じ場面と読む

## 弱いところ（確かめていないこと）

- **顔**: YuNet の重みが無い箱では Haar に落ち、横顔・小さな顔（書き出しで 48px 未満）・青や緑の照明の下の顔
  （肌色に入らない）を見逃し、顔でないものを顔と数える。重みは `fetch_fonts.sh` が `render/models/` に落とす
  （raw.githubusercontent.com ではなく media.githubusercontent.com から。この箱からも取れる）。Actions の書き出し
  （`render/remote.py`）も同じ重みを `SHORTS_QA_YUNET` で渡している。下の selftest は合成素材と公有の顔写真で回し、
  CI に重みは無いので、Haar の側で当てている（重みを置いた手元でも、YuNet で2本とも思ったとおりになるのを確かめた。2026-10-18）
- **OpenCV 5 には Haar が無い。** `opencv-python-headless<5` を入れる（4.12.0.88 で確かめた）
- **透かしの型は1つの配信（yk）から作った。** 別の配信（hk）の静止画 32枚でも 0.70 以上で当たったが、
  PRISM Live の版で透かしの形が変われば型を作り直す（`make_logo_template.py`）
- **止まったコマの線（0.5）**は合成素材でしか決めていない（止めたコマ 0.0〜0.1、動くコマ 3 以上）。
  三脚で動かない景色は、実物で測っていない
- **黒の線**は、夜道で街灯や看板が 2% は光る、という見込み。実物の夜の区間で測っていない
- **loudness の -14 LUFS** は YouTube の広く知られた振る舞いに合わせた線で、TikTok の基準は確かめていない
- **カクつきと使い回しの線は、5本（出した4本と p2）から決めた。** カクつきは 54% と 71% の間、使い回しは 22%・3回と
  31%・4回の間で、どちらも隙間は広くない。あやとが新しく「カクカク」「見飽きる」と言った本、言わなかった本が出たら、ここに足して線を見直す
- **カクつきは「完全に同じ絵の繰り返し」しか見ない。** 配信ソフトがコマを混ぜて埋める（前後の絵を重ねる）素材や、
  そもそも 15fps で撮った素材は、繰り返しとしては出ない（後者は 50% と出て線の手前）
- **使い回しは「同じ素材のファイル＝1場面」に頼っている。** 配信を1本まるごと1つのファイルにして素材にすると、
  同じ配信のどこでも同じ場面と読み、似た色の別の場面（同じ通りの別の時刻）まで束ねて落としやすくなる
- **本人の画の見分けは顔の検出器に頼る。** 検出器が無ければ not-checkable。Haar に落ちると横顔の自撮りを見逃し、
  その画どうしを色で束ねる（厳しい側に倒れる）

## selftest（落ちるときに落ちるか）

2本（壊し方の表は `drill.py` の頭）。**全部の PR で走る Selftests からは外してある**
（`python/selftest_runner.py` の `SKIP`、理由は「遅い」）。ショートを触った PR・master への push
（`tools/shorts/**` が変わったとき）で `.github/workflows/shorts_selftest.yml` が名指しで回す。
島の直しの PR まで、毎回4〜5分と ffmpeg の取り付けを待たせないため:

```bash
python3 tools/shorts/qa/qa_selftest.py         # 音・字（ずれ・置き場）・形式の壊し方（clean＋8通り）と、元素材のカクつきの足4本
python3 tools/shorts/qa/qa_video_selftest.py   # 絵・長さの壊し方（clean＋7通り）と、同じ画の使い回しの足7本
python3 tools/shorts/qa/drill.py all --keep DIR  # 両方を1回で。作った動画と報告を残す
```

壊れていない1本は 16本とも pass、壊した1本ごとに**壊したところを見る検査だけ**が落ちることを当てる
（字と顔の検査は字なしの版でしか測れないので、字なしの版を渡さない足では not-checkable が正しい。
字なしの版の字幕の下に顔を貼った足で、字と顔の検査だけが落ちることを当てる）。
あわせて分母（顔が見たコマ・字幕が測った行…）が 0 でないこと、ぼかした顔が「検出されたうえで
ぼかし済み」と判定されること、透かしの「一色の地は測らない」守りを外すと化けて守りがあれば化けないこと
（1コマで当てる。動画の一色の箱では化けを再現できなかった）、`render/verify.py` の字幕の出入りの照合が
同じ clean で通ることも見る。

元素材のカクつき（`source_stutter`）と使い回し（`shot_reuse`）は、**出来上がりの画素ではなく時間割と元素材**を
見る検査なので、書き出しを通さずに時間割と素材だけを差し替えた足で当てる（壊し方の表は `drill.py` の
`stutter_legs` と `reuse_legs` の頭）。カクつきの足（4本）は `qa_selftest.py`、使い回しの足（7本）は
`qa_video_selftest.py` に置いた（使い回しの足は顔を探すぶん重いので、2本の時間を揃えた）。
カクつきは「使った区間だけ4コマずつ繰り返す → その区間だけ落ちる」「使っていない所だけ繰り返す → 通る」
「全部を2コマずつ（15fps）→ 繰り返しを 4〜6割と測ったうえで通る」「写真 → 止まった画として通る」、
使い回しは「同じ区間を4回 → 落ちる」「同じ素材の別の時刻を4回 → 落ちる」「同じ並びで顔を据える → 本人の画として通る」
「短く4回 → 回数だけで落ちる」「長く2回 → 割合だけで落ちる」「全部別（1つだけ行の境で割って続けて並べる）→ 1回と数えて通る」
「冒頭と終わりだけ → 呼び戻しとして通る」を当てる。どの足でも、もう一方の検査は落ちないことも見る。
あわせて、差し替えの言い添え「ゆっくり寄せている」が動く寄せ（from と to が違う）の区間にだけ付くこと、
配信の時刻が 0.1秒に丸めてから時・分・秒に割られること（299.97秒 → 0:05:00.0。割ってから丸めると 0:04:60.0）も当てる。

要るもの: ffmpeg（libx264・libass）、numpy・Pillow、`opencv-python-headless<5`、書体
（`render/fetch_fonts.sh` か、無ければ箱の書体を同じ名前で置く）。どれかが無ければ **2**（数えるものが無い）。
この箱（4コア・ほかの作業で load 7 前後）で、runner から 166秒と 154秒（1本の上限は 5分）。
2つの検査と足を足す前と後を、同じ時間帯に続けて回して比べた（2026-10-19、ほかの書き出しと並んで load 3〜8）:
`qa_selftest.py` 216秒 → 232秒、`qa_video_selftest.py` 184秒 → 252秒。足した分は、clean ほか絵の変わる足ごとに
2つの検査で 2〜4秒と、足そのもの（カクつき 約10秒・使い回し 約30秒）。
上限に近づいたら、時間割と素材だけの足を別の見張りに分ける（`selftest_runner.py` の `SKIP` と
`shorts_selftest.yml` の名指しに足す）
