# ショートの書き出し（編集指示書 → 縦型 mp4）

編集指示書（JSON）1つから、1080×1920・30fps のショートを ffmpeg で書き出す。
同じ指示書からは、同じバイト列が出る（`verify.py --twin` で確かめる）。

```bash
bash tools/shorts/render/fetch_fonts.sh                 # 書体（OFL）を落とす。git には入れない
python3 tools/shorts/render/render.py edit.json --out out.mp4 --work out.work
python3 tools/shorts/render/verify.py out.mp4 out.work  # 形式・カット位置・字幕の出入り・音量差
```

要るもの: ffmpeg（libx264 入り。ubuntu-24.04 の apt の 6.1.1 で確かめた）、
python3 の numpy・Pillow・budoux（**0.9.3**。無いと止まる。行を割ってよい所が決まらない。版は `qa/linebreak.py` の `BUDOUX_PIN`）・OpenCV（`opencv-python-headless`。5.0.0 で確かめた）、
仮ナレーションに open_jtalk（`open-jtalk open-jtalk-mecab-naist-jdic hts-voice-nitech-jp-atr503-m001`）。
`fetch_fonts.sh` は書体と、顔の見つけ役（YuNet、MIT）の重みも落とす。

**コマは Python を通る。** ffmpeg は復号と符号化だけで、その間で1コマずつ
透かしを切り落とし・顔をぼかし・1080×1920 に収め（ゆっくり寄るもここ）・字を重ねる。
ffmpeg のフィルタだと、寄りが整数の画素に丸められて震え、ぼかしの箱の大きさを
時間で変えられず、テロップの「ポン」が作れなかった（`render.py` の頭）。
30秒で約1分（4コア。復号・加工・符号化を別の糸で重ねている）。

### 本番の素材で回す（企画 → 指示書 → 書き出し → 確かめる）

```bash
python3 tools/shorts/plan/build_edit.py shorts/videos/<id>/p1/spec_A.json \
  --clips <clips>/index.json --voice <voice>/lines.json --bgm <bgm>.mp3 \
  --overrides ov_A.json --blur blur_<id>.json --video <id> --out edit_A.json
python3 tools/shorts/render/face_scan.py edit_A.json faces_A/          # 顔の見落としを探す（決めるのは人）
python3 tools/shorts/render/render.py edit_A.json --out A.mp4 --work A.work
python3 tools/shorts/render/contact_sheet.py A.mp4 A.work A_sheet.jpg       # 行ごとの真ん中の1コマを並べた1枚
python3 tools/shorts/render/render.py edit_A.json --out A_bare.mp4 --work A_bare.work --no-text
python3 tools/shorts/render/safearea.py A.mp4 A_bare.mp4           # 字の画素が安全領域の外に無いか
```

`verify.py` のカット照合は合成素材の箱を読むので、本番の素材では使えない（字幕の出入り・音量・
`--twin` は本番でも意味がある）。

**コマ番号で抜き出す式（`select=`）は `selectexpr.py` で組む。** `verify.py`・`proof.py`・`contact_sheet.py`・
`qa/common.py` が使う。`+` で横につなぐと、ffmpeg 8.1 の枝から入った式の深さの上限（100）で101項から止まる。
`-vsync 0` は 9.0 で消えたので `-fps_mode passthrough` を使う（2026-10-23、PR #1015 の CI の赤。
見張りは `selectexpr_selftest.py`）。

**1案1本。YouTube も TikTok も同じファイルを出す（BGM 入り）。** BGM は**最初のコマから鳴らす**
（あやと F-041「BGM の初めのミュート部分は切ってください」）。曲の頭の無音は書き出しが測って飛ばす
（`render.py` の `bgm_head_silence`。5ms の窓の RMS が「曲の鳴っている間」から −40dB の線を初めて越えた所の 5ms 前から。
線は −70dBFS より下に引かない。mp3 の頭の無音は 0 ではなく −135dB ほどのデコーダの床が鳴っているので）。
ポケットサウンドの「クシコス・ポスト」は 1.42秒を飛ばす。飛ばした秒は `plan.json` の `bgm.head_trim_s`。
回ごとに `start_s` を手で書かない（曲を替えたときに付け忘れる）。頭は1コマ（0.033秒）で上げ（前の 0.3秒だと
最初のコマが −24dB でほぼ鳴らなかった）、終わり 1.2秒で下げて最後のコマでちょうど 0 になる。

**最後の画に注の札「※YouTubeで毎日22時から配信」を出す**（あやと F-042「このCTAテロップ、次から全部入れて」。読み上げない）。
様式の `end_note` を書き出しが足すので、spec にも指示書にも書かない。出すのは最後のカットの頭から終わりまで
（最後のカットが2秒より短ければ、終わりの2秒前から）。見た目と置き場は注（`note`）のまま。前の終わりの注
「※生配信のアーカイブ」は外してこれに替える。同じ時に出る注があれば、下に積む。
守りの見張りは `bgm_cta_selftest.py`（足8本・守り8つを1つずつ外して、その足だけが落ちるかを見る）。曲のクレジットは
画面ではなく投稿の文に書く（いまの曲と書き方は `docs/shorts.md` 4）。BGM 抜きの版が要るときだけ `--no-bgm-out` で同じ絵の2本目を書ける
（映像は書いたものをそのまま写すので、2本の絵は1画素も違わない）。

**BGM の高い側は、ナレーションの間もう一段下げる。** BGM 全体はナレーションの間 12dB 下げる（`duck_db`）。
明るい曲（クシコス・ポストのような弦・シンバル・高い旋律）は、それでも 2〜5kHz で声の子音とぶつかり、
その帯域だけ声との差が 7dB まで縮んだ（全帯域では 15dB 以上あった）。全体をもっと下げると曲の土台
（低音と拍）まで消えるので、BGM を 1.5〜2.5kHz で低い側と高い側に分け（足せば元に戻る）、高い側だけ
さらに `duck_hi_db`（−6dB）下げる。子音の帯域の差は 13dB 以上になった。

**声は1行ずつ揃える。** Fish Audio の声は1文ずつ作るので、行ごとに −28〜−21 LUFS とばらつく。
行ごとに「話している間の RMS」（50ms の窓のうち、いちばん大きい窓から 20dB 以内）を −16 dBFS に合わせる。
全体で1つの倍率だと、行の変わり目で音量が跳ねた。

**声の頭と尻は、声の大きさに対する比で詰める。** 出だしは「その行のいちばん大きい所から −30dB を越えた
最初のサンプル（2.5ms の後ろ向き RMS）」で、その 20ms 前から使う（品質チェック `tools/shorts/qa/` の
測り方と同じ）。20ms は1コマより短いので、行の頭のコマに字幕を出せば声も同じコマで始まる。
前は ffmpeg の silenceremove（−45dBFS）で詰めていたが、Fish Audio の声は頭に息や部屋鳴りが
それより大きく入っていて、詰め残した分だけ字幕が声より先に出た。

**最後に音量を仕上げる。** 束を足したものを、一定の倍率で **−14 LUFS** に合わせ、4倍に上げてから
リミッターで山を抑えて AAC にする。符号化したものを測り、**トゥルーピーク −1.5 dBTP 以下**と
音量 ±0.4 に入るまで、天井と倍率を直して作り直す（AAC は山が 0.5〜1dB 上に出るので）。
loudnorm の動的な合わせ方は、声と BGM の差を時間で変えてしまうので使わない。
倍率・天井・測った値は `plan.json` の `master` に残る。

**品質チェックのための控え。** `plan.json` には、使った様式（`style`）・重ねた字の絵の全部
（`overlays`。テロップの「ポン」の数コマも1件ずつ、x/y/w/h/from/to と PNG）・書き出しの画素での
ぼかしの箱（`blur_out`）も入る。様式の `avoid_faces.enabled` が true（既定）なら、字なしの書き出しは
**書き出しが自分で `work/no_text.mp4` に書く**（顔を探すために1回目に書く版。品質チェックはそれを読む）。
顔よけを切った様式で字なしの版が要るときだけ、時間割を上書きしないように work を分けて書く:

```bash
python3 tools/shorts/render/render.py edit_A.json --no-text --out A.work/no_text.mp4 --work A_plate.work
```

`--no-bgm-out` のときは、BGM 抜きの版の時間割と束（BGM の束は 0）を `--no-bgm-work`
（既定 `<work から拡張子を外した名前>_nobgm.work`）に置く。

### 下書きの段（`--draft`）

中身（字・時間割・顔よけ）を直している間は、本番の書き出しを待たない。

```bash
python3 tools/shorts/render/render.py edit_A.json --draft --out A_draft.mp4 --work A_draft.work
python3 tools/shorts/qa/check.py A_draft.mp4 A_draft.work --draft    # 字幕のずれ・安全域・黒・強調の言い直し
```

- **置き場と時間割は本番と同じ 1080x1920 の座標で決め、コマだけ縦横半分（540x960）で作る。**
  x264 は veryfast・CRF 23・コマ単位の並列（バイト一致は求めない）
- 字なしの版（`no_text.mp4`）は書かない。顔はその場のコマで1コマおきに探し、`work/faces_draft.json` に
  控える。**字だけ直した回は控えを使う**（素材・カット・ぼかし・寄り・画の効果が変われば探し直す）
- `check.py --draft` は下書きを時間割の大きさに広げて測る（`plan.json` の `draft`）。形式（container）は
  本番の大きさで見るものなので回さない。顔・透かし・字と顔は本番の段で
- **出す前は必ず本番の段で書き直す。** 顔よけの置き場は本番と数px ずれることがある（半分の絵で探すと、
  際どい小さな顔の数が変わる。v2 の C で、本番 92コマ・下書き 70コマに顔があり、【大】の字が 2px ずれた）

1コマあたりの CPU（2026-10-17、v2 の C を測った）: 元のコマを収める 59ms → 16ms、x264（medium・
スライス並列）168ms → veryfast 16ms、顔の見つけ役 47ms → 1コマおきで 24ms、字なしの版の符号化と読み直しは無し。

| v2（作業箱。ほかの担当と相乗りで load 4〜11） | 本番 | 下書き |
| --- | --- | --- |
| C の書き出し（36秒） | 302秒 | 92秒（顔の控えを使う回は 59秒） |
| 検査 1本 | 約280秒（14項目） | 47〜69秒（4項目） |
| 3本の1周（書き出し＋検査。本番は双子も） | 約42分 | 約9分（A 179秒・B 197秒・C 161秒） |

同じ画の使い回し（`shot_reuse`）を足し（2つで 42秒の動画に 25秒ほど足した）、2026-10-21 にカットの長さ（`cut_length`）・

決まるので、下書きの段で落とす（本番で見つけると区間の選び直しになる）。止め絵はカクつきと同じ元素材の読み、似た見た目の連続は

使い回しだけ 5.1秒 → 似た見た目の連続と一緒に 6.8秒、カクつきだけ 13.4秒 → 止め絵・カットの長さと一緒に 14.1秒。2026-10-21）。

### Actions で並べる（`remote.py`・`.github/workflows/shorts_render.yml`）— **書き出しの既定はこちら**

**担当がすることは「指示書を置く → 要約（`summary.json` 1つ）と絵を読む」だけ**（#1011。あやと F-044）。
2026-10-21 の担当は、書き出し・20項目の検査・1秒ごとのコマ一覧・字の切り抜き一覧・下見（`put.py`）を手元の4コアで
順に回し、1本 約2時間・30〜70万トークンかかっていた。この道は 10-17 から在ったが、使われなかった。使いにくかった所:

| 使いにくかった所 | いま |
| --- | --- |
| `up` は結果が揃うまで手元を塞ぎ（約10分）、mp4 と work 一式（数百MB）を全部落とした | `--detach` で素材を上げたら手を離す（1〜2分）。`fetch` は要約と目で見る絵だけを落とす（`--all` で全部） |
| 1秒ごとのコマ一覧・字の切り抜き一覧は Actions で作らず、担当が手元の使い捨て（スクラッチパッドの `proof.py`・`sheet.sh`）で作り直していた | 本体の job が `proof.py` で作る（コマ一覧・字の切り抜き・顔の切り抜き・頭の BGM と終わりの札の数） |
| 下見は別の道（`put.py` → `shorts_preview.yml`）で、落とした mp4 を作業枝に暗号文で積んで上げ直していた | report の job が、job が GCS に置いた mp4 をそのまま Hosting のプレビューチャンネルに配る（作業箱を通らない） |
| 結果は品目ごとの検査の合否の数だけで、何が「人が見る」なのかは qa.md を開くまで分からなかった | 要約に20項目の合否と測った値の1行・BGM の頭・終わりの札・下見の URL・絵の置き場が並ぶ |
| 手引き（`production.md`）では「3本の本番は Actions に並べる」で、1〜2本の直しは手元が既定に読めた | 本数に関わらず、本番の段はこちら |

```bash
K=<スクラッチパッド>/keys/ref_private.pem; O=<スクラッチパッド>/remote
python3 tools/shorts/render/remote.py up --detach --name ng-p1-v4 --key $K --out $O edit_A.json edit_B.json
#   … 待つあいだは別の仕事をする（ランナーで書き出し・検査・絵・下見まで、約10分）
python3 tools/shorts/render/remote.py fetch --name ng-p1-v4 --key $K --out $O
#   → $O/ng-p1-v4/summary.json と $O/ng-p1-v4/<id>/<id>.{sheet1s,texts,faces}.jpg
python3 tools/shorts/render/remote.py up --draft --name yk-v3d …                # 下書きの段（下見なし）
```

`summary.json`（`shorts-render-summary/1`）の品目ごとの中身: `sha256`・`seconds`・`frames`・双子の一致・
`qa.checks`（20項目の id・合否・測った値の1行）・`bgm`（飛ばした頭の秒・最初の1秒のコマごとの音量）・
`end_notes`（終わりの札の字・出るコマ・最後のコマに描かれているか＝字なしの版との差）・`preview`（この1本の URL）・
`look`（絵と mp4 の見る URL）・`local`（落とした絵の手元の道）。全体の `preview.page` が下見のページ（7日）。
URL は依頼の公開鍵で包んで返るので、リポジトリには平文で入らない。制作 issue には貼ってよい（下見の README）。
`moved` は顔を避けて動かした字（前の版から道を替えたときに、字の置き場が前と同じかをここで見る）。

**承認を取る版と出す版は、同じ道で書く。** Actions は x264 を cpu-independent で符号化し（下の「同じものが出るか」）、
作業箱の既定は付けないので、同じ指示書でも字なしの版のバイト列が変わり、顔の見つけ役の箱が動いて字が動くことがある。
銅像 p2 は手元で書いた v7 が承認されたあと、v8 を Actions で書くと7行目の字幕が 216px 下へ動いて字と顔の検査が落ちた
（2026-10-21。v8 は手元で書いた版を出した）。地下鉄 p1 は【大】が 2px 動いただけだった。新しい回は最初から Actions で書く。

| 2本（地下鉄 p1 37秒・銅像 p2 42秒）・本番の段（双子・20項目・絵・下見）。2026-10-21 | 担当の手元が塞がる | 起動から要約まで |
| --- | --- | --- |
| 前（2026-10-21 の担当。手元の4コアで順に・コマ一覧と字の切り抜きと下見も手元） | 1本 約2時間 | — |
| r1011-ng4-ckj8（素の checkout・素材 1355MB を初めて上げる回） | 274秒（`--detach` まで） | 1095秒 |

ランナーの内訳（r1011-c）: prepare 3秒 → 書き出し 242〜268秒・検査 146〜159秒・絵 約30秒（本体・双子の4台を並べて、

それぞれ 92秒・85秒かかっていた（下の write-tree）。3回とも、2本の本体と双子の sha256 は同じだった。
担当の手元が塞がるのは `--detach` までの 38秒と、結果が来てからの `fetch`（要約と絵を落とす 3秒）だけ。
**作業枝の先に暗号文が 736MB 載っていて**、素の checkout は prepare で 2分39秒・書き出しの job で 1分30秒かかっていた。
checkout は `filter: blob:none` と `sparse-checkout`（tools/shorts と依頼）にし、push の `write-tree` には `--missing-ok` を付けた
（付けないと write-tree が木の全部の中身を確かめに 889MB を取りに行き、1回の push が 65〜92秒になる。`tools/shorts/preview/branch.py`）。

- 指示書が指す素材・声・BGM を全部集め、**中身の sha256 の名前で** GCS の非公開バケット
  （`render/cas/<sha256>`、#938）に作業箱から直に上げる。同じものは2回上げない（2回目からは0MB）
- **速める声は作業箱で作ってから運ぶ**（`remote.py` の `bake_narration`）。声を速める Rubber Band はランナーに
  入っていないので、作業箱で速めた wav を行の `file`（そのまま使う声）に差し替える。ランナーの道具を足さずに済み、
  声のバイト列も作業箱と同じになる
- 本体の job は書き出し → 検査（20項目を4組に分けて同時に。止め絵はカクつきと、似た見た目の連続は使い回しと同じ組に置き、
  同じ元素材・同じコマを2度読まない。`QA_GROUPS` の名指しに無い検査は
  5つ目の組で回る（`qa_groups`）。検査を足しても Actions で黙って回らないことがないように）→ 帯の絵（`<id>_strips.jpg`）→
  一覧の絵（`<id>.sheet.jpg`）→ GCS に置く。双子の job は同じ指示書を別のランナーで書いて sha256 だけ置く
- 出来たものは GCS に7日（見る URL は要約の `look`）。`fetch` が落とすのは `--out/<name>/<id>/` の
  `qa.json`/`qa.md`・帯・`sheet1s`・`texts`・`faces`・`proof.json` だけ。`fetch --all` で mp4・`plan.json`・`work.tgz` も。
  `work.tgz` を開けば、手元で検査をやり直せる（字なしの版と音の束も入っている）
- **書き出すのは作業枝に push してある版の render.py**。手元で直した道具は push してから回す
  （品質チェック `tools/shorts/qa/` も同じ。道具は運ばず、ランナーが作業枝を checkout したものを使う）
- 取り込みの素材は、どの配信の何秒目かを指示書の素材の欄（`stream`）に写して運び、job が `in/index.json` に
  書き戻す。ランナーでは素材が sha256 の名前で並ぶので、無いと使い回しの検査が「同じ配信の同じ瞬間」を見られず、
  カクつきの検査も差し替える区間を配信の時刻で出せない
- artifact は使わない（公開リポジトリの artifact は誰でも落とせる）
- **「道具を入れる」はコマンドごとに上限を置き、止まったら1回だけ取り直す**（取り込みの `tools/shorts/ingest/retry.sh`・

### 道具が壊れていないかを確かめる（合成素材で）

`make_assets.py` が、コマごとにフレーム番号を白黒の箱で焼いた合成映像を作る。
`verify.py` はその箱を書き出しから読み戻して、指示書のカット位置と1コマ単位で照合する。

```bash
python3 tools/shorts/render/make_assets.py /tmp/sh/assets      # 縦・横の合成映像と BGM（2分ほど）
cp tools/shorts/render/example.edit.json /tmp/sh/edit.json
python3 tools/shorts/render/render.py /tmp/sh/edit.json --out /tmp/sh/a.mp4 --work /tmp/sh/a.work
python3 tools/shorts/render/render.py /tmp/sh/edit.json --out /tmp/sh/b.mp4 --work /tmp/sh/b.work
python3 tools/shorts/render/verify.py /tmp/sh/a.mp4 /tmp/sh/a.work --twin /tmp/sh/b.mp4
```

**x264 はスライス単位の並列にしてある**（`sliced-threads=1`）。コマ単位の並列だと、
箱が混んでいるときだけ別のバイト列が出た（同時に3本回して1本違った）。
ffmpeg の版が変わればバイト列も変わる。照合とダッキングの検査は版に依存しない。

**字幕は声の長さから決まる。** 行ごとの声の頭と尻の無音を詰め、声が鳴っている間（＋6コマ）だけ出す。
だから字幕と声は同じフレームで始まる。次の行が12コマ以内に始まるなら、そこまで出したままにする
（消えるのと画が変わるのが同じコマになる。7コマだけ消えてまた出る、のちらつきも無くなる）。
2行に収まらない字幕は、文ごと（長ければ「、」ごと）に何枚かに分け、切り替えを**声の間**に合わせる
（字数の比で見当をつけ、いちばん近い「間のあと声が出るコマ」へ寄せる）。

## 字の置き場（タイトル・テロップ・字幕）

画面に出す字は3種類だけ。縦に重ならないように、置き場を固定している。

| | 置き場（1080×1920） | 形 |
| --- | --- | --- |
| タイトル | y=380 から（2行で 380〜640） | 黄色の角丸の箱に黒い太丸ゴシック。全編 |
| テロップ | タイトルの下端＋20 〜 字幕2行ぶんの上端−20（660〜869）の**真ん中** | 黄色い字・黒の太い縁・下に影。数字だけ 1.3倍。出だしの5コマで「ポン」と出る（0.7→0.92→1.06→1.02→1.0）。**動画の1コマ目からのテロップは「ポン」しない**（1コマ目は字が出きった絵にする） |
| 字幕 | 中心 y=1000（2行で 889〜1110） | 白い字に黒の縁（箱は敷かない）。文節で2行まで（文節が幅に入らなければ、割らずにその行の字を小さくする。`fit_size`）。`highlight` の言葉だけ黄色で 1.12倍（幅に収まらなければ大きさはそのまま） |

- テロップの帯の高さは、**字幕が1行でも2行でも同じ**にしている（行数で動くと目が迷う）

- 帯の下端（869）は右のボタン列（y≥840）に掛かる。テロップの幅が 696 を超えるときは、840 より上に寄せる
- `inset`（札）はテロップと同じ帯を使う。だから札のカットにはテロップを出さない（`build_edit.py` が外す）。
  北マケドニアの回のメニューは「280 Lekë」の行がどのコマでも素材の上の端（y 20〜113）にしか無く、
  画面いっぱいに寄ると、その行は画面の上の UI の帯に入る（素材の外は見せないので、真ん中へは運べない）。
  だから、メニュー全体を後ろに敷いたまま、幅いっぱいの縁なしの帯（タイトルの下 650〜）で行を拡大し、
  手ぶれを `keys` で追う。値段の字は元で 13px なので、帯の倍率を 3.1 以上（元の幅 345px 以下）に保って
  **40px 以上**にする。字幕が2行の行は、帯を字幕の上端（889）より上に収める

  終わるコマ＝次の行の字幕が出るコマで、カットで消す（4秒は上限。参考のショートも題は 2.3秒で、最初の字幕と同じコマで

  代わりに上の置き場を使う。札はその行（1行目）の字幕を兼ねるので、1行目の字幕は出さない（同じ言葉を2回出さない）。
  ただし**札が1行目と別の言葉**のとき（あやと F-043。札「🇫🇷 フランスを10日レンタカー旅してみた！」・1行目「フランスに行ったら、10日で…回れた！」）は、

    書く（`build_edit.py` が指示書の行へ、書き出しが時間割の字幕と重ね物へ写す）。品質チェックはその行を書いたコマ数まで
    通し、超えたら落とす。コマ数は「いま重なっているコマ数」を書く（例外が黙って広がらないように）。
    `"keep_size": true` を足した行は、顔を避けるために小さくしない（顔の誤検出のために字が 36px まで縮むのは逆効果、
    と統括が決めた C17 の床と扉。2026-10-17）

## 感情の字幕（spec の行の `mood`）

字は3段: ふつうの字幕（事実の行）・**感情の字幕**・【大】の字。感情の字幕は字幕と同じ置き場（縦のまん中、顔は下へ）に
60〜72px で出し、書体・色・縁・動きは様式の `moods.looks[mood]` で決まる（あやとの直し #926「もっと感情に合わせて
フォントとか色変えて欲しい」を受けた割り当て）。カットで出て消え、動きは出ている間だけ。

**v3（`style_v3.json`。北マケドニアの B・C から）では、書体を1つ・色を2系統にまとめ、キラキラをやめた**（あやと #926、
2026-10-16 23:31 UTC「キラキラは男のショートには合わない」「字幕のフォントのバリエーションが多すぎる」「なんの感情もない
ナレーションは基本の字幕で良い」「感情ある系もある程度系統束ねて色のばらつきを抑えて欲しい」「大きさとかアニメーションは
色々変えて良い」）。感情の動かない行は `plain`。大きい字の色も白・黒・黄・赤だけ（d3 は黄の字に茶の縁と淡い黄の光、
d2 は白い字に黒縁で止まったまま）。下の v2 の表（`style_p3.json`）は、v2 のまま出した A のために残してある。

- 幅は、出る動きでいちばん大きくなったとき（弾む字は 1.06倍）にも右のボタン列に掛からないように測る
- 震える・弾む字は、頭の2コマを同じ絵にする（品質チェックは同じ絵が2コマ続くことで字幕が出たと読む）
- **キラキラ**（`sparkles`。喜びとピンクの大きい字 d3）: 字の見える箱を `margin_em` だけ広げた中に、白〜淡い黄の四角い星を
  `count` 個、それぞれ `period` コマで瞬かせる。字のかたまりの楕円（`core`）の中には置かない。乱数の種は行の字で決まる。
  明るい地で溶けないように金色の光（`glow_color`）で縁取る。安全領域（右のボタン列も）から出ないように切り、
  **字なしの書き出しには入れない**（置き場が字に付いているので、顔を探す前の版と位置が合わない）

## 字の見た目と動き（すべて様式の JSON で決まる）

書体・字の大きさ・縁（何重でも）・塗り（色の段のグラデーション）・発光・かすれた地・影・地の箱・字間・行の送り・
出入りの動きは、コードに書かず様式に書く（`textlook.py` がそのとおりに描く）。参考の動画に合わせるときは
様式だけを差し替える。動画ごとの違いは `"extends": "style.json"` で差分だけ書いた様式を作り、
`build_edit.py --style` で指定する（例: `style_p3.json`。参考のショート HPJrXDpkfuo を測った値を入れてある）。

```json
"look": {"fill": {"stops": [[0.0, "#FBEE1E"], [0.35, "#FDFCA1"], [0.75, "#FDE103"]]},
         "outline": [{"color": "#EF0101", "width_em": 0.057}, {"color": "#000000", "width_em": 0.079}],
         "glow": {"color": "#EBD050", "half_px": 16, "extent_px": 35},
         "tracking": -0.07, "line_pitch_em": 1.105},
"anim": {"in":   {"frames": 13, "first_hold": 2, "scale": {"keys": [[0, 0.29], [8, 1.09], [12, 1.01]]}},
         "hold": {"type": "shake", "first_hold": 2, "dx_sd": 13.5, "dx_max": 21, "dy_sd": 19, "dy_max": 36}}
```

- `look` は `caption`・`title`・`title_card.lines[]`・`note`・`big.looks.*` のどれにも書ける（古い `color`・`stroke`・`strokes` も読む）
- 縁（`outline`）は字の輪郭から外へ、内側の層から順に。幅は px（`width`）か字の大きさに比例（`width_em`）。
  `rough` で外側をざらつかせる。発光（`glow`）は「半分になる距離・消える距離」か、輪郭からの距離ごとの色の段。
  `backing` は字のまわりのかすれた地（筆字の白いスプレー）。縁と発光は字の形からの距離を2倍の細かさで測って塗るので、
  4.5px のような半端な幅もそのまま出る
- 参考の字は M PLUS Rounded 1c Black より字の高さの約1%太い。塗りと同じ色の 0.75px の縁を内側に足して寄せている
- `anim` の値は2つなら `ease` の曲線で `frames` コマかけて、`frames` 個並べればコマごとの値そのもの、
  `{"keys": [[コマ, 値], …]}` なら計測した曲線をそのまま直線でつなぐ。動かせるのは `scale`・`alpha`・`dx`・`dy`・
  `rotate`・`sharp`（1 でくっきり、0.15 で字の高さの1割ほどぼける。`sharp_blur_em` で変える）。
  `hold.type = shake` は、出ている間ずっと位置だけを毎コマでたらめに跳ねさせる（乱数の種は字で決まるので、書き出しは毎回同じ）。
  `first_hold` は最初の状態を何コマ続けるか（2 にしておくと、品質チェックが「同じ絵が2コマ続いた所」で字幕の出を読める）
- 濃さが 1 より小さい途中の絵は、品質チェックが不透明な画素で字の位置を探せない。`plan.json` の `overlays` ではなく
  `overlays_anim` に控える（安全領域は字なしの書き出しとの差で、薄い字も含めて確かめられる）。
  薄い所から現れる見た目には `pre_roll_frames` を書く。`build_edit.py` が行の頭にそのコマ数を足し、字がほぼ出たところで声を出す
  （声の頭で字が読めないと、字幕と声がずれる。オチの前のひと呼吸にもなる）。品質チェックが「出た」と読むコマは地の明るさで
  前後するので（白い字は白い地の上で早く読まれる）、明るい地と暗い地の両方で ±1コマに入る値にする。d3 は 8（理由は style の `_pre_roll`）
- 【大】の行の見た目は spec の行の `big_style`（`big.looks` の名前）。`speedlines` を書いた見た目は、集中線（画の効果。
  字なしの書き出しにも入る）を重ねる。見た目ごとに `font`・`size`・`min_size`・`wrap_below`・`fold_floor`・`max_lines` を書ける。行を割ってよい所は、品質チェックの `qa/linebreak.py` を写さずに読む（budoux の文節の切れ目から、数と単位・関西の打ち消しと言い切り（「貢献して｜へんて」）・弱い仮名どうし・仮名1字・禁則・国旗・語の帳面を除いたもの）。前は budoux の文節に節の終わり（〜たら）と「カタカナの語｜ひらがな」の切れ目を足していて、「北マケドニア｜さん」「中身スカスカ｜やないかい」と割れた。品質チェックの `line_breaks` が、書き出しが選んだ割れ目を同じ決めと突き合わせる
- 題の札（`title_card`）は題の改行ごとに `lines[k]` の見た目で積み、`max_height` に収まるまで小さくする
  （下の字幕の置き場と、右のボタン列（y≥840）に掛けないため）。発光は箱の余白に広がってよく、箱の縁で切る
- **国旗**: 字の中の国旗の絵文字（🇦🇱）は、`flags/<小文字の2字>.png` を1字ぶんとして置く（書体に絵文字の字形が
  無いので、字としては豆腐 □□ になる）。高さ 0.82em・角を丸め・内側に細い白い縁（黒い箱の上でドイツの黒い帯が
  消えないように）。国旗もその行の字と同じ縁・発光・影を受ける。数は look の `flag`（既定は `textlook.py` の
  `FLAG_DEFAULT`）。折り返しは国旗の中・直後で割らない（国旗は後ろの国の名前と1つの塊）。絵の無い国は豆腐を焼かずに
  止まり、`flags.py add XX` を言う。`remote.py up` も上げる前に、絵が無い・git に入っていない国旗で止まる。
  テロップ（`telops[]`）は別の描き方なので国旗を置けず、書くと止まる。国旗の無い字は、入れる前と1画素も変わらない
  （2026-10-21、3つの様式の題・字幕・【大】の 123 通りを直す前の版と比べた）。絵の出どころと許諾は `flags/README.md`
- 書体は `fonts` の名前か、`fonts/`（または `SHORTS_FONTS_DIR`）に置いたファイル名をそのまま書ける。
  Kaisei Tokumin ExtraBold（揺れ・筆の拡大）は `fetch_fonts.sh` が sha256 を確かめて落とす
- BGM の大きさは `audio.bgm_rms_dbfs`、ナレーションの間の下げ幅は `audio.duck_db`（高い側の追加は `duck_hi_db`）。
  `audio.bgm_level` は BGM のゆっくりした大小をならす（参考の BGM は ±1.5dB で一定だった。行ごとの「声 − BGM」がそろう）

## 顔のぼかし・透かし

- **透かし（PRISM Live）は切り落とす。** 18窓・273コマの「どの場面でも明るい画素」の外枠が
  720×1280 で `[405, 1204, 270, 39]`。その帯より12px上（y=1192）から下を捨て、cover で左右を切る。
  ぼかしや描き埋めと違って跡が残らない。捨てる帯（下の 7%）はどのみち説明文とチャンネル名で隠れる。
  切り落とせない素材には `"mode": "inpaint"`（周りから描き埋める）もある
- **顔は、モザイクにしてからぼかす。** ぼかしだけだと目鼻の位置と肌の色が残り、知っている人には分かる。
  箱の短い辺を `cells` マスにして、マス目が見えなくなるまでぼかす。縁は外側にだけ広げて馴染ませ、角は丸める
- 箱を決めるのは人。`face_scan.py` は見落としを減らす道具で、指示書の各カットを YuNet に通し、
  「同じ人」の列にまとめ、箱に覆われていない顔を赤で出す。看板・お菓子の箱・タイヤも顔と言うので、
  **絵を見て決める**。決めた箱は動画ごとの帳面（元動画の時刻で書く）に置き、`build_edit.py --blur` で
  どの案のカットにも当てる（同じ店・同じバスを3案が使い回しても、1回決めれば効く）
- **大きな面でぼかさない。** バスの横の窓ごと・通路の奥の頭の帯ごと潰すと、画が壊れて見える。
  先に「顔の写らない画・顔が写る前で切る」を選び、それでも残る顔だけを、顔の大きさの箱で
  コマごとに追う（暗い通路は明るくしてから低いしきい値で拾い、人ごとにつないで `keys` にする）

`--work` に `plan.json`（できあがりの時間割）が残る。人が直す画面や、
ほかの書き出し先は、これを読む。

## 企画から指示書を組む（`tools/shorts/plan/build_edit.py`）

企画の `spec_X.json`（絵コンテの行）＋取り込んだ窓の `index.json`＋声の `lines.json` → `edit_X.json`。

- 1行の長さ ＝ 声の長さ（詰めたもの）＋ 0.25秒 ＋ `hold`。最後の行だけ `--tail`（既定0.5秒）足す。
  最後の声のあと、字幕が消えてから画だけが 0.5〜0.8秒残る（締めの間）
- 元動画の時刻が2つある行は2カットに分ける。ナレーションが2文なら、1文目が終わった**声の間**で切る
- 「上（全編）: …」がタイトル、「中央: …」がその行のテロップ。演出に「寄る」があれば、そのカットをゆっくり寄せる。
  「順に」があれば、テロップを言葉ごとに、ナレーションでその言葉を言うあたりで足していく
- カットの入りは、spec の時刻を窓の頭からのコマ数に直したもの。窓や `until` を越えるなら前にずらして知らせる
- spec の `same_as_prev`（絵コンテの「同上」）の行は、前の行の画をそのまま続ける（元動画の次のコマから。
  寄り・明るさ・札も引き継ぐ。引き継がないと、つなぎ目で寄りが外れて隠していた顔が出る）
- spec の `orig_voice` の行（帳面 F-051「叫びは配信の本人の声で」）は**元の声の行**。声の一覧にその行のぶんは要らない
  （`brief.py edit --voice-lines` も作らない）。カットと同じコマの元の音をつないだ wav を声の行の `file` にする
  （カットの `audio_db` で鳴らすと、BGM がその間だけ下がらず、元音声の漏れの検査も落ちる）。画と声を同じ秒から取るので、
  その行のカットは `len` か区間の `t` で長さを決め、窓や `until` に合わせて入りをずらさない（越えるなら止まる）。
  喋る速さの倍率には数えない。16bit に書くと割れる頂点（1.0 越え）は 0.9 まで下げる
- spec に `title_card` があれば、`card` の行のナレーションに重ねて頭の `title_card_seconds` 秒だけ題の札を出す。
  `big` の行は【大】の字幕、`corner_note` は小さな注になる
- spec の `caption_parts`（`[{"text": 前置き}, {"text": オチ, "big": true}]`・`{"text": チャットの文, "mood": "chat"}`）は、
  指示書の `narration.lines[].parts` になる（上の「編集指示書」）。前半はふつうの字幕・後半だけ【大】、
  前置きはふつうの字幕・チャットの文だけコメントの札、のように1行の中で見た目を替える。その行の【大】の前の間は取らない
- **喋る速さ**: spec の `narration_cps_target`（毎秒の字数。伸びているショートは 8.7〜9.2）に合わせ、
  動画に1つの倍率で声を速める。倍率 ＝ 詰めた声の長さの合計 ÷（喋る字数 ÷ 目標）。喋る字数は句読点・記号・
  空白を数えない。倍率の上限は様式の `narration.max_tempo`（いま 1.4）を読む（`--max-tempo` は渡さなくてよい。渡せばそちら）。
  要る倍率が上限を越えたら上限で読ませ、そのときの尺（行の長さと同じ足しかた: 声＋行の間＋`hold`＋【大】の前の間＋末尾）を見積もる。
  **59秒を越えるなら、指示書を書かずに終了コード 2 で止まる**（出る字の例:「上限 1.4 でも 61.8 秒になる。60秒未満にするには、字を約 7% 減らす（あと 23 字）」）。
  越えなければ「上限で止めた」の注意を1行出して上限で組む（目標の速さに届かないのは正しい。倍率を上げずに原稿の字を減らす）。行の間は `--gap`（伸びているショートは 0.1〜0.15 秒）。
  `--max-pause` を付けると、速めたあとの行の中の間（その行のいちばん大きい所から −35dB より小さい所）も
  その秒数までに縮め、縮めたぶん倍率を下げて目標の速さに合わせ直す。
  倍率と、できた速さ（声の間だけ・動画全体）は `meta.speech` に残る。
  声の大きさは速めたあとの行で揃える

### テロップを出すか

同じことを2回も3回も字で見せない。テロップの言葉を1つずつ（空白・矢印・＝・括弧で切る）見て、
その行のナレーションかタイトルに、3文字以上続けて同じ並びがあれば「もう言っている言葉」とする
（NFKC・小文字・記号と「約」を落として比べる。2文字の言葉は2文字のまま比べる）。
**言葉の6割以上をもう言っていれば、テロップは出さない。** 代わりにその要の言葉
（数字を含む言葉があればそれだけ。3つまで。直前の「約」は含める）を字幕の `highlight` に入れて、
字幕の中で黄色く大きくする。
足しているもの（本人のことば、アルバニア語の意味、国の矢印）だけがテロップに残る。
`edit.json` の `meta.rows[].telop` に、比べた割合と出したかどうかが残る。
人が決めたいときは overrides の `telop_keep`（`true` / `false`）と `highlight` で上書きする。

spec に書けないこと（どの画を使うか・どこに寄るか・誰の顔をぼかすか）は overrides と帳面に書く。時刻は元動画の時刻。

```json
{"rows": {"3": {"telop": "", "telop_cuts": [1], "hold": 0.4, "cuts": [
  {"t": "0:48:46.0", "len": 2.0, "until": "0:48:48.0", "inset": {"rect": [175, 15, 530, 140]}, "note": "なぜこの画か"},
  {"t": "0:58:03.0", "until": "0:58:05.4", "zoom": {"to": 1.1, "x": 0.5, "y": 0.75}, "share": 0.5, "audio_db": -14}]}}}
```

| 欄 | 中身 |
| --- | --- |
| `cuts[].t` / `until` | 使い始める時刻と、それより後ろを使ってはいけない時刻（指が映る・場面が変わる） |
| `cuts[].len` / `share` | 長さを秒で固定 / 行の中での割合（全カットに書いたときだけ効く） |
| `telop` / `telop_cuts` | テロップの文字を差し替える（`""` で出さない）/ 出すカットの番号 |
| `telop_keep` / `highlight` | テロップを出すかを人が決める / 字幕で目立たせる言葉を人が決める |
| `cuts[].zoom` / `gamma` / `inset` | 指示書の同じ欄へそのまま入る。`inset.keys` だけは時刻（`"t"`）で書き、窓のコマ番号に直す |

帳面（`--blur`）は `{"regions": [{"from_t", "to_t", "rect" か "keys": [{"t", "rect"}], "cells", "note"}]}`。
箱は元素材（720×1280）の画素。そのカットに掛かる時間のぶんだけ、指示書の `cuts[].blur` に入る。

## 様式（style.json）

全ショートで使い回す。書体は M PLUS Rounded 1c（タイトル ExtraBold、字幕 Black）。
あやとの既存ショートのテロップ（黄色地に黒の太い丸ゴシック・白に黒縁）と
並べて比べて、いちばん近かったもの。
