# 足す前に、設計の関所を通す

**あやとから「こういうのをやりたい」「こういうページが欲しい」が来たら、作る前にここを通す。**
決めた理由は `docs/adr/0008-feature-design-gate.md`。仕様は `docs/spec/model.md`（種類と関係）と `docs/spec/routes.md`（道）。

通す対象: 新しい面・新しい道の型・新しい表（`site/content/*.ts`・Firestore の箱）・机の道具・口（`/island-api/*`）・島の建物。
通さなくてよいもの: 既に在る表に行を足すだけ（料理1品・街の話題1本・国1つ）、文言の直し、見た目の直し。

---

## 1. 先に仕様を読む

`docs/spec/model.md` の3章（種類の表）と、`docs/spec/routes.md` の2章（道の表）。**思い出で答えない。**

## 2. 3つの問いに、1行ずつ答える

| 問い | 答えの形 |
| --- | --- |
| **主語は何か** | 種類の表のどれか1つ（国・街・街の話題・滞在・旅・旅の1日・企画・配信の型・月・料理・アプリ・グッズ・カード・住人・お題・付箋） |
| **主語は1つか** | 1つ。2つ出たら、2つに分けて、それぞれに問い直す |
| **ほかの切り口とは、何の鍵で結ぶか** | 名前の鍵（国・街・旅・企画の slug）か、日付。ほかの結びかたは使わない |

## 3. 枝を選ぶ

### 3-A. 既に在る種類に入る（ほとんどがこちら）

**表に行を足すだけにする。** 新しい面の型・道の型・建物・表・机の道具を作らない。

- どの表に、何の行を足すかを書く
- その種類の面が、足したい姿（たとえば「行く前の旅」）をまだ持っていないなら、**その種類の面を育てる。** 別の面を建てない
- 仕様は変わらないので、決定の記録は要らない

### 3-B. 既に在る種類に入らない

**作る前に、決定の記録を1枚書き、仕様を直す。** 順番を逆にしない。

1. `docs/adr/` に1枚（雛形は `docs/adr/README.md`）。なぜ既に在る種類で足りないか・新しい種類の定義・主キー・鍵・持ち主・道・どの入口の下か・捨てた案
2. `docs/spec/model.md` の種類の表と、`docs/spec/routes.md` の道の表に行を足す（同じ PR）
3. それから 5 へ

### 3-C. あやとが何を求めているかが分からない

主語が決まらない・出来上がりが何に見えるかが言えないときは、**自分の読みで埋めない。** issue で聞く（`/ask-ayato`）。聞くときは、3-A で作るとこうなる・3-B で作るとこうなる、を並べる。

## 4. 足す前のチェック

1つでも「いいえ」なら、設計を直す。

- [ ] 面は、種類をちょうど1つ持つ（`model.md` M-2）
- [ ] 道は、種類の接頭辞と名前だけで出来ている。状態・旅・入口の名前が入っていない（`routes.md` R-1 R-2）
- [ ] 同じ事実・文章・数字を、2か所に書かない。持ち主は1つ（`model.md` M-20）
- [ ] ほかの種類とは、名前の鍵か日付で結ぶ。リンク先の直書き・文字の一致で結ばない（M-6）
- [ ] 終わりの日を見立てで書かない（M-22）
- [ ] 「いま・これから」のための面や建物を作らない。表紙が言う（M-31）
- [ ] 入口は9つのまま。増やすなら 3-B（`routes.md` R-20）
- [ ] 視聴者さんが口を出す先は付箋（お題）。別の投稿の仕組みを作らない
- [ ] 画面で、仕組みの説明をしない（`CLAUDE.md`）

## 5. 作業にする

- issue を立てる。本文は `/hand-off` の型（合格の条件・確かめかた・触ってよい範囲・出しかた）。合格の条件に、仕様の条の番号を書く
- 3-B のときは、決定の記録と仕様の PR を先に出す。作る PR はそのあと
- 出す前に `python3 python/route_spec_selftest.py` と `python3 python/docs_index_selftest.py` が通ること

## 6. あやとへの報告

1行目に「何の種類として、どこに入れたか」を書く。新しい面・道・建物を足さなかったなら、そう書く。

## 例: 「インドを回る旅を、来年の1月から予定している。意見がほしい」

| 問い | 答え |
| --- | --- |
| 主語は何か | **旅**（これからの旅） |
| 主語は1つか | 2つ。旅そのものと、意見を集める先。意見の先は**お題** |
| 鍵 | お題は、旅を名前の鍵で指す。行き先の国が決まったら、滞在の表に予定の行（着く日）を足す |

枝は 3-A。

| 足すもの | どこに |
| --- | --- |
| 旅1行（名前・始まる予定の日。終わりは空） | 旅の表 |
| お題1つ（「インドでこれやって・ここ行って」） | お題の表。旅を指す |
| 決まった行き先から、滞在の予定の行 | 滞在の表 |

- 面は `/island/india`。**旅の島の「行く前」の姿**として出す。表紙の「これから」には、ひとりでに出る
- **足さないもの**: `/india` のような直下の道、企画の面、専用の投稿フォーム、建物
- 「インドのカレーを食べ歩く」を名前のついた挑戦としてやるなら、それは**企画**。企画の表に1行足し、旅と期間で重ねる
- 旅の島が「行く前」の姿をまだ持っていなければ、旅の面を育てる。仕様（`docs/island-atlas.md`）に1条足すなら、決定の記録を1枚

## 例: 「配信1回ごとのページが欲しい」

| 問い | 答え |
| --- | --- |
| 主語は何か | **配信1回**。種類の表に在るが、面を持たない種類 |

枝は 3-B。面を持たせるのは仕様の変更なので、決定の記録（なぜ YouTube へ出るだけでは足りないか・道は `/streams/<型>` とぶつからないか・videoId の表を1つにするか）を先に書く。
