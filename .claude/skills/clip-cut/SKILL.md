# 切り抜き候補を出す

**出すのは「どこを切るか」まで。** 動画の編集はこの箱ではできない。
あやとは長めに切ったものを受け取って、自分でテンポと字幕をやる（#153）。

**旅の最中にスマホから呼ぶもの。** 引数は基本ゼロ。返すのは5本ぶんの
タイムコードとリンクと1行ずつの説明で、読み上げて分かる長さにする。

## 1. まず、素材があるか

コメントの置き場は2つある。**配信からの経過時間で変わる。**

| いつ | どこ | 誰が入れる |
| --- | --- | --- |
| 配信中〜その日 | Firestore `streamChatMessages` | `collectLiveChat`（5分おき） |
| 翌日以降 | BigQuery `chat_messages` | 毎晩の `fetch_chat_data`（yt-dlp） |

**アーカイブのチャットは YouTube 側の都合で1日ほど遅れて出る。** 配信の
当日に切りたければ Firestore しかない。取り込み待ちの配信は `videos.status`
が `WAITING` で、`chat_messages` に1件も無い。

素材があるかは BigQuery に1本聞けば分かる（**必ず日付で絞る**）:

```sql
SELECT video_id, status, actual_start_time
FROM `live-streaming-d3cac.youtube_chat.videos`
WHERE actual_start_time >= TIMESTAMP_SUB(CURRENT_TIMESTAMP(), INTERVAL 5 DAY)
ORDER BY actual_start_time DESC LIMIT 10
```

## 2. 候補を出す

GitHub Actions の「管理スクリプトを実行」を `workflow_dispatch` で回す。

| 入力 | 値 |
| --- | --- |
| script | `clip_cuts` |
| args | `{}` — いちばん新しい配信 |
| | `{"video":"<id>"}` — 配信を指定 |
| | `{"source":"live"}` — 配信当日、Firestore だけ見る |
| | `{"top":5,"sec":60,"lead":20,"show":12}` — 本数・長さ・前倒し・出すコメント数 |

**`fetch_chat_data`（Fetch YouTube Chat Data）は手で起動しない。**
毎晩 `YOUTUBE_COOKIES` を書き換えるので、定期実行とぶつかると壊れる。
ここで回すのは `run_admin_script.yml` だけ。

出るもの（1本あたり）: 切り出す区間 / `https://youtu.be/<id>?t=<秒>` /
コメント数・人数・笑いの数と平均の何倍か / 編集用に長めの区間と
`yt-dlp --download-sections` の指定 / **その時間帯のコメント本文**。

選び方は `python/admin/clip_cuts.py` の頭に書いてある。要点だけ:

- はじめの1分と終わりの3分は外す（あいさつが重なるだけ）
- 3人以上・8件以上・その配信の平均の2倍以上に届いたものだけ。
  **届かなければ本数を減らす。数合わせをしない**
- 1人が連打しても3件までしか数えない
- 笑い（`www` `笑` `草` 笑い系の絵文字）は3倍に重く見る。
  **ただし笑いの印が書かれない笑いの場面がある。** 2026-09-07 でいちばん
  面白かった「9割種言うてたやん」には w も 笑 も入っていない。
  **数えて出てくるのはここまで。残りは次の章で拾う**
- **山の 20秒前から切る。** コメントは出来事の後に来るので、
  山の頭で切るとオチだけの動画になる

## 3. コメントを読んで、1行を書く

**ここが本体。** 山は「何かが起きた」の目印でしかない。数字だけ並べたものは
成果物にならない。出たコメントを読んで、候補ごとに
**「何が起きていたか」を1行**で書く。書けなければ、その候補は落とす。

読むときの手がかり:

- **同じ言葉が別々の人から続く**（「ストップ！」「9割種言うてたやん」）→ 掛け合い。
  **数え上げでは出てこないことがある。** 3人が同じツッコミを重ねても、
  30秒に3件では山にならない。**通読して自分で足す**
- 笑いが集中している → 事故・ボケ
- 質問が重なっている → 説明の場面。**切り抜きには向かない**ことが多い
- スパチャの直後 → お礼の拍手が並ぶだけのことがある。中身を見る

## 4. 返し方

あやとに返すのは、1本につきこの4つだけ。

```
[1] 1:00:20〜1:01:20  https://youtu.be/xxxx?t=3620
    ミキサーが分解できず悪戦苦闘。「バキっといきそう」で総ツッコミ
    コメント 24件 / 7人（平均の 7.4倍）
    長め: 0:59:50〜1:01:50
```

**ずれる前提で渡す。** コメントは出来事の1〜2分後に来ることがあるので、
「長め」のほうを渡して、そこから詰めてもらう。こちらで詰めると、
前置きの消えたものを渡すことになる。

## 5. 溜まっていなかったら

`clip_cuts` が「コメントが1件も無い」で終わったとき、**原因を憶測で書かない。**

```
script: functions_log
args:   {"name":"collectLiveChat","hours":36}
```

`collectLiveChat` が自分で書いたログが出る。どれかが並んでいるはず。

| ログ | 意味 | 次にやること |
| --- | --- | --- |
| `Doneru の鍵がまだ入っていません` | `islandUsers` の admin に `doneruKey` が無い | あやとに `/me` から入れてもらう |
| `トークンが取れません` | 鍵はあるが Doneru が返さない | 鍵が古い。入れ直してもらう |
| `いま配信していません` | 正常。配信中でないだけ | 配信中に見る |
| `N件 足した` | 動いている | Firestore を数える |
| 1行も無い | そもそも起動していない | Functions のデプロイを確かめる |

Firestore の件数は `collections_audit`（入力なし）で数える。
`streamChatRuns` / `streamChatMessages` がコレクションごと無ければ0件。

**溜まっていない日ぶんは、あとから取り返せない。** 翌日 BigQuery に
アーカイブのチャットが入るので、そちらで切る。
