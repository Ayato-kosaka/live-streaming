# 配信の議事録（stream-notes）

AI が「あの配信で何があったか」を少ないトークンで知るための記録を作る。
**読み手は AI**（月末の授賞式を作る担当など）。視聴者さん向けの文章ではない。
だから**事実を密に、飾らず**。あとで「あの話どの回？」を引けるように、
固有名（場所・店・食べ物・金額・人の名前）と時刻を残す。

決まりの出どころは #965（置き場・長さ・順番はあやとと決めた）。

## 0. 置き場

```
streams/
  manifest.tsv                         # 1配信1行。字幕の状態・字数・件数（Actions が書く）
  2026/10.md                           # 月の目次（このスキルの道具が機械で作る）
  2026/10/
    2026-10-18_2202_TDArug_te90.transcript.txt   # 自動字幕（Actions が書く）
    2026-10-18_2202_TDArug_te90.chat.txt         # チャット（Actions が書く）
    2026-10-18_2202_TDArug_te90.md               # 議事録（このスキルで書く）
```

材料（transcript / chat）が入る仕組みは `streams/README.md`。**材料は手で直さない。**

## 1. 手順

1. **まだ議事録の無い配信を出す。**
   `python3 python/stream_notes.py pending --month 2026-10`（`--month` を外すと全部、新しい順）
2. **1本につき1人、エージェントに配る**（下の §3 の依頼文）。一度に6人まで。
   エージェントは `.md` を書くだけで、コミットしない
3. **確かめる。** `python3 python/stream_notes.py check --month 2026-10`
   字数・見出し・投げ銭の件数（chat.txt の額付きの行と一致するか）・時刻の範囲を見る。
   落ちたものは同じエージェントに理由を渡して書き直させる
4. **月の目次を作る。** `python3 python/stream_notes.py index --month 2026-10`
   各議事録の見出しと「ひとことで」から `streams/2026/10.md` を作る（手で書かない）
5. コミットして push（「なぜ」を書く。何本足したか）

**順番は新しい月から遡る**（月末の振り返りにすぐ効くから）。

## 2. 議事録の形

長さの目安は **本文で約4,000字（3,400〜4,800字）**。本文は、頭（`# ` の題の行と直下の `- ` の行）を除いた字数。
ただし**字幕が短い回は短くする**——目安は字幕の字数の25%（上限4,000・下限600字）。
字幕 16,000字以上なら4,000字、8,000字なら2,000字。中身の無い字で膨らませない。
**長時間の回は伸ばす**——字幕が4万字を超えたぶん、2万字ごとに1,000字足す（上限8,000字）。
字幕 6.7万字なら約5,350字、10.7万字なら約7,350字。4,000字に押し込むと、決めた理由（漏れ）がそのまま起きる。
式: `c≤40000: min(4000, max(600, c×0.25))`／`c>40000: min(8000, 4000 + (c−40000)×0.05)`

```
# 2026-10-18 22:02 北マケドニアで城塞みにいこ！
- URL: https://www.youtube.com/watch?v=<id> / 長さ 3:08:30（字幕の最後の時刻）
- 場所: 国・街（その日に回った場所を順に）
- チャット 570件
- 投げ銭 11件（¥6,440＋$2.00）: 名前 額・額／名前 額 …（chat.txt の額付きの行を全部）

## ひとことで
（1〜2文。月の目次にそのまま載る）

## 流れ
### [0:00:00] 見出し
何をして・何を話したか。チャットがどう反応したか（目立つコメントは @名前「本文」を短く）。
細かい出来事は「- [0:06:30] …」の箇条で足す。

## 視聴者さん
（よく話した人・初見・投げ銭した人・名前を呼ばれた人・通話に出た人、を一言ずつ）

## 持ち越し・決まったこと
（次回やると言ったこと・約束・企画・あやと島に上げると言ったもの。無ければ「なし」）
```

見本：`streams/2026/10/2026-10-18_2202_TDArug_te90.md`（あやとが「4,000字ないと漏れが多い」と言って決めた版）。

### 書くときの決まり

- **字幕とチャットに無いことを書かない。** 推し量ったことは「〜らしい」と書く
- **自動字幕の誤変換をそのまま写さない。** 文脈・チャット・地名で読み直す
  （「オタまジ」→トビリシ、「チャッピー」→ChatGPT、「綾島」→あやと島）。読めない語は書かない
- **時刻は字幕の時刻。** チャットは話より10〜30秒遅れて付く
- **投げ銭は chat.txt の額付きの行を全部数えて**、件数と合計を合わせる。
  チャットの外で告知された投げ銭は「別に告知あり」と書き分ける
- 名前は chat.txt の表記（`@まこも-z3i`）。2回目からは短くしてよい（@まこも）
- 本人の言い間違いは直さず「本人談」として残す
- **歌詞を写さない。** 配信で流した曲・歌った曲は、曲名と誰が勧めたかまで。字幕に歌詞が拾われていても議事録には載せない
- **視聴者さんの素性は書かない。** 本人がチャットや通話で明かしても、生年月日・本名・住んでいる所・学校・年齢は残さない
  （このリポジトリは公開。未成年らしい人は特に）。書いてよいのは配信の中の出来事と、チャットの表記の名前まで
- **配信者本人のことも、本人がふだん出していない素性は書かない。** 本名・生まれた所・家族のことなど。
  本人が配信でいつも言っている話（例：奈良出身）はよい。迷ったら書かない
- **長い版を削って短くしない。** 短い回でも、その回の大事なこと（企画・約束・事件・初めて来た人）は全部残す

## 3. 配るときの依頼文

```
配信1本の議事録を書いてください。日本語。
手順と形は /home/user/live-streaming/.claude/skills/stream-notes/SKILL.md の §2 に従うこと（先に読む）。
見本: /home/user/live-streaming/streams/2026/10/2026-10-18_2202_TDArug_te90.md

材料（両方とも全部読む。飛ばし読みしない）:
- <stem>.transcript.txt（字数 N）
- <stem>.chat.txt
書く先: <stem>.md（本文の目安 M 字。python3 python/stream_notes.py check <stem> で数える）
コミットしない。返すのは字数と、迷った点（読めなかった語・推し量った箇所）を数行。
```

字幕が無い回（`manifest.tsv` が `none`）はチャットだけから短く書く（「字幕なし。チャットから」と頭に書く）。

## 4. 月末の振り返り（monthly-review）で使う

授賞式を作る前に、**その月の pending を 0 にしてから**目次と議事録を読む。
6分割ふりかえり・案内鳥からの手紙・おもしろ場面は、まず目次で回を選び、議事録で中身を拾う。
字幕そのもの（transcript）は、言った言葉を正確に引くときだけ開く。
