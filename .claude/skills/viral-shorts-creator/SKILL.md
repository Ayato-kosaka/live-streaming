# 配信アーカイブから、ショートを作る

```
/viral-shorts-creator <YouTube の URL>
```

**仕組みと「なぜそうしたか」は `docs/shorts.md`。** ここは手順と判断の基準。
親の issue は #907。段ごとの issue と、あやとに聞いて決まったこと（#908 声・#909 BGM・#911 投稿）はそこから引く。

## 0. 先に知っておくこと（2026-10-15 に実測）

- **この箱からは YouTube・TikTok・fish.audio に届かない。** YouTube を落とすのは Actions（`shorts_ingest.yml`）
- **リポジトリは公開。** 途中の結果（フレーム・文字起こし）は暗号化して作業枝に置き、手元で復号して読む。平文をリポジトリに書かない
- **あやとが出してと言った案を、そのまま出す。** 言葉は issue の返事でもチャットでもよく、書きかたは問わない（`A`・`全部`・`Aは今出して`）。書き直しを頼まない。読みかたに迷ったら1回だけ確かめる。機械の関所は置かない（`docs/island-misses.md` #283）
- **取り込みはいつ push してもよい。** 毎晩の取り込み（同じ `YOUTUBE_COOKIES` を使う）が動いていれば、取り込みの道具が Actions の中で終わるまで待つ（最長60分。`tools/shorts/ingest/gate.py`）。時刻を見て push を遅らせない。Actions のログの `判定:` の行で、待ったかどうかが分かる
- **やってはいけない:** `YOUTUBE_COOKIES` を書き換える／あやとが企画を決める前に本編集をする（決まるのは issue の返事かチャット）／あやとが出してと言う前に投稿する／あやとの返事を AI が代わりに書く／台帳 `posted.json` が止めたのに、投稿先を見ないで `--again` で出し直す

## 1. 段と、どこまで終わったかの見分け

| 段 | やること | 終わった印 | 手引き |
| --- | --- | --- | --- |
| 1 取り込み | 依頼ファイルを作業枝に push（`archive`）→ Actions → 復号 | `shorts/.work/<id>/archive/manifest.json` が ok、手元に `captions.txt`・`transcript.txt`・`sheets/` | `tools/shorts/ingest/README.md` |
| 2 見どころ | 字幕・コマ・音・チャットを重ねて候補を8本以上。上位は zoom で1秒刻みに確かめる | 候補の表（時刻・前後の文脈・根拠・採点） | `references/highlight_rubric.md` |
| 3 企画 | 体験の違う3案（どの案にも土台 → 山 → 結末 → 問い）。原稿（1行ずつ根拠と使う画）・尺の確認・自己評価・事実の表 | `shorts/videos/<id>/p1/plan.md` | `references/planning.md` |
| 4 企画を見せる | 制作 issue に plan.md を出す（**1次レビューは原稿だけ**）→ あやとが作る案を言うのを待つ。待つあいだに絵コンテ（コマに原稿入り）を作って同じ issue に足す。チャットで決まったら待たない | あやとの返事、またはチャットで決まったことの書き置き | この手引きの 5 |

| 6 完成を見せる | `tools/shorts/preview/put.py up` でプレビューチャンネルに置き（7日で見られなくなる）、下見の URL と案ごとの投稿文を1つのコメントにまとめて制作 issue に出す | 出す案を言ったあやとの言葉（issue の返事かチャット。`B`・`全部` など） | `tools/shorts/preview/README.md`・この手引きの 5 |
| 7 投稿 | 出してと言われた案だけ、EC2 の Chrome から出す。YouTube は非公開で上げる → 関連動画（元のアーカイブ）→ サムネイル → 公開、TikTok は投稿文・カバー。台帳 `posted.json` が同じ動画（sha256）を同じ場所へ2回出すのを止める | 媒体ごとの URL を制作 issue に書き、台帳の変わりをコミットした | `tools/shorts/post/README.md`・`references/production.md` 1 |
| 8 数字・改善 | 途中（#921 数字・#922 仮説の台帳）。数字の取りかたと判定の手順は、1本目を回してから書く | まだ決まっていない | `references/playbook.md` |

**落ちた段だけをやり直す。** 段の出力が揃っていれば、前の段は回し直さない。

## 2. 取り込み

```bash
# 鍵はセッションごとに作る（秘密鍵はスクラッチパッドから出さない）
openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:3072 -out <scratch>/keys/ref_private.pem
openssl pkey -in <scratch>/keys/ref_private.pem -pubout -out <scratch>/keys/ref_public.pem
```

依頼ファイルの形・mode（`archive` / `reference` / `zoom` / `channel`）・復号のしかたは `tools/shorts/ingest/README.md`。
master からは `workflow_dispatch` でも回せる。

**文字は2系統を突き合わせて読む。** whisper は固有名詞に強く、自動字幕は数字と英単語に強かった（実測: 「SIM」を whisper は「新聞」と書いた）。

配信チャットは BigQuery（`youtube_chat.chat_messages`、配信開始 `videos.actual_start_time` からの秒）。**出来事の 15〜35秒あと**に付く。
視聴者さんの名前はチャットから読まない・どこにも書かない。

## 3. 見どころ（いちばん大事な段）

`references/highlight_rubric.md` に従う。要点だけ:

- **チャットの山＝初見に刺さる、ではない。** 北マケドニアの回の最大の山は登録者1900人のお祝い（常連向け）だった
- **前後の文脈（原因と結末）を必ず確かめる。** 結末の無いハプニングは面白くならない
- **依頼文の説明を信じない。元動画で確かめる。** 北マケドニアの回は「国境を越える」と説明されていたが、アーカイブに国境越えは入っていなかった
- 外の事実（建物の由来・値段・歴史）は出典を付ける。チャットの「〜らしい」は事実ではない
- 1候補に、元動画の区間・冒頭に置ける画の時刻・根拠（字幕の時刻・見たコマ・チャット）を付ける

コマを切り出す・並べる道具: `tools/shorts/plan/frame_at.py`（指定の秒の1コマ）、`tools/shorts/plan/mont.py`（並べて1枚に）

## 4. 企画3案

`references/planning.md` に従う。要点だけ:

- 3案は**視聴体験が違う**もの（ハプニング／グルメ／日本との違い／発見／クイズ など、素材に合わせる）。
  **ただし話の強みは案ごとに分けない。どの案にも「土台（なぜ応援したくなるか）→ 山 → 結末 → 問い」を全部持たせる**
  （体験で割って、土台を C・山を A に分けたら、どれも弱くなった。`references/planning.md` 1.5、`docs/island-misses.md` #287）
- **1次レビューは原稿だけ。絵コンテは返事を待つあいだに作り、同じ issue に足す。コマにはその行の原稿を必ず入れる**（あやと 2026-10-18。`references/planning.md` 5）
- **0秒目にいちばんの画と、1行で言い切ったタイトル。4〜8秒に2つ目の山。** あやとの過去ショートは4〜8秒で離れていた（`references/playbook.md` の H1）
- 0秒目の画は原稿の1行目の画のまま決めない。`tools/shorts/plan/hook.py` で素材から候補3つを測って並べ、その動画の答え（オチ）を先に見せる画を選ぶ（`references/production.md` 3）
- 見る人の頭に「？」を残さない。話の前提が見る人の常識と食い違うところは、先に前提をそろえてから違いを見せる（`references/script_writing.md` 0.7）
- **原稿は `references/script_writing.md` に従って書く。書く前に全部読む。** あやとが自分の言葉（関西弁）で喋る一人称の台本を AI の声が読む。
  事実1行→反応1行を2〜3秒ごと、最後は「みんな」への問い。外の語り手の説明口調（「あやとは〜」「本人いわく」）は使わない（`docs/island-misses.md` #275）
- 言い回しは、まず配信の文字起こしからあやとの言葉を拾う。原稿は1行ずつ根拠の時刻を持つ。言い切れないことは「〜とも」にする
- **原稿はあやとに先に見せてから声を作る**（声の無料枠は月 8,000 クレジットで、作り直すほど減る）
- 尺は毎秒7字前後で見積もり（声を速める倍率の上限 1.4 で読んだ速さ。60秒未満なら 350字・22行前後まで）、声を作ったら実物の長さで測り直す。**上限を越える原稿は、倍率ではなく字を減らす**（`script_writing.md` 6、`docs/island-misses.md` #285）

作る順: 原稿（plan.md。1行ずつ根拠と使う画）を先に書いて出す → 返事を待つあいだに絵コンテ。

```bash
python3 tools/shorts/plan/storyboard.py <spec_A.json> <復号した材料/videoId> <出力>   # 表と絵コンテの絵（コマの下に秒・元動画の時刻・原稿）
python3 tools/shorts/plan/assemble.py <本体.md> <出力> <spec の接頭辞> shorts/videos/<videoId>/p1   # 3案の本体に表と絵を差し込むとき
```

spec の still は `H:MM:SS`（その回）か `videoId@H:MM:SS`（同じ置き場に復号したほかの回）。前提を画で埋めるのに、ほかの回の画を混ぜられる。
行の秒は、声を様式の上限の倍率で読んだ速さ（毎秒6.8字）で割り付ける。字を読ませたい行は `crop`（0〜1 の比の箱）で寄せる。

## 5. あやとに見せる（企画と完成）

見せるのは2回——企画（3案）と、完成動画。どちらも制作 issue に出して、あやとが「出して」と言った案を作る・出す。

1. 制作 issue を立てる（札 `shorts`）。題は「【ショート制作】<回の名前>（<videoId>）」
2. plan.md の中身をそのままコメントに貼る（絵は raw.githubusercontent.com のコミット固定の URL）。頭に付ける印は無い。
   **1次は原稿だけで出す。** 絵コンテ（コマに原稿入り）は返事を待つあいだに作り、できたら同じ issue に別のコメントで足す
3. 札 `待ち-あやと` を付け、`call_ayato.yml` で通知する（`ask-ayato` スキル。**自分のアカウントの @ は飛ばない**）
4. **あやとが決めるまで本編集に進まない。** 決まるのは issue の返事かチャット。**返事はあやとの言葉をそのまま読む**（`A`・`全部`・`Aがいい`・`Aは今出して`、ひとこと付きでも、あとで書き足してあっても同じ）。チャットで決まったら、issue に「あやと（日付・チャット）: …」と書き残して進む——**issue で書き直してもらわない**。読みかたに迷ったときだけ、1回確かめる。待つあいだは別の段（取り込み・調べ）を進める
5. 直してほしいと言われたら、直して次の版（p2）として出し直す
6. 完成動画も同じ形で見せる。`tools/shorts/preview/put.py up` で下見の URL を作り（7日で見られなくなる）、案ごとの URL と投稿文を1つのコメントにまとめる。URL は issue に貼ってよい（あやと 2026-10-16）。あやとが「B」「A C」「全部」のように言った案を出す。出す時刻・順番の指示（「Bは14時に」）もそのまま守る
7. **投稿の担当は、出す前にあやと本人の言葉を読んで、出す案を確かめる。** 読むのは issue のあやとのコメントか、チャットの書き置き。こちらが書いたコメント（提出・書き置き）を、あやとの返事として数えない。出したら媒体ごとの URL を制作 issue に書く（手順と台帳は `tools/shorts/post/README.md`）
8. **制作 issue では、出す案のほかの問い（声・BGM の選択など）を混ぜない。** 別の issue で聞く——同じ issue の `B` がどの問いへの返事か、読み分けられなくなる

## 6. 学びの置き場

- 動画ごとの制作記録: `shorts/videos/<videoId>/`（企画・原稿・絵コンテ・編集指示書・投稿の URL・確かめる仮説）
- **作り方の学び（本編集〜完成を見せるまで）: `references/production.md`。直しが出るたびに、決めたことと人の目の検査の表に足す**
- **参考の見た目と音（書体・大きさ・位置・縁・色・動き・BGM の差）: `references/style_reference.md`。参考を渡されたら、台本だけでなくここも測ってから作る**（`docs/island-misses.md` #278）
- 仮説とベストプラクティス: `references/playbook.md`。**複数の動画で支持されたものだけを上げる。** 矛盾したら規則のほうを疑う
- 参考ショートの分析（日付つきの記録。あとから直さない）: `references/reference_shorts_2026-10.md`
