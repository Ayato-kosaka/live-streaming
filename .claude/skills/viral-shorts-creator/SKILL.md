```

```

## 2. 取り込み

### 視聴者さんの頼み（島の付箋）

どの回を作るかの頼みは、島の付箋（テーマ `shorts-idea`）に来る。「この回のこのあたりをショートに」と、配信のリンクつきで貼られる。

- **読むのは Actions の「付箋を読む」（`stickies_pull.yml`）。EC2 を起こして curl しない。** この箱から島には届かないが、Actions からは届く。依頼（`{"theme": "shorts-idea", "limit": 300, "pubkey": …}`）を作業枝の `shorts/stickies/<名前>.json` に push → 暗号文が `shorts/.work/stickies/shorts-idea/` に届く → `python3 tools/shorts/stickies/read.py --key <秘密鍵> --ref FETCH_HEAD` で手元に表を出す。手順は `tools/shorts/stickies/README.md`
- **依頼を `shorts/requests/` に置かない。** そこは取り込み（`shorts_ingest.yml`）が見ている
- **視聴者さんの名前は、どこにも出さない。** issue・コミット・企画・台本・投稿文のどれにも。本文もそのまま写さず、「どの回の、どのあたりか」を自分の言葉で書く。リンクは動画IDと時刻だけにする（`si=` は共有した人を指す。`read.py` は落として出す）

### 配信の材料

```bash
# 鍵はセッションごとに作る（秘密鍵はスクラッチパッドから出さない）
openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:3072 -out <scratch>/keys/ref_private.pem
openssl pkey -in <scratch>/keys/ref_private.pem -pubout -out <scratch>/keys/ref_public.pem
```

依頼ファイルの形・mode（`archive` / `reference` / `zoom` / `channel`）・復号のしかたは `tools/shorts/ingest/README.md`。
master からは `workflow_dispatch` でも回せる。

**取り込みを使う担当を何人も並べるときは、依頼文に「push の前に `shorts_ingest` の run に queued / waiting / pending が無いのを確かめる」を必ず入れる。**同じ枝の取り込みの枠は「走っている1本＋待っている1本」までで、3本目の push が待っていた run を取り消す（`tools/shorts/ingest/README.md`。2026-10-29、イギリスの4本を5人で並べて、参考調査の push がエディンバラの zoom を消した）。

**文字は2系統を突き合わせて読む。** whisper は固有名詞に強く、自動字幕は数字と英単語に強かった（実測: 「SIM」を whisper は「新聞」と書いた）。

配信チャットは BigQuery（`youtube_chat.chat_messages`、配信開始 `videos.actual_start_time` からの秒）。**出来事の 15〜35秒あと**に付く。
視聴者さんの名前はチャットから読まない・どこにも書かない。

`references/planning.md` に従う。要点だけ:

- **1次レビューは原稿だけ。絵コンテは返事を待つあいだに作り、同じ issue に足す。コマにはその行の原稿を必ず入れる**（あやと 2026-10-18。`references/planning.md` 5）
- **0秒目にいちばんの画と、1行で言い切ったタイトル。4〜8秒に2つ目の山。** あやとの過去ショートは4〜8秒で離れていた（`references/playbook.md` の H1）
- 0秒目の画は原稿の1行目の画のまま決めない。`tools/shorts/plan/hook.py` で素材から候補3つを測って並べ、その動画の答え（オチ）を先に見せる画を選ぶ（`references/production.md` 3）
- 見る人の頭に「？」を残さない。話の前提が見る人の常識と食い違うところは、先に前提をそろえてから違いを見せる（`references/script_writing.md` 0.7）
- **作文者には `tools/shorts/script/brief.py writer` の1枚だけを渡す**（先頭に約束のカード——帳面 `references/ayato_feedback.md` の原稿の段の項目を、
  決まり（する／しない）と直しの全文で。帳面から毎回組む——、次に方針（参考7本の研究。#1019）、4欄の表と当て表の雛形、いちばん後ろに配信の字幕。
  **チャットの本文は入れない**（F-048）。頼む文は `references/writer_prompt.md`。2026-10-23 にゼロから作り直した——前の1枚は帳面を題と例の頭に縮めていて、
  約束26個のうち10個が届いていなかった）。参考の書き起こし全文は読ませない。**書く時間は削らない**（F-050）。書いたら
  `python3 tools/shorts/script/lint.py shorts/videos/<id>/p1/script.txt`（隣の spec.json の題の札と当て表も見る。spec は `rows` の鍵で）を通し、✕ が残っているうちは批評役に回さない。**✕ を「あやとの指定だから」で外せるのは、あやと本人の言葉（issue のコメントか、チャットの書き置きに引いた原文）がその決まりを名指しで外しているときだけ。** 「落ちはこれ」は落ちの指定で、最後の CTA を外す指定ではない。こちらの読み替えで例外を作らない・前の担当の例外を原文に当てずに引き継がない（2026-10-28 #1043。`docs/island-misses.md` #305）
- **批評役は `tools/shorts/script/critic.py` で回す**（`brief.py critic` の1枚——作文者と同じ約束のカード・lint の結果・参考の拍・原稿の表・配信の字幕——だけを `claude -p` に渡し、
  決まった型の JSON を返させ、合否は `critic_gate.py` が数える。`script_writing.md` 7.4）。批評役は (h) でカードを1枚ずつ当てて ID を全部並べ（欠けたら ✕）、
  (i) で全部の行のつなぎ、(j) で1行ずつ「その行だけで意味が通るか」、(k) で「画に居ない人（視聴者のコメントなど）の言葉を持ち出したか」を当てる。lint が緑でも、
  字で拾える指摘に当たっていないだけ——題が現実か・「？」が残るか・映像の枠の外でも正しいかは (h)、前の行から渡れるか・話が二転三転していないか（F-039・F-040）は (i) で見る
- **回数の上限: 批評役は2人まで・直しは2回まで**（`script_writing.md` 7.3。2人目は、1人目の ✕ に帳面・(h)・(i) が残ったときだけ。点の 3・離れる行の △ では呼ばない）。
  あやと（帳面 F-044）「半分ぐらいで大丈夫です。その代わりプロンプトとかを磨き上げて」。使った数は `python3 tools/shorts/cost/tally.py` で段ごとに数える
- **原稿の表は、1行ずつ「元の出来事（配信の時刻）／見る人に届く文／残した本人の言葉／選んだ理由」の4欄で書き、約束のカードごとの当て表を付けてから批評役に回す**
  （`script_writing.md` 0.8。あやと #1019「なぜそれを選んだか理由付きで」、帳面 F-051。叫びを配信の本人の声で流す行は「元の声」と秒を書く）
- **原稿は `references/script_writing.md` に従って書く。書く前に全部読む。** あやとが自分の言葉（関西弁）で喋る一人称の台本を AI の声が読む。
  事実1行→反応1行を2〜3秒ごと、最後は「みんな」への問い（入りきらなかった見どころは「アーカイブ見てね」の1行で渡してよい。帳面 F-032）。外の語り手の説明口調（「あやとは〜」「本人いわく」）は使わない（`docs/island-misses.md` #275）
- **配信の文字起こしは材料。** 字幕の文を起きた順につなげて行にしない（F-050）。残すのは本人の擬音・口ぐせ・味の言い方・ツッコミで、文の形は見る人に向けて組み直す。
  原稿は1行ずつ根拠の時刻を持つ。言い切れないことは「〜とも」にする
- **原稿はあやとに先に見せてから声を作る**（声の無料枠は月 8,000 クレジットで、作り直すほど減る）
- 尺は毎秒7字前後で見積もり（声を速める倍率の上限 1.4 で読んだ速さ。60秒未満なら 350字・22行前後まで）、声を作ったら実物の長さで測り直す。**上限を越える原稿は、倍率ではなく字を減らす**（`script_writing.md` 6、`docs/island-misses.md` #285）

作る順: 原稿（plan.md。1行ずつ根拠と使う画）を先に書いて出す → 返事を待つあいだに絵コンテ。

```bash
python3 tools/shorts/plan/storyboard.py <spec_A.json> <復号した材料/videoId> <出力>   # 表と絵コンテの絵（コマの下に秒・元動画の時刻・原稿）
python3 tools/shorts/plan/assemble.py <本体.md> <出力> <spec の接頭辞> shorts/videos/<videoId>/p1   # 3案の本体に表と絵を差し込むとき
```

spec の still は `H:MM:SS`（その回）か `videoId@H:MM:SS`（同じ置き場に復号したほかの回）。前提を画で埋めるのに、ほかの回の画を混ぜられる。
行の秒は、声を様式の上限の倍率で読んだ速さ（毎秒6.8字）で割り付ける。字を読ませたい行は `crop`（0〜1 の比の箱）で寄せる。

## 5. あやとに見せる（企画と完成）

見せるのは2回——企画（3案）と、完成動画。どちらも制作 issue に出して、あやとが「出して」と言った案を作る・出す。

1. 制作 issue を立てる（札 `shorts`）。題は「【ショート制作】<回の名前>（<videoId>）」
2. plan.md の中身をそのままコメントに貼る（絵は raw.githubusercontent.com のコミット固定の URL）。頭に付ける印は無い。
   **1次は原稿だけで出す。** 絵コンテ（コマに原稿入り）は返事を待つあいだに作り、できたら同じ issue に別のコメントで足す
3. 札 `待ち-あやと` を付け、`call_ayato.yml` で通知する（`ask-ayato` スキル。**自分のアカウントの @ は飛ばない**）
4. **あやとが決めるまで本編集に進まない。** 決まるのは issue の返事かチャット。**返事はあやとの言葉をそのまま読む**（`A`・`全部`・`Aがいい`・`Aは今出して`、ひとこと付きでも、あとで書き足してあっても同じ）。チャットで決まったら、issue に「あやと（日付・チャット）: …」と書き残して進む——**issue で書き直してもらわない**。読みかたに迷ったときだけ、1回確かめる。待つあいだは別の段（取り込み・調べ）を進める
5. **返事を受けたら、直すより先に帳面（`references/ayato_feedback.md`）に足す。** 指摘は「指摘」の節に1項目（同じ決まりを前にも言われていたら、
   新しい ID を作らずその項目の「言われた」に1行）。承認・時刻・素材などは「指摘ではないコメント」に URL を1行。チャットで受けた指摘も同じで、
   issue に「あやと（日付・チャット）: …」と書き置きを残し、その URL を出どころにする。足したら、字で拾えるか（`tools/shorts/script/lint.py` の規則に
   できるか）を見て、できるなら規則・帳面の `lint:<規則>`・`lint_selftest.py` の例を一緒に足す。形は `python3 tools/shorts/feedback/ledger.py --check`。
   足し忘れたコメントは、毎日 `tools/shorts/feedback/watch.py` が数えて issue（`待ち-システム`）を立てる
6. 直してほしいと言われたら、直して次の版（p2）として出し直す
7. 完成動画も同じ形で見せる。`tools/shorts/preview/put.py up` で下見の URL を作り（7日で見られなくなる）、案ごとの URL と投稿文を1つのコメントにまとめる。URL は issue に貼ってよい（あやと 2026-10-16）。あやとが「B」「A C」「全部」のように言った案を出す。出す時刻・順番の指示（「Bは14時に」）もそのまま守る（その場で予約するか、その時刻に起きる仕掛けを置く。帳面 F-017）
8. **投稿の担当は、出す前にあやと本人の言葉を読んで、出す案を確かめる。** 読むのは issue のあやとのコメントか、チャットの書き置き。こちらが書いたコメント（提出・書き置き）を、あやとの返事として数えない。出したら媒体ごとの URL を制作 issue に書く（手順と台帳は `tools/shorts/post/README.md`）
9. **制作 issue では、出す案のほかの問い（声・BGM の選択など）を混ぜない。** 別の issue で聞く——同じ issue の `B` がどの問いへの返事か、読み分けられなくなる
