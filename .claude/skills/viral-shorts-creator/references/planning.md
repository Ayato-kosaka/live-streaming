# 企画3案の作り方

2026-10-15 に、北マケドニアの回とティラナの回で作った形（`shorts/videos/<videoId>/p1/`）。

## 0. 段取り: 1次の原稿は `streams/` から書く。取り込みを待たない

`streams/` には、どの配信の自動字幕（30秒ごと）とチャットも置いてある（`streams/README.md`。議事録のある回は `streams/YYYY/MM/<stem>.md`）。
2026-10-21 の3本は、取り込みの関所（最長60分。`tools/shorts/ingest/gate.py`）と回まるごとの取り込み（`archive`）を待ってから書き始めて遅れた。

1. **見どころと1次の原稿は `streams/` から書く。** 議事録で流れを掴み、字幕（`.transcript.txt`）とチャット（`.chat.txt`）で行ごとの根拠の時刻を取る
2. **取り込むのは、原稿が使う区間だけ。** 原稿の行の時刻に余白を付けて `clips`（素材の mp4）か `zoom`（1秒刻みのコマ）で頼む。
   回まるごとの `archive` は、`streams/` に字幕の無い回（`manifest.tsv` が `none`・`error`）にだけ使う
3. **画の確かめは、あやとが原稿を見ているあいだに並べて回す。** 写っているか・3秒未満で切り替えられるか・カクつき（`production.md` 2）と、
   0秒目の画の候補（`hook.py`）。1次の原稿の「使う画」は「画は確認中」と書いて出してよい。画の無かった行は、返事を受けた版（p2）で直す
4. 自動字幕は固有名詞に弱い（`SKILL.md` 2）。固有名詞が怪しい行は、取り込んだ区間の音で確かめてから本編集に入る
5. **急ぐときに削るのは待ちで、書く時間とレビュー（`script_writing.md` 7）ではない**（`docs/island-misses.md` #295）

## 1. 3案は「見る体験」が違うものにする

題だけ違う3案にしない。素材に合わせて型を選ぶ:

| 型 | 例 |
| --- | --- |
| ハプニング・緊迫 | 出発25分前に、朝ケバブを頼んだら（残り時間が減る → 最後の1席） |
| 物語 | 日の入りに間に合え！ 急いだら、早すぎた |
| グルメ | 国を出る前に、残りの現金590円で朝ごはん |
| 日本との違い | 路線バスの運賃は「人」に払う |
| 発見・文化 | この国、英雄の顔をビルにした |
| クイズ・歴史 | 街なかのキノコ、何だと思う？ |

同じ場面を2案で使ってもよいが、**山とオチが違うこと。**

### 1.5 体験で割っても、話の強みは案ごとに分けない（#287）

**どの案にも「土台（なぜ応援したくなるか）→ 山 → 結末 → 問い」を全部持たせる。** 違えるのは、どこから入るか・何を山に置くか・どう見せるか。

3案を「見る体験の違い」だけで割ると、1つの話が持っている強みが案ごとに分かれて、どれも弱くなる。
食べログ越えの回（Hc-z52fs108、2026-10-18）がそれで、A（順位の実況）はハラハラだけで応援したくなる土台が無く、
C（1年の物語）は土台はあったが山が薄かった。あやとの返事は「原稿がだいぶ弱い。C ベースで A の構成で」。
p2 は「人が来ない1年とどん底 → バズは2行で走り抜ける → 勝負の場面に尺の4割 → 結末 → 問い」にした。

- 書いたら、案ごとに「この案の土台はどの行か・山はどの行か」を1行で言えるかを見る。言えない案は、強みを別の案に取られている
- 土台と山を両方持たせると尺が足りなくなる。削るのは「どうしてそうなったか」の途中（例: どん底からバズまで）で、勝負の場面ではない
- **結末は、題の約束を同じ気持ちで閉じる。** 実際の話がその後どうなったかを言う枠ではない。題が「異常すぎた」なら「異常」の側で終える。
  題と逆の気持ち（住めば都・友達ができた・結局よかった）に着地させない（`docs/island-misses.md` #292）
- **1本で伝えることは1つ。** 1行足す前に「この行は題の気持ちを強めるか」を問う。新しい話（新しい人・予定の変更・心変わり）を始める行は、
  本当で確かめてあっても切る。別の回の「その後」も、題の気持ちを強めるときだけ使う。
  最安ホステルの回（zjHZucyfrq8、2026-10-19）は、2日後の回の「宿に友達できてん」「結局、引っ越しやめた。住めば都やな」を足して、
  あやとに「唐突すぎる…ホステルやばすぎ！で終わる方で良い」と消された

### 1.6 画の種類が足りるかを、企画の段で数える

**原稿を書く前に、その話で使える画の種類を数える。** 22行に対して画が3〜4種類しかないと、同じ絵面が続く。
食べログ越えの回（2026-10-18）は、本編の画が「路上で喋る顔」「左上のダッシュボード」「スマホ越しの順位表」だけで、
あやとの返事は「絵面が毎回一緒なのが気になる。こういう系は絵が映えないのは仕方ない。例外パターンなので良し」だった。

- 旅の回のように景色・料理・人が次々写る回は気にしなくてよい。アプリ作り・数字・順位の回は、まず数える
- 足りないときは、企画を出すときに一緒に頼む素材を書く（例: アプリを触っている画面の録画・作っている手元）。
  **動く素材を頼む。止め絵（写真・画面の写し・止めたコマ）は使わない**（あやと 2026-10-21「静止画はやめて欲しい」。
  `check.py` の `still_image` が落とす）。Hc-z52fs108 p2 ではあやとが貼ってくれた App Store の画面2枚を止め絵にして
  暗い配信の画の代わりにしたが、それはこの決めより前の、もう取れない手。画面を見せたいときは、その画面を触っている録画を頼む
- **似た見た目のカット（同じ場所の引きと寄り・同じ区間を寄せの倍率だけ変えたもの）を、続けて 3秒以上使わない**
  （あやと 2026-10-21「同じような見た目のカットも連続3秒以上使わないで欲しい」。`check.py` の `similar_run`）。
  続けたいときは、間に見た目の違う画を挟む。画の種類を数えるときは、この並べ方ができるだけの種類があるかを見る
- **種類だけでなく、1つの画の秒も数える。** 同じ場面（同じ素材の別の時刻を含む）は合わせて尺の 25% まで・3回まで。
  呼び戻し（冒頭の画を終わりに）もこの中に数える（屋上のベッドが 42秒中 13秒・4回で「見飽きる」と言われた。
  `check.py` の `shot_reuse`、`docs/island-misses.md` #293）

### 1.7 話の幅: 狭すぎず、広すぎず（#296）

あやとの言葉（#975、2026-10-21）:

> ※ナレッジ: 話の内容を狭めすぎると映像も単調になるし飽きるから、もう少し広くストーリーを作れれば良い。とはいえ広すぎると着いていけなくなるので難しいところ

**筋は1本。その筋が上がっていく段ごとに、違う種類の場面が載る幅にする。**

- 狭すぎる: 1つの物・1つの数字だけの話。ストックホルムの地下鉄の p1 は券の値段と乗り方だけで、画は改札・ホーム・車内が続いた。
  土台の場面（ストックホルムに来た・友達に会いに行く）を落としたので、残った「友達の家」の行が「？」になった
- 広すぎる: 筋に乗らない出来事を並べる。回をまたぐ・場面の多い話は、場面を「ほんで」でつながず、前の段より大きいことが起きる順に1本の筋へ並べる
- あやとが直した地下鉄の筋は「ストックホルムに来た → 友達に会いに地下鉄に乗る → 高い」。題「ストックホルム来たら、地下鉄が高すぎた！」が、
  前提（来た）と山（高すぎた）をもう持っている（題はあやとの字のまま引く。いまなら助詞を戻して「ストックホルムに来たら」。F-049）。**題を決めたら、題の言う前提から山までを筋にする**
- 書いたら、筋の段（3〜5段）と段ごとの場面の種類を並べる。全部が同じ場所・同じ物なら狭い。どの段にも乗らない場面があれば広い（乗らない場面は切る。1.5）

## 2. 1案に必ず入れるもの

| 項目 | 中身 |
| --- | --- |
| 概要 | 仮タイトル・狙い・狙う視聴者・尺・感情の流れ・伸びると考えた理由（**数字の根拠つき**）・今回確かめる仮説（`playbook.md` の番号と物差し） |
| 伝えたいこと | 1行で（`script_writing.md` 0.5）。全部の行がここへ向かっているかを見る |
| 写す参考 | 書く前に選んだ参考1〜2本と、拍ごとの写し表（`script_writing.md` 7.1） |
| 見る人とそろえる前提 | この企画の驚きが、見る人の常識（日本の常識）のどれと食い違うか。食い違うなら、原稿のどの行で先にそろえるか（例: 日本ではケバブ＝ラップ → ここはパンをプレスしたパニーニ風。`script_writing.md` 0.7）。食い違いの無い企画・行には書かない（違いを毎回入れる、ではない） |
| 0秒目の画 | `tools/shorts/plan/hook.py` で素材から測った候補3つと、選んだ1つ（元動画の時刻）・選んだ理由。その動画の答え（オチ）を先に見せる画にする（`production.md` 3） |
| 原稿 | ナレーションの全文。1行1文。**1行ずつ4欄**（元の出来事＝根拠の回と時刻／見る人に届く文／残した本人の言葉／**選んだ理由**）と使う画・参考の手（要の行だけ。`script_writing.md` 0.8・7.2）。あやとに出す表も4欄で（#1019「なぜそれを選んだか理由付きで」）。約束のカードの当て表を付ける |
| 尺の確認 | 記号を除いた字数（`readtime.py` の `chars`）を、声を上限の倍率（様式の `narration.max_tempo`、いま 1.4）で読んだ速さ＝**毎秒6.8字**で割り、行の間を0.25秒ずつ足す。**60秒未満・350字・22行前後まで**（`script_writing.md` 6）。声を作ったら実物の長さで測り直す |
| 絵コンテ | **1次レビューには入れない**（下の 5）。動画内の時間・元動画の時間・映像・ナレーション・テロップ・演出の表と、静止画を並べた絵（`storyboard.py`）。**絵の各コマの下に、その行の原稿を必ず入れる** |
| 自己評価 | 冒頭の引き・初見の分かりやすさ・意外性・画の魅力・物語・テンポ・見終わった満足・狙いとの合い（各1〜5）と、低い点の理由。書いた本人の見込みで、出すかどうかは決めない |
| レビューの記録 | `lint.py` の出力と、往復を知らない批評役（2人まで）の回ごとの点・離れる行・帳面に当たった ID・`critic_gate.py` の結果（`script_writing.md` 7.3・7.6）。関所を通っていない原稿は出さない |
| 確かめた事実 | ナレーションの1文ずつに、元動画の時刻か外の出典 |
| 気をつけること | ぼかす場面・言わないこと |

3案の比べ表と、推薦する1案とその理由を頭に置く。**自己採点は予想であって、結果で判断する**と書く。

## 3. 冒頭と2つ目の山

- **0秒目に、その回でいちばんの画と、一行で言い切った題。** 題の札は0秒目から出す（H2・H4）。
  画は原稿の1行目の画のまま決めない。`tools/shorts/plan/hook.py` で素材（取り込んだ窓と、その話の範囲のコンタクトシート）から色の強さ・暖色の寄り・動き・顔の寄り・山場かどうかで候補3つを並べ、**その動画の答え（オチ）を先に見せる画**を人が選ぶ。選んだ画は1行目の `src`（と overrides の row 0 の `cuts`）に置き、題の札の下に出す
- **4〜8秒に2つ目の山**（意外な数字・障害・決める一言）。あやとの過去ショートはここで離れていた（H1）。
  作ったあとで、原稿の2文目が何秒から始まるかを表で見る。1文目が長くて山が8秒を過ぎるなら、文を割るか順番を入れ替える
  （北マケドニアの C案は1文目が7秒あったので、「1A……これ、違う？」を2文目に上げた）
- 常連向けの情報（何日目・区間・シリーズ名・配信の題）を頭に置かない

## 4. ナレーション（原稿）の決まり

**書き方は `script_writing.md` に従う。** 要点だけ:

- **あやとが自分の言葉で喋る一人称の台本**を、AI の声が読む（西園寺さんと同じ形）。外の語り手が「あやとは〜」と説明しない。
  配信の文字起こしは材料。残すのは本人の擬音・口ぐせ・味の言い方・ツッコミで、文の形は見る人に向けて組み直す（関西弁。F-050）
- 事実1行 → 反応1行を2〜3秒ごと。最初の反応は5秒まで、見続ける枠は10秒まで。最後は「みんな」への問いで切る（入りきらなかった見どころは「アーカイブ見てね」の1行で渡してよい。帳面 F-032。次の配信に誘うなら時刻まで言う。F-047）
- 値段は円だけで言う（現地の通貨は読まない。画面の小さな字ならよい。F-007）。数字は感情か比較と組で（「590円」→「微妙すぎる額やん」）
- **盛らない。** 確かめられたことだけを言う
  - 「全財産590円」→ 本人が持っていたのは**残りの現金**（カードはある）。「残りの現金590円」と言う
  - 本人の思い違いは、思い違いのまま本人の言葉で言う（ティラナの「あと10分」は実際は約23分あった →「俺の計算では、あと10分」）
  - 数が資料で割れるものは「〜とも」（シェルターの数は17万〜75万 →「数十万とも」）
- 言わないこと: 国や人をひとまとめにする笑い・相手の国を笑う冗談・確かめていない「世界初」・他人の作品の名前（漫画のキャラクターなど）・
  視聴者さんの名前（配信の文字起こしに出てくる）・視聴者のコメントやチャットの話と、配信の中の呼び名（F-048。「配信のコメントで…」「ポチ」）

## 5. 絵コンテの決まり

- **1次レビュー（企画を見せる）は原稿だけ。** 絵コンテは、あやとの返事を待つあいだに作り、できたら同じ issue に足す
  （あやと 2026-10-18「絵コンテは時間かかるからやめましょう。1次レビューは台本だけで良いや」「レビューの返信に、時間余ってたら、絵コンテ作る感じで」）。
  絵コンテに時間を取られて、原稿の詰めが弱いまま出したのが #287
- **絵コンテのコマには、その行の原稿を必ず入れる。** セリフが分からない絵コンテは見られない
  （あやと 2026-10-18「絵コンテ自体に原稿入れて欲しい。じゃないとセリフがわからない」）。`storyboard.py` は各コマの下に秒・元動画の時刻と原稿を入れる
- **同じカットは 3秒未満。例外は無い**（料理の寄りや景色も含む。あやと 2026-10-21「同じカットを3秒以上使わない約束を守って」。
  `check.py` の `cut_length` が 3.0秒ちょうども落とす）。3秒以上の行は、元動画の時刻を2つ以上書いて画を切り替える。
  切り替えた先も前と似た見た目なら、合わせて 3秒未満（上の 1.6）。止め絵を頭から使い直して寄せを続けても、1つのカットと数える
  （前は「1行は3秒前後。4秒を超える行は切り替える（ただし料理の寄りや景色は長く見せてよい）」で、p2 v9 はそれで 4.8秒の止め絵を通した）
- 絵コンテのコマ（静止画）は zoom（1秒刻み）から取る。**第三者の顔が映るコマには `blur` を付ける**（絵コンテは issue に貼るので、その時点で公開になる）。
  絵コンテのコマは見せるための1枚で、動画の中は動く映像（止め絵は使わない。1.6）
- 配信の透かし（PRISM Live）・固定コメントの帯・投げ銭の表示は、書き出しで隠す前提で「気をつけること」に書く
- 本人の短い一言を元の音で残す候補は、演出の欄に「残す候補」と書く（原則はミュート）
- **テロップの「中央」欄には、その行のナレーションにもタイトルにも無いことだけを書く**（本人の元の声の言葉・訳・地図の矢印など）。
  数字や値段を目立たせたいだけなら「字幕で強調: 25分」と書く（書き出しが字幕の中のその語を黄色にする）。
  1本目は中央欄の半分がナレーションの言い直しで、画面に同じ言葉が2〜3回並んだ（`production.md` 2）
- **使う区間は、絵コンテの真ん中の1コマで選ばない。** その行の長さぶんを1秒刻みで見て、行のあいだずっと強い画が続く区間を選ぶ。
  何も無い壁・歩道・暗い車内が2秒以上続く区間は使わない。値段や看板を見せる行は、字が画面いっぱいに近く写るコマを選ぶ
- 第三者の顔が大きく写る場面は、ぼかしで済ませる前に別の画を探す（大きくぼかすと画が壊れて見える）

## 6. テロップの読み方（2026-10-15 の約束）

依頼は「タイトルは上部配置で背景あり、セリフは中央配置で文字枠あり」。
**「文字枠」は縁取り（白字に黒の縁）と読んだ**（参考スクショ2枚目の形）。箱のことなら、企画を見せたときに直してもらう。
