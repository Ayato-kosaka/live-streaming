# あやとの指摘の帳面（ショート）

あやとの言葉（2026-10-21）:

> 私の毎回の指摘は以後繰り返さないようナレッジ溜まる仕組みは用意してね。

ショートであやとから受けた指摘を、**1か所に**集める。指摘1つ＝1項目で、「どうすればいいか（決まり）」と「どこで当てるか」を持つ。
同じ決まりをもう一度言われたら、新しい ID を作らず、その項目の「言われた」に足す。**回数の多い項目ほど、二度言わせてしまった重い項目。**

## 誰が、いつ読むか・足すか

| いつ | 誰が | 何をする |
| --- | --- | --- |
| 原稿を書く前 | 作文者 | 全部読む（題・言い回し・事実・構成は必ず）。書いたら `python3 tools/shorts/script/lint.py <script.txt>` を通す |
| 添削・関所 | 編集長・批評役 | 依頼文でこの帳面を受け取り、`script_writing.md` 7.4 の **(h)** で1行ずつ当てる。1つでも当たれば通らない |
| 書き出しの前後 | 作る人 | 画・音・投稿の項目を、`check.py` と人の目の検査（`production.md` 3）で当てる |
| **あやとの返事を受けたとき** | まとめ役 | **直すより先に、ここに足す。** 指摘なら「指摘」の節に1項目（同じ決まりなら「言われた」に1行）、承認・時刻・素材などは「指摘ではないコメント」に URL を1行。足したら、`lint.py` の規則にできるかを見る（できたら規則と自己テストを足す）。チャットで受けた指摘も同じ（issue に書き置きを残し、その URL を出どころにする） |

決まりの一覧だけを見たいときは `python3 tools/shorts/feedback/ledger.py`（分類ごとに1行ずつ）。

**取りこぼしは機械が見る。** `tools/shorts/feedback/watch.py` が毎日（`.github/workflows/shorts_feedback_watch.yml`）、札 `shorts` の issue にある
あやと本人のコメントのうち、下の2つの節のどちらにも URL が無いものを数え、あれば赤くして「【見張り】ショートへのあやとの指摘が帳面に入っていない」の
issue を立てる。帳面はどの枝にあっても数える（作業枝に足しただけで止まる）。こちらの書き込み（末尾に `_Generated by [Claude Code]…_`）と bot の呼び出しは数えない。

## 書きかた

- **分類**: 題・言い回し・事実・構成・画・音・投稿・進め方（進め方＝承認の読みかた・段取り・受け持ちなど、作りかたへの指摘）
- **当てる場所**（どれか1つは必ず）: `lint:<規則>`（原稿の機械の検査 `tools/shorts/script/lint.py`）／ `check:<検査>`（書き出しの機械の検査 `tools/shorts/qa/check.py`）／ 批評役 (h)（`script_writing.md` 7.4）／ 人の目（`production.md` 3 など。どこで見るかを括弧に書く）
- **言われた**: 日付・issue・コメントの URL。チャットや付箋のときは「チャット」と書き、残っている場所（書き置きのコメント・`docs/island-misses.md` の番号）を添える
- ID は末尾に足す（途中に差し込まない。ほかの手引きが ID で指している）。形が崩れていないかは `python3 tools/shorts/feedback/ledger.py --check`

  - 2026-10-21 #998 https://github.com/Ayato-kosaka/live-streaming/issues/998#issuecomment-6324663875
- **分類:** 画
- **あやとの言葉:**
  > （Drive のフォルダ）この素材で入れ替えて。
  > 配信だと分かるように一分配信の素材も残すこと
  > 出来たら2026/10/22 07:00 JSTで出して
- **決まり:** する — あやとが渡した手元の素材（スマホの写真・動画）で画を入れ替えるときも、配信の画面（配信の録画の素材）を一部残し、見た人が「配信の切り抜き」だと分かるようにする。配信に画が無かった所（運転・料理など）から先に、手元の素材に替える。しない — 全部を手元の素材に替えて、配信の回だと分からなくする
- **直す前 → 直した後:** フランス A v2「配信の画だけ（運転とパエリアは画が無く、近い画で代用）」→ 手元の素材に入れ替え、配信の画も一部残す
- **当てる場所:** 本編集（画を当てる段）／ 人の目（下見でまとめ役が、配信の画が残っているかを数える）

### F-046 原稿までが遅い。全編の書き起こしを待たずに原稿に入る

- **言われた:**
  - 2026-10-22 チャット（書き置き #1014 https://github.com/Ayato-kosaka/live-streaming/issues/1014#issuecomment-6352927689）
- **分類:** 進め方
- **あやとの言葉:**
  > なぜ原稿に1時間以上もかかるんですか？
- **決まり:** する — 書き起こしが `streams/` に無い回は、配信の自動字幕とチャットだけを先に取って（数分）見どころの区間を決め、原稿に入る。whisper は原稿が使う区間だけにかける。取り込みの道具を入れる段には時間の上限を付け、止まったら取り直す。しない — 配信まるごとの whisper（数十分）が終わるまで、見どころ探しも作文も待つ
- **直す前 → 直した後:** フォカッチャの回「取り込み 4分＋道具を入れる段で 32分止まる＋全編の whisper（19分を過ぎても終わらない）→ そのあと原稿」→ 字幕とチャットで区間を決め、原稿と区間の whisper を並べて回す
- **当てる場所:** 取り込み（`shorts_ingest.yml`・`tools/shorts/ingest/`）／ 人の目（まとめ役が段を配るとき、全編の書き起こしを待たせない）
