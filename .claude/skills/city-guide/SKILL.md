# 街のガイドの面を、次の街で同じ形のまま作る

ソフィア（行く前 → 行った）・スコピエ（行った）・ブカレスト（行く前）で固まった形を、**依頼文3通をコピーして配るだけで**公開まで回す。
**運営（取りまとめ役）の手は、差し込み欄を埋めて配る・確かめ表を見る・公開して知らせる、の3つだけ**（`docs/island-standards.md` §9「細かいのは、エージェントに配る」）。

決めごとの本体は docs が持つ（拘束力あり。2章の表）。ここに置くのは段・受け渡し・合格の門・物差しだけ。
**同じことを2か所に書かない**——ここにある決まりと docs が食い違ったら docs が勝つので、ここを直す。

### 数の下限（ソフィアの面の数。2026-11-19 から。ここが1本の出どころ）

面に出た数で数える（材料の数ではない。写真が揃わない見たいものは面から落ちる）。**届かない面は、noindex でもあやとに見せない・公開しない**（#337）。

| 何 | 下限 | 見張り |
| --- | --- | --- |
| やりたいこと | **8**。札の絵は8枚とも描いた絵（`do-<key>`。材料は `photo.drawn: "do"`）。写真と混ぜない | `guide_watch.py` の「数」 |
| 見たいもの | **22**（日帰りの遠出を含む。借りた写真が全部置き場に在ること） | 同じ |
| 食べたいもの | **23** | 同じ |
| 買いたいもの | **9** | `guide_book_check.py` の表 |
| 店 | **9**。品と結ぶのは、その店のいまの献立・品書きに載っている品だけ（結べない品は `unknown` へ） | 同じ |
| どんな街の問い | **2〜3** | `tools/sprites/guidebook.mjs` の問いの数 |
| 字 | ソフィアの面の本文（「行った」を除く）が目安 | `guidebook.mjs` の字の量（`BASE_PAGE=/travel/bulgaria/sofia`） |

## 3. 段ごとに、運営が決めておくこと

### 段1 配る

- **差し込み欄**: `<国>`（slug）・`<街>`（slug）・`<街の名前>`・`<国の名前>`・`<段>`（行く前／行った）・`<移る日>`（`site/content/plans.ts` の移動の日）・
  `<前の国>`（付箋を閉じる国の slug）・`<運営のスクラッチ>`（運営のセッションのスクラッチパッドの道。絵と表の受け取り先）
- **配るのは1通ずつ。** 材料担当の報告（PR 番号・枝・注文書の道）が来てから絵担当。行った担当は、その街を出て議事録がそろってから
- **言葉は型で決めて出す。** キャッチ・見出し・地区名の候補をあやとに並べて待たない（`docs/guide-copy.md` の型と手本の文言で決まる）。
  知らせ（段6）にキャッチと地区名を載せ、直しが返ってきたら次の直し。**仕様（何を作るか・どこまでが対象か）が揺れたときだけ** issue で聞き（`/ask-ayato`）、待つあいだ止まらない
- **動いている担当に割り込みを足さない**（企画を1件足す、など）。別の担当に配る（#342）

### 段2〜4 担当（依頼文のとおり）

運営が見るのは報告（15行以内）と、`<運営のスクラッチ>/<街>/` に置かれた絵だけ。報告を鵜呑みにせず、数とどう測ったかを見る（`/hand-off` 3）。
**材料担当の PR に、絵担当が絵を squash で積み、見張りが全部 0 なら札 `出す` を付ける**（noindex のまま出る。公開は段5）。

### 段5 確かめて公開（`review.md`）

1つでも欠けたら公開しない。**直す担当に配る**（あやとに見せて待つのでもない）。全部そろったら、材料担当が用意した公開の枝
`claude/<街>-public`（`draft: true` を消す・`seo_audit.py` の prod の線・付箋・お知らせ）を PR にして札 `出す`。
旗を倒した値での書き出し・`seo_audit`・`crawl` はその PR の CI が回す（#331）。

### 段6 知らせる・載せる

1. **知らせる**: #1228 に1コメント（本番の URL・型の数・キャッチと地区名・まだ粗い所）。通知は `call_ayato.yml`（自分のトークンで書いた `@` は飛ばない。`/ask-ayato`）。
   **報告で、OK を待たない。** 返事はセッションの頭で `待ち-システム` の札から拾う（#330）
2. **入れた手の控え**: `docs/seo.md` 2章に1行（公開の枝に材料担当が書いた行の日付を、公開の日に合わせる）
3. **インデックス登録**: 街の面と国の面を `gsc_request.py`（`docs/seo.md` 4章）。押す前の状態を #1262 に1行
4. **週の表**: `docs/seo.md` 3章の線（2週・4週・8週）で読む。**1週の上下で決めない**
5. **控え**: `tokens.md` に1行（6章）。終わった担当の worktree を外す（`/hand-off` 5）

## 4. 道具の呼び方

**呼び方は依頼文の中に1回だけ書いてある**（材料: `briefs/materials.md`・絵: `briefs/art.md`・行った: `briefs/articles.md`・運営: `review.md`）。
道具の頭の docstring が正。食い違えば依頼文を直す。

まだ道具が無いもの（次に手で回したら、その街の PR で道具にする）:

- 新しい国を足す雛形（企画・付箋・`/all`・`cities.json`・`CITY_ONLY`・締め切りの写し）——いまは依頼文の表で1か所ずつ
- 記事の名簿の配線（`travel.ts`・`articles.ts`・`dead_stream_watch.py` の表）——いまは依頼文の表で1か所ずつ
- 人物像と狙う語——サジェストは curl（`docs/seo-2026-11/G_skopje_intent.md` の測りかた）
- `guide_article.py` の icon の名前と、表紙の写真を本文に置いた検査——いまは依頼文の合格の条件
- `guide_art.py finalize` が中身の同じ地図・共有の JPG を書き直す——いまは依頼文で `git checkout --`

## 5. トークンの物差し

### 基準（ブカレスト、2026-11-18〜20）

| 担当 | 道具の呼び出し | 最大の文脈 | 何を持たせたか |
| --- | --- | --- | --- |
| 材料 | 約870回 | 約90万トークン | 材料・写真の 429・絵の一部・書体の焼き直し・見張りの赤・#1311 の割り込み（1人に全部。#342） |
| 絵 | 約80回 × 2人 | — | 注文書1枚と一覧の絵1枚を合格の条件にして、1往復で通った |
| 運営の転送 | 十数回 | — | 担当の `send_later` の控えが運営のセッションに届き、読んで回した |

### 次の街の目標（ブカレストの半分）

| | 目標 |
| --- | --- |
| 材料担当 | 道具の呼び出し **430回以内**・最大の文脈 **45万以内** |
| 絵担当 | **40回以内**（1人） |
| 運営の転送 | **0**（担当に `send_later` を使わせない） |

### 測りかた・控える場所

- 担当の完了の通知（Agent の結果の usage）から、`tool_uses`（道具の呼び出し）と `total_tokens`（終わりの文脈＝いちばん育った文脈）を写す
- 街を1つ公開したら、[`tokens.md`](./tokens.md) に1行（配った担当の数・呼び出しの合計・最大の文脈・運営の転送・目標との差）。公開の PR に積む
- 目標を越えた街は、越えた担当の何が重かったかを `tokens.md` の注に1行。2街続けて同じ所なら、道具か Actions にする（`/hand-off` の「同じ仕事を2回したら」）

### 文脈を育てない決まり

1. **段ごとに新しい担当を立てる。受け渡しはファイル**（`book.py`・`art_order.json`・PR 番号・`<運営のスクラッチ>` の絵）。前の担当の会話を次へ渡さない
2. **担当が300回を超えたら、いまの段を push して止まり、残りを報告に書く。** 運営は同じ依頼文の残りを新しい担当に配る
3. **重いもの（写真・調べ・書き出し・書体・見張り）は Actions。** 読むのは表と、落ちた step の末尾だけ（`actions.md`）
4. **担当は `send_later` と `subscribe_pr_activity` を使わない**（どちらも運営のセッションに届く）。Actions の待ちは `gh run watch <id> --exit-status` を `run_in_background` で
5. **長いファイルを丸ごと読まない。** 台本は手本の頭と1項目ずつ、docs は依頼文が名指しした章だけ
6. 報告は依頼文が決めた行数まで。表は CI のコメントを貼る
