# SUZURI のグッズ

**1本のスキルで、ファイルを用事ごとに分けてある。** まずここを読み、用事のファイルへ進む。

| 用事 | 読むファイル |
| --- | --- |
| どの用事でも先に（ログイン・読み書き・絵の上げ方・大きさ・確かめ方） | [`ops.md`](ops.md) |
| 島に新しいキャラクターが入った／キャラの絵が描き直された | [`characters.md`](characters.md) |
| あやとのステッカー（や、あやとの絵）をグッズにする | [`ayato.md`](ayato.md) |

道具:

| ファイル | どこで動く | 何をするか |
| --- | --- | --- |
| `suzuri_ops.py` | EC2（`/home/ubuntu/cdp/`） | 読む・書く・上げる・消す・大きさを決める・見本を並べて焼く |
| `login.py` ＋ `login_ec2.sh` | EC2 ＋ 手元 | ログインの確かめ（`check`）と、切れていたときの Google ログイン（確認コードはあやとから） |
| `characters.py` | EC2（`/home/ubuntu/cdp/`） | 島のキャラと SUZURI を突き合わせ、「作る／差し替える／島に居ない／透過なし」を出す |
| `python/suzuri_common.py` | どちらでも | 大きさ・下ごしらえ・透過・題と本文。**EC2 のスキルと Actions が同じものを読む** |
| `python/suzuri_api.py` ＋ `.github/workflows/suzuri_api.yml` | GitHub Actions | 公式の API を呼ぶ口。**早いときはこちらを先に使う**（あやと #732）。毎晩、新しいキャラの住人グッズを5品目（大きさまで）で作る |

**EC2 の Chrome の触り方は `ec2-chrome` に書いてある（共通の土台）。** SSM で送る・ファイルを持ち帰る・
Chrome を起こす・固まったときの直し方は、ここには書かない。

## 決まっていること（あやと 2026-10-09、#731）

- **利益（トリブン）は 1アイテム 300円。** 全部そろえる（イギリスのトートだけ 1,000円で別物）
- **品目は5つ:** Sticker / Acrylic Key Chain / Tin Badge / Mug / Acrylic Panel。**大きさは絵ごとに合わせる**
- コンセプトは「架空のシェアハウス カサ・アヤト」から**「あやと島」に変わった。** 本文はあやと島の文。
  題の「カサ・アヤトの住人 ○」は、あやとの指定でそのまま
- 他社のロゴに似た絵を出すときは、**題と本文にその会社の名前を入れない**（Q4）
- 島の `/goods` 面の「SUZURI グッズ」欄の写真は、グッズを足しても差し替えない（#732）

## 出す前に、必ず目で見る

**API が 200 を返しても、絵は切れうる。** 作ったら `sheet()` で売り場の見本を1枚に並べ、
`ec2.py get` で持ち帰って `Read` で見る。缶バッジとアクリルパネルが切れていないか、
大きさがほかの住人とそろっているか（2026-10-09 に、見本を見て3回直した）。

## 公式の API と MCP について（2026-10-09 に読んだ）

SUZURI には **REST API**（`suzuri.jp/api/v1`、ユーザごとの API キー）と、**SUZURI MCP**
（`https://mcp.suzuri.jp/mcp`、Claude から OAuth で繋ぐ）がある。何ができて何ができないかは
[`ops.md` の「公式の API と MCP」](ops.md#公式の-api-と-mcp) に表にしてある。
**どちらで回すかの表は `ops.md` の同じ節にある。** API はドキュメントに無いが缶バッジとパネルの大きさも
保存できる（2026-10-09 に確かめた）。EC2 のスキルに残るのは、絵の差し替えと、見本を並べて確かめるところ。
