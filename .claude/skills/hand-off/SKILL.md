### ① 合格の条件

**「前より良い」は条件ではない**（`docs/island-standards.md`）。
**何が見えていれば通るか**を数で書く。

```
- `cd site && npx tsc --noEmit` が通る（`echo $?` で 0 を確認）
- `python3 python/selftest_runner.py`（`echo $?` まで報告）
- **次の6通りを実際に走らせて、出力を報告に貼る。** 頭の中で辿るのは不可
- **守りを1つ外したら、その足だけが落ちること**（対照。BREAK= で切り替える）
```

**対照を必ず入れる。** 「通った」だけでは、見張りが空回りしていても緑になる
（`docs/island-misses.md` の「空回しの緑は、本当の緑より弱い」）。

### ④ 出しかた

**いちばん上に、これを書く。**

```
- **動くようになった時点で、確認の前に一度 push する。** 確認はそのあと。
  「全部終わってから1回」にしない
```

**2026-10-15、箱が再起動して担当2人が消えた。** 片方は 590行、もう片方は 436行
書き終わっていて、**どちらも1行も push していなかった。** worktree が
たまたまディスクに残っていたので拾えたが、**運で助かっただけ**で、
箱が作り直されていたら 1,000行まるごと無かったことになっていた。

落ちる理由はこちらで選べない（箱の再起動は中から止められないし、
**原因も中からは出せない**——カーネルのログは再起動で消える）。
**選べるのは「落ちたときに何が残るか」だけ。** 押してあれば残る。

途中の枝が増えることを嫌がらない。**確認の通っていない枝は PR にしなければよい**
だけで、消えた作業より安い。

```
- ブランチ `claude/<短い名前>` を master から切る（`git fetch origin master` してから）
- コミットメッセージは日本語で、**なぜそうしたか**を書く。モデル名を入れない
- 末尾に:
    Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>
    Claude-Session: <このセッションのURL>
- `git push -u origin claude/<名前>`
- PR を作る。本文に実測を貼る。閉じる issue があれば `Closes #NNN`、
  **触れるだけで閉じないものは `#NNN は閉じない` と1行**（`closes_check` の逃がし方）
- **出しかたは依頼文で1つに決めて書く**（下の3つから）。書かなければ「PR 番号と実測を報告して止まる」
  - 道具・ワークフロー・手引きだけ（配信に出ない）→ 合格の条件を満たしたら**自分でマージしてよい**
  - 配信・島に出るもの（`app/` `public/` `site/`）→ **札 `出す` を付けてよい**（ship.yml がマージ・デプロイ・本番の突き合わせまでやる）。
    出す判断を先に渡すときだけ書く。見てから決めたいなら「札は付けずに報告」
  - `.github/workflows/` を触るもの → ship.yml では出せない（GITHUB_TOKEN でマージできない）。自分でマージ
```

## 3. 配ったあと

- **報告を鵜呑みにしない。** 数字と、それをどう測ったかを見る。
  「枠を広げないと載らない」のように、**2つの別の話が混ざっている**ことがある
- **出す前に自分で差分を読む。** 特に「何かを捨てる判定」は、
  捨てすぎていないかを自分で確かめる
- 担当が挙げた「指示に無かったが直した」は**丁寧に読む。** たいてい本物の地雷
- **出す判断はこちらに残す。** 依頼文で先に渡す（④の「札を付けてよい」）か、上がってきてから自分で札 `出す` を付ける。
  手で `workflow_dispatch` を押してデプロイの run を見張るのは、ship.yml で出せないものだけ
- **確かめは CI の表と一覧の絵1〜2枚で。** 担当の録画を全部開き直さない。出す前に自分で見るのは「指摘された場面」と「いちばん高い段」
- **返事の要らない報告には返さない。** 「違えば一言」は、違わなければ黙っていてよい
- 次の段階に要る相手（後ろの担当）へは、マージした sha を1行で知らせるだけ

書いている途中のファイルも、そこでは区別が付かない。**

2026-09-23、これで毎回止まった。見張りの文は「誰かの作業中なら、その人に
任せて良い」と言っていたのに、**コードにその逃げ道が無かった。**

**書いた道だけが外れる。** 書いていないものは今までどおり止まる
（対照で確かめてある）。

## 5. 並べて走らせるとき

- **同じファイルを2人に触らせない。** 先に範囲を切る
- **`git add -A` を使わない。** 2026-09-23、これで**担当2人の書きかけを
  巻き込んで、担当の枝にコミットした。** 同じ作業ディレクトリで動いている
  あいだは、`git add` に**自分が触ったファイルを名指しで並べる**
- **できれば worktree を分ける。** 自分が手を動かすなら
  `git worktree add -B <枝> /tmp/wt-<名前> origin/master` で別の場所を作る。
  同じところに居ると、**担当が枝を切り替えた拍子に、自分のコミットが
  担当の枝に乗る**（実際に乗せた）
- worktree を切るなら `functions/node_modules` は symlink 可、
  **`tools/sprites/node_modules` は実体を複製**（CLAUDE.md の表。symlink だと1本落ちる）
- ビルドは `tools/build.sh` から。**並列で `next build` を3本回すと箱が止まる**
- **終わった担当の worktree は、その日のうちに片づける。** 担当の worktree
  （`.claude/worktrees/agent-*`）は、担当が終わっても残る。2026-10-21 に30個・約8GB 溜まっていて、
  ショートの暗号文（作業枝に1.5GB）を開いた担当が「unable to write file」で止まった（空き 1.3MB）。
  片づける前に1本ずつ `git -C <wt> status --porcelain` が空なのを見て、`git worktree remove <wt>`
  （`--force` は使わない。枝は残るのでコミットは消えない）。動いている担当と、ロックの掛かったものは残す
