# 配信から「実際に行った」を抜く（guide-facts）

行った街のガイドは、**行った日・払った額・本人の一言・その場面の時刻つきリンク**で答える（#1196・#1203）。
その材料を、配信1本につき1ファイルで作る。**読み手は、面を作る担当と道具**（視聴者さん向けの文章ではない）。

分担は議事録（`/stream-notes`）と同じ。**1本につき1人の担当が読んで抜き、道具 `python/guide_facts.py` が確かめる。**

## 0. 置き場

```
streams/2026/10/
  2026-10-24_2123_eHBAnQF56-E.transcript.txt   # 材料（手で直さない）
  2026-10-24_2123_eHBAnQF56-E.chat.txt         # 材料（手で直さない）
  2026-10-24_2123_eHBAnQF56-E.md               # 議事録（地図として使う。先に要る）
  2026-10-24_2123_eHBAnQF56-E.facts.json       # ← これを書く
streams/guide/north-macedonia/skopje.md        # 街ごとの下書き（city が作る。手で直さない）
python/data/guide/cities.json                  # 寄せる表（国・街・通貨の言いかた・場所の名前）
```

## 1. 手順

1. **まだの配信を出す。** `python3 python/guide_facts.py pending --country north-macedonia`
2. **1本につき1人、エージェントに配る**（§4 の依頼文）。エージェントは `.facts.json` を書くだけで、コミットしない
3. **確かめる。** `python3 python/guide_facts.py check --country north-macedonia`（1本なら stem を渡す）。
   終了 0=通った / 1=NG / **2=見るものが無い**（項目0件・材料が読めない）。落ちたものは同じ担当に NG の行を渡して直させる。
   NG の札（`number` `quote` `readaloud` `chatfirst` `identity` `music` `split` …）の意味は `python/guide_facts.py` の頭の表
4. **寄せる表に足す。** check が「寄せる表に無い場所の名前」と数えたものを見て、同じ場所の別の書きかたなら
   `cities.json` の `places` に足す（担当には触らせない。同じファイルを何人もが踏むので）
5. **束ねる。** `python3 python/guide_facts.py city --country north-macedonia --city skopje --out streams/guide/north-macedonia/skopje.md`
   （check を通っていない材料が1本でも在れば組まない）
6. コミットして push（「なぜ」を書く。何本足したか）

## 2. 結果の形

```json
{
 "schema": 1,
 "video_id": "eHBAnQF56-E", "start_jst": "2026-10-24 21:23", "date_local": "2026-10-24",
 "country": "north-macedonia", "city": "skopje", "place_line": "北マケドニア・スコピエ",
 "items": [
  {
   "kind": "price",
   "text": "バスは片道50。本人の計算では150円で、往復で100。",
   "t": 4260,
   "src": {"lines": ["1:11:00"], "notes": "[1:00:30] 山の入り口から30分のハイキング"},
   "what": "マトカ渓谷へのバス（片道・往復）",
   "amounts": [{"value": 50, "unit": null, "as": "said"}, {"value": 150, "unit": "円", "as": "said"}],
   "verify": "50 は単位を言っていない。150円は本人がその場で3倍にした額",
   "place": {"name": "マトカ渓谷", "heard": ["ま渓谷", "警谷"]},
   "quote": "…"
  }
 ]
}
```

**頭の7欄は `new` が機械で埋める**（stem・議事録の `- 場所:`・寄せる表から）。手で書かない。

| 欄 | 中身 |
| --- | --- |
| `kind` | `move` どう行く・どう動く／`price` いくらかかる／`place` どこへ行った／`food` 食べたもの／`stay` 泊まる／`fact` 街のようす／`caution` 気をつけること（失敗談）／`quote` 本人の言い回し（`about` に、どの問いの話かを上の7つから） |
| `text` | 短い事実の1文。こちらの言葉でよいが、**言っていないことを足さない** |
| `t` | その場面の秒。時刻つきリンクはここから機械で組む（`&t=<t>s`）。根拠の行の中に置く |
| `src.lines` | 根拠にした文字起こしの行の時刻（30秒きざみの `h:mm:ss`）。頭から尻まで5分以内 |
| `src.notes` | 議事録のどの見出しか。`new` が出す見出しを**そのまま写す** |
| `what` `amounts` | 額が在るとき。`as` は `said`（配信で言ったまま）か `converted`（こちらの換算。`from` と `rate` が要る）。`unit` は言ったままの単位、**言っていなければ `null`** |
| `other_amounts` | 根拠の行の近く（前後1行）に在るが、この項目の品ではない額（`{value, unit, what}`） |
| `verify` | 「確かめが要る」の印。**何を確かめるか**を字で書く。面に載せる前に、動画か外の出どころで確かめる |
| `place` | `name` は読める正の名前、`heard` はその配信の字幕での形（崩れたまま。無ければ `[]`） |
| `quote` | 本人の言い回し。**字幕に在る字のまま** |

## 3. 抜くときの決まり

- **正は文字起こし。** 議事録は地図（どの時刻に何が在るか）で、機械が書いたもの。**議事録に在って字幕で確かめられないものは抜かない**
- **本文の算用数字は、全部「配信で言った数字」として確かめられる**（根拠の行の前後 ±90秒）。
  言っていない数（「1泊」と言っていないのに書く 1、こちらが数えた「3つ」）は書かない。**換算した額は本文に書かない**（`amounts` にだけ）
- **1項目に、同じ単位の額は1つ。** 2つ言っているなら、割れている（→ 両方挙げて `verify`）か、別の品（→ `other_amounts` か別の項目）
- **言い回しは字幕の字のまま。** 直してよいのは2つだけ——明らかな誤字のすぐあとに `[正しい字]` を**足す**
  （字幕の字は消さない。「吉の屋[吉野家]より早い」）、途中を飛ばすときは `…`。崩れがひどい所は、言い回しにしない
- **チャットが出どころの話は抜かない。** 本人はチャットを声に出して読むので、字幕では本人の発話に見える。
  `read --chat` で同じ時刻のチャットを並べて見る。**本人がその通りだったと体験したぶんだけ**、本人の体験として書く
  （「手前で折り返すことがあるらしい」は抜かない。「この日は手前で降ろされた」は抜く）
- **視聴者さんのことは1字も書かない。** 名前・呼びかけ・チャットの文・投げ銭。本人（配信者）の発話と体験だけ
- **第三者（宿の人・同宿の人・店の人・通りがかりの人）は、名前を書かない。** その人が特定できる話
  （どこの誰が何をした）と、特定できる店への悪い評判は抜かない
- **歌詞の印の付いた行（`[音楽]`）は根拠にしない**
- 屋内の回（料理・雑談・アプリ作り）は、街の事実がほぼ無い。**食材の値段・宿の様子**だけ抜いて、無理に増やさない

## 4. 配るときの依頼文

```
配信1本から「実際に行った」を抜いて、<stem>.facts.json を書いてください。日本語。
手順と形は /home/user/live-streaming/.claude/skills/guide-facts/SKILL.md の §2・§3 に従うこと（先に読む）。
見本: /home/user/live-streaming/streams/2026/10/2026-10-24_2123_eHBAnQF56-E.facts.json

進めかた（文字起こしを丸ごと読まない）:
1. python3 python/guide_facts.py new <stem>        … 頭を埋めた空のファイルと、議事録の見出しが出る
2. 議事録 <stem>.md の「## 流れ」を読んで、外で見た・払った・乗った・食べた・泊まった・しくじった場面の時刻を拾う
3. その時刻の前後だけを読む: python3 python/guide_facts.py read <stem> 0:17:00 0:24:00 [--chat]
   （言い回しにする所と、額の出どころが怪しい所は --chat を付けて、読み上げでないかを見る）
4. 項目を書いて、python3 python/guide_facts.py check <stem> が終了 0 になるまで直す。
   直せないもの（字幕に無い・チャットと重なる）は落とす。verify で黙らせない

触ってよいのは <stem>.facts.json だけ。材料（transcript / chat / md）も、寄せる表も触らない。コミットしない。
返すのは10行以内: 項目の数（種類ごと）／落とした数と理由／verify を付けた数／
寄せる表に足してほしい場所の名前／迷った点。視聴者さんの名前とチャットの文は、報告にも書かない。
```

字幕が無い回（`manifest.tsv` が `none`）と、議事録がまだの回は配らない（議事録が先）。

## 5. 1本あたりの手間と、つまずく所（2026-11 の試作3本の実測）

| | 到着の日（1:16） | 旧市街と食堂（1:46） | マトカ渓谷（3:47） |
| --- | ---: | ---: | ---: |
| 字幕の字数 | 1.5万 | 1.7万 | 3.2万 |
| 読んだ字幕（窓の合計） | 約9千字（6割） | 約6.5千字（4割） | 約8.5千字（3割） |
| `read` の回数 | 6 | 6 | 8 |
| 項目 | 26 | 15 | 21 |
| check を回した回数 | 5 | 3 | 3 |

議事録の「流れ」（3〜4千字）を足して、**1本あたり読む字は1〜1.3万字、往復は10回前後**。

つまずいた所（どれも実際に起きた）:

- **議事録の数字と言い回しが、字幕に無い。** 「1泊19ユーロ」→ 字幕は `eur` と `price 19` が別の行で「1泊」は言っていない。
  「片道50デナール」→ 字幕は「50」だけで、単位はチャットの字。「サウナの後に入る水風呂みたい」→ 字幕は「サウナの後に入る。冷たいな」
- **議事録に、チャットが出どころの事実が混ざっている**（市内の運賃・店の支払いかた・水面の棒の正体）。3本で6件、抜かなかった
- **読み上げを、本人の一言として2件入れかけた**（道具が `readaloud` で落とした。うち1件は、字幕が「やばい」・
  チャットが「ヤバい」で、はじめの比べかたをすり抜けていた）。言い回しは必ず `--chat` で見る。
  本文のほうは道具では見きれない——**チャットが先に言ったこと（「ゴミが増えた」「真っ暗」）を、本人の観察として書かない**
- **チャットが出どころの数字を、本人の数字として1件書いていた**（料理が来るまでの「1分」。本人はチャットを読んだだけ）。
  数字は道具が `chatfirst` で見る（本人が言う前に、同じ数字＋あとの1字がチャットに在る）。本人が先に言った行を根拠にする
- **値段はほぼ全部「円」で喋る。** 本人がその場で値札を円に直している（北マケドニアは「3倍」）。現地通貨の単位はほとんど言わない。
  「600」が円かデナールか字幕から決められないときは `unit: null` か、言ったまま「円」にして `verify`
- **場所の名前は字幕にほとんど無い。** 「マトカ」は題名にだけ在り、本文は「ま渓谷」「警谷」。`heard` は本文に在る形を書く
- **字幕には周りの人の声も入る**（外国語の行）。本人の発話ではないので抜かない
- **お祈りの放送が曲として伏せられている**ことがある。その前後の話は根拠にできない
- **所要時間は、言った数字より配信の時刻の差のほうが確か**（乗った 0:11 → 降りた 1:00）。いまの形には入れていない（言った数字だけ）
