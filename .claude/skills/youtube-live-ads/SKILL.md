# ライブアーカイブの広告をオンにする

**Studio の触り方は `youtube-studio` に、EC2 の触り方は `ec2-chrome` に書いてある。** ここは見回りの手順だけ。

## 0. 何をする見回りか（あやと 2026-10-09）

> 対応する → 曲を消去する → 申し立てを受けたセグメントのすべての音をミュートします → 保存
> そうすると「動画編集が進行中です...」となるので、一旦OK。
> 対応中のものはリポジトリの何処かにメモする。次回からは、対応中のものが解消されていれば収益化をオンにして、
> まだ申立があれば再度対応をする。ライブ配信の日付が一番見たものの中で最新を記録しておけば、
> 次回からは差分のライブ配信の動画を確認する。

決まっていないこと（#757 で聞いている。答えが来たら、この節と台帳の `hold` を書き換える）:

- Q1 申し立てが無いのに収益化がオフの43本を、オンにしてよいか
- Q2 権利者と収益を分け合っている3本をミュートするか
- Q3 ミュートで2割以上の音が消える7本をどうするか

## 1. 台帳（`ledger.json`）

| キー | 中身 |
| --- | --- |
| `checked_through` | 見た中でいちばん新しい配信（開始時刻・id）。次回はこれより新しいもの＋その前14日ぶんを見る |
| `hold` | 手を付けない動画と、その理由（`#757 Q3 の答え待ち` など） |
| `videos` | **片づいていない動画だけ。** 収益化されたら消える |
| `videos.*.state` | 下の表のどれか |
| `videos.*.history` | 送った対応（日付・申し立て・曲・区間の秒） |

**台帳はこのリポジトリの中に置く**（期限や状態を持つが、見回りの道具が毎回読み書きする入力なので、
`docs/` ではなくスキルの横）。あやとが見たいときは issue ではなくこのファイルを見ればよい。

## 2. 手順

```bash
E=.claude/skills/ec2-chrome/ec2.py
python3 $E put .claude/skills/ec2-chrome/cdp.py /home/ubuntu/cdp/cdp.py
python3 $E put .claude/skills/youtube-studio/yt_studio.py /home/ubuntu/cdp/yt_studio.py
python3 $E put .claude/skills/youtube-live-ads/live_ads.py /home/ubuntu/cdp/live_ads.py
python3 $E put .claude/skills/youtube-live-ads/ledger.json /home/ubuntu/cdp/ledger.json
```

1. **まず `--dry`。** 何も送らず振り分けだけを出す:
   `cd /home/ubuntu/cdp && timeout 280 python3 live_ads.py ledger.json /home/ubuntu/shots/ledger.dry.json --dry`
2. 振り分けを読む（`ledger.dry.json.log.json`）。`to-mute` の本数と曲が妥当か、`manual` が無いかを見る
3. 本番: `live_ads.py ledger.json /home/ubuntu/shots/ledger.out.json`。
   **ミュートは元に戻せない。** 何本に送るかを、流す前にあやとへ一言添える
4. `ec2.py get` で `ledger.out.json` を持ち帰り、`ledger.json` に上書きしてコミット
5. 1本、`url_of("video/<id>/claims")` を `shot` して「動画編集が進行中です…」を目で見る

## 3. 振り分け（`live_ads.py` の `classify`）

| state | いまの状態 | すること |
| --- | --- | --- |
| `done` | 収益化されている | 台帳から消す |
| `editing` | 動画編集が進行中 | 待つ。次回また見る |
| `mute` → `editing` | 申し立てがあり、ミュートで対応できる | **1件だけ**ミュートを送る。残りは次回 |
| `to-mute` | （`--dry` のとき）上と同じ | 次の本番で送る |
| `enable` | 申し立てが無いのに収益化がオフ | 収益化をオンにする（下の「まだ」） |
| `hold` | `hold` に載っている／権利者と分け合っている | 何もしない |
| `manual` | ミュートで対応できない申し立て、または申し立て以外の理由 | 人が見る。issue にする |
| `error` | 送ったが失敗した | 理由を読んで次回やり直す |

**1本に申し立てが何件あっても、1回の見回りで送るのは1件。** 編集中は次の申し立てに触れないから
（画面の「対応する」も押せなくなる）。2026-10-10 時点で、1本に複数件ついている動画は34本、最多は35件。

## 4. まだ分かっていないこと

- **収益化をオンにする要求を、まだ写していない。** 申し立てが解けた動画が出たら、`/video/<id>/monetization/ads`
  で1回だけ画面で押し、`capture(t, act=…)` で写して `yt_studio.py` に `enable_ads()` を足す。
  それまで `enable` は台帳に積むだけ
- **編集にどれくらいかかるか。** 画面は「数分から数時間」と言う。hK0SwIeAxg0（3時間30分の配信、31秒のミュート）を
  2026-10-10 に送ったので、終わった時刻を測って書く
- **配信の数日後に付く申し立て。** 前回より14日さかのぼって見直しているが、それより後に付いたものは拾えない。
  ときどき `--all` で全件を見る
