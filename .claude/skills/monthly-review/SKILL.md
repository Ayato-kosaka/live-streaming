# 月末配信ふりかえり授賞式スキル

前月末〜当月末の配信を1枚のOBS画面で表彰式にする。参考実装: `public/202609_monthly_review.html`(2026年9月版・完成形)。**8月版を土台にしない**——王冠が賞名にかぶる形が残っている(#649)。新しい月は `public/2026MM_monthly_review.html` として新規作成する(過去ページは上書きしない)。

## 1. ワークフロー

1. **期間確定**: **前回の月末配信の日 〜 今回の月末配信の前日**(あやと 2026-09-26。
   9月版なら 8/29〜9/25)。**勝手に「月初〜月末」にしない。**
   JSTで扱い、BigQueryにはUTCで渡す(JST 0:00 = 前日15:00 UTC)。
   0時をまたいだ続き枠は**前日に寄せる**(開始が 6:00 JST より前の枠)。
   出席の分母・投げ銭・はじめましての人数は、**全部この同じ期間**で数える。
2. **データ取得**(§2): 統計・全コメント・出席を最小クエリで取得。
3. **通読・選定**: 全コメントをローカルで通読し、各コーナーの候補(名言・おもしろ・流行語・盛り上がり等)を選ぶ。
4. **企画会議**(毎回必須): AskUserQuestion で **コーナー構成とデザインテーマの案を複数出して決める**。固定3コーナー(§3〜§5)は必ず入れる。**量と順番は §6 に決めがある。**過去の採用実績: 今月の軌跡タイムライン / 初見さんいらっしゃい / 常連さん表彰 / どの配信でしょうクイズ / 盛り上がりの瞬間TOP3 / 流行語大賞 / 名言・いい話アワード / おもしろコメント大賞(部門賞+グランプリ) / 投げ銭ありがとう / あやと島案内鳥 からの手紙 / エンディング。
5. **実装**(§7) → **検証**(§8) → **デプロイ**(§9) → view/ctrl のURLを報告。

## 2. BigQuery の知見

- プロジェクト `live-streaming-d3cac`、データセット `youtube_chat`。`chat_messages`(パーティション: published_at、`event_type` は TEXT/PAID等)、`videos`。
- フィルタ: `event_type = 'TEXT'` かつ bot除外 `author_name != '@あやとグルメアプリ'`。
- **課金最小方針**: 1クエリ≒10MB最小課金(1円未満)だが回数を増やさない。コメント本文は一括ダンプしてローカルで分析。MCPは約3000行で切れるので `video_id` 範囲などで分割。
- **正確性が要る集計はBQ集約1発で確定させる**(ローカルダンプは行落ちすることがある)。出席は `STRING_AGG(DISTINCT video_id)` を著者ごとに取るのが確実。
- 表示名は `ARRAY_AGG(author_name ORDER BY published_at DESC LIMIT 1)[OFFSET(0)]`(最新名)。

## 3. 固定コーナー①: 出席リスナー表彰

- **日毎集計**: 同じ日の複数配信はまとめて1日。その日どれかに1コメントでもあれば出席。
- **深夜0時跨ぎ**: 0時過ぎに再開した続き枠は前日の配信日に帰属させる。
- **コメント消失日**(YouTube側バグで全コメントが消えた配信日)は、当時すでに来ていた人(初出席がその日以前)を出席扱いにする。
- 集計後の日(作成日前後)は分母から除外。分母=期間内で配信があった日数。
- 表示は **出席日数リスト(日数のみ) → 皆勤賞の表彰台**(アイコン大+「出席 N/N日」+「N ヶ月連続」+ひとこと)。
  **皆勤賞が後。**(あやと 2026-09-27)。先に全員の日数を出して、いちばん上を最後に立てる。
  逆にすると、皆勤賞のあとにリストが続いて盛り上がりが下がる。注記に集計ルールを明記。
- **皆勤賞には「何ヶ月連続か」を必ず出す**(あやと 2026-09-26)。月末配信の日で区切った期間ごとに
  皆勤を数えて、当月から遡って続いている数。**1ヶ月目は「1ヶ月連続」と書かない**——連続は2つ目から
  数えるもので、初めての人には別の言葉(「はじめての皆勤賞」)と別の色が要る。
- **個人別コメント数は絶対に表示しない**(嫌がる人が多い)。「コメント王」等の賞も作らない。出席も発言も多い人は名言・クイズなどのコーナーで紹介してあげる。極端にコメントが少ない人は無理に扱わない。

## 4. 固定コーナー②: 投げ銭ランキング

**表彰するのは「いくら出したか」ではなく「いくら貢献したか」**(あやと 2026-09-26):

> ランキングの仕様 = 豚の貯金箱の仕様 = いくら配信の企画や私の夢への応援に
> 貢献してくれたか。……**実額は視聴者には一切見せない仕様整理です。**

- 額は **貢献額 = スパチャ ÷ 2 + Doneru**。スパチャは YouTube が半分持っていくので、
  出してくれた額と夢に届いた額が違う。表彰するのは届いたほう。
  **式は `python/fund_box.py` の `viewer_yen()` ひとつ。ここで割り算を書かない。**
  端数は豚の貯金箱と同じ**切り捨て**。
- 作るのは `python/admin/monthly_tips_run.py`(Actions の `run_admin_script`)。
  `{"from":"<前回の月末配信の日>","to":"<今回の前日>"}` を渡すと、
  BigQuery と図鑑を読んで順位まで作り、`data.js` に貼る JSON を出す。
  **1バイトも書かない。** 決め方の見張りは `python/monthly_tips_selftest.py`。
- **名寄せは図鑑(`islandCharacter`)が正。自作しない。**
  スパチャは `channelId`、Doneru は**名乗り → `lookupKeys`**。
  配信中のカードとアラートボックスが同じ欄で引いているので、別の当て方を
  ここだけ作ると**画面に出ている絵とランキングの並びが食い違う**。
  ちょうど1人に当たったときだけ寄せ、寄らなかった人は**その人ひとりで1行**。
- 演出: 4位以下リスト → 3位 → 2位 → ドラムロール → 1位+紙吹雪 → 「合計 N円 ありがとうございました🙏」。同額は同順位タイ。
- **画面で式を説明しない**(`CLAUDE.md`)。出すのは順位と呼び名と額だけ。
- 背景画像はこのシーンだけ差し替え(data URI埋め込み・半透明ベールで可読性確保)。

## 5. 固定コーナー③: あやと島案内鳥 からの手紙

- 全コメントを読んだ案内鳥からの所感を段落ごとにステップ表示。その月の固有名詞・出来事・リスナーの言葉を織り込む。締めの署名は「あやと島案内鳥 より」。
- **感動する手紙にする**(あやと 2026-09-27)。9月版は「9月を客観的に総括した文章」で、
  よく書けてはいたが**読んで胸に来るものではなかった。** 事実を並べるだけでは足りない。
  効いたのは「止まらない時間の長さが、止まった瞬間の値打ちを作っていた」のように、
  **その月にしか言えないことを1つ言い切る**段落。そこを増やす。
  逆に効かないのは、月の出来事を時系列でなぞるだけの段落。
- **「誰々が何々と言いました」を並べない**(あやと 2026-09-25)。引用は文章の中に溶かす。
- **視聴者さんに見せる名前は「あやと島案内鳥」。画面にも署名にも `Claude` と書かない**（あやと 2026-09-20）。

## 6. コーナーの量と順番

**2026-09 の配信を実際にやったあと、あやとが言ったこと**(2026-09-27)。
ここは毎回読む。**「前より良い」で量を決めない。**

### 6-1. 並び

```
オープニング
 ↓
今月の6分割ふりかえり   ← **新しく入れる**（6-3）
 ↓
出席日数リスト
 ↓
皆勤賞                 ← **出席ランキングの後**（あやとの指摘）
 ↓
（以下、その月の構成）
 ↓
投げ銭ありがとう
 ↓
あやと島案内鳥 からの手紙
 ↓
エンディング
```

### 6-2. 1コーナーの量

| コーナー | 2026-09 | 次から | なぜ |
| --- | --- | --- | --- |
| おもしろコメント大賞 | 部門賞6 + グランプリ6 | **部門賞6 + グランプリ1** | 「対象が6人いて副対象も6人」で**くどかった**。頂点は1つ |
| はじめまして | 名乗ってくれた人を素直に並べた | **閾値をつけて厳選** | 6-4 |
| 名言・いい話 | （9月版の数） | **2つ減らす** | 長い |
| 流行語大賞 | — | **そのまま** | — |
| 調べもの大賞 | 9月から入れた | **そのまま。ただし次は別のトピックに替えてよい** | 毎月同じ切り口だと飽きる |
| どの配信でしょうクイズ | 3問 | **7問くらい** | 少なすぎた |
| 皆勤賞 | 表彰台のみ | **「N ヶ月連続」を必ず出す** | §3 |

**賞の形は「多い側を広く、頂点を1つ」。** 部門賞をN人出すなら、グランプリは1人。
両方N人にすると、どちらが上なのか画面から読めない。

### 6-3. 今月の6分割ふりかえり（オープニングの次）

**その月を6つに割って、軽く振り返る面。**(あやと 2026-09-27
「毎月の振り返りが6分割振り返りみたいなのがあるとすごいいい」)

- 置くのは**オープニングと出席日数リストのあいだ**
- **軽く。** 1コマにつき短い見出しと1〜2行。読み上げて10秒で次へ行ける量
- 割り方は月による。9月なら「台所の前半 / 出発 / ヒッチハイク前半 / ヒッチハイク後半 /
  到着 / 帰ってからの台所」のように、**出来事の区切りで割る**（週で機械的に割らない）

### 6-4. はじめまして の閾値

**「今月はじめてコメントした人」を全部出さない。**(あやと 2026-09-27
「投げ銭してくれてる人か、新しく出会って毎日来てくれるようになった人以外はあんまり記憶に残ってない」)

出すのは次のどちらかに当たる人だけ。

1. **その期間に投げ銭してくれた人**
2. **初コメントの日から、その期間の残りの日をよく来ている人**
   （目安として、初コメント以降の配信日の半分以上に出席）

**総数（「今月 N 人がはじめてコメントしてくれました」）はそのまま出してよい。**
減らすのは**札にして並べる人数**のほう。

## 7. 実装の技術要件

- `public/2026MM_monthly_review.html` **単一ファイル・実行時の外部依存なし**(オフラインでも開ける。例外はFirestore同期時のgstatic SDKのみ)。
- シーン/ステップ進行機構: `SCENES`配列+`[data-step]`表示制御+進行ドット+紙吹雪+`?auto=秒`の自動進行。クリック/Enterで進む、←で戻る。1920×1080前提、横スクロール禁止。
- **アバター**: YouTubeチャンネルページの og:image をビルド時に取得し `=s176-c-rj`(JPEG)でdata URI埋め込み。取れない人はイニシャルの丸にフォールバック。投げ銭アバターはユーザー提供URLから取得。巨大なdata URIはEditツールでなくnodeスクリプトのプレースホルダ置換で注入する。
- **Firestore同期**: `?role=ctrl`(スマホコントローラ) / `?role=view`(OBS側)。**同期まわりは `public/202609_monthly_review.html` からまるごとコピーする**(firebaseConfig・SDKの版・ログイン・札の出しかたが1式で噛み合っている)。ドキュメントは `monthlyReview/2026MM-<ランダム>` を月ごとに新規発行。
- **書けるのはあやとだけ**(2026-09-11〜)。`firestore.rules` の monthlyReview は「読むのは誰でも1件ずつ／書くのは `islandUsers/{uid}.admin` が立っている人だけ」。前は誰でも書けて、**外から進行を飛ばせた**。
  - **ctrl はログインしていないと進行を送れない。** 同じ端末で島(`/`)にログイン済みなら押さずに繋がる(SDKの版と apiKey を島に合わせてあるのがその仕掛け)。繋がらないときだけ「Google でログイン」が出る。
  - **SDKの版を勝手に下げない。** 島(`site/package.json` の firebase ^12)と大版がずれると、ログインの引き継ぎが効かなくなって、配信の当日に押させることになる。
  - **OBS(view)は今までどおりログイン不要。** 読みは開けてある。
- **ctrlの教訓(重要)**: ①グローバルの pointerdown/contextmenu ハンドラは ctrl では登録しない(ボタンclickと二重発火し1タップで複数進むバグになる) ②自分の書き込みエコー(`snap.metadata.hasPendingWrites`)と手元より古い `ts` のスナップショットは無視 ③ボタンに `touch-action: manipulation`。
- コンテンツポリシー: 引用はほぼ原文(絵文字コードは実絵文字に)、名前は「〜さん」付け、`escapeHtml` を必ず通す。

## 8. 検証

- Playwright(`playwright-core` + `executablePath: '/opt/pw-browsers/chromium-*/chrome-linux/chrome'`, `args: ['--no-sandbox']`)+ `python3 -m http.server`。
- 確認項目: 全シーンのスクリーンショット / Enter連打で最後まで→Backspaceで先頭まで戻る / 横スクロールなし / **ctrlで5タップ=ちょうど5進む** / 個人コメント数が出ていないことをgrep。
- Firestore の読みは REST で確かめられる(`GET https://firestore.googleapis.com/v1/projects/live-streaming-d3cac/databases/(default)/documents/monthlyReview/<docId>?key=<apiKey>` が 200)。**書きは apiKey では通らない**(403。2026-09-11 に閉じた)。
  - **書類の作成と初期化(scene:0/step:0)は `.github/workflows/run_admin_script.yml` から。** `python/admin/firestore_write.py` に `{"collection":"monthlyReview","doc":"<docId>","data":{"scene":0,"step":0,"ts":1,"confetti":0}}`。サービスアカウントはルールを迂回する。
  - **同期そのものを確かめるなら、Firestore と Auth のエミュレータにブラウザ2枚を繋ぐ。** この箱のブラウザは gstatic に届かないので、SDK を curl で落として Playwright の `route` で差し替える。見るのは「ログイン前は送れない／あやと以外も送れない／あやとは送れて OBS が追う／古い `ts` では巻き戻らない」。

## 9. デプロイ・運用

- GitHub Actions `firebase-hosting-deploy-prod.yml` を workflow_dispatch で起動(`npm run build:web` が public/ を dist にコピーする)。masterマージ後に master で起動するのが基本。
- 反映確認: `https://live-streaming-d3cac.web.app/2026MM_monthly_review.html` が200+新版内容。
- ユーザーへの案内: OBS用 `?role=view` / 操作スマホ用 `?role=ctrl` / 1台運用は無指定。数字キーでコーナー頭出し(リハーサル用)。
