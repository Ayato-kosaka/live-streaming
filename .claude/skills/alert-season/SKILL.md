### 演出の水準（あやと 2026-11-02、#1079）

次の季節の演出は、これを基準に作る。

- めざすのは**投げた人がワクワクする**こと
- 質は **TikTok のギフトの水準**（光・奥行き・ぼけ・粒・光の筋・なめらかな動き）。ハロウィン2版目は75点で、足りなかったのは**絵と動きの質（高級感）**
- 「TikTok 風」は物の数を増やすことではない。**テーマに合った質の高さ**のこと。ごちゃごちゃさせない
- **低い段は背景を汚さない。高い段ほど画面を大きく派手に使う**（ハロウィンの高い段は「全然物足りない」）
- お手本は **1,500円の魔女**。魔法陣から呼び出し → 注目 → 魔法陣へ帰る、の一本の物語がある。**金額が上がるほど高品質で、段ごとに違う物語**にする（被らせない）
- **主役（投げた人のキャラ）と背景のキャラの間を空けすぎない**（邪魔に見える）
- 長さはハロウィン2版目でちょうど良い。前兆はもう少しあってよい。1,000円からあやとが出る区切りは効いている。字はハロウィン2版目のままでよい
- 500円未満は控えめでよいが、**豪華さと可愛さは要る**。500円のお菓子落としは見えにくく、可愛くなく、豪華さに欠けた。300円のほうきのピポとこうもりのほうが人気
- **性能を落とさない。** 「前はもっと動かしてもなめらかだった」と言われた（調べた結果と決まりは4節の「重さの決まり」）

## 1. 配信の画面（実測。推測しない）

- アプリは **PRISM Live（スマホ）**、配信は 9:16。貯金箱とアラートは**同じウィジェット**
- ウィジェットのページの大きさ（CSS px）: **ふだん 436×776、投げ銭のとき手で広げて 664×1180**（9:16 のまま大きさだけ変わる）。PRISM の「140%」は、ページを 1.4 倍に拡げて見せる倍率
- **resize の知らせが絶えず来る**（数百回）。寸法で React を描き直さない（rAF で1回にまとめ、1px 未満は捨てる）。
  **箱を手で広げているあいだは並べ直さない**（`useSettledBoxSize`。止まった大きさのまま面を transform で拡げ、止まって 200ms で並べ直す。#1079）
- **PRISM では `visualViewport.scale` が 0.5。豚だけが半分に描かれる**（#1078 / `docs/island-misses.md` #311）。react-native-web の `Dimensions`（`useWindowDimensions` も）は `visualViewport.width × scale` を返すので、ページ幅の半分になる（豚が箱の4割に出るのはこれ）。物差しが部品ごとに違う:

  | 部品 | 物差し | PRISM では |
  | --- | --- | --- |
  | 豚（`PiggyGauge`・`ThemedGauge`） | `useStableWindow`（Dimensions） | **半分**（箱 436 で幅 178px・41%） |
  | 季節の貯金箱（`KuroBank`。10月） | `useBoxSize`（`<html>` の幅） | 縮まない |
  | 季節の貯金箱（`CastleBank`。11月から） | `useStableWindow`（Dimensions） | **豚と同じに縮む**（いつも豚の 1.6 倍） |
  | アラート（段の演出・字・キャラ絵・季節の小物） | `useSettledBoxSize`（同じ `<html>` の幅。広げているあいだは止まった大きさ） | 縮まない |
  | 絵文字の雨（`components.tsx` の `RainEffect`） | `Dimensions.get("window").height` | 落ちる先が箱の半分の高さ |

  ふつうの Chromium では scale は 1 なので、入れずに撮ると**豚だけが PRISM の2倍に写る**（41% → 82%）。**`tools/sprites/alert-*.mjs` は全部、既定でこの縮み方を入れて撮る**（`tools/sprites/prism.mjs`）。`--no-prism` で外せるが、それは「外すとこう外れる」を見せる対照だけ。**外して測った数で判断しない。** 新しく撮る道具を足すときも、context を作ったらページを開く前に `await prism(ctx)` を通す
- **scale は PRISM の % に比例する**（2026-11-02、あやとのスマホで 100% のとき 0.36。`/alert/perf` の「拡大」）。% は「ページを何倍に拡げて見せるか」で、枠の見た目の大きさは変わらない。なので `<html>` の幅は % に反比例し（140% で 436 なら 100% で約 606）、Dimensions の幅（`<html>` の幅 × scale）は % に依らず約 218。**豚は CSS px で同じ大きさに描かれて、% 倍に拡げて見える。** `<html>` の幅で決めた部品は枠に対して同じ割合に見えるので、% を変えると豚との比が変わる。道具では `--prism-scale 0.36`（箱は `prism.mjs` の `boxAt` で拡げる）
- 迷ったら測る: ウィジェットの URL を一時的に `https://live-streaming-d3cac.web.app/alert/probe` に向けてもらい、2枚撮ってもらう（`public/alert/probe.html`）
- 録画の箱（1080×1920 の配信画面の座標）: ふだん `--frame 401,722,607,1082 --zoom 1.39`、広げたとき `--frame 76,445,927,1452 --zoom 1.40`（どちらも PRISM 140%）
  - **配信の写真（`bg/prism-street.jpg`）の豚とは合わない**（2026-11-02。右に約 95px・1.13 倍）。写真の豚に、PRISM の条件で描いた豚を当てはめると、CSS px 1 つが配信の 1.57px（140% の 1.39 の 1.13 倍）で、豚の下の端の真ん中が (800, 1815)。写真の日は PRISM が約 158% だった、と読むと揃う（scale が % に比例するのと同じ比）。**貯金箱（豚・城）だけを写真に重ねて録るなら** `--frame 455,597,685,1218 --zoom 1.57`（箱 436×776 のまま、豚が写真の豚にぴったり乗る）。豚と城は Dimensions と下の端の真ん中だけで決まるので、枠の幅が分からなくても位置と大きさは合う。**アラート（`<html>` の幅で決まる）はこの枠では合わない**: その日の枠の幅が分からないから
- 配信画面の背景（`--bg street|face|alert-now|alert-fish`）はスクラッチの `bg/` に置く。**本人の顔が写っているので git に入れない**

## 2. 提案する（issue で）

1. `app/alertbox/themes.ts` の `THEMES` を読み、いま効いているテーマと次に切れる日を出す
2. 今日から 6〜8 週の季節の候補を、7段の主役の表で出す。作るのに 2〜3 日かかる（ハロウィンは設計からリリースまで約2日）

## 3. 描く（ChatGPT、EC2 の Chrome）

操作は `/chatgpt`・`/chatgpt-image`。**1つの会話で続けて描く**（絵柄が揃う）。EC2 は鍵を持って使い、終わったら止める
（ほかのセッションが止めることがある。止まったら起こし直して時刻を控える）。返事待ちが 600 秒で切れても、会話を開き直すと絵はできていることがある。

1. **設定画を先に**: あやとの仮装を4つ並べた1枚・脇役を並べた1枚。ここで可愛くなければ全部が可愛くない。オーナーの目線合わせにも使う
2. **あやとは「ポーズ絵」**（部品に分けない）: 並べた設定画からその仮装を切り出して添え、「この子の次のポーズ」と頼む。見せ場ごとに1枚（例: 魔法使い fly / cast / idle、ドラキュラ rise / spread / idle）。**設定画と並べて、顔が同じで崩れていないかを見てから使う**。顔の幅は仮装の中でそろえる（切り替えで顔が跳ねない）
   ```bash
   python3 tools/alert-theme/poses.py add <置き場> <名前> <ChatGPT の絵.png> --face-w 300
   python3 tools/alert-theme/poses.py check <置き場> <out.png>     # 紺と緑の地・顔の枠
   python3 tools/alert-theme/poses_webp.py ...                      # WebP q90 に（容量が半分）
   ```
   ChatGPT は「透過で」と頼んでも市松模様を描いて返すことがある（poses.py が地として抜く）
3. **小さな脇役と小物は「部品」**（切り絵。60fps で体ごと動かす）: 貯金箱のマスコット・かぼちゃ坊や・おばけ・こうもりなど。関節の側を丸く余分に描かせ（重なりしろ）、`rigbuild.py` で rig.json と PNG を作り、`rig.py jointcheck` で ±30° 回して穴 0
4. 置き場: `public/alert/themes/<id>/poses/<仮装>/`（poses.json: 寸法・中身の外接矩形・顔の枠・足元・向き）、`rig/<名前>/`（rig.json: parts の id・parent・pivot・at・z・swaps、anchors・items）、`items/<段>/`（items.json）
5. 黒い体・黒い服は、外形にだけ光のふち（ラベンダー・金・淡い紫）を付ける。配信者の黒い服や暗転の上で溶ける

## 4. 動かす（`app/alertbox/season/`）

- 段を足すのは「`season/show/` に1ファイル＋ `TierShow.tsx` の kind に1分岐＋ `themes.ts` の段の `show` 1件」。テーマを足すのは `THEMES` に1件
- 主役は登場で箱の中央を使い、**字が出る瞬間には顔が字のブロックより上**。滞在中は箱の上の帯（`headroom`）の角へ退く
- 読み込み: 開いたら貯金箱の絵だけ展開。ほかの段の絵は4秒後からダウンロードだけ。**展開（decode）は投げ銭が来たその段のぶんだけ**（スマホの記憶を食わない）。間に合わない段は小物の演出に落ちる（欠けた主役は出さない）
- 動かすのは transform と opacity だけ（CLAUDE.md の描画コスト）。待機中は rAF を回さない
- `live: false` で作り、出すときに外す（`?theme=<id>` の試し見では `live: false` でも出る）

### 重さの決まり（#1079。ハロウィン2版目を 2026-11-02 に測った）

**どの段も、PRISM の条件で1秒60コマを保つ。** ハロウィン2版目は段7で 20〜23 コマだった。

決まり（次の季節から）:

- 小さく出す絵は、出す大きさ（の2〜3倍まで）に縮めてから使う
- 無限に動く合成の層（`will-change`・止まらない Web Animations）は、数と面積を絞る
- 大きな光る面の上で別のものを動かすときは、段ごとに `/alert/perf` か GPU の数で確かめる

わかったこと:

- こうもりは、画面で 40×18px なのに、元の大きさの絵（体 362×394・羽 430×270）を、無限に動く合成の層で使っていた。段2・段7でいちばん重い
