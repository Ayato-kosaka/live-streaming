# あやと島 — 遊びの設計

**なぜ人は毎日あつ森を起動するのか**を分解して、あやと島に移せる形にした文書。

読む順番としては [`island-concept.md`](./island-concept.md)（何のための島か）と
[`island-design.md`](./island-design.md)（拘束力のあるデザイン仕様）のあと。
ここに書いてあるのは「何を作るか」であって、「どう見せるか」ではない。
見せ方でぶつかったときは `island-design.md` が勝つ。

この文書が答えようとしている問いは1つ。

> 昨日も来た人が、今日もう一度ここを開く理由は何か。

いまのあやと島には、その理由が無い。昨日と今日で島が同じだからだ。
6つの入口はいつも同じ顔で立っていて、住人はいつも同じことを言い、
数字だけが静かに増えている。作りは良いが、**一度見たら終わる**。

---

## 1. 本物の分解

思い出しで並べても意味がないので、仕掛けごとに「**何が起きるか**」と
「**なぜそれが効くのか**」を分けて書く。効く理由が言えないものは、移しても効かない。

### A. 時間が現実と同期している

**何が起きるか** — ゲーム内の時刻は本体の時計そのもの。朝は朝、夜は夜。
BGM が1時間ごとに変わる。19時にしか出ない虫がいる。季節で魚が入れ替わる。
自分が起動していない間も世界は進んでいて、放っておくと雑草が生える。

**なぜ効くか** — 3つある。

1. **開くたびに違うものが返る**ことが構造として保証されている。
   同じ操作をしても違う結果が返るなら、もう一度やる理由がある。
2. **見逃しが発生する。** 19時の虫は19時にしか居ない。
   「今しか見られない」は、来る理由であると同時に、来なかったことの損でもある。
3. **自分がいない間も世界が動いていた痕跡**が残る。雑草、伸びた木、引っ越した住人。
   これが「この世界は自分のためだけに用意されたのではない」という実在感を作る。
   起動を待って止まっている世界は、書き割りに見える。

### B. 毎日リセットされる小さな用事

**何が起きるか** — 化石が4つ埋まっている。光る地面が1つある。岩は8回叩ける。
木を揺すると家具が落ちる。流れ星が流れる。どれも**毎日ぶん決まった数**があり、
その日ぶんを取り切ると、それ以上は出ない。

**なぜ効くか** —

1. **上限があるので、やめどきが来る。** 終わりの無い用事は1回で嫌になる。
   「今日ぶんは終わった」と言い切れるから、毎日戻れる。
2. **1周が短い。** 探す場所が島の中に固定されているので、5分で回れる。
   1周が長い日課は、忙しい日に飛ばされ、飛ばした日から来なくなる。
3. **毎日同じ手順なので考えなくていい。** 判断が要らない行動は儀式になる。
   儀式は習慣として定着する。

**加えて重要な点** — 用事は「作業」ではなく「**探す**」形をしている。
化石は地面のヒビ、光る地面は光、という**見つけられる合図**が地面に置いてある。
合図を探して島を一周する、という動線が、用事そのものではなく合図から生まれている。

### C. 集める枠が目に見えている

**何が起きるか** — 博物館の台座が空いている。カタログに未所持の欄がある。
「あと3種」と書いてある。

**なぜ効くか** —

1. **空欄は「未完了」として認識され、埋めたくなる。**
   持っているものを数える表示（35品つくりました）より、
   持っていないものを見せる表示（9月の枠が空いている）のほうが強く効く。
2. **空欄には形がある。** 何が入るのかが見て分かるので、
   図鑑を開くだけで「次に何をすればいいか」が決まる。図鑑が TODO リストとして働いている。

### D. 少しずつしか進まない

**何が起きるか** — 建物は1日1軒。通販は翌日届く。木は3日で育つ。橋は翌日完成。
どれだけ急いでも、その日のうちには終わらない。

**なぜ効くか** —

1. **明日ぶんの理由が、今日のうちに置かれる。**
   プレイヤーが「明日も来よう」と決心するのではない。
   世界のほうが勝手に明日の予約を入れてくる。これが決定的に楽。
2. **待ちの向こうに確定した楽しみがある**ので、待ちが期待になる。
   待ちの先が不確定だと、同じ遅延がただの苛立ちになる。
3. **催促しても進まない**ことが、世界の自律性を示す（A-3 と同じ効果）。

### E. 誰かがそこにいる

**何が起きるか** — 住人が向こうから話しかけてくる。名前を覚えている。
しばらく来ないと「久しぶり」と言う。誕生日を覚えている。あだ名を付けてくる。
「あなたの島は花が多いね」のように、**こちらを観測した発言**をする。

**なぜ効くか** —

1. **一方的に呼びかけられる。** こちらが何もしなくても、向こうから来る。
   参加の入口が向こうから運ばれてくる。
2. **記憶されている。** 前回を参照した発言が**1つあるだけ**で、
   関係が途切れていないと感じる。実装量と体感の差がいちばん大きいところ。
3. **数が有限で、それぞれ違うことを言う。** 全部聞くと一周するので、また来る。

### F. 自分の痕跡が残る

**何が起きるか** — 置いた家具はそこにある。作った道は残る。マイデザインは他人の島でも使われる。

**なぜ効くか** —

1. **世界に対して自分が原因になれる。** 変えたものが、次に来たときも変わったままである。
2. **他人に見せられる。** 作ったものは、見られるために作られる。
3. 少しずつしか変えられない（D と組む）ので、長期の投資になり、捨てにくくなる。

### G. 稀に起きる

**何が起きるか** — ジョニーが浜に倒れている。風船が飛んでくる。流れ星。
つねきちの船。季節限定の虫。

**なぜ効くか** — **変動比率の報酬**。何も無い日があるからこそ、ある日が効く。
毎日必ず起きることは、3日で背景になる。
「今日は誰か来てるかな」という問いが、毎日の起動理由そのものになっている。

### H. 島に降りた直後に、今日の要約が1つ渡される

**何が起きるか** — 朝の島内放送。空港のアナウンス。「今日は◯◯です」。

**なぜ効くか** — **起動から行動までの距離をゼロにする。**
何をすればいいか探させない。探させると、探しているあいだに離脱する。

### I. 1アクションが短く、必ず何かが返る

**何が起きるか** — 走る、木を揺する、穴を掘る。0.5秒で完結し、音と動きとモノが返る。

**なぜ効くか** — **用事の中身がつまらなくても、手触りそのものが報酬になる。**
逆に言えば、手触りが悪いと、どんなに良い仕掛けも回らない。

### J. 達成すべき目標が無い

**なぜ効くか** — 「できていない」が存在しないので、何日空けても罪悪感なく戻れる。
進捗バーを置いた瞬間に、離れた人が戻りにくくなる。

---

### この9つに共通していること

分解してみると、全部が3つの原理に収束する。**移すべきなのは仕掛けではなく、この3つ。**

1. **明日ぶんの理由が、今日のうちに世界の側から置かれている。**
   利用者に「また来よう」と思わせるのではなく、世界が勝手に明日の予約を入れる（A・D・G）。
2. **1回ぶんが極端に短く、終わりが明示されている。**
   終わりが来るから、毎日戻れる（B・I・J）。
3. **世界のほうが先に口を開く。**
   探させない。向こうから声をかける（E・H）。

**オーナーの「みんなが能動的に参加したくなる」への答えは、3番にある。**
人は促されて能動的になるのではない。**向こうから声がかかったときに応じる。
応じたことが、あとから能動に見える。** 参加を呼びかけるボタンをいくら増やしても、
声をかけるのがこちら側でなければ、誰も押さない。

## 2. いま、あやと島に何があるか

**この章の表は、この文書を書いた時点の棚卸し。もう追いついていない。**
いま何が入っているかは、8章の各仕掛けに付けた「入れた」の見出しを見る。
2026年9月の時点で入っているのは 1・2・3・5・6・7・8・9・10・13・15・16。
入っていないのは 11（スタンプ帳の空いた月）・12（採用された企画を島に残す）・
14（島の人口）と、作らないと決めた 4・17・18。

列の「**昨日と今日で変わるか**」が、この文書の主眼。

| ある場所 | いまできること | 昨日と今日で変わるか |
| --- | --- | --- |
| 島（`IslandStage`） | 歩く。建物を押して入る。住人に話しかける | **変わらない** |
| 島の空 | 見ている人の時計で朝昼夕夜が変わる（`app/layout.tsx`） | 1日の中では変わる。**日をまたいでは変わらない** |
| 島の景色 | あやとの現在地でテーマが変わる（`Theme.tsx`） | 国が変わる時だけ。数か月に1度 |
| 住人（12人） | 持ち場をうろうろする。押すと1言しゃべる。3人ずつ「話しかけて」の合図 | セリフは順に回るが、**中身は固定** |
| 入口の札 | 6つ。近づくと開く。「これから」だけ「あとN日」バッジ | **カウントダウンだけが毎日変わる** |
| いまどこ `/now` | 現在地・ひとこと・今週やること・今夜まであとN分 | あやとが手で書いた時だけ。**週単位** |
| これから `/next` | 企画の一覧。付箋を貼れる | 企画を足した時だけ |
| 企画をだす `/board` | 企画を貼る。さんせいを押す。採用済みに札が付く | みんなが書けば変わる |
| クッキング `/kitchen` | 35品のスタンプ帳。月ごとの並びもある | 料理を足した時だけ |
| 歩いた国 `/map` | 17カ国の地図と滞在期間 | 国が変わる時だけ |
| 愉快な仲間達 `/friends` | 22人のキャラクターの壁 | **「押しても何も起きません。眺めるところです」と本文に書いてある** |
| 数字（`LiveNumber`） | 配信本数・コメント数を最新値に差し替える | 毎日わずかに増える。**気付かれない** |

**結論。毎日変わるものが、実質「あとN日」の1つしかない。**
これでは1周する理由が作れない。

いっぽうで、**土台はほぼ揃っている**ことも分かった。

- 時計を読む仕組み（`NowLive.tsx` の `readClock`）はある。島では使っていないだけ。
- 吹き出しの仕組み（`talkbox`）はある。住人を押した時にしか出ないだけ。
- 「新しいものがある」の合図（`NextUp` のベルと赤い丸）はある。トップにしか無いだけ。
- 押して意思表示する仕組み（`islandVotes`・1人1票）はある。企画にしか付いていないだけ。
- 665本の配信と 132,000件のコメントが BigQuery にある。**日付で引けば、365日ぶんの中身がすでに手元にある。**

**新しく作らなければならないものは、思ったより少ない。並べ替えと接続で相当いける。**

## 3. あやと島が本物より強いところ／弱いところ

### 強いところ（あつ森が絶対に真似できない）

1. **時間の同期が本物。**
   あつ森の「今しか見られない」は疑似的なもので、本体の時計を進めれば崩せる。
   ここは**本当に毎晩22時に配信がある**。3時間だけ点いて、消える。
   これは真似ではなく、本物のほうを持っている。
2. **世界が本当に進む。** 明日には別の国にいる。9月11日にジョージアを出る。
   D（少しずつしか進まない）が演出ではなく事実として存在している。
   「あと6日でポーランド」は、誰も作っていない本物のカウントダウン。
3. **痕跡が現実を変える。** 掲示板に書いたことが、本当に配信で実行される。
   F（自分の痕跡）の最上位。ピクセルではなく、人の行動が変わる。
   これができるゲームは無い。
4. **住人が実在の人。** キャラクターは投げ銭で作られた本人の絵で、
   セリフはその人が実際に書いたコメントの口調から起こしてある。
   E（誰かがそこにいる）が、借り物の NPC ではない。
5. **過去が全部残っている。** 665本の配信、132,000件のコメント、17カ国、35品。
   C（集める枠）の中身を、これから作る必要がない。**もう埋まっている。**

### 弱いところ

1. **静的書き出し。** 時間で変わるものは、画面が出てから JS で計算し直す必要がある。
   サーバ側で「今日のページ」を作れない。
2. **ブラウザから Firestore を直接触れない。** 読み書きは `islandApi` 1本を通す。
   リアルタイム同期（誰かが今ここにいる）は作れないと考えたほうがいい。
3. **島は「人の島」であって「自分の島」ではない。** ここが一番大事な違い。
   あつ森のプレイヤーは島の主人だが、あやと島に来る人は**客**である。
   客に毎日の用事を課すのは筋が違う。**（→ 4章）**
4. **来る回数が少ない。** ゲームは起動する気で起動するが、
   サイトは何かのついでに開かれる。1周は1分でなければならない。あつ森の5分は長すぎる。

## 4. 何を移して、何を移さないか

### 移すもの

| 本物の仕掛け | あやと島での形 | なぜ移せるか |
| --- | --- | --- |
| A 時間の同期 | 配信の22時、旅の日数、1年前の今日 | 本物のほうを持っているから |
| B 毎日の小さな用事 | **用事ではなく「便り」として**（下記） | 形を変えれば移せる |
| C 図鑑の空欄 | スタンプ帳の空いた月、まだ行っていない国 | 中身がすでにある |
| D 少しずつ進む | 旅そのもの。出発までの日数 | 演出ではなく事実 |
| E 誰かがいる | 住人の「久しぶり」。ミナトの一言 | 仕組みはもうある |
| F 痕跡が残る | 企画が採用されて島に残る | 本物より強い |
| G 稀に起きる | **乱数ではなく、本当に稀なこと**（新しい国に入った日、100本目の配信） | 嘘をつかずに作れる |
| H 今日の要約 | 島に降りた瞬間の1枚（→ 仕掛け1） | いちばん効く。いちばん先にやる |

### 移さないもの

**理由まで書く。理由が残っていないと、半年後に誰かが同じことを思いつく。**

| 移さないもの | なぜ移さないか |
| --- | --- |
| **育成・レベル・経験値** | 何が育つのかを説明できない。視聴者が育つ物語ではないし、あやとが育つのを視聴者が操作するのも違う。数字を増やすためだけの数字は、置いた瞬間に安っぽくなる |
| **アイテム収集・島内通貨** | 集めても何にも使えない。使い道を作ると、今度は使い道のための作業が生まれる。**投げ銭という本物の経済がすぐ隣にあるので、偽の通貨は特に嘘くさい** |
| **ランキング・個人スコア** | 月末配信のポリシーで「個人別コメント数は絶対に表示しない」と決まっている（`.claude/skills/monthly-review/SKILL.md`）。嫌がる人が多いというのは実測された事実。競争を持ち込むと、いま来ている人の居心地を壊す |
| **ログインボーナス・連続日数** | 切れたときに罰として働く。来なかった日を責める仕掛けを、配信者のサイトに置いてはいけない。**来なかった日には触れず、「久しぶり」とだけ言う**（→ 仕掛け6） |
| **ガチャ・確率の当たり** | 投げ銭の導線の隣に置くと、射幸性の匂いがする。G（稀に起きる）は、乱数ではなく**本当に稀な出来事**で作る |
| **進捗バー・達成率** | J のとおり。「できていない」を作ると、離れた人が戻りにくくなる |
| **配信のコメントをそのまま島で喋らせる** | `island-design.md` が明確に禁じている。文脈のないコメントは初めて来た人に意味が通らない。口調だけ借りて中身は島の案内にする、といういまの `chatter.ts` の作りが正しい |
| **「いま何人が島にいます」のリアルタイム表示** | 作れないうえに、作れたとしても**たいていの時間帯は「1人」と出る**。1人と出た瞬間に、この島は寂れて見える。日単位のカウントなら数十〜数百になるので、出すならそちら |

### いちばん大事な線引き — 用事ではなく、便り

**あやと島に来る人は客である。客に日課を課してはいけない。**

あつ森のデイリーは「自分の島の手入れ」だから成立する。
あやと島で同じことをやると、「人の家に毎日通って掃除をさせられる」になる。

なので B（毎日の小さな用事）は、形を変えて移す。

- **こなす**のではなく、**受け取る**
- **集める**のではなく、**見て帰る**
- **今日ぶんが終わる**という上限だけは、そのまま移す

具体的には、毎日1つ「今日はこれがあった」を渡して、
それを見たら今日ぶんは終わり、という形にする。
拾うものは残らないし、貯まらない。貯まらないことが正しい。

## 5. 毎日の1周

**1分で終わること。長い周回は誰もやらない。**

| 経過 | 何が起きるか | どの仕掛けか |
| --- | --- | --- |
| 0:00 | 島に降りる。空は見ている人の時計の色 | いまもある |
| 0:03 | 右上（PC）／下バーの左端（スマホ）に**今日の1枚**。赤い丸が付いている | 仕掛け1 |
| 0:08 | 押す。今日の1行が開く。「1年前の今日はボルジョミにいました」 | 仕掛け1・2 |
| 0:20 | 閉じる。島のどこかに、いつもは無いものが1つ落ちている | 仕掛け4 |
| 0:35 | 歩いて押す。吹き出しで中身が出る。島から出ない | 仕掛け4 |
| 0:45 | 住人が1人、合図を出している。押す。「久しぶり」から始まる | 仕掛け6 |
| 0:55 | 帰る |

**この1周には「入る」が1回も含まれていない。** それでいい。
島の中で完結する周回がまずあって、そのうえで気が向いたら建物に入る。
いまは島の中でできることが「入る」しかないので、島がただの玄関マットになっている。

**配信中（JST 22:00–25:00）の1周はこう変わる。**

| 経過 | 何が起きるか |
| --- | --- |
| 0:00 | 島に降りる。**やぐらに灯りがついていて、煙が出ている**（仕掛け7） |
| 0:05 | 今日の1枚が「いま配信の時間。トビリシから繋いでます」 |
| 0:10 | 押す。YouTube へ出る |

配信中に来た人を島に留めない。**外へ出すのが正解。** 島は留守番の場所である。

## 6. はじめて来た人の5分

### いまの姿

カモメと一緒に降りる（3.4秒）→ 島 → 6つの札 → どれか押す → ページへ → **戻ってこない**。

問題は3つ。

1. **島に降りた時点で、この人が誰で何をしているのか1文も出ない。**
   看板ロゴに「毎晩22時、世界のどこかから生配信」と書いてあるが、
   絵として沈んでいて読まれない。
2. **押すと島から出てしまう。** 「島にもどる」はあるが、
   戻ると `AYATO_HOME` に戻され、到着演出からやり直しになる。2軒目に行く気にならない。
3. **何も残さずに帰る。痕跡がゼロ。** 参加の階段のいちばん下の段が、いきなり「200字書く」。

### 設計する5分

| 経過 | 何が起きるか | 仕掛け |
| --- | --- | --- |
| 0:00 | 降りる。空はいまの時刻 | いまもある |
| 0:06 | **ミナトが1回だけ言う。**「あやとは今トビリシ。今夜22時から配信するよ」。1文だけ | 仕掛け9 |
| 0:15 | 歩く。住人が合図を出している | いまもある |
| 0:25 | 押す。「初めてやったら、『あやとのこと』から見てみ」 | いまもある |
| 0:40 | 今日の1枚を押す。「1年前の今日はボルジョミにいました」 | 仕掛け1・2 |
| 1:10 | 「これから」の札に「あと6日」。押して入る | いまもある |
| 2:30 | 島にもどる。**さっきの建物の前に立っている** | 仕掛け8 |
| 3:00 | 掲示板へ。**問いが1つ出ている。**「次に作るなら、どっち？」 | 仕掛け3 |
| 3:10 | 押す。棒が伸びて「いま37人がこっちを押した」 | 仕掛け3 |
| 3:20 | 「理由も書ける？」が下に出ている。書くか、書かずに帰るか | 仕掛け3 |

**0:06 と 3:10 の2つが要。**
前者で「この島は何か」が1文で伝わり、後者で**文章を書かずに参加が成立する**。

## 7. 参加の階段

### いまの段差

| 段 | いまあるか | 摩擦 |
| --- | --- | --- |
| 何もしない | ある | — |
| 見る | ある | — |
| 押す（建物・住人） | ある | 低い |
| **押して意思表示する** | **無い** | — |
| 書く（企画200字・付箋120字） | ある | **高い。いきなり文章** |
| 名前を出す | ログイン必須。しかも未有効化（issue #90） | 高い |
| 投げ銭する | 外部サイト（Doneru） | 高い |

**いちばんの断層は「押す」と「書く」のあいだにある。**
押すだけで参加になる段が、1つも無い。

「さんせい」は既にあるが、**誰かが書いた企画にしか押せない**。
掲示板が空だと押すものが無いし、他人の企画に押すのは自分の意思表示になりにくい。

### 埋める

いちばん下に「**選択肢が用意されている問いを1つ押す**」を入れる（仕掛け3）。

- 書かない。選ぶだけ
- 押した瞬間に数字が動く（自分の1票が絵として見える）
- 押したあとに、次の段への橋がその場にある（「理由も書ける？」）

さらに、その1つ上の段として「**付箋を1行だけ**」を用意する。
120字を上限として見せるのではなく、**「ひとことでいい」と書く**。
上限の提示は「これだけ書け」に読まれる。

### 段位 A — これを1つやるなら、これ

#### 仕掛け 1. 今日の島（島に降りた瞬間に1つだけ届く）

**画面** — 島に降りると、PC は右上、スマホは下バーの左端に小さな板が1枚出る。
赤い丸が付いている。中身は今日の1行。押すと開いて3行になる。もう一度押すと閉じる。
**その日はじめて開いたときだけ、自動で開く**（`localStorage` に日付を持って判定）。

**中身の決め方** — 上から順に見て、最初に当たったものを出す。全部ブラウザ側で判定できる。

1. いま配信中（JST 22:00–25:00）→「いま配信の時間。トビリシから繋いでます」＋ YouTube へ
2. 今日が企画の当日（`plans.ts` の `date`）→「今日は Food & Wine Fest」
3. きのう新しい料理が増えた（`recipes.ts` の `date`）→「きのう、おしんこを作りました」
4. 1年前の今日に配信があった（仕掛け2）→「1年前の今日はボルジョミにいました」
5. どれも無い日 →「今夜22時から。あと3時間20分」

**効く理由** — H そのもの。**起動から「今日は何が違うか」までの距離をゼロにする。**
1〜4は毎日中身が変わるので A（開くたびに違う）が成立し、
5に落ちる日があることが1〜4の日を効かせる（G・変動比率）。
そして**世界のほうが先に口を開いている**（3つの原理の3番）。

**合図について** — 「入口＝札」「新しいものがある＝赤い丸」の2種類は既にある
（`NextUp` のベルと赤い丸）。**3つ目の合図を作らない。** ここでは赤い丸を使う。

**重さ** — 中。1・2・3・5 は既存データだけで作れる。4 だけ仕掛け2に依存する。

**触るファイル**
- `site/components/island/Today.tsx`（新規）
- `site/components/island/IslandStage.tsx`（差し込み。スマホは `.island-bar` の左端）
- `site/app/css/island.css`
- `site/content/voice.ts`（文言）

#### 仕掛け 2. 1年前の今日（665本の配信を日めくりにする）

**画面** — 仕掛け1の4番、および `/now` の中。
「1年前の今日、あやとはボルジョミにいました」＋配信のサムネイル＋タイトル＋国旗。
押すとその配信の YouTube へ。

**データの作り方** — `youtube_chat.videos` の `actual_start_time` を JST の月日でまとめて、
`site/content/onThisDay.ts` に 366日ぶん焼き込む。
1日あたり数百バイト、全体で 60KB 程度。
**静的書き出しなので、表示は画面が出てから今日の日付で引く**（`daysUntil` と同じ理由）。

**効く理由** — A の時間同期。しかも**ゲームの疑似同期ではなく、本当に1年前**。
「去年の今ごろ何してたっけ」は既存の視聴者にいちばん刺さる感情で、
新しく来た人には「この人はこんなに長くやっているのか」が数字ではなく出来事で伝わる。

そして決定的なのは、**365日ぶんの中身がもう手元にあること**。
毎日必ず違うものが出る仕掛けを、コンテンツを1本も書かずに作れるのはこれだけ。

（実測: `videos` は 665本、2024-10-28 から。9月1日〜8日はどの日にも去年の配信が1本ある。
穴の空く日はほとんど無い）

**重さ** — 小〜中。集計スクリプトは `python/build_city_streams.py` の型がそのまま使える。

**触るファイル**
- `python/build_on_this_day.py`（新規）
- `site/content/onThisDay.ts`（自動生成。**手で直さない**）
- `site/components/live/NowLive.tsx` / `site/app/now/page.tsx`
- `site/components/island/Today.tsx`（仕掛け1）

**注意** — `docs/island-db.md` に「`timestamp_usec` は配信開始からのマイクロ秒」とあるが、
実際に見ると**エポックからのマイクロ秒**（1730110510990040 = 2024-10-28）。
配信内の経過時間が要るときは `published_at` と `videos.actual_start_time` の差を取る。
このドキュメントは直しておいたほうがいい。

#### 仕掛け 3. 今夜のおたずね（押すだけで参加できる、いちばん下の段）

**画面** — `/board` のいちばん上に、選択肢2〜4個の問いが**1つだけ**出ている。
「次に作るなら、どっち？」／「次はどっちの国から入る？」／「この料理、また作ってほしい？」。
押すと、その場で棒が伸びて「いま37人がこっちを押した」。
押したあとに、小さく「理由も書ける？」と、既存の企画投稿欄への橋を1本。

島の掲示板（`signboard`）の札にも、問いが出ている間は赤い丸を付ける。

**効く理由** — 参加の階段のいちばん下の段。**文章を書かずに、押すだけで数字が動く。**
押した瞬間に自分の1票が絵として見えるので、F（痕跡が残る）が最短で成立する。
そして次の段（書く）への橋が、押した直後という**いちばん気分が乗っている瞬間**に置かれる。

これは「参加してください」と呼びかけるのではなく、
**こちらから問いを出している**（3つの原理の3番）。

**サーバ側** — `islandPolls/{id}` に `{ question, options: [{id, label}], votes: {a: 12, b: 37}, openUntil, hidden }`。
投票の重複止めは `islandPollVotes/{pollId}_{uid|cid}`。
**`islandVotes` とまったく同じ作りなので、`islandApi.ts` に 40行足せば済む。**
問いの入稿は Firestore を手で書く（`python/admin/firestore_write.py` がある）。

**重さ** — 中。

**触るファイル**

- `site/lib/api.ts`

### 段位 B — 安くて、効きが大きい

#### 仕掛け 4. 今日の落とし物

**画面** — 島のどこかに、いつもは無い小物が1つ落ちている。
**置き場所は毎日変わる**（日付をシードにした固定乱数。SSR と CSR で同じ位置になるよう
`geometry.ts` の `rng` を使う）。近づくと札が開く。押すと、**その場で吹き出しに中身が出る**。
1日1つ。開いたら、その日はもう出ない。

中身は3種のどれか。
- きのうの配信のタイトルとサムネイル
- 作った料理1品（`recipes.ts` からその日のシードで1つ）
- 歩いた国1つ（`countries.ts` の `highlights` から1つ）

**効く理由** — B（毎日の小さな用事）を「便り」の形にしたもの。
1個しかないので1周が短く、終わりが明示される。
**置き場所が毎日変わるので、島を見回す理由ができる。**
いまの島には見回す理由が1つも無い（建物は動かないので、場所を覚えたら二度と見ない）。

**貯めない。集計しない。何個拾ったかを出さない。** 出した瞬間に「用事」になる。

**合図** — 既存の札と同じ形にする。光やきらめきを足さない（`island-design.md` 3-3）。

**重さ** — 中。

**触るファイル**
- `site/components/island/Drop.tsx`（新規）
- `site/components/island/IslandStage.tsx`
- `site/components/island/layout.ts`（置いていい場所の候補。建物と重ならない座標）
- `site/app/css/island.css`

##### 4周目に検討して、作らないことにした。理由を残す

**1 と 3 が入ったあとに読み直すと、この仕掛けは居場所を失っている。**

1. **中身が「今日の島」と同じところから出てくる。** ここに書いてある3種
   （きのうの配信・料理1品・国1つ）は、`lib/todayNews.ts` の 4・7 とそのまま重なる。
   しかも今日の板は、**おたずねが無い日には2つめまで出す**ようになっている
   （`components/today/Today.tsx` の `more`）。島に押すものが1つで終わらないように、
   という同じ目的の手当てが、すでに板の側で済んでいる。
2. **「今日ここに何かある」の印は1つと決めてある。** `app/css/island.css` に
   「『!』の意味を変えた。『今日ここに何かある』だけに使う。**だから出た日に
   本当に目が行く**」と書いてある。落とし物はその2つめになる。
   `island-design.md` 3-4「注目させるのは一度に1つ」に正面からぶつかる。
3. **島を見回す理由は、もう住人が持っている。** この仕掛けが埋めようとしていた
   「島の中でできることが『入る』しかない」は、12人の住人と
   `callOut`（向こうから声をかける）で埋まった。
4. **残った部分が、いちばん移してはいけない形をしている。**
   「1日1つ」「開いたら消える」「置き場所が毎日変わる」の3つを足すと、
   中身が何であれ**毎日の宝探し**になる。数を出さなくても、貯まらなくても、
   形がそれである。4章の「客に日課を課さない」に反する。

**もし将来やるなら**、日替わりの中身を持たせないこと。
島の景色が昨日と少し違う（誰かがベンチに座っている、道に落ち葉がある）だけで、
押しても何も起きない、拾うものが無い、という形なら移せる。
それは仕掛け4ではなく、A-3（自分がいない間も世界が動いていた痕跡）になる。

#### 仕掛け 6. 住人が「久しぶり」と言う

**画面** — 最後に来た日を `localStorage` に持つ。

#### 仕掛け 7. 島にもどったとき、さっきの場所に立っている

#### 仕掛け 8. 到着演出を、毎回見せない

**画面** — いまは `sessionStorage` なので、**セッションをまたぐと毎回3.4秒の演出が入る**。

ただし**30日以上空いた人には、もう一度見せる**（帰ってきた感じがするので）。

#### 仕掛け 10. 「歩いた国」に「滞在◯日目」と「あと◯日で次の国」

**画面** — `/map` と、島の桟橋（`signpost`）の札に
「ジョージア 滞在 106日目」「あと6日でポーランド」。

**効く理由** — D（少しずつしか進まない）が、演出ではなく事実として存在している。
日数が毎日1ずつ増えるので、**毎日違う数字が出る**（A とも組む）。
`countries.ts` の `stays` に `to: ""` が「まだそこにいる」を表しているので、
現在の滞在日数はそのまま計算できる。次の国は `plans.ts` の `date` から。

**重さ** — 小。ただし静的書き出しなので**画面が出てから計算する**（`LiveNumber` と同じ形）。

**触るファイル** — `site/app/map/page.tsx`、`site/components/island/layout.ts`（札の文言）、
`site/components/island/IslandStage.tsx`

##### 入れた。ただし島の札には付けていない

出したのは2か所。`/map` の「いまここ」の欄（「ジョージア／滞在 107日目」）と、
`/now` の帯（「ジョージアに来て 107日目」）。数えるのは `site/lib/stay.ts`。
いまいる国＝滞在の終わり（`to`）が空いている国、という決め方は `/map` と同じにしてある。

**島の道しるべの札には付けなかった。** 理由が2つある。

1. 札の添え書き（`blurb`）は「**そこで何が分かるか**」を言う場所と決まっている
   （`island-design.md` 6章）。滞在の日数は「歩いた国」の中身の答えではない。
   置くと、押す前に読める答えが1つ減る。
2. **出発までの数字は、すでにテントの札が持っている。**
   島の1画面に「あと6日」を2回出すことになる。同じ数字を1つの面で二度読ませない。

「あと◯日で次の国」も出していない。**次の国の名前が、軽く引ける場所に無い。**
`countries.ts` はまだ入っていない国を持たないし、`nordic.ts` を島に読ませると
見どころ161件（44KB）が一緒に落ちてくる。
出すなら `plans.ts` の企画に「どの国に入るか」を1つ持たせるところから。

#### 仕掛け 12. 採用された企画を、島に残す

**画面** — 採用された企画（`islandIdeas` の `status: "picked"` / `"done"`。
**API のスキーマには既にあるが、島には出ていない**）を、
島の掲示板のまわりに小さな板として立てる。押すと「これは9月3日にやりました」＋その配信へ。

**効く理由** — F（痕跡）の最上位。**自分が書いた企画が現実に実行されて、島に残っている。**
これはあつ森にはできない、この島だけの強み。
そして「書けば残る」が**目に見える形で島に立っている**ことが、
参加の階段の上のほう（書く）を引き上げる。

**必要になること** — `done` の企画に「いつやったか」と「どの配信か」を持たせる。
いまの `islandIdeas` には無いので足す。書くのは管理スクリプト側
（`python/admin/firestore_write.py`）。

**重さ** — 中。

**触るファイル**
- `functions/src/islandApi.ts`（`listIdeas` に `doneAt` / `videoId` を通す）
- `site/components/island/IslandStage.tsx` / `layout.ts`
- `site/components/live/Board.tsx`

#### 仕掛け 14. 島の人口が増えるところを見せる

#### 仕掛け 15. その配信の、盛り上がったところ

**画面** — 配信1本のカード（`components/streams/Vid.tsx`）に、
コメント密度の折れ線を1本。いちばん高いところに「ここが1時間12分」。
押すと、その時刻から YouTube を開く（`&t=`）。

**効く理由** — 132,000件のコメントは、**外の誰も持っていないデータ**。
そこからしか出せない情報（3時間のどこで盛り上がったか）を出せる。
3時間のアーカイブは、入口が無いと誰も再生しない。**入口を作るのがこれ。**

**データ** — `chat_messages` を `video_id` × 5分バケットで数えて JSON に焼く。
665本 × 最大36バケットで 24,000行程度。国ごと・年ごとに分割して置く。
配信内の経過時間は `published_at - videos.actual_start_time` で出す
（`timestamp_usec` はエポック時刻なので、そのままでは使えない）。

**重さ** — 中〜大。

**触るファイル**
- `python/build_stream_peaks.py`（新規）
- `site/content/streamPeaks/*.json`（自動生成）
- `site/components/streams/Vid.tsx`、`site/components/ui/Bits.tsx`

##### 入れた。ただし折れ線は出していない

**データを見たら、折れ線は残らなかった。**

3分の窓で見て、山は平均の 2.8倍しかない。5分でならすともっと平らになる。
平らな線を 665本ぶん並べても、読む人には何も分からない。
それは `island-design.md` 4章の言う**飾りの数字**なので、置かないことにした。
残ったのは1点だけ ——「コメントがいちばん重なったところ」と、そこから開くこと。

**山そのものは本物。** コメントを1件おきに2組へ割って、それぞれの山を別々に出して
突き合わせた（split-half）。250件以上・60分以上の 151本のうち **118本（78%）が
2分以内で一致**、ずれの中央値は0分。雑音ではない。

ただし本数の少ない配信では雑音になるので、3つの基準を満たすものだけ焼いてある
（コメント150件以上・45分以上／山の3分に15件以上／平均の2.0倍以上）。
**756本のうち残ったのは 212本。** 残りでは何も出さない。
無い配信に何か出すために基準を下げると、出ているものまで信用されなくなる。

**終わりぎわは山から外した。** 「おつかれさま」が重なるのは合図であって話の中身ではない。
外す前は 306本のうち 29本の山が終わりの3分以内にあった。
最初の1分と最後の3分を、山を探す範囲から外している。

**いちばん効いたのは、仕掛け2との接続だった。**
「1年前の今日」の行き先が3時間の頭だったので、押しても誰も再生しない。
山の分かっている日はそこから開く（`content/onThisDay.ts` の `k`）。
毎日の板の**押した先**が、これで初めて中身のあるものになった。
2025年ぶんの代表 345本のうち、山が引けるのは 107日（31%）。
引けない日は今までどおり頭から開いて、そのことも言わない。

**表はサーバー側にしか置かない**（`content/streamPeaks.ts` は 8KB）。
字と URL を作る2つだけ `lib/peak.ts` に分けてある。板はブラウザで動くので、
同じファイルに入れると表ごと落ちてくる。

#### 仕掛け 16. 島に「今日ここに来た人」の数を出す

**画面** — 島の上（または仕掛け1の板の中）に小さく「今日、42人が島に来ました」。

**触るファイル** — `functions/src/islandApi.ts`、`site/lib/api.ts`、`site/components/island/Today.tsx`
