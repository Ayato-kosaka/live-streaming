# 配信のサムネを作り直す — 調べたことと、進め方

配信のサムネのうち「縦で撮ったものを、そのまま横に押し込んだだけ」のものを洗い出して、
ちゃんと作ったサムネに差し替えたい。どこまで機械にやらせられるかを調べた。

結論から書くと、**棚卸し・素材づくり・作画・差し替えまで、全部つなげられる。**
ただし詰まるところが3つある。ベストショットの取り出し、GPT のキー、OAuth の権限。
それぞれ後ろに書いた。

---

## 1. いま、どうなっているか

### 「未編集」をどう判定したか

YouTube Data API では「カスタムサムネか自動サムネか」が取れない。
`videos.list` の `thumbnails` は、どちらでも同じ形で返ってくる。
なので画像そのものを見て決めた。手がかりは2つ。

1. **左右に無地の黒帯があるか。** 列ごとの標準偏差と明るさを見て、
   端から連続して暗い列を数える。黒帯が横幅の 25% 以上なら「縦のまま」。
   縦配信のサムネは 1280×720 のうち左右 438px ずつが黒で、中身は 404×720（9:16）。
2. **`maxres1.jpg` / `maxres2.jpg` / `maxres3.jpg` と一致するか。**
   この3枚は YouTube が自動で選んだ候補フレーム。誰でも取れる。
   いま出ているサムネがこのどれかと同じなら、自動サムネのまま。
   16×16 の dHash で距離 12 以下を「同じ」とした。

1 は縦配信に、2 は 16:9 配信に効く。両方外れたものを「作ったサムネ」とみなした。
目視で 18本ずつ確かめて、取りこぼしも誤検出も無かった。

ぼかしで左右を埋めている配信（PRISM Live のぼかし埋め）は 1 では拾えないが、
そういう回は 2 で拾えている。

## 2. サムネの型のカタログ

思いつきで作っても仕方がないので、**いま日本で実際に伸びている動画のサムネを集めて、
型を読んでから作った。** 集め方は `tools/thumbs/scrape.py`。
YouTube の検索結果から videoId と再生数を拾って、あやとと同じジャンル
（海外在住 / 旅 / 海外スーパー / 毎日ライブ / 個人開発）の直近の動画を見た。

読み取れた共通点:

- **文字は10文字前後。** 20文字を超えるサムネは、この176件の中に1つも無かった
- **極太ゴシック＋黒フチ＋落ち影。** ほぼ例外なし
- **色は2〜3色。** 白・黒フチ・そこに黄色か赤を1色
- **国旗と地名を必ず入れる。** 旅系はこれが無いと何の話か分からない
- **数字を色替えで強調。**「3時間」「230円」「42日目」
- **顔は大きく、片側に寄せる。** 反対側を文字に使う
- **ライブは赤の LIVE バッジ。** 箇条書きで「今日やること」を並べる型がある

出どころの実例（`tools/thumbs/ref/index.json` に全件）:

| 型 | 実例 |
| --- | --- |
| 下部テロップ帯 | たろたん「トルコ狂ってた」/ バカイト「これがアメリカの現実」 |
| 上下2段コピー | さきの海外不動産「30年間アメリカのATMだった日本／今後バグり始めます」 |
| 顔アップ＋左コピー | 週末海外ノマド「海外在住"税理士"なのですが」/ 埼玉スマホ教室 |
| 国旗＋地名タグ | よしみ子のおひとり様ライフ「トルコひとり旅」/ jomi jomi life |
| 引き出し線＋値段 | バカイト「ラーメン3000円／納豆700円」/ Kira Kira USA |
| 料理を主役＋袋文字 | Kay & ZooKatsu「アメリカで日本食を作って振る舞った」 |
| 明朝＋余白 | Maibaru Travel「ウズベキスタン紀行」/ パリちゃうねん「2年ぶりの再会 #5」 |
| ライブ箇条書き＋LIVEバッジ | DK-Travel「旅好きが集まるLIVE」 |

この8つを、あやとの実際の配信フレームに当てて描いたのが `tools/thumbs/out/1.jpg` 〜 `8.jpg`。
`tools/thumbs/catalog.mjs` を直せば作り直せる。

**縦動画でいちばん効くのは「顔アップ＋左コピー」（3番）。**
縦を横に伸ばすと何も見えないが、顔だけ切り出せば横位置の主役になる。
`tools/thumbs/facecrop.py` が自動でやる。18本試して14本で取れた。
サングラス・横顔・暗い場所では外す（後述）。

## 3. ベストショットをどう取るか

ここがいちばんの詰まりどころ。

### 自動候補フレーム（`maxres1〜3.jpg`）だけでは足りない

認証もダウンロードも要らず、1本につき3枚、1280×720 で取れる。手軽ではある。
ただし **10本ぶん30枚を見たら、ほぼ全部が「カメラに向かって話しているあやと」だった。**
料理の皿も、買い物の棚も、山の絶景も、候補には出てこない。
YouTube は 25% / 50% / 75% あたりから機械的に選んでいるだけらしい。

顔アップ型（3番）だけなら、これで足りる。料理回・旅回はこれでは作れない。

### 配信本体から切り出す

`yt-dlp` で映像を落として `ffmpeg` でフレームを抜く。これができれば全部解決する。
**が、この Claude Code のサンドボックスからは落とせなかった。**

```
yt-dlp -f 160 → HTTP Error 403: Forbidden
player_client=mweb/ios → Sign in to confirm you're not a bot
player_client=tv → The page needs to be reloaded
```

チャットの取り込み（`schedule_fetch_chat.yml`）は GitHub Actions 上で毎日通っていて、
昨日も成功している。ただしあれは `--skip-download --write-subs` で、
映像そのものは取っていない。**GitHub Actions で映像が落とせるかは、やってみないと分からない。**
Actions の IP は YouTube に bot 判定されやすい。ここは実験してから決める。

落とせる前提なら、どこを切るかは決められる。**BigQuery にチャットがある。**

```sql
-- 30秒ごとのコメント数と、盛り上がりワードの数
WITH v AS (SELECT video_id, actual_start_time FROM ...videos WHERE video_id = @vid)
SELECT DIV(TIMESTAMP_DIFF(TIMESTAMP_MICROS(c.timestamp_usec), v.actual_start_time, SECOND), 30) AS b,
       COUNT(*) AS n,
       COUNTIF(REGEXP_CONTAINS(c.message_text, r'草|w{2,}|笑|かわい|すご|うま|やば|神|美味')) AS hot
FROM ...chat_messages c JOIN v USING(video_id) GROUP BY b ORDER BY n + hot*2 DESC
```

これで「その日いちばん沸いた30秒」が出る。実際に `5-1bHix5X1s`（おしんこ回）で試すと、
上位に「醤油でキメてる人ってかなりやばい人」「やりすぎwwww」が並んだ。使える。

ただし2つ注意がある。

- **`timestamp_usec` は配信開始からの経過ではない。UNIX時間のマイクロ秒。**
  `docs/island-db.md` に「配信開始からのマイクロ秒」と書いてあるが、これは誤り。
  経過秒がほしければ `actual_start_time` を引く（このドキュメントで直した）
- **引いた値が動画の長さを超えることがある。** `5-1bHix5X1s` は動画が2時間23分なのに、
  最大 23時間ぶんの差が出た。待機所のコメントか、配信をまたいだものが混ざっている。
  切り出す前に動画の長さで頭打ちにする

沸いた瞬間だけでは足りない回もある（料理回は「完成した皿」がほしい）ので、
候補は複数出して選ぶ形にする。フレームを抜いたあとに機械で足切りできるもの:

- ブレていないか（ラプラシアンの分散）
- 明るすぎ・暗すぎないか（輝度のヒストグラム）
- 顔が写っているか、目が開いているか
- 直前のフレームと似すぎていないか

### 顔の検出について

いまは OpenCV の Haar カスケード（`haarcascade_frontalface_default`）を使っている。
18本中14本で取れたが、サングラス・横顔・夜の屋外では外す。
数を出すなら YuNet（`cv2.FaceDetectorYN`）か MediaPipe に替える。
**OpenCV 5.0 では Haar カスケードが消えているので、`opencv-python-headless<5` を入れること。**

切り出した顔はたいてい暗い（夜の路上が多い）。明るさ1.28倍・コントラスト1.12倍・彩度1.18倍を
かけてようやくサムネとして見られる状態になる。

## 4. 画像生成（GPT）

`api.openai.com` にはこのサンドボックスから届く（キーが無いので 401 が返る）。
**キーさえあれば、この環境から直接叩ける。**

使うモデルは `gpt-image-2`（`gpt-image-1.5` / `gpt-image-1` も現役）。
横向きは 1536×1024 が正式サポート。1280×720 に縮めて使う。
**参照画像を渡せる**（Image API の edits、または Responses API）ので、
配信のフレームを渡して「この人・この場所の絵にして」ができる。

現実的な使いどころは3つ。全面を AI に描かせるより、部分に効かせるほうが当たる。

| 使い方 | 何を渡す | 向く型 |
| --- | --- | --- |
| **背景だけ生成** | 切り抜いた人物＋その日の場所 | 顔アップ型（3番） |
| **全面を絵にする** | 配信フレームを参照に、油絵風 | 明朝＋余白（7番）・月末配信 |
| **文言を考えさせる** | タイトル＋その日のチャット | 全部 |

3つ目は画像生成ではないが、いちばん効く。**「10文字のコピー」を考えるのは文章の仕事で、
チャットのログが BigQuery にある。** 沸いたコメントをそのまま使う型（8番のカタログ参照）は、
生成すら要らない。

なお **人の顔を AI に描かせるのは避ける。** 似ない、時間で表情が変わる、
「本人じゃない絵で釣った」と受け取られる。人物は写真のまま使って、周りを作る。

## 5. 差し替え（YouTube にアップロードする）

`thumbnails.set` で入れ替えられる。調べた制約:

- **必要なスコープ:** `youtube.upload` / `youtube` / `youtubepartner` / **`youtube.force-ssl`** のどれか
- **クォータ:** 1回およそ 50。既定の1日 10,000 なら **1日200本まで**。320本なら2日
- **サイズ:** 2MB まで。JPEG か PNG。1280×720 推奨

ここで効くのが、**このリポジトリはすでに `youtube.force-ssl` が要る操作をしている**こと。
`functions/src/commentOnLive.ts` が `liveChatMessages.insert` を叩いていて、
これには `youtube.force-ssl` が要る。使っているのは GitHub Secrets の
`YOUTUBE_CLIENT_ID` / `YOUTUBE_CLIENT_SECRET` / `YOUTUBE_REFRESH_TOKEN`。

**つまり、いまあるリフレッシュトークンでそのまま差し替えられる可能性が高い。**
確かめるには `tokeninfo` を1回叩けばいい（あやとの操作は要らない。
GitHub Actions から Secrets を読んで確認するワークフローを足すだけ）。
足りなければ、あやとに再同意を取る（issue に切る）。

Doneru 経由のトークン（`python/youtube_api/oauth.py`）は他社のもので、
スコープをこちらで決められない。差し替えには使わない。

## 6. この Claude Code のセッションで、どこまでできたか

| やりたいこと | ここでできるか |
| --- | --- |
| BigQuery から配信を読む | **できた**（MCP 経由。753本） |
| サムネを全件落として判定する | **できた**（753本を約2分） |
| 縦フレームから黒帯を落とす | **できた** |
| 顔を切り出して明るくする | **できた**（18本中14本） |
| 参考サムネを集める | **できた**（176件） |
| カタログを 1280×720 で描く | **できた**（Chromium + Google Fonts） |
| 配信本体を落としてフレームを抜く | **できない**（403 / bot 判定） |
| GPT で画像を作る | **できない**（キーが無い。届きはする） |
| サムネを差し替える | **できない**（トークンが無い） |

**できない3つは、どれも GitHub Actions 側に置けば解ける**（Secrets がそこにある）。
映像のダウンロードだけは、Actions でも通るか実験がいる。

## 7. 進め方

### 第1段 — 顔アップ型だけで、直近を埋める

映像のダウンロードも GPT も要らない。**今日から回せる。**

1. `python/thumbnail_audit.py` で対象を出す
2. `maxres1〜3.jpg` から顔が取れるものを選ぶ（`tools/thumbs/facecrop.py`）
3. タイトルから10文字のコピーを作る（Claude でよい）
4. カタログ3番の型で 1280×720 を描く（`tools/thumbs/catalog.mjs` の仕組み）
5. `thumbnails.set` で入れる

これで縦配信の「話している回」（企画会議・雑談・アプリ作り）はだいたい片づく。
数でいうと 320本のうち半分くらい。

### 第2段 — フレーム切り出しを足して、料理回・旅回を作る

GitHub Actions で `yt-dlp` が通るか確かめるところから。
通れば、チャットの盛り上がりから候補を出して、ブレ・明るさ・顔で足切りする。
通らなければ、あやとの手元で流すスクリプトにする（毎日1本なら数分）。

### 第3段 — GPT を足す

背景生成と、月末配信のような節目の全面絵。キーが要る。

### 第4段 — 毎日の配信に自動でつける

配信が終わって取り込みが済んだら、翌朝のワークフローでサムネを作って入れる。
`schedule_fetch_chat.yml` の後ろに足すのが素直。
**入れる前に一度あやとが見る**形にしておきたい（自動で本番に出すのは、型が固まってから）。

## 9. 触るところ

| ファイル | 何をする |
| --- | --- |
| `python/thumbnail_audit.py` | 未編集サムネの棚卸し。BigQuery を読んで JSON を出す |
| `tools/thumbs/facecrop.py` | 縦フレームから顔を切り出す |
| `tools/thumbs/catalog.mjs` | 型のカタログを 1280×720 で描く |
| `tools/thumbs/scrape.py` | 参考にする実物のサムネを集める |
| `tools/thumbs/out/` | カタログの出力（1〜8番） |

`tools/thumbs/` は `npm install` が要る（`playwright-core`）。
Chromium は `/opt/pw-browsers/chromium-1194/chrome-linux/chrome` にある。

**HTML から画像を描くときは `<meta charset="utf-8">` を必ず入れる。**
無いと Chromium が latin-1 と誤認して、日本語が全部化ける。
