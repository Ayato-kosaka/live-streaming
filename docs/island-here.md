# いま島にいる人を、島に出す

**これは仕様である。** オーナーからの依頼:

> ログインしたら、そのログインしたチャンネルのアイコンをトップページの島の中に出せるようにしてほしい。
> で、それがトップページの島の中で操作したら、**他の人から見ても操作が動く、見える**ようにして。
> で、チャンネルのアイコンの右下とかに**オンライン中ってわかる**ようにしてほしい。
> で、例えば企画掲示板のページを見に行ったら、**企画掲示板のところにそのチャンネルのアイコンがいる**みたいな感じがいいかなと思います。
> **これはもう特にそのチャンネルのアイコンとかは押せなくて大丈夫**です。ただ動きが見れたら、
> 他の人から見たら、誰々さんがオンラインやみたいなのが見えたら面白いってだけです。

---

## 1. 何を作るか

- ログインした人の **YouTube のチャンネルのアイコン**が、島の上に出る
- **その人が動かすと、他の人の画面でも動く**
- アイコンの右下に **いまオンラインだと分かる印**
- **その人が見ているページの場所に立つ。** `/board` を見ていれば「企画をだす」の建物のそば
- **押せなくてよい。** 見えるだけ

## 2. 島の住人（キャラクター）とは別物

島にはすでに、視聴者さんが作った**キャラクター**が12人立っている（`content/residents.ts`）。
**あれは日替わりの顔ぶれで、その人がいまいるかどうかとは関係ない。**

ここで足すのは**「いま、ほんとうにここにいる人」**。
**同じ島に2種類のものが立つので、見た目で分ける。**

| | キャラクター（いまある） | いる人（これ） |
| --- | --- | --- |
| 絵 | 視聴者さんが作った絵 | **YouTube の丸いアイコン** |
| 押せる | 押すと喋る | **押せない** |
| いつ出る | その日の顔ぶれ | **いまページを開いているあいだだけ** |
| 印 | なし | **右下にオンラインの印** |

## 3. どうやって「他の人からも動いて見える」ようにするか

**いまの島は、ブラウザから Firestore を直接触らない**（全部 `islandApi` 経由、`firestore.rules` は全部 deny）。
その形のままだと、他の人の動きを見るのに数秒ごとに問い合わせることになる。

**ここだけは、ブラウザから Firestore を直接読み書きする。** 新しいコレクションを1つ作り、
**そこだけルールを開ける。** 他は全部 deny のまま。

### SDK は落とさない。REST で読み書きする

**`firebase/firestore` は使わない**（`site/lib/hereRest.ts`）。あれを落とすと
**JS が 590KB（縮めて 125KB）増え、島を開いて12秒までの CPU が +270ms 増える。**
しかも**ログインしていない人にも乗る**（いる人が見えるのは全員なので）。
これは飾りで、**ほとんどの時間帯は0人**。0人のために全員がその代金を払うのは
釣り合わない。この島は数十KB を何日もかけて削っている。

**`onSnapshot` にしても、届く中身は変わらない。** 居場所が変わるのは2秒に1回で、
書く側が4章のとおり間引いているから。2秒ごとに REST で読めば同じものが届く。
違うのは遅れだけで、平均1秒。絵は届いた点へ0.4秒かけて寄せていくので
（`IslandStage` の rAF）、滑らかさも同じ。

| | 聞く間隔 |
| --- | --- |
| 誰も居ない | **20秒に1回**（返りは数百バイト。ほとんどの時間帯はこちら） |
| 誰か居る | **2秒に1回**（書き込みと同じ間隔。これより速く聞いても中身は増えない） |
| 裏に回したタブ・通信を節約したい設定 | 聞かない |

置くほうは `:commit`、読むほうは `:runQuery`。`seenAt` は
`updateTransforms` の `REQUEST_TIME` で送る（これがルールの
`seenAt == request.time` を満たす）。形が1文字でも違うと本番でだけ静かに
落ちるので、**エミュレータに実際に弾かせて確かめてある**
（`tools/rules/here.rest.test.mjs`）。

```
islandHere/{uid}
  at      いま見ているページ（"/", "/board" など）
  x, y    島の上の位置（ワールド座標）
  seenAt  最後に動いた時刻（サーバー時刻）
```

### ルール

- **読むのは誰でも。** ログインしていなくても、いる人が見える
- **書けるのは自分のぶんだけ。** `uid` がドキュメント ID と一致すること
- **書ける項目を絞る。** 上の4つ以外は受け付けない
- **`seenAt` はサーバー時刻でなければならない。** 手元の時計を書かせると、いつまでも「オンライン」でいられる
- **1秒に1回より速くは書かせない。** 書いた回数で課金されるので、ここを開けるのは
  財布を開けるのと同じでもある。ブラウザ側の2秒しばりは自分で外せるので、
  速さを決めるのは外せないほうに置く。`update` だけに掛けると
  「消して作り直す」で抜けられるので、`delete` も同じだけ縛る

### 「読むのは誰でも」の代金

**外から叩き続ければ、第三者が「誰がどこを何時に見ていたか」を溜められる。**
このコレクションは誰でも読めて、`GET /state` の `residents` が uid と名前を
結んでいるので、両方を定期的に取れば履歴が作れる。

**それを承知でこの形にしている。** 「他の人から見たら、誰々さんがオンラインや
みたいなのが見えたら面白い」がこの機能の中身で、見えることそのものが目的だから。
5章の「履歴を残さない」は**こちらが持たない**という話であって、
**外から見えないという話ではない。** ここを勘違いしたまま
「履歴は残らないから安全」と書き足さないこと。

出るのは、**名前かアイコンを出してよいと本人が言った人だけ**（`residents` に
載っている人だけ）。何もしていない人は、居場所を置く側もそもそも書かない。

### なりすまし

**名前とアイコンを、このドキュメントに書かせない。** 書かせると、他人の名前を名乗れる。

名前とアイコンは **`islandApi` の `GET /state` が返す `residents`**（サーバーが本人確認したもの）から引き、
**チャンネル ID で突き合わせる。** つまり `islandHere` には**位置と時刻しか入らない**。

**ただし `islandHere` の鍵は `uid`、`residents` の鍵はチャンネル ID** なので、そのままでは結べない。
カスタムクレーム（`setCustomUserClaims`）にチャンネル ID を入れる手も考えたが、
**`listResidents` が `uid` も返すようにするほうが軽い**ので、そちらにした。
クレームを足すと、いま入っている人に**もう一度ログインしてもらわないと効かない**。

`residents` に載るのは「名前かアイコンを出してよい」と本人が言った人だけなので、
**uid が外に出るのもその人たちだけ**。何もしていない人の uid は出ない。
`islandHere` に居場所を置く側も、そこに自分が載っているかを見てから置く
（`components/live/Here.tsx`）。**「いま見ている」を、名前を出す同意より緩くしない。**

## 4. 書き込みの回数を抑える

**指で動かすたびに書かない。** Firestore は書いた回数で課金され、読むほうも
「見ている人の数 × いる人の数」で効いてくる。

- **2秒に1回まで**。しかも**位置が変わったときだけ**（ルール側でも1秒で縛ってある）
- ただし**30秒黙っていたら1回だけ置き直す。** そうしないと、動かない人が60秒で消える
- ページを離れたら消す（`pagehide` と、`visibilitychange` で隠れたとき）。
  `beforeunload` は使わない（スマホでは発火しないことがあるうえ、
  それだけで戻る/進むのキャッシュが効かなくなる）
- **隠れているあいだは置かない。** `setInterval` は隠れても止まらない
  （1分に1回まで遅くなるだけ）ので、消しても次のタイマーがまた作ってしまう
- **60秒より古い `seenAt` は、画面に出さない。** 消し忘れたぶんは、読む側で無視する
- 古いものの掃除は、毎日の集計ジョブのついでにやる

## 5. 出さない・やらない

- **人数を数えて出さない。** 「いま3人」は、たいていの時間帯に「1人」と出る
  （`docs/island-play.md` 仕掛け18。日単位の「今日◯人が来た」はすでにある）
- **誰がどこを見ていたかの履歴を残さない。** いまいる人だけ。過去は持たない
- **話しかける・つつくを作らない。** 押せなくてよい、と言われている

## 6. 島の外のページでは

**そのページの建物のそばに立つ。** `/board` を見ている人は「企画をだす」のそばに、
`/kitchen` の人は「作った料理」のそばに。

**島の外のページそのものにアイコンを出すかは、まだ決めていない。**
オーナーの言葉は「企画掲示板のページを見に行ったら、企画掲示板のところにそのチャンネルの
アイコンがいる」で、**島の上の話とも、そのページの上の話とも読める。**
まず島の上に出して、撮ってから決める。
