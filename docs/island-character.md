# キャラクターの絵と呼び名

視聴者さんが作ってくれたキャラクターの絵を、どこから読んで、どこへ移すか。
発端は issue #284 の C 群（Google ドライブの依存11件）と、
あやとの言葉（2026-09-11）:

> Google ドライブの画像は firebase storage に入れて、firebase functions
> `islandCharacter` みたいなので管理したい。オーナー画面から追加・編集できるように。

---

## 1. いまの姿（移す前）

**原本が3つに割れている。3つを結ぶ鍵は「絵文字」。**

```
  ┌─ あやとのスプレッドシート（GAS の Web App 越し）────────────┐
  │  Viewers 表  141行                                           │
  │    name / Emoji / Icon / videoUrl（videoUrl は141行とも空）  │
  │    ・絵の入った行  133                                       │
  │    ・絵文字の入った行 136                                    │
  │    ・**同じ Icon を持つ行が複数ある** → それが「他の呼び名」 │
  └──────────────┬───────────────────────────────────────────────┘
                 │ Icon（＝ドライブの画像 id）でまとまる → **97人**
                 │
     ┌───────────┴────────────┬───────────────────────────┐
     │                        │                           │
  ┌──▼─────────────────┐  ┌───▼──────────────────┐  ┌─────▼──────────────┐
  │ ドライブ・背景なし │  │ ドライブ・背景あり   │  │ Git に焼いてある   │
  │ 101ファイル        │  │ 69ファイル（67名）   │  │ residents.ts   22 │
  │ **ファイル名＝絵文字**│ │ **ファイル名＝絵文字**│ │ characterBox.ts 22│
  │ 97/97 が表と一致   │  │ 65/97 をおおう       │  │ residents_map   22 │
  └──┬─────────────────┘  └───┬──────────────────┘  └─────┬──────────────┘
     │                        │                           │
     │ lh3.googleusercontent.com/d/{id}=s{大きさ}          │ icon: の値がそのまま
     │                        │                           │ ドライブの画像 id
  ┌──▼────────────────────────▼───────────────────────────▼──────────────┐
  │ 出る面                                                                │
  │   島（Next.js）  / /island/[章] /friends /cards /me /kitchen/[日]     │
  │   OBS（Expo）    /alertbox  /ve-comment  /credits                     │
  └───────────────────────────────────────────────────────────────────────┘
```

| 誰が原本か | 何を持っているか | 実測 | 誰が読むか |
| --- | --- | --- | --- |
| **Viewers 表**（スプシ） | 名前 ↔ 絵の id ↔ 絵文字 | 141行 / 97人 | `app/alertbox` `app/ve-comment` `app/credits` |
| **ドライブ・背景なし** | 絵そのもの（透過 PNG、800〜1000px） | 101ファイル | 島の7か所 ＋ OBS の3画面 |
| **ドライブ・背景あり** | 絵そのもの（1024×1024、不透過） | 69ファイル | **どこからも読まれていない**（配布用） |
| **`site/content/residents.ts`** | 島に立つ22人（絵の id ＋ 絵文字 ＋ 日数 ＋ チャンネル） | 22行 | 島のほぼ全面 |
| **`site/content/characterBox.ts`** | 絵の中で実際に描かれている範囲 | 22行 | 島に置くときの寸法 |
| **`python/residents_map.json`** | 絵の id → YouTube チャンネル id | 22行 | `build_residents.py` |

### `residents.ts` はどう作られているか

**BigQuery から `python/build_residents.py` が焼く**（`.github/workflows/rebake.yml`
が毎晩 21:30 UTC に回す）。ただし**焼き直すのは日数だけ。**

- 顔ぶれ（`icon` と `emoji`）は、**いま並んでいる `residents.ts` から読み直す**
  （`read_icons()`）。BigQuery には絵の情報が無いので、そこは触らない
- `channel`（YouTube のチャンネル）は `python/residents_map.json` から引く。
  **この表はあやとが Viewers 表から手で写した22行**で、写す仕組みが無い
- 表が無ければ `--report` を書き出すだけで `residents.ts` には触らない

**つまり「スプシが反映されて焼かれる」わけではない。**
スプシ → `residents_map.json` は**手写し**で、そこから先だけが自動。
だから Viewers 表に絵が133件あっても、島に立つのは22人のまま増えない。

### 大きさをドライブに任せている

| 出る場所 | 使っている大きさ |
| --- | --- |
| `IsleReview`（章のふりかえり） | `=s96` |
| `IslandStage` `IsleStage`（島の住人）／`CardSheet` の一覧 | `=s128` |
| `MeHero` `CardOne` `KitchenDay` | `=s256` |
| `CardSheet` の1枚絵 | `=s512` |
| `FriendsWall` の主役 | `=s640` |

`lh3` は `=s{数}` を付けるだけでその場で縮めてくれる。
**Storage は縮めてくれない。** ここが移行のいちばんの引っかかり。

## 2. 移したあとの形

### `islandCharacter/{characterId}` — 1人1書類

| 欄 | 何 |
| --- | --- |
| `channelName` | `@aoi1685`。入力そのまま（画面に出す用） |
| `emoji` | `🐟` |
| `aliases` | `["aoi", "ちゃんあお"]`。入力そのまま |
| `channelKeys` | **スパチャが引く欄。** `["@aoi1685", "aoi1685"]` |
| `lookupKeys` | **Doneru が引く欄。** チャンネル名と呼び名を全部、`@` あり／なしで |
| `images.plain` | 背景なし。`url`（元のまま）＋ `sizes.{128,256,640}`（webp） |
| `images.scene` | 背景あり。同じ形 |
| `channelId` | 分かれば YouTube のチャンネル id |
| `editedAt` `editedBy` | **画面から直した印。移行の道具はこの行を触らない** |

### 書類 id は、いまのドライブの画像 id

`residents.ts` の `icon:` も、`characterBox.ts` の鍵も、`residents_map.json` の
鍵も、**もう全部これで引いてある。** 別の id を振ると、3つを同じ日に書き換え
ないと島の住人が消える。**意味のある値としては使わない**（これから足す人には
ドライブの絵が無いので、そのときは同じ形の乱数を振る）。

### 引き方が2つ。どちらも単一フィールド

**うちのサービスアカウントには複合索引を作る権限が無い**（#168）。
`where` を2つ重ねた瞬間に本番で 500 になる。

```
スパチャ  →  where("channelKeys", "array-contains", norm(表示名))
Doneru    →  where("lookupKeys",  "array-contains", norm(打たれた名前))
```

`array-contains` は**単一フィールドの索引**で、Firestore が勝手に張る。
`orderBy` も2つ目の `where` も足さない（並べ替えは引いてから）。

**2つに分けてあるのは、取り違えを減らすため。** 呼び名には「あお」のような
短い字が入る。スパチャの表示名がたまたまそれと同じだったとき、別の人の絵が
配信の画面に出る。だからスパチャはチャンネル名だけを見る。

**2件当たったら決めない。** 呼び名は誰でも同じにできる。当てずっぽうで1人
選ぶと別人の絵が出るので、そこで止める（`functions/src/donors.ts` と同じ）。

実測では、いまの141行から作った鍵に**ぶつかりは1件も無い**
（`channelKeys` 154個 / `lookupKeys` 208個、どちらも重複0）。

### `@` なしは、保存するときに作る

`@aoi1685` を入れたら `aoi1685` でも引ける。その変形は**保存のときに作って
配列に入れておく。引くときに作らない。**

1. **引くのは配信中で、投げ銭1件につき1回。保存は年に数回。** 手間を安い
   ほうへ寄せる
2. 引くときに変形すると、変形の数だけ Firestore を往復する
3. 何で引けるかが**画面から見える。** オーナー画面は `lookupKeys` をその
   まま出せば「この名前で当たります」が言える

正規化の決まりは **`app/alertbox/matching.utils.ts` の `normalizeName` と同じ**
（NFKC → 異体字と見えない文字を落とす → 空白を1つに → 小文字）。
片方だけ変えると、配信中のアラートだけが人違いを始める。
`functions/src/islandCharacter.ts` と `python/admin/characters_migrate.py` の
2つに実装があるので、**141件の実データで突き合わせて0件ずれを確かめてある。**

### 大きさは、置くときに焼く

ドライブの `=s{数}` の代わり。**5つ使われていたものを3つに寄せる。**

| 焼く幅 | 形式 | 受け持つ場所 |
| --- | --- | --- |
| 128 | webp | `=s96` `=s128` |
| 256 | webp | `=s256` |
| 640 | webp | `=s512` `=s640` |
| 元のまま | png / jpeg | **持ち帰り用**（縮めたものを配らない） |

**引き伸ばさない。** 欲しい大きさ以上で、いちばん小さいものを返す。

webp にするのは軽いから。実測で 256px が **19.5KB**（ドライブの `=s256` は
88.8KB）。全部で **元162枚 295.6MB → 焼いた webp 355枚 15.7MB**。

**焼くのはブラウザと移行の道具。Functions ではやらない。** Functions に画像の
道具を足すと冷えた1回目が目に見えて遅くなる。北欧の写真（#202）も同じで、
ブラウザ側で焼いてから送っている。

### 名前は、誰にでも見せない

島は視聴者さんの名前を出さない（`site/content/residents.ts` 冒頭）。

| 口 | 誰が呼べるか | 名前が付くか |
| --- | --- | --- |
| `GET /characters` | 誰でも | **付かない**（id・絵文字・絵だけ） |
| `GET /characters/lookup?channel=` `?alias=` | 誰でも | **付かない**（打った名前は呼ぶ側が持っている） |
| `GET /alertbox/{32桁}/characters` | OBS の合言葉を持つ人 | 付く（名簿ぜんぶ） |
| `POST /characters` `POST /characters/{id}` `DELETE` | あやとだけ | 付く |

移す前のスプレッドシートは、**URL を知っていれば誰でも141行を全件読めた**
（#284 の (i)）。ここは合言葉で閉じるほうへ変える。

## 3. 移す道具

`python/admin/characters_migrate.py`。**既定では1バイトも書かない。**
書くには `{"apply": true}`。走らせ方は「管理スクリプトを実行」から。

```
{}                             … 数えるだけ
{"limit": 3}                   … 3人ぶんだけ試す
{"apply": true}                … Storage と Firestore に書く
{"apply": true, "only": "🐟"}  … 絵文字で1人だけ
```

### ログインは要らなかった

- **フォルダの一覧**は `drive.google.com/embeddedfolderview?id=…` が
  合言葉なしで返す（`drive/folders/…` のほうは「Sign in」を返す）
- **絵そのもの**は `lh3.googleusercontent.com/d/{id}` が合言葉なしで返す

**クローム操作は要らない。**

### 中身を見てから置く

ドライブは権限が無いと HTML を返す。**状態番号は 200 のまま**なので、
そこで見分けようとすると「取れた」と誤診する。
先頭のバイトが PNG / JPEG / WebP のどれかであることを見てから置く。

### 空回しの実測（2026-09-11）

```
背景なし 101ファイル / 背景あり 67ファイル
Viewers 表 141行 → キャラクター 97人（絵の無い行 8、@付きの名前が無い人 20、@付きが2つある人 3）
背景なしの絵: 97人ぶん / 背景ありの絵: 65人ぶん（背景ありが無い 32人）
97人ぶん / 元の絵 162枚 295.6MB / 焼いた webp 355枚 15.7MB / 画像でなかった 0枚
```

## 4. 決まっていないこと

- **@ 付きの名前が無い20人。** チャンネル名が空のまま入る。スパチャからは
  引けない（呼び名からは引ける）。あやとが埋めるまでそのまま
- **@ 付きが2つある3人。** いまは先に出てきたほうをチャンネル名にして、
  もう一方を呼び名に落としてある
- **背景ありが無い32人。** フォルダに絵が無い。作るのは人の仕事
- **`site/content/site.ts` の `CHARACTER_DRIVE`（キャラクター置き場のリンク）**は
  消す。図鑑から背景なし・背景ありの両方を落とせるようにするため
  （あやと「キャラクター置き場の url は消したい」）。**画面側の担当の範囲**
- **図鑑を全員分にすると 97人。** いま出ているのは22人で、それは
  `residents.ts`（直近90日の常連）を見ているから。97人にするなら
  `/friends` は「一緒にいた日数」を持たない人を並べることになる
