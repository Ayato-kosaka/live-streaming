# あやと島 — コンセプトと作りかた

このドキュメントは、あやと島（https://live-streaming-d3cac.web.app）が
何のためにあって、どう作られているかを書いたもの。
新しくコーナーを足すとき、文言を書くとき、絵を描き足すときは、まずここを読む。

---

## 1. これは何か

**旅して、食べて、グルメアプリを作る、夜の居場所。**

あやとは2024年秋に日本を出て、ヨーロッパ・中東・コーカサスを旅しながら
毎晩22時（日本時間）に生配信している。旅先で自作のグルメアプリ「なに食べよ」を作っている。

このサイトは、その配信の「留守番の場所」。
配信していない時間にも、来た人が何かを見て帰れるようにする。

### 島にした理由

配信の内容は、料理・旅・アプリ作り・企画会議とばらばらで、
リストで並べると「情報サイト」になってしまう。それでは配信の空気と合わない。

島にすると、
- ばらばらの内容が、島の中の場所として自然にまとまる
- 「歩いて、気になったところに入る」という、順番のない見方ができる
- 視聴者さんが作ったキャラクターに、住む場所ができる

配信に来てくれる人たちが「あそこに自分がいる」と思える場所であることが、いちばん大事。

## 2. 見た目の原則

目指しているのは **どうぶつの森**。柔らかくて、明るくて、輪郭線がない世界。
「かわいい」を狙うのではなく、**ずっと見ていられる**ことを狙う。

絵を作るときの決まりごとは5つ。

1. **輪郭線を引かない。** 形は色の差だけで見せる。線を足すと途端に「イラスト」になる。
2. **環境光をとても強くする。** 影で立体を作らず、明るさの差で作る。影は落とすが薄く。
3. **接地影を焼き込む。** 物が地面から浮かないように、スプライトの下に柔らかい影を焼く。
4. **彩度と明度をどちらも高く。** 彩度だけ上げると毒々しくなる。両方上げると絵本になる。
5. **急な変化を作らない。** グラデーションと丸い角。四角い切り替わりを作らない。

これは `tools/sprites/render.html` の光の設定と、`app/globals.css` の色にそのまま入っている。

### スプライトの作りかた

Kenney の CC0 の 3D キット（nature-kit / building-kit / holiday-kit / food-kit / mini-characters）を
three.js で読み込み、どうぶつの森の色に塗り替えてから、Playwright のヘッドレス WebGL で
PNG に焼いて WebP にする。

```
tools/sprites/manifest.mjs   何を焼くか（57枚）
tools/sprites/render.html    光と色の設定。ここが絵のすべて
tools/sprites/meta.py        切り抜き・縮小・WebP化・sprites.json 出力
```

色の塗り替えは2通り。
- **nature-kit** … マテリアル名で塗る（`MATERIALS`）
- **テクスチャのあるキット** … colormap.png の色相の帯ごとに塗る（`BANDS`）
  building-kit では `green`=壁、`blue`=柱と縁、`neutral`=屋根 に対応している。

food-kit は専用の `Textures/colormap.png` を持っているので、
**必ず `models/food/` に自分のテクスチャごと置く**。他のキットで上書きすると色が壊れる。

### 島の座標

`site/components/island/layout.ts` の `WORLD`(1200) 四方が唯一の座標系。
絵・当たり判定・カメラ・歩行がすべてこれを共有する。

奥行きは **足元の y で並べ替える** だけ。景色も住人もあやとも同じ列に混ぜて並べる。
そうしないと、木の手前に立つべき人が木の裏に隠れる。

## 3. 触りごこちの原則

ゲームの「これは触れる」を伝える作法を、そのまま持ち込んでいる。

1. **押す場所は物そのもの。**
   ヒットエリアが絵からずれていると、人は「壊れている」と感じる。
   建物の当たり判定はスプライトの実寸から作る（`IslandStage` の `.spot-hit`）。
2. **指で押せる最小の大きさを守る。**
   どんなに小さい絵でも 48px は確保する（フィッツの法則）。たき火のような小物のため。
3. **押せる物には灯りを置く。** 近づくと強くする。触れる物と触れない物を、色ではなく光で分ける。
4. **注目させるのは一度に1つ。**
   近づいたときに名前が出るのは、いちばん近い1つだけ。全部に名札を出すと島が字で埋まる。
5. **反応を返す。** 近づいた建物は軽く弾む。押したら沈む。
6. **勝手に消さない。** 吹き出しは押すまで出ないし、閉じるまで消えない。
   読みかけで消えるのがいちばん困る。

### スマホと PC の出し分け

スマホは島に降り立った視点（`span 340`）で、行き先は下のバーにまとめる。
島の上に9つの名札を置くと島が見えなくなるため。
「島をながめる」を押すと引いて全体地図になる（`span 850`）。

PC は島が大きく映るので、名前は薄く全部出しておき、近づいた1つだけ濃くする。

看板ロゴは、引き（スマホ）と PC は看板まるごと、寄り（スマホ）は右上に小さくバッジだけ。
寄り引きは `.stage[data-view]` に出ていて、兄弟セレクタで `.hero-ui` が受け取る。

## 4. 言葉の原則

`site/content/voice.ts` の先頭にも書いてあるが、要点は3つ。

1. **説明口調を使わない。** 「〜できます」「〜になっています」と書かない。
2. **ボタンは動作そのものの言葉にする。** 「送信」ではなく「はりだす」、「詳細」ではなく「はいる」。
3. **見出しは、読む人の頭の中の問いにする。** 「これまでのあしあと」ではなく
   「これまで、どこへ行って何を作ったんだろう」。

案内役のカモメ（ミナト）は、見出しの言い直しをしない。
「ここでどう遊ぶか」だけを言う。

## 5. トップページの並び

分類ではなく、**来た人が順に浮かべる問い**の順にしてある。

1. いま、いちばん近い企画（＋日は先でもいちばん大きい企画）
2. あやとって、どんな人
3. どんな配信をしてる人なんだろう
4. グルメアプリを作ってるらしいけど
5. これから何をするんだろう / 自分も企画を出せる
6. これまで、どこへ行って何を作ったんだろう
7. 今夜も22時から

**1がいちばん大きい。** 島に来た人が真っ先に知りたいのは「次に何をするのか」なので、
どのコーナーよりも先に、いちばん大きく出す（`components/live/NextUp.tsx`）。

既存の視聴者さんは「これからの予定」を、新しく来た人は「いま何をしてるか」と
「これまで何をしたか」を知りたい。1と5が前者、2〜4と6が後者にあたる。

## 6. 島の住人

島に住んでいるのは **視聴者さん本人**。
自分で作ったキャラクターの絵（Google Drive）がそのまま島を歩いている。
借り物の NPC にキャラクターを紐づけるのはやらない。それだと本人がそこにいることにならない。

### しゃべること

セリフは `site/content/chatter.ts`。
**その人が実際に配信で書いてきたコメントの口調から起こしている**（出典は BigQuery の
`youtube_chat.chat_messages`）。

書き足すときの決まりごと:
1. その人らしい言い回しにする。似てないセリフは、いない人が喋っているのと同じ。
2. ただの挨拶で終わらせない。初めて来た人が「へぇ」と思える中身を必ず入れる。
3. 本人の代弁はしない。事実はサイトに載っている範囲だけ。
4. 名前は出さない。誰が喋っているかは、その人のキャラクターだけが示す。

### 名前と YouTube アイコン

**出すか出さないかは本人が決める。** 何もしていない人は、キャラクターだけが島にいて名前は出ない。

ログインして `/board` などの「島での見え方」で自分のキャラクターを選び、
名前とアイコンを出すかを選ぶと、はじめて島に出る（`components/live/IslandMe.tsx`）。

## 7. データがどこから来るか

| 出どころ | 何が来るか | どうやって |
| --- | --- | --- |
| BigQuery `youtube_chat` | 配信本数・コメント数・住人の数・国と街ごとの代表配信 | `python/island_daily_stats.py`（毎日）/ `python/build_city_streams.py`（手動） |
| Firestore `island/state` | 上の集計結果と、いまいる場所 | Cloud Functions `islandApi` の `GET /state` |
| Firestore `islandIdeas` / `islandNotes` | 企画提案と付箋 | `islandApi` |
| Firestore `islandUsers` | ログインした人。島での見え方の設定 | `islandApi` の `POST /me` |
| Firestore `islandDrafts` | 企画ページの下書き | `islandApi` の `/drafts` |
| Google スプレッドシート（GAS） | 視聴者さんのキャラクター画像 | 手で `content/residents.ts` に反映 |
| 手書き | 料理・国・伝説・アプリ・企画・北欧ガイド | `site/content/*.ts` |

静的書き出し（`output: "export"`）なので、ビルド時の値がページに焼き込まれる。
配信を重ねても数字が増えない、という事故を防ぐため、
数字は `LiveNumber` が画面表示後に `/island-api/state` の最新値で上書きする。
同じ理由で、カウントダウンと「いちばん近い企画」も画面が出てから計算し直す。
