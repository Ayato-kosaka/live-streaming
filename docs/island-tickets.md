## 1. 札（待ちの相手）

**題名の【あやとの操作】は、機械からは読めない。**
読むのはこの3つだけ。

| 札 | 誰が動かすと進むか |
| --- | --- |
| `待ち-あやと` | **あやとだけ**（鍵・権限・コンソールの操作・「どうしたいか」の答え） |
| `待ち-システム` | **システム開発担当**（この AI）。直せるが、まだ手が回っていない |
| `旅のあと` | 時間（旅が終わるまで着手すると壊れる） |

**迷ったら `待ち-システム`。** あやと待ちに置くと、**開発の手が止まったまま**
「待っている」ことにできてしまう。

**札にも文にも「こちら」と書かない。** 読む人から見てどちらか分からない
（あやとの指摘、2026-09-23）。書くなら **システム** か **あやと**。

2026-09-19 に、開いていた25本ぜんぶへ付けた（あやと14／システム9／旅のあと2）。
**2026-09-23 に `待ち-こちら` を `待ち-システム` へ改名した**（上の理由）。
**機械が立てる issue にも付く**——`donor_calls` は `待ち-あやと`、
`bake_down` は `待ち-システム`、`ingest_down` は落ち方で分かれる。

**2026-10-13 から、あやとが答えたら `待ち-あやと` はひとりでに外れる**（5章）。
それまでは**外すものが1つも無かった**——札は付くだけで、人が手で外すまで
「あやと待ち」のまま並んでいた。

**2026-10-28 から、`待ち-あやと` を付けたら機械があやとを呼ぶ**（6章）。
それまでは呼ぶのがセッションの手順（`call_ayato.yml`）にしか無く、札だけ付いて
1通も飛ばない issue が4本できた。

## 2. 毎週の棚卸し（`Ticket Stock`）

開いている issue を数えて、**同じ1本**（ラベル `ticket-stock`）の本文を
書き換える。**毎週新しく立てない**——それこそ溜まる。

本文に出るのは、待ちの相手ごとの本数、**30日以上だれも何も言っていないもの**、
札の付いていないもの。

### 「動いていない」を `updated_at` で数えない

**札を1枚付けただけで今日になる。** 2026-09-19 に25本へ札を付けたら、
589日と541日 放置されていた2本が、その瞬間「0日」になった。
**片づけの操作で、片づいていないことが見えなくなる。**

数えるのは「最後に誰かが**何か言って**から」——立てた日と、いちばん新しい
コメントの日の、遅いほう。

### 走りかた

繋ぎ先は `Fetch YouTube Chat Data` と `Fetch Doneru Donations`
（`workflow_run`）。**cron は保険。** 理由と落とし穴は
`.github/workflows/rebake.yml` の 190〜210行と同じ:

- **`conclusion` は見ない**（あちらは呼び出しで `exit 1` する晩がある）
- **繋ぎは `name:` で解決される。** あちらの名前を変えると**黙って切れる**
- 繋ぎが生きているかは `Fetch Doneru Donations` を `probe: true` で確かめる

繋ぎ先は毎晩終わるので、**曜日で週1に間引く**（`workflow_run` は月曜だけ）。
cron はもともと週1なので、遅れて火曜に着いても通す。

## 3. `Closes #NNN`（`Closes Check`）

PR の本文に `Closes #NNN` が在れば、**マージした瞬間に GitHub が閉じる。**
この仕組みはずっと在ったのに、使えていなかった。

直近30本のマージ済み PR（2026-09-19 実測）:

| | 本数 |
| --- | --- |
| `Closes` / `Fixes` / `Resolves` が在る | **1本（3%）** |
| 本文が `#NNN` に触れている | 29本 |

### 落ちる条件を、わざと狭くしてある

「`#NNN` に触れているのに `Closes` が無い」で落とすと **28本**が赤くなる。
このリポジトリの `#173` は `docs/island-misses.md` の**節番号**でもあって、
そちらのほうが多いからだ。関係ない PR まで赤くすると、誰も読まなくなる。

落ちるのは「**いま開いている issue の番号**を指していて、`Closes` が無い」
ときだけ。直近30本に当てて1本（3%）で、その1本も節番号の巻き添え。
逃がし方は本文に1行:

```
#147 は閉じない
```

`.github/PULL_REQUEST_TEMPLATE.md` の頭に `Closes #` の行を置いてある。

## 4. 整備の漏れを、仕組みの不具合と混ぜない（`Upkeep Watch`）

あやとの言葉（2026-10-03）:

> 整備系の漏れは github actions で気付くべきなので落ちても良いところは良いですよ。
> 整備系の漏れは定期的にあなたに依頼するつもりです。
> **その漏れがわかるようにチケットとか使いながらの運用にしてね。**

### なぜ分けたか

2026-09-29 からの12晩、毎晩の焼き直しが続けて赤かった。原因は4つで、
**性質が2種類に分かれていた。**

| 赤 | 正体 |
| --- | --- |
| キャラクターの箱の関所が永久に断る | 仕組みの不具合 |
| `og.png` が枠を埋められない | 仕組みの不具合 |
| 終わった旅に「今日まで届いていろ」と要求 | 仕組みの不具合 |
| `albania.from` が空 | **整備の漏れ**（人が欄を埋めていない） |

**人待ちは4本のうち1本だけ。** それが `bake_down` の issue 1本（#511）に
まとまって出ていたので、「どれが人待ちか」は読めなかった。しかも #511 は
16日間ずっと開いていて、一覧の中で背景になっていた。

**知らせる仕組みは正しく鳴っていた。** 鳴り方が1本に混ざっていたほうが問題で、
だから**人の手入れ待ちだけ**を別の札へ分ける。

### 札は #664 ひとつ。新しく立てない

`#664`（`整備` の札）の本文に `<!-- upkeep:begin -->` 〜 `<!-- upkeep:end -->` の
区画を切って、**その中だけ**を書き換える。**人が手で書いた経緯は1文字も触らない。**

毎晩 issue を立てる作りにすると、一覧がこの係の札で埋まって、
いま直そうとしている「背景になる」をこちらが起こすことになる。

**0件の日も区画を空にしない。** 「いま手入れ待ちはありません」と、
**測った日**をいっしょに置く——空だと「測っていない」と見分けが付かない。

### 何を数えるか

| 口 | どこが決めているか |
| --- | --- |
| 焼き込みが古い（`site/content/*.ts`） | `python/stale_content_watch.py` の `BOOKS` |
| 旅が進んで欄が空いた | `upkeep_watch.TRIGGERS` |

**しきい値を2か所に書かない。** 前者はあちらの判定をそのまま借りて、
**持ち主が「人」の赤だけ**をこちらへ出す。

| 持ち主 | どちらへ |
| --- | --- |
| 人 / 外の地図 | **整備の漏れ**（#664 の区画へ） |
| 機械 / 導出 / 言葉 | **仕組みの不具合**（`bake_down` の側。#664 には出さない） |
| 機械/上流が人（①b） | 既定は仕組み。**上流も同じ回で赤いときだけ**整備 |

**迷ったら仕組みへ倒す。** 整備の札に機械の赤が混ざると、この札がまた
「読んでも自分の出番が無い一覧」になって背景に戻る。

### **呼ぶ相手は3人いる**（2026-10-13 / #808）

あやと:「これ、わたし打つの面倒なので仕組みを見直してください。
最低でもあなたは知ってるはずだし、**過去のものが出るのはシステムとして
おかしい**」

ここは島の便りについて、**機械が知っていることまであやとに打たせていた。**
「9/27 が過ぎた」ことも「いまどの国か」も、こちらが知っている。
知っているものを人に消させるのは、見張りの向きが逆。

| 持ち主 | どこへ出るか | 赤くなるか |
| --- | --- | --- |
| **あやと**（`UPKEEP`） | #664 の区画 | **ならない**（溜まっていても緑） |
| **こちら**（`Count.ours`） | **区画に出さない** | **なる**（この仕組みが動いていない） |
| **焼くほう**（`Count.system`） | `bake_down` の側 | こちらでは赤くしない |

**2列目を区画に混ぜない。** 出してもあやとには直せないし、
また「読んでも自分の出番が無い一覧」に戻る。
そのかわり**黙らない**——job を赤くして、どこを見ればいいかを要約に書く。

引き金は9つで、**1行で足せる**（関数を1つ書いて `TRIGGERS` に足す）。

| 引き金 | 空いている欄 | 誰を呼ぶか |
| --- | --- | --- |

**島の便りの引き金は、2026-10-13 に2つへ割れた。** 前は `place` と `week` も

**「急ぐ」と「急がない」を分ける。** 全部を同じ赤さで並べると、

### 8つめだけ、見るのが `chapters.ts` ではなく **git の履歴**（2026-10-13）

「島をなおしたところ」（`/updates`）は、**出したときに1行足す**紙。
手順は `/island-ship` の3章に入れてあるが、手順は忘れられる。だから
**`site/app` / `site/components` が動いたいちばん新しい日**を git から読んで、
表のいちばん新しい日付がそれより古ければ出す（`last_shown_change`）。

- **焼き込み（`site/content`）と絵（`site/public`）は見ない。**
  毎晩ひとりでに焼き直されるので、入れると毎朝鳴る
- **あやとの机（`site/app/me`）も見ない。** 読む人の画面は何も変わらない
- **毎 PR の見張りにしない。** 内側だけの PR まで赤くする見張りは、
  いつも通る見張りと同じだけ悪い（`docs/island-standards.md` 13章 / 15章）
- `.github/workflows/upkeep_watch.yml` の checkout に `fetch-depth: 300` が要る。
  既定の1コミットだと履歴に面の変更が見えず、**毎晩黙って通る**

後ろの4つは 2026-10-07 に足した。それまでここは `chapters.ts` の欄しか
見ていなくて、**埋まっていないのに札に出ないもの**が4つ残っていた。
実害も出ていた——アルバニアの配信11本が「スウェーデン」として焼かれ、
10/06 の `/now` が「9/27 ストックホルムを発つ」を**今週の予定**として
出していた（島の便りも年表も、機械では新しくならない）。

引き金に渡すものは `upkeep_watch.World` にまとまっている。
**引き金は自分でファイルも口も開かない**ので、仕込みで両側を当てられる。

**読めなかったものを、空で渡さない。** 空を渡すと、その引き金が
「空いていない」と答えて毎晩通る。国の表・年表・島の便りのどれかが
読めなければ「数えられない」（2）で止まって、区画は書き換えない。

**日数を2か所に書かない。** 便りの古さの境目は、画面が使っている
`site/lib/place.ts` の `PLACE_STALE_DAYS` をそのまま読む。読めなければ
「数えられない」で止める（既定値を置くと、黙ってすり替わる）。

### 走りかた

`.github/workflows/upkeep_watch.yml`。**cron を当てにしない**ので、
`島の数字を焼き直す` と `Fetch YouTube Chat Data` の完了に繋いである
（`conclusion` は見ない。繋ぎ先が赤い日こそ動かないといけない）。
cron は保険。手で押したときの既定は「見るだけ」。

**赤くしない。** 手入れが何件溜まっていても緑で終わる。落ちるのは
「数えられない」（2）と「GitHub に届かない・書く先が違う」（1）だけ。

## 5. 答えが来たら、札がひとりでに裏返る（`答えが来たら待ち札を裏返す`）

あやとの言葉（2026-10-13）:

> あと、返信したのに「あやと待ち」にするのはやめて欲しい

### なぜ起きていたか

**`待ち-あやと` を外すものが、このリポジトリに1つも無かった。**
札は付くだけで、外れない。あやとが答えても、セッションが気づいて手で外すまで
「あやと待ち」のまま並ぶ。#808 と #809 が実際にそうなった。
**人の記憶に頼っている時点で、仕組みが無いのと同じ**——この文書の立て付けそのもの。

### 見分けの肝: 著者では分からない

**セッションが書くコメントも、GitHub 上の著者は `Ayato-kosaka`**
（セッションはあやと本人のトークンで書いている）。だから
「著者があやとなら本人」は**誤爆する。** 直近100本の実測（2026-10-13）:

| 著者 | 本数 | 中身 |
| --- | ---: | --- |
| `Ayato-kosaka`（type=User）・末尾に署名**あり** | 55 | **セッション** |
| `Ayato-kosaka`（type=User）・署名**なし** | 19 | **あやと本人** |
| `github-actions[bot]`（type=Bot） | 26 | 機械（`call_ayato` ほか） |

見分けの印は**末尾の署名1行**（`ticket_labels.SIGNATURE`）だけ。
55本とも**最後の行**が署名で、**うしろに1文字も無かった。**
判定は `ticket_labels.flip_verdict()` ひとつで、**ワークフローは判定を持たない。**

### 壊れたとき、どちらへ転ぶかを先に決めてある

| 壊れ方 | どう転ぶか | 代償 |
| --- | --- | --- |
| こちらが署名を付け忘れた | **裏返る** | 札がシステム側に移るだけ。読むのはシステム自身で、次に聞くときに付け直す |
| あやとが引用でこちらの署名を貼った | **裏返る**（引用・囲いの中の署名は数えない） | 無し |

**「裏返らなかった」は静かな失敗。** 誰も赤くならず、あやとの目には
「答えたのに、まだあやと待ち」としか映らない——いま直している不具合そのもの。
だから**疑わしいものは裏返す側へ倒す。** 迷ったら `待ち-システム` という
1章の決めごとと向きが同じ。

### 取りこぼしは、翌日ひとりでに拾う

`issue_comment` が届かなかった日・あやとが札より先に答えた issue・
口が断った回は、どんな判定を書いても裏返らない。**しかも誰も赤くならない。**
「`待ち-あやと` なのに、いちばん新しいコメントがあやと本人」は札とコメント
だけで数えられるので（`ticket_labels.missed_flips()`）、見回りが毎日当てる。
**その場の判定と同じ関数を通す**ので、見分けは1か所のまま。

**遡るのは1週間ぶん**（`SWEEP_WINDOW_DAYS`）。見回りの仕事は「届かなかった
ぶんを翌日までに拾う」ことで、**昔のコメントを読み直して札を付け替えること
ではない。** 窓を外して本番に当てたら、2026-09-22 の備忘1行（#147。答えでは
なく控え）で、審査待ちの issue が「システムの番」になった。窓を入れたあとの
本番は **4本見て0本**（2026-10-13 実測）。

### 走りかた

`.github/workflows/wait_flip.yml`。

- 裏返すのは **`issue_comment` の `created`。cron は使わない**（4〜7時間遅れる）
- 見回りは `Fetch Doneru Donations` と `Fetch YouTube Chat Data` の完了に繋ぐ
  （`conclusion` は見ない。cron は保険。手で押したときの既定は「数えるだけ」）
- **何も書かない。** 札を張り替えるだけで、コメントは1本も足さない
- 対象外のコメント（署名つき・機械・札が無い）では、**issue の口を1回も叩かない**
- **本文も題名もログに出さない。** 受け取りは `$GITHUB_EVENT_PATH` から読む
  （`${{ github.event.comment.body }}` を差し込むと、公開のログに出るうえに
  中身がそのままシェルの字になる）。要約に出すのは番号と `VERDICT_WHY` の訳だけ

**job の `if:` に札の名前を書いていない。** `contains(github.event.issue.labels.*.name, …)`
で先に落とせば速いが、札の名前がこの yaml にも住むことになり、変えた日に
**赤くならずに走らなくなる。** コメント1本ぶんのランナーは安い。

## 6. 待ち札が付いたら、機械が必ず呼ぶ（`待ち札が付いたらあやとを呼ぶ`）

あやと（2026-10-28・チャット）:

> なぜ通知してない？運用徹底してよ

### なぜ起きていたか

`待ち-あやと` を付けた4本（#1043・#1045・#1046・#1047）で、`call_ayato.yml` を
1本も回していなかった（`docs/island-misses.md` #306）。**札を付ける手順と、
鳴らす手順が別々で、鳴らす側がセッションの記憶にしか無かった。**
夜の見張り（`donor_calls`・`ingest_down`・`ship_down`）は自分で開く issue でだけ
`should_ping()` で鳴らしていて、**人が付けた札は誰も見ていなかった。**
5章と同じ形——人の記憶に頼っている時点で、仕組みが無いのと同じ。

### 何を見て鳴らすか

| 受け取り | 鳴らすか |
| --- | --- |
| 札 `待ち-あやと` が付いた（`labeled`。札つきで開いた `opened` も） | **鳴らす** |
| `待ち-あやと` の issue に、**末尾がシステムの署名**のコメントが足された | **鳴らす** |
| あやと本人の返事（署名なし） | 鳴らさない（答えた人を呼ばない。札は5章で裏返る） |
| 機械・ほかの人の書き込み／ほかの札／札の無い issue／閉じた issue | 鳴らさない |
| 上で「鳴らす」でも、**もう呼んである** | 鳴らさない（下の「重ねない」） |

判定は `ticket_labels.wait_ping_verdict()` ひとつ。**ワークフローは判定を持たない**
（札の名前・署名・待つ秒数・鳴らす字を yaml に書かない。5章と同じ理由）。
システムの書き込みの見分けは5章と同じ**末尾の署名**（`signed_by_system()`）。

鳴らす字は1行と署名だけ（`wait_ping_text()`）。**issue の中身は1文字も入れない**
——題名にも本文にも視聴者さんの素性がありうる。何を待っているかはすぐ上に書いてある。

### 重ねない

「最後に**あやとのアカウントで**書かれたもの（システムの問いでも、あやと本人の
返事でも）より後に、**通知の飛ぶ** `@` が在るか」で見る（`already_called()`）。

- **飛ぶのは、あやと以外が書いた生きたメンションだけ。** セッションが書いた
  `@Ayato-kosaka` は、字として在っても1通も飛んでいない（自分で自分を呼んでいる）。
  これを「呼んだ」に数えると #306 がそのまま戻る。囲い・引用・バッククォートの中も
  数えない（`mention_live()`）
- **issue の本文も1本に数える。** 機械（`donor_calls` ほか）が本文に `@` を入れて
  開いた issue は、開いた時点で鳴っている
- **あやとのアカウントで書かれたら、前の呼び出しは使い終わり。** システムの新しい
  問いならまだ誰も呼んでいないし、あやと本人の返事なら前の呼び出しはもう読まれて
  いる。答えたあとに札を付け直したら、新しく呼ぶ

**なぜ重ねないか。** 人が `call_ayato.yml` を回したあと・同じ issue に続けて
書いたあとにも毎回鳴ると、1つの問いに2通3通届く。**毎回鳴るものは、そのうち
読まれなくなる**（下の「全部には入れない」と同じ）。

### 待ってから読む

札を付けた人は、たいてい続けて問いを書き足すか `call_ayato.yml` を回す。
すぐ読むと、あちらの書き込みが載る前に「まだ呼んでいない」と見えて2通鳴る。
だから**鳴らす見込みがあるときだけ**、`PING_SETTLE_SECONDS`（2分）待ってから
並びを読み直す。札と状態も**読み直したほう**で決める（待つあいだにあやとが
答えて札が裏返る・閉じられる、がある）。

同じ issue の回は1本ずつ流す（`concurrency`）。続けて2本書いたとき、2本目の回は
1本目の回が鳴らしたあとの並びを読む。

**それでも重なることはある**——札を付けてから2分より遅れて `call_ayato.yml` を
回したとき。重なっても2通で、鳴らないよりよい。

### 走りかた

`.github/workflows/wait_ping.yml`。

- `issues` の `labeled` / `opened` と、`issue_comment` の `created` で起きる。**cron は使わない**
- 対象外の受け取りは、**issue の口を1回も叩かず、待たずに帰る**
- 鳴らすのは GITHUB_TOKEN（`github-actions[bot]`）なので通知が飛ぶ。**この書き込みは
  ほかのワークフローを起こさない**（GitHub は GITHUB_TOKEN の書き込みでワークフローを
  起こさない）。同じ理由で、**機械が付けた札ではここは起きない**——あちらは自分で
  鳴らす（`should_ping()`）
- 権限は `issues: write` と `contents: read` だけ。秘密情報はほかに使わない
- **本文も題名もログに出さない。** 要約に出すのは番号と `PING_WHY` の訳だけ

**`call_ayato.yml` は残す。** 札を付けずに呼びたいとき・この仕組みが落ちたときの
手の口。札を付けてすぐ（2分以内に）回しても重ならない。

## あやとに、本当に届くようにする

**題名に【あやとの操作】と書いても、通知は1通も飛ばない。**
2026-09-19 にあやとから「これ、私にメンションしてほしいと言ったはず」と
言われた #478 は、**人ではなく機械（`github-actions[bot]`）が立てたもの**
だった。機械が立てる issue は、立てる側のコードに入っていなければ、
あとから誰も書き足せない。

### 全部には入れない

毎晩鳴るものに毎晩メンションを付けると、そのうち誰も読まなくなる。

| 立てるもの | メンション | なぜ |
| --- | --- | --- |
| `donor_calls`（紐付け待ち） | **する** | 対応表を触れるのはあやとだけ |
| `ingest_down` の `session_expired` | **する** | cookie を入れ直せるのはあやとだけ |
| `ingest_down` の「何日も入っていない」 | しない | システム側で流し直せば入ることがある |
| `bake_down`（焼き直しの赤） | しない | システム側で直せる |
| 毎週の棚卸し | **あやと待ちが在る週だけ** | 0本の週に鳴らす意味が無い |
| 人（セッション）が `待ち-あやと` を付けた issue（`wait_ping`） | **する**（もう呼んであれば重ねない） | 待っているのはあやとだけ（6章） |

### 「書いてある」と「飛ぶ」は別

GitHub は**コードブロック・引用（`>`）・バッククォート**の中の `@名前` を
メンションとして扱わない。字として在るのに1通も飛ばない、がいちばん
起きやすい外し方なので、`ticket_labels.mention_live()` が機械で見る。

### 本文を書き換えても飛ばない

飛ぶのは**issue を開いたとき**と**コメントを足したとき**だけ。
毎晩本文を差し替える形（`donor_calls` / `ingest_down`）では、本文に
置いただけだと最初の1回しか届かない。かといって毎晩コメントすると雑音になる。

**変わり目でだけ鳴らす**（`ticket_labels.should_ping()`）:

| いま | 鳴らすか |
| --- | --- |
| 開いた（`create`） | 鳴らさない（本文のメンションで飛ぶ） |
| 開き直した（`reopen`） | **鳴らす**（状態を変えるだけでは飛ばない） |
| 書き換えで、前の本文にメンションが無かった | **鳴らす**（ここで初めてあやとの番になった） |
| 書き換えで、もう入っていた | 鳴らさない |

毎週の棚卸しは、これに加えて `PING_COOLDOWN_DAYS`（6日）で止める。
繋ぎ先が2本あるので、同じ週に2回走ることがある。

### `@Ayato-kosaka` は、素性の見張りから外してある

`tools/logident.py` はハンドル（`@…`）を「公開のログに出た個人」として
数える。**オーナーの名乗りは視聴者さんの素性ではない**ので、そこだけ
`OWNER_HANDLES` で落としてある。落とすのはこの1つだけ。

## 見張り

| 見張り | 何を見るか | 対照 |
| --- | --- | --- |
| `python/ticket_labels_selftest.py` | 札の読みかた／メンションが飛ぶ形か／鳴らす条件 | 飛ぶ側・飛ばない側の両方 |
| `python/ticket_stock_selftest.py` | 棚卸しの数えかたと本文 | `nostale` と `nolabel` が**別々に**落ちる |
| `python/closes_check_selftest.py` | 抜けを見つける／関係ない PR で落ちない | 両側 |
| `python/upkeep_watch_selftest.py` | 人の赤が区画に出る／**機械の赤が出ない**／手で書いた本文が消えない | 振り分けを潰す・引き金を外す・印を変える、の3通りで落ちる |
| `python/wait_flip_selftest.py` | あやと本人／セッション／機械の見分け・裏返したあとの札・取りこぼしの拾い直し | **足の数だけ**（`BREAK=sig loose bot label keep miss window` の7通りが、別々に落ちる） |
| `python/wait_ping_selftest.py` | 鳴らす側（札が付いた・システムが書き足した）／鳴らさない側（あやとの返事・機械・ほかの札）／重ねない側／鳴らす字が飛ぶ形 | **足の数だけ。毎回ひとりでに当てる**——足を1本ずつ外した自分を子として起こし、**その足の印を付けた判定だけが落ちる**ことを見る |

どれも `python/selftest_runner.py` が名前で拾うので、
`Selftests`（毎 PR）で走る。**表に書き足す作業は要らない。**

`ticket_stock` は `BREAK=` で守りを外せる。**本番では空。**

```bash
BREAK=nostale python3 python/ticket_stock.py   # 30日の線を外す
BREAK=nolabel python3 python/ticket_stock.py   # 札を読まない
```

`wait_flip` も同じ形。**守りを外すと、どれが落ちるかが1本ずつ違う**
（まとめて1つにすると、同じ足を7回折っていても緑に見える）。

```bash
BREAK=sig    python3 python/wait_flip_selftest.py  # 署名を見ない
BREAK=loose  python3 python/wait_flip_selftest.py  # 署名を「どこかに在れば」に緩める
BREAK=window python3 python/wait_flip_selftest.py  # いくらでも遡る
```

`wait_ping` は、外した足ごとに**どの判定が落ちるべきか**の印を判定の側に持っていて、
印と落ちたものが1つ残らず一致するかを毎回見る（`--no-drill` で外せる。子の中から呼ぶ用）。
1本だけ外して眺めたいときは:

```bash
BREAK=again python3 python/wait_ping_selftest.py --no-drill  # 重ねて鳴らす
BREAK=self  python3 python/wait_ping_selftest.py --no-drill  # セッションが書いた @ を「呼んだ」と読む
```
