# 旅のガイドの面 — デザイン仕様

**行った国・街の「実際に行った人のガイド」の型。** 道は3段。

| 道 | 面 | いつ建てるか |
| --- | --- | --- |
| `/travel/<国>` | 国 | 行った国ぜんぶ。数日しか居ない街は、ここの1節 |
| `/travel/<国>/<街>` | 街 | 材料が十分な街だけ |
| `/travel/<国>/<街>/<話>` | 体験記 | 厚い街の、厚い話だけ（日帰りの遠出・街から街への移動） |

最初に作るのはスコピエ（北マケドニア）。**作る人は、これを読んでから手を付ける。**
この文書は [`island-design.md`](./island-design.md)（拘束力あり）の下に置く。食い違ったら island-design.md が勝つ。
守れない所が出たら、実装を曲げずにこの文書を直してから作る。

決まっていること（#1196・#1197・#1201。ここでは動かさない）:

| | |
| --- | --- |
| 誰に | 検索と AI の回答から来た、**初めての人**。日本語だけ |
| 何をしてもらう | 配信（YouTube）を見てもらう。あやと島を知ってもらう |
| 声 | **あやと島案内鳥が書く。** あやとの言葉は「」でそのまま引き、その場面の配信へ時刻つきで繋ぐ |
| 絵 | あやと島カード（その日の写真）＋ AI で描いたイラスト ＋ 借りた写真（出どころつき） |
| お金 | 広告・予約リンクを載せない。配信へ繋ぐのは、ふつうのブログの定石で |
| 目通し | 最初の街（スコピエ）は、あやとが全部読んでから出す |

材料は配信から抜いた `streams/YYYY/MM/<stem>.facts.json`（手順は `.claude/skills/guide-facts/SKILL.md`）。
街ごとに束ねて読むのは `python3 python/guide_facts.py city --country <国> --city <街>`。

## 0. ひとことで

**aruco の紙面の分かりやすさ**（絵が先・1つの番号で地図と一覧と説明が結ばれる・1件ぶんが毎回同じ並び）に、
**ca-voir の「行った人の1軒ぶん」**と、**いまの `/bulgaria` の印と地図**を載せて、
**どの一文も、配信のその場面か外の出どころへ1押しで辿れる**ようにする。

ほかのガイドに無いのは最後の1つだけで、そこが勝ち筋（2019年の記事に、2026年の実測と本人の声で勝つ。#1196）。
だから面の上での「強さ」の順は決まっている。

1. **行った日**（いつの話か）
2. **本人の一言と、その場面のリンク**（本当にそう言ったか、押せば確かめられる）
3. **測った値・払った額**（数字で答える）
4. **その日の写真**（そこに居た絵）
5. 外の出どころの事実（行かなかった所・歴史・現地のつづり）

上の4つが、一般のガイドの中身（5）より前に・大きく出る。

## 1. 手本から取る型

### 1-1. aruco（地球の歩き方の、写真の多い観光ガイド。紙面5枚）

紙面の絵は版権物なので、リポジトリに置かない・写さない。**型だけを言葉にしたもの。**

| 紙面 | 何が分かりやすいか | この面での部品 |
| --- | --- | --- |
| 料理の一覧 | 写真が先、その下に名前（大）→ 原語の名前（色違いの小さい字）→ 2行の説明。**マスが全部同じ形**なので、目で横に流して比べられる | 料理の格子 |
| 番号つきの絵地図と「1時間でぐるり」 | 絵地図の番号＝コース表の番号＝説明の番号。**1つの番号で、地図と順路と説明が結ばれる。** Start と Goal があって、歩く順がそのまま読める | 番号つき地図とコース |
| 見どころのカード | 色の小見出し（何の場所かを一言）→ 名前（大）→ 原語の名前 → 3〜4行 → 写真に吹き出しの豆知識。**見出しが先に「何の場所か」を言う** | 見どころのカード |
| Keyword の枠 | 本文で引っかかる語を、**問いの形の題**（「〜とは？」）で別枠に出す。本文を止めずに済む | Keyword の枠 |
| 地域の絵地図に品を散らす（チーズマップ） | 国の形の上に地方の札と品の写真を散らし、点線で地方へ結ぶ。**「どこで何が名物か」が1枚** | 国の面の食べものマップ |
| 漫画の名場面とその場所 | 名場面の絵の横に、その場所の写真と地図。**「あの場面の場所に立てる」が旅の動機になる** | **配信の名場面とその場所**（本人の一言＋場面のボタン＋その場所の番号）。この面でいちばん効く型 |

## 2. 面の節立て

### 2-0. 材料の種類と、行き先の節

`facts.json` の `kind` が、そのまま節を決める。**人が節を選び直さない。**

| `kind`・欄 | 行き先 |
| --- | --- |
| `fact`（街のようす） | どんな街？ |
| `move` | どう行く？ どう動く？ |
| `price` | いくらかかった？（値段の表） |
| `place` | どこへ行った？（`place.name` で1枚のカードにまとめる） |
| `food` | 何を食べた？ |
| `stay` | どこに泊まった？ |
| `caution` | 気をつけることは？ |
| `quote` | `about` の節に、本人の一言として |
| `trip` が付いたもの | 街の面では「日帰りで」のカード1枚。厚ければ体験記の面へ |
| `measured` | 測った数字の札 |
| `verify` が付いたもの・`via: "chat"` | **面に出さない**（`city` が後ろの山に回すもの） |

**材料が0行の節は立てない。** 空の見出しを置かない。
節の並びは街が変わっても変えない（ca-voir の「毎回同じ並び」）。どの街の面も、同じ場所に同じ問いがある。

## 3. 部品

**押せるものには厚み（48px のボタンで 6px、30px の札で 4px）、押せないものは平ら**（island-design 3章3）。
吹き出しと驚く数と札は押せる（配信のその場面へ）。Keyword・値段の表の地・出どころの1行は押せない。

| # | 部品 | 中身 | スマホ（390px）での見えかた | 材料 |
| --- | --- | --- | --- | --- |
| 1 | パンくず | 島 › 歩いた国 › 国 › 街（› 話） | 1行。あふれたら折り返す（頭を省かない） | 道の名簿。`BreadcrumbList` と同じ値 |
| 2 | 表紙 | その日の写真・現地のつづり（`lang`）・h1・一言（40字まで）・行った日・公開／最終更新・撮影の札 | 写真は横幅いっぱい 4:3。字は下3分の1に暗幕つきで重ねる（`/bulgaria` と同じ）。日付の行は写真の下 | カードの写真・`date_local` |
| 3 | 驚く数 | 数（大）＋単位＋1行。**測った値には「実測」の2字** | 1列に3段。押すとその場面へ | `measured`・`price` |
| 4 | 目次の格子 | 印の絵＋問いの短い形（「どう行く？」）＋件数 | 2列 | 節の名簿 |
| 5 | 印 | **行った**（日付つき）／★1〜3（一般の重要度）／好みの印（◎○注意）。読みかたは印と一言の対応表だけ | 名前の行の横に小さく。写真の上に重ねない | 行ったは `facts`。★は外の事実、好みの印は議事録から測った好みを規則1本に通したもの（`/bulgaria` の `python/data/bulgaria/taste.json` と同じ作り。country-guide 2章） |
| 6 | 節の頭 | 番号（01）・印の絵・問いの見出し（h2）・答えの1〜2文 | 見出しは2行まで。答えの文は太字にしない | 案内鳥 |

### 一言と場面ボタンの使い分け

**どの一文も配信の時刻か外の出どころへ辿れる**（#1196 の4）。ただし全部の文にボタンを付けると読めない。

- **一言（吹き出し）** — 本人の声。押すとその場面。1節に3つまで
- **場面の時刻** — カードと表の行が持つ（「10/14 0:56:30」）。その行の事実の場面
- **この場面の配信ボタン** — 節に1つ。いちばん見てほしい場面

**案内鳥の地の文は、必ずどれかのカード・行・節に属す。** 属さない文（どの場面か分からない文）は書かない。

## 4. 絵の決まり

### 4-1. 3種類と、それぞれの役

| 絵 | 役 | 使う所 | 使わない所 |
| --- | --- | --- | --- |
| **あやと島カードの写真**（あやとがその日に貼った写真） | **そこに居た証拠** | 表紙・行った所のカード・食べたものの格子・体験記のタイムライン | 行かなかった所 |
| **借りた写真**（Wikimedia Commons ほか。public domain / CC0 / CC BY / CC BY-SA だけ。country-guide 1-2-1） | 行かなかった所の姿・写真の無い所を埋める | 行かなかった所・写真の無い料理・カードの無い日の表紙 | — |
| **AI のイラスト** | 位置と意味を、絵で先に分からせる | 絵地図・食べものマップ・Keyword の小さな絵・写真の無いマスの最後の埋め | **実在の場所・料理・人を、写真のように描いたもの（全部）** |

- **1枚の絵に2つの役を持たせない。** 証拠の絵（カード）と、説明の絵（イラスト）を混ぜない
- 写真の無いマスは、カード → 借りた写真 → イラスト（島の料理の絵と同じ絵柄）の順で埋める。**空のマスを置かない**（`/bulgaria` の「穴を見せない」）
- **通りがかりの人の顔が分かる写真は使わない**（第三者の扱い。guide-facts §3 と同じ）
- カードの写真は、住人のキャラクターが立った「カード」ではなく**素の写真**を使う案（9章で決める）

### 4-2. AI のイラストの描きかた

**island-design 2章の5つをそのまま守る**（輪郭線を引かない・環境光を強く・接地影を焼く・彩度も明度も高く・急な変化を作らない）。
島のスプライトの隣に置いて、同じ世界に見えること。

aruco の手描きの絵地図から取るのは、**見下ろしの見取り図の感じ**だけ。

- 斜め上から見下ろす。建物は**特徴を1つだけ残して丸く単純に**（モスクなら尖塔、橋ならアーチ）
- 道と川は太く、緑は面で。地は紙のような暖かい色
- **デフォルメしても、位置関係は保つ。** 北・川・丘の向きは本物と同じ。正確な位置は Google マイマップの仕事（`/bulgaria` と同じ分担: 絵は位置関係、歩くのは本物のアプリ）

描かないもの:

- **字。** 番号の丸と名前は、絵の上に HTML／SVG で重ねる（island-design 6章「看板の言葉は、絵に焼かない」・8章）。読める・直せる・検索に載る。番号の置き場所は絵ごとに JSON に持ち、絵を描き直したら打ち直す
- **写真らしさ。** 光沢・レンズのぼけ・本物の看板の字・実在の店の外観をそのまま、は描かせない。料理は島の料理の絵（`site/public/sprites/`）の絵柄で
- **人。** 描くならあやと（島の絵）だけ。視聴者さん・通りがかりの人を描かない

描く道具は `/chatgpt-image`（EC2 の Chrome）。背景の抜きは手元で（同じスキルの原則）。

### 4-3. 「イラスト」の添えかた

- 絵の左下の角に、小さな札「イラスト」（字。印にしない）。地の上で字の濃さ 4.5 以上
- 絵地図は「イラスト・位置は目安」
- `alt` の頭にも「イラスト：」
- 面の終わりの出どころの一覧に1行「イラストは、あやと島案内鳥が AI で描いたもの」

### 4-4. 出どころの書きかた

| 何 | 絵の真下 | 面の終わりの一覧 |
| --- | --- | --- |
| 借りた写真 | 「撮った人／ライセンス」。撮った人の字が元のページへのリンク（`/bulgaria` の `Credit`。`aria-label` に何の写真か） | 同じもの |
| カードの写真 | 「あやと撮影・2026年10月14日」。その日の配信へのリンク | — |
| イラスト | 「イラスト」 | 4-3 の1行 |
| 外の事実（入場料・現地のつづり・歴史・治安） | その行の最後に、出どころの名前（リンク）。調べた日 | URL の一覧 |

**書けない絵は載せない。出どころの無い事実は載せない。** いまの `site/content/northMacedonia.ts` には出どころの URL が無いので、
そのまま街の面へ流さない（出どころを足してから）。

## 5. 言葉の決まり

### 5-1. 案内鳥の文

- **説明口調にしない。**「〜できます」「〜になっています」「〜がおすすめです」を書かない。言い切る短い文（island-design 5章）
- **起きたことは過去形で、日付を付ける。**「2026年10月24日は、バスが渓谷の手前で折り返した」。
  **1回の体験を決まりにしない**（「バスは手前で折り返す」と書かない）
- **いつ読んでも本当のことだけ。**「いま」「今年」「最新」「〜中」を書かない（island-standards 16章）
- **言っていないことを足さない。** あやとの感想を強めて言い換えない（「すごい当たり」を「絶品」にしない）。
  地の文も facts の `text` を越えない
- 主語は「あやと」。案内鳥は自分のことを書かない
- 答えの文で見出しを言い直さない（island-design 5章4）
- **画面の仕組みを書かない。**「配信から抜き出しました」「確かめが要る額は出していません」「印は規則で付けています」は全部書かない（CLAUDE.md）

### 5-2. あやとの「」

- **字幕の字のまま。** 直すのは2つだけ: 明らかな誤字のすぐあとに `[正しい字]` を足す（「吉の屋[吉野家]より早い」）、途中を飛ばすときの「…」
- 関西弁も崩れた言いかたも直さない（「詐欺やんけ」）
- 1つの一言に、日付と配信の時刻を必ず付ける。押すとその場面
- **読み上げたチャット・チャットが先に言ったこと（`via: "chat"`）は引かない。** 本人が言ったことにしない
- 1節に3つまで。前に案内鳥の文で、どの場面かを1文だけ（「着いてすぐ」）

### 5-3. 行かなかった所

- 見出し「ほかに、近くに何がある？」の下に、**まとめて置く。** 行った所と混ぜない
- 各行に「行っていない」の札。**感想・体験の言葉を書かない**（「良かった」「混んでいた」）
- 中身は外の出どころつきの事実だけ。入場料・行きかたには調べた日を付ける
- 行けなかった理由が配信にあれば、それは「気をつけることは？」か本人の一言で書く（ボートに乗れなかった、など）

### 5-4. 値段

- **「1,400円（2026年10月14日の配信で言った額）」。** 表なら「いつ・場面」の列に日付と時刻
- 円の額は、あやとがその場で円に直して言ったもの。**表の下に1行だけそう書く**（値札の額と取り違えさせないため）
- 現地の額は、あやとが現地の単位で言ったか、外の出どころで確かめたときだけ。単位（デナール）を書き、換算には日付とレートを添える
- **`verify` の付いた額は、面に1つも出さない。** 表の空欄にもしない（行ごと出さない）
- 差額・比べた額（「アルバニアより100円ぐらい高い」）は表に入れず、本文に
- 「ぐらい」は「約」に。3桁ごとにカンマ。「安い」「高い」は本人が言ったときだけ「」で

### 5-5. 日付と時刻

- 本文は「2026年10月14日」、表と札は「10/14」（年は節の頭で一度）。HTML は全部 `<time datetime="2026-10-14">`
- 配信の時刻は、配信の頭からの経過「0:56:30」。現地の時刻は「16時」と書いて混ぜない

## 6. 検索と AI のための作り

見た目ではなく、面の作りとして守る。根拠は `docs/seo-2026-11/C_research.md`。

| 決まり | 形 |
| --- | --- |
| 題（`<title>`） | **街の名前＋行った年月＋その面がいちばん答える語2〜3つ。**「物価」「行き方」「治安」「費用」は個人が上位を取れている語（#1196）。「おすすめ」「観光」は大手の語なので入れない。例: 「スコピエ旅行記 2026年10月｜物価・行き方・マトカ渓谷 — あやと島」 |
| 一文（`description`） | **面に見えている実測か払った額を2つ入れた1文**、120字まで。例: 「2026年10月にスコピエへ行った配信者あやとの記録。マトカ渓谷へは60番のバスで実測49分、ホステルは10日延ばして1泊約1,400円。」 |
| 見出し | h1 は場所の名前。h2 は問いの形（2章の表）。h3 は名前（見どころ・料理） |
| 節の頭 | **1〜2文で答える。** 数字と日付を入れる（AI が抜き出すのはここ。Bing の公式の助言） |
| 数字 | 値段と移動は `<table>` で。div で表を組まない |
| 日付 | 行った日・公開・最終更新を表紙に見える字で。「公開」「最終更新」と書く。`<time datetime>` と、構造化データの `datePublished` `dateModified` を**同じ値に。** **最終更新は、中身の字が変わった日だけ進める**（ビルドの日にしない。#1196 のやらないこと） |
| 構造化データ | `Article`（`headline` `author` `datePublished` `dateModified` `image` `inLanguage: "ja"`）と `BreadcrumbList`（見えるパンくずと同じ）。`lib/jsonld.tsx` に足す（あちらの決めごと「見えている字と同じことだけ」）。**入れない**: `FAQPage`（廃止）・`HowTo`・`TouristAttraction`・`Review`・`VideoObject`（視聴の面ではない） |
| 生の HTML に本文 | 静的書き出しで、本文・表・一言・場面のリンクを全部焼く。**画面が出てから取りに行く所（Firestore など）に本文を置かない。** AI の読み手は JS を動かさない |
| 畳んだ中身 | `<details>`（`Fold`）だけを使う。中身は最初から HTML に在る。開いたときに取りに行く・描く作りにしない |
| iframe の中身 | 地図と埋め込みは iframe でよいが、**場所の名前・Google マップへのリンク・配信の URL と時刻は、HTML の字でも置く**（iframe の中は読まれない） |
| 場面のリンク | `https://www.youtube.com/watch?v=<id>&t=<秒>s` の素の `<a href>`。JS で開かない |
| 現地のつづり | `lang="mk"` などを付ける |
| 画像の `alt` | 何が・どこで・いつ（カード）。イラストは「イラスト：」 |
| 内部リンク | 国 ⇄ 街 ⇄ 体験記、同じ国のほかの街、`/about`（書き手）、配信。**どこからもリンクされない面を作らない** |
| 面の割りかた | 言い換えごとに面を割らない（「物価」「生活費」で2枚にしない。#1196 のやらないこと） |

## 8. 出す前に確かめること

島ぜんぶの出す前のチェック（island-standards の末尾）に、この面だけのものを足す。

- 面に出た額のうち、`verify` の付いた行が **0**（`guide_facts.py city` の後ろの山と突き合わせる）
- 一言の **全部**に場面のリンクがあり、リンクの秒が facts の `t` と同じ
- 借りた写真の全部に出どころ、イラストの全部に「イラスト」の札
- **JS を切って開いて**、全部の節の見出し・答えの文・表・一言・場面のリンクが HTML に在る（`python/seo_audit.py`）
- 見える日付と、構造化データの日付が同じ
- 説明口調の語（できます・なっています・おすすめです）と、画面の仕組みの説明が 0
- 視聴者さんの名前・チャットの字が 0
- キリル文字が面に増えるので、字の束を焼き直した（country-guide 6-2）

道具がまだ無いもの（上の1つめ・2つめ・6つめ）は、**街の面を作る担当が `python/` に見張りとして作るところまでが仕事。** 2つめの街で同じことを手でやらない。
