## 0. 字が正しいだけの面は、0点ではなく25点

**最初に作ったソフィアの面は、調べた中身が全部合っていて、それでも25点だった。**

あやと（2026-11-06）:

> 写真もgoogle mapもなくて、ほかの人が見てワクワクしない、全くみたいと思わない。
> 文字が多い。写真メインにしたい。付箋を張る仕組みもない。縦長すぎて読みにくい。

**次に作る人は、ここから始める。**

| 要るもの | なぜ | どこから |
| --- | --- | --- |
| **写真**（見どころ・料理・買いもの 全件＋表紙1枚） | 絵が無いと、読む前に閉じられる | Wikimedia Commons（§2-2） |
| **本物の地図** | 自前の丸だけの絵は「地図」に見えない | OpenStreetMap のタイル（§3） |
| **付箋の板** | 視聴者さんがその場で口を出せる | `content/themes.ts` に宛先1つ＋`<StickyNotes>` |
| **短さ** | 狭い画面で 44,000px あった。**絵のタイルで 1/3 になる** | §4 |

**1件800pxのカードを縦に積まない。** 絵のタイルの格子にして、字は押すまで出さない
（`<details>`）。これだけで 44,372px → 14,106px（実測）。

## 0-1. この型でいちばん大事なこと

**「名物を並べる面」にしない。**

ソフィアで分かったのは、**ブルガリア料理の看板がほぼ全部、あやとが食べられないもの**
だということだった。кебапче も кюфте も луканка も свинско も**豚**で、本人は豚が苦手
（ハム・ソーセージ・チャーシューも含む）。ракия とワインは**酒**で、2年ほど前にやめている。
баклава は「外国の料理は好きなものが多い」の**唯一の例外**として名指しされている。

普通にガイドを引き写すと、**上位の半分が食べられないもの**になる。
だから重要度を**2本立て**にした。

| | |
| --- | --- |
| **星**（★1〜3） | 一般の重要度。必見／行けたら／余裕があれば |
| **印**（◎○⚠） | **あやとに合うか** |

**混ぜない。** 混ぜると「有名だけどあやとには合わない」が表せなくなる。

**⚠ を隠さない。** 隠すと配信の場で頼んでしまう。
出したうえで、**なぜかを1行**添える（「豚なので」「酒なので」「入場料が高いので」）。

## 1. 調べる順番

**好み → 現地の事実 → 突き合わせ。** この順でないと、好みが後知恵になる。

### 1-1. 好みは、議事録から実測する（一般論を書かない）

`streams/` の文字起こしと議事録を引いて、**本人の発言の引用つき**で表にする。
ソフィアのときの置き場は `python/data/bulgaria/taste.json`。

```bash
grep -rn "豚\|お酒\|苦手\|美味しい\|好き" streams/2026/ | head -200
```

集めるのは4つ。

| | 中身 | ソフィアでの実測 |
| --- | --- | --- |
| **食べもの** | 好き／苦手／ふだんの習慣 | 好き15・苦手13・習慣13 |
| **場所** | 機嫌がいい／嫌がる | 10／7 |
| **お金** | 1日の買い出し・許せる線 | 11件（1日600〜700円、5,280円の入場料は入らなかった） |
| **買うもの** | 持ち帰るもの | 10件 |

**合格の条件:** 1件も残らず**本人の発言の引用がある**こと。
「たぶん好き」は書かない。書くと、あとで印の理由が説明できなくなる。

### 1-2. 現地の事実は、出どころの URL をつけて集める

`python/data/<国>/facts.json`。粒度の見本（ソフィアの実測）:

| | 最低 | ソフィア |
| --- | --- | --- |
| 見どころ | 12件以上 | 22件 |
| 食べもの | 12品以上 | 22品 |
| 基本情報 | 10件以上 | 14件 |
| ことば | 12語以上 | 19語 |
| 歴史 | 4件以上 | 5件 |
| イメージ（「◯◯の国」） | 3件以上 | 4件 |
| 買うもの | 5件以上 | 9件 |
| その時期の行事 | 3件以上 | 6件 |

見どころ1件が持つ欄: `name` `cyr`（現地語のつづり）`roman` `kana` `rank` `what` `how`
`walk` `stay` `advice` `maps` `lat` `lon` `src`。
**`lat` `lon` は6桁まで。** 地図を焼くのに要る。

**合格の条件:**

- **全件に `src`（出どころの URL）がある**
- **値段が全件にある。** 「◯◯ユーロ（約◯◯円）」と、レートの日付
- **情報が割れていたら、割れたまま書く。** ソフィアではボヤナ教会の入場料が
  公式10ユーロ／ガイド12レフ（約6ユーロ）で食い違っていた。
  どちらかに決めると、現地で違ったときに紙のせいになる
- **その年の日付を書かない。** 「毎年11月中旬」とは書くが「11月14日」とは書かない

### 1-2-1. 写真は Actions から探す。この箱からは探せない

**この箱から `upload.wikimedia.org`（絵そのもの）は curl で取れるのに、
検索の口（`commons.wikimedia.org/w/api.php`・`api.wikimedia.org`）は 429 で断られる。**
断っているのは Wikimedia の枚数制限で、出口の住所が他の作業と共用なので
こちらでは減らせない。**時間を置いても戻らない。**

```
Actions の「写真の候補を探す」を押す（workflow_dispatch）
  queries: {"サルマ":"sarma","ムサカ":"moussaka"}
  limit:   10
→ artifact `photos` を落とす → python/data/<国>/photos.json へ移す
```

**探す言葉は短くする。** 「sarma stuffed vine leaves balkan dish」は**0枚**で、
「sarma」は10枚だった。語を足すほど当たらない。**料理名1語から始める。**
現地語（`сарма` `мусака`）でも引けるので、英語で0枚なら現地語を試す。

道具（`python/commons_photos.py`）が持っている判断は3つ。**どれも間違えても
絵は出てしまうので、目では気づけない。**

- **許諾** — public domain / CC0 / CC BY / CC BY-SA だけ。NC・ND・fair use は落とす
- **縮尺** — 原寸ではなく 500/960/1920 の道。原寸（5MB の JPEG）を貼ると転送量が跳ねる
- **絵かどうか** — ファイルの置き場には PDF も居る。「バニツァ」で EU の官報が返ってきた

**選ぶときは、必ず見る。** 字だけで選ぶと、鍋と漬物の写真を「サルマ」として
貼ることになる（1枚目で実際にそうなった）。落として並べて、1枚ずつ見る。
この箱からでも `thumb.wikimedia.org` には届くので、そちらから落とせる。

**場所が違う写真を貼るときは、そのつもりで選ぶ。** 料理の寄りならよいが、
浜辺で持っている絵のように**その土地が写っているもの**は、別の国の面に貼らない。

### 1-3. 通貨は、必ず現地の「いま」を引く

ブルガリアは**2026年1月1日にユーロを導入**し、レフは2026年2月1日に法定通貨でなくなった
（固定 1ユーロ＝1.95583レフ）。**日本語のガイド記事はまだ全部レフ表記。**
あやとが参考に挙げた `ca-voir.com` も含めて、そのまま写すと**全部の値段が間違う。**

```
→ 面を作る前に、必ず「その国の通貨はいま何か」を検索で確かめる。
→ レートは日付つきで `rate_note` に書く（`BG_RATE`）。
```

## 2. 印を、機械で付ける

**手で書かない。** 手で書くと、好みが変わったときに全件を見直すことになるし、
「なぜその印なのか」が消える。

`python/build_bulgaria.py` の冒頭に、規則が1本だけある。

```python
def mark_food(d):
    if d.get("alcohol"): return "warn", "お酒。あやとは2年ほど前にやめている"
    if d.get("pork"):    return "warn", "豚。あやとは豚肉が苦手（ハム・ソーセージも）"
    for word, why in LIKE_FOOD:          # taste.json の実測から引いた言葉
        if word in (d["jp"] + d["what"]): return "good", why
    if d.get("meat") == "なし":          return "ok", "肉が入らないので、豚を避けられる"
    return "ok", ""
```

**規則は理由の字も一緒に返す。** 印だけ返すと、面の側で理由を手で書くことになって、
規則を直しても字が古いまま残る。

判定に要る欄（`pork` / `alcohol` / `meat` / 入場料）は、
`facts.json` とは**別のファイル**（`fill.json`）に、名前を鍵にして置く。
調べ直したときに、どちらが事実でどちらが突き合わせかが混ざらない。

**焼くほうは、名前が1つでも合わなければ焼かない。**

```python
miss = [x["jp"] for x in F["food"] if x["jp"] not in fill_food]
if miss: raise SystemExit("材料の名前が合いません: %s" % miss[:5])
```

## 3. 地図を焼く

**面の側で緯度経度から座標を出さない。必ずズレる**
（`components/macedonia/NmMapSvg.tsx` と同じ決まり）。

### 3-1. 遠いものを同じ絵に載せない

最初の版はリラ修道院（中心から62km）を街の地図に入れて、紙が **1000x10359px** になり、
中心部の印が1本の線に潰れた。3kmで切り直しても、絵の半分以上が空いて印が左上に固まった。

**距離を並べて、切れ目で切る。**

```
0.95km（ネフスキー大聖堂） ← ここまでが徒歩圏
1.34km（NDK）              ← 切れ目
```

ソフィアは `WALK_KM = 1.0` で16か所が絵いっぱいに散った（1000x601）。
入らないものは「中心から◯km」で地図の下に出す。**歩けない距離だとは言わない。**

### 3-2. 記号は英字（A・B・C…）

**一覧とコース表と地図が、同じ字で対応する**のが、るるぶの見開きの要。
番号（1・2・3）にすると、星（★1〜3）と混ざって読めなくなる。
記号は**歩くコースの順**に振ると、コース表がそのまま A→B→C… と読める。

### 3-3. 縮尺も焼く

中心からの輪（300m・600m）を出すために、`kmPerPx` と中心の画素位置（`cx` `cy`）を
焼いた JSON に入れる。絵の側で割り戻すと、紙の大きさを変えたとき輪だけ取り残される。

## 4. 面の並び（9つ）

```
 0 ヒーロー        どういう街か。驚く数を3つ以上（ソフィアは9つ）
 - 読みかた        ★と◎○⚠の説明。**いちばん上に置く**
 - 目次            CONTENTS の帯
 1 どんな街か      歴史と、みんなが持っているイメージ（ブルガリア＝ヨーグルト）
 2 ここでしたいこと 好みと現地の事実を突き合わせた結論。その週にある行事も
 3 基本情報        通貨・両替・物価・言葉・交通・空港から・治安・水・チップ・電源・SIM・気候
 4 歩くコース      A→B→C→GOAL、間に「徒歩◯分」、合計の所要時間
 5 見たいもの      星で3段。所要時間・徒歩分・入場料・ADVICE・Google マップ・印
 6 食べたいもの    星で3段。キリル/ラテン/カナ・どこで・値段・肉の有無・印
 7 買いたいもの    値段と買える場所
 8 ことば          文字が読めないと看板も地図も引けない
```

**「読みかた」を上に置く。** 下に 22+22 件が全部その印を持っているので、
読み方を知らないまま一覧に入ると、記号が飾りに見える。

**畳まない。** るるぶの見開きは開いた状態で並んでいるもの。
ただし長くなる（ソフィアは狭い画面で 44,000px）ので、
**節の終わりに「目次へ」を1本**置く。追従する板を重ねるより場所を取らない。

**歩くコースの所要時間は、機械で出す。** 直線距離に 1.3 を掛けて道のりの目安にし、
分速80mで割る。**概算だと面の側に書く。**
滞在時間は「蛇口だけなら10分、博物館を入れて1時間30分」のように2通り書いてある欄が
あるので、**短いほうを合計に足す**（長いほうで足すと「丸2日」になってコースに読めない）。

## 5. トップページに出す期間を切り替える

`site/components/isle/spec.ts` の `GUIDES` が1本の出どころ。
**島の札（`guidePlace`）も、トップページの「いま」の板も、ここから引く。**
国の名前を紙のほうへ書き写すと、国を越えた日に**紙だけが前の国を指す。**

```ts
const GUIDES: Record<string, Guide[]> = {
  balkans: [
    { slug: "bulgaria", name: "ブルガリア・ソフィア", href: "/bulgaria", icon: "church", lead: "…" },
    { slug: "north-macedonia", name: "北マケドニア", href: "/north-macedonia", icon: "mountain", lead: "…" },
  ],
};
```

**いつ出すかは、ここに書かない。** 出るのは**その国に居るあいだだけ**で、
居るあいだは国の表（`site/content/countries.ts`）から導く——その国に入った日
（`AHEAD_COUNTRIES` の `entered`）から、つぎの国に入った前の日まで。
つぎの国がまだ表に無ければ、開いたまま。

- **行を足すのは、国を `AHEAD_COUNTRIES` に足すのと同じ変更で**（＝入った日に）。
  片方だけだと——
  - 行だけ足した → その案内は1日も当たらない。`python/upkeep_watch.py` の
    引き金「案内している国」がこちらに鳴る
  - 国だけ足した → 表紙から案内が消える。面（`site/app/<国>/`）が在るのに行が無ければ
    `site/selftest/islechapter_selftest.mjs` が落ちる
- **居る国に案内の面が無ければ、何も出ない。** 前の国へは戻さない
  （もう居ない国の歩きかたを「いま」に出さない）
- **期間を手で書かない。** 前は行ごとに `from`〜`to` を書いて、期間の無い行を
  「戻る先」にしていた。「一週間ほど」を `to: "2026-11-19"` と書いたら、
  出る日が決まらないまま 11-20 に前の国の案内へ戻る形になった（#664）。
  同じ事実（いつどの国に入ったか）は国の表がもう持っている

**入れ替わりを、焼いた日で決めない。** 島は静的書き出しなので、面に直に書くと
ビルドした日の国が焼き込まれて、次のビルドまで直らない。
**画面が出てから**今日の日付で選び直す部品を通す（`components/live/GuideLink.tsx`）。
最初の1枚は焼いた日（`BUILT_AT`）で出す——ここで `new Date()` を呼ぶと、
焼いた HTML とブラウザの最初の描画が別の国を指して、1フレームだけ違う札が出る。

日付は **JST で切る。** ブラウザの時間帯で切ると、日本の夜に見ている人と
現地（UTC+2）で見ているあやとで、入れ替わる日が1日ずれる。

## 6. 面を1枚増やす仕事は、面だけではない（7か所）

**7か所ある。** 忘れると CI の見張りが赤くする（配ったあとに `prodsweep.mjs` が拾うものもある）。

| | どこ | 忘れるとどうなるか |
| --- | --- | --- |
| 1 | `site/app/<国>/page.tsx` ＋ `<国>.css` | — |
| 2 | `site/app/sitemap.ts` | 「sitemap.xml に無い」で赤 |
| 3 | `site/content/directory.ts`（`/all` の棚） | 索引から着けない |
| 4 | `site/lib/ogCards.json` ＋ `tools/sprites/ogcards.mjs` の物3つ | 貼ったときの絵が 404 |
| 5 | `site/components/island/layout.ts` の `under` | 砂浜の「いま居る場所」が決まらない（`here_selftest`） |
| 6 | `python/stale_content_watch.py` の `BOOKS` | 「仕分けを決めて足してください」で止まる |
| 7 | `tools/fonts/weights.json`（下の 6-2） | その面だけ端末の書体に落ちる |

**6 の仕分けは「日数で測らない（SKIP）」にする。** 円の数字はレートから出しているので
実勢とは離れていくが、面の頭に取った日を書いてあるので嘘にはならない。
日数で見ると**滞在が終わった日から消しようのない赤**が立つ——行ってしまえば
取り直す理由の無い表なので、誰にも直せない。

**その日が来ると嘘になる字**（`python/text_expires_watch.py`）にも引っかかりうる。
行事の説明に「前年は11月14日に開き、12月21日まで」のような**過去の記録**を書くと
拾われるので、`ALLOW` に理由つきで入れる（鍵は「ファイル＋本文の頭40文字」）。

…と、**字の束**（下）。4つめは `ONLY=<鍵> node tools/sprites/ogcards.mjs` で1枚だけ焼く。
**全部焼くと、触っていない18枚まで差分に出る。**

```bash
ONLY=bulgaria node tools/sprites/ogcards.mjs
```

## 6-2. 字の束を焼き直す（忘れると、その面だけ別の書体になる）

`site/public/fonts/*.woff2` は「島で実際に出てくる字だけ」を切り分けて焼いた丸ゴシック。
切り分けの元は `tools/fonts/weights.json`（面ごと・太さごとに画面に出る字）で、
**面を1枚足したら数え直して焼き直す。** しないと、その面にしか出ない字が
端末の書体に落ちる（`fontbudget_selftest` が赤くなる）。

```bash
tools/build.sh 3130
python3 -m http.server 4130 --directory site/.next-3130 &
DIST=site/.next-3130 SPORT=4130 node tools/sprites/fontweigh.mjs   # 153面を1枚ずつ。20分ほど
python3 tools/fonts/subset.py --export site/.next-3130
```

**`fontweigh` を2本同時に回さない。** どちらも `weights.json` を書くので、
あとから書いたほうが勝つ（1回やって、途中で止めて回し直した）。

**面を1枚足すと、触っていない面が太る。** 束は「どの面で使われるか」が同じ字どうしを
まとめて作るので、字の多い面が増えるとまとめかたが変わって、ほかの面が巻き添えで払う。
ソフィアを足したとき `/nordic/guide` が 850 → 931KB になった。
`fontbudget_selftest` の上限に当たったら、**まず `subset.py --dry --buckets N` を
いくつか当てて、切り分けで直るのかを確かめてから**上限を動かす。

## 7. 出す前に測る6つ

授賞式で作った物差しをそのまま通す。

```bash
tools/build.sh 3130
python3 -m http.server 4130 --directory site/.next-3130 &
DIST=site/.next-3130 SPORT=4130 node tools/sprites/crawl.mjs
```

1. **見切れ0**（`scrollHeight - clientHeight`）
2. **字が「…」で切れている要素 0件**
3. **横スクロールなし**（`documentElement.scrollWidth === clientWidth`）を **1440 と 430 の両方で**
4. **書体が本当に当たっているか**を**幅で測る**。`document.fonts.check` は嘘をつく
   （落ちた書体でも true を返す）。同じ字を `serif` で描いた幅と比べて、違えば当たっている
5. **外の宛先が全部 200 で返るか**（地図・写真）
6. **リンク切れ0**（`crawl.mjs`）

**測るときは開発サーバーを使わない。書き出したものを静的に配る**
（開発サーバーは 3.7GB まで膨らむし、数字が本番と違う）。

## 8. つまずいたところ（同じところで転ばないために）

- **`/** … `app/*/page.tsx` … */`** — JSDoc の中に `*/` を含む道を書くと、
  そこでコメントが終わって構文エラーになる。TypeScript の parse エラーは
  **閉じた位置ではなく、次に出てきた行**を指すので原因が見えない
