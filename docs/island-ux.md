# あやと島 — 情報設計と操作感

この文書は「どこに何があるか」と「押したときに何が返ってくるか」を扱う。
絵の決まりは [`island-design.md`](./island-design.md)、なぜ島なのかは
[`island-concept.md`](./island-concept.md)。**この3つは食い違ってはいけない。**

**1〜3章と8〜10章は測った事実。4〜7章と11〜12章は提案。**
8章から先は、全21面を撮って並べて見たときに足したもの。
世界観（型の割りあて・色の意味・部品の一覧）は
[`island-world.md`](./island-world.md) にある。**この文書と食い違ってはいけない。**

`island-design.md` のほうが拘束力を持つので、ここの提案とぶつかるところは
**先に `island-design.md` を直してから**実装する。直す必要があるものは、
そう分かるように書いてある。

2026年9月5日に測った。`site/app/**` と `site/components/**` は全部読んでいる。
px の数字（高さ・押しどころの大きさ）は、スマホ幅 390×844 の実測。
画面は同時に何人かで直しているので、**px の数字はその日のもの。
数字そのものより、その数字が示している形のほうを見る。**

## 1. いまの形

### 1.1 島と、島の外

トップページは「島のステージ」と「その下に続く4つの章」の二段でできている。
島の外には、同じヘッダーを共有する面が14（うち2つは非公開）と、
その下に詳細ページが約70（料理32・国18・伝説8・型5・アプリ2・北欧6）。

```
/  トップ
├─ 島のステージ（`height: 100svh`。スマホでは1画面まるごと）
│    押せる建物 6
│      これから    テント     → /next
│      たき火広場  たき火     → /about
│      配信やぐら  やぐら     → /streams
│      アプリ工房  工房       → /apps
│      企画掲示板  掲示板     → /board
│      旅の桟橋    道しるべ   → /map
│    押せない建物 3   キッチン小屋 / 伝説の丘 / いまのポスト
│    スマホは下のバーに同じ6つ ＋「島をながめる」
│
└─ 島の下（4章・全体で 5,309px ＝ 6.3画面ぶん）
     これから  NextUp（→ /nordic, /next）＋ 掲示板へ
     いま      /about /streams /apps ＋ 配信の型5つ ＋ /now /friends
     これまで  /map ＋ 国旗18 ＋ 料理12 ＋ /legends
     見にいく  YouTube 2本 ＋ 外部リンク4

島の外（ヘッダーはどのページも同じ6つ）
  /about    あやと島について      ├ /now      いま何してる
                                  └ /friends  愉快な仲間達
  /streams  どんな配信をしてるか  ├ /streams/[型] ×5
                                  ├ /kitchen  クッキング・スタンプ帳 → /kitchen/[品] ×32
                                  └ /legends  伝説の丘 → /legends/[企画] ×8
  /apps     アプリ工房            └ /apps/[アプリ] ×2
  /next     これから              ├ /nordic 北欧ヒッチハイク → /nordic/[国] ×6, /nordic/guide
                                  └ /next/new 企画のページを作る（非公開）
  /board    企画掲示板
  /map      これまでに歩いた17カ国 → /map/[国] ×18
  /design   デザインの見本（非公開）
```

### 1.2 何タップで着くか（スマホ）

島の建物は**押しても入れない**。押すとあやとがそこまで歩くだけで、
ページに入るのは建物の頭の上に立っている札のほう（`IslandStage.tsx` の
`.spot-hit` は `goTo()`、`.spot-mark` だけが `<Link>`）。
下のバーの6つも `goTo()` なので同じ。

| 行き先 | 島から | 島の外のページから（ヘッダー） |
| --- | --- | --- |
| /next /about /streams /apps /board /map | **2タップ**（歩く → 札） | 1タップ |
| /now /friends | 3 | 2 |
| /kitchen /legends | 3 | 2 |
| /nordic | 2（トップを0.9画面スクロール） | 2 |
| /nordic/guide | 3 | 3 |

**島の外のページのほうが、島より速く動ける。** 玄関がいちばん遅い。

### 1.3 実測（390×844）

| ページ | 高さ | リンク | 44px 未満の押しどころ |
| --- | --- | --- | --- |
| `/` | 5,309px（6.3画面） | 61 | **34個**。うち `.spot-mark` 34×34 が6、`.bar-spot` 90×32 が6、`.who-hit` 44×56 が多数 |
| `/about` | 5,522px（6.5画面） | 17 | 7個。`.ih-link` が高さ 40px ×6 |

`island-design.md` は「指で押せる最小 48px」と決めている。
**島の入口も、下のバーも、ヘッダーも、全部それを割っている。**

## 2. 来る人は3種類いる

最初の10秒で何を知りたいか。いまのトップページが、それに答えているか。

### A. はじめて来た人（切り抜きから飛んできた。あやとを知らない）

知りたいのは、この3つだけ。

1. **この人だれ**（顔と、一言）
2. **何が面白いの**（いま見られる1本）
3. **いつやってるの**（毎晩22時）

いま出るのは、島の絵と、右上の小さな看板ロゴ1枚。
h1 は画像で、文字としての自己紹介は 0.9画面ぶんスクロールした先にある。
**「この人だれ」に答えるまでに、スクロールと2タップが要る。**

### B. 常連（今日の配信の前に見に来た）

知りたいのは、

1. **今夜ある?**（22時までの残り）
2. **いまどこ?**
3. **今日なにやる?**
4. **この前の話の続き、どこ?**

1〜3 の答えは全部 `/now`（いまのポスト）にある。
`/now` は島に建物があるのに押せず、パンくずは `島 › あやと島について › いまのポスト`。
**サイトでいちばん毎日書きかわるページが、いちばん奥にある。**

トップを 0.9画面スクロールすれば「いちばん近い企画」は出るが、
「今夜の配信」は 6画面目（第4章「今夜も22時から」）。

### C. 企画に口を出したい人

知りたいのは、

1. **どこに書くの**
2. **書いたらどうなるの**
3. **前に誰かの案は通ったの**

`/board` はこの3つに全部答えている（書く欄 → 3歩の流れ → 「むちゃな企画ほど通る、の証拠」）。
**サイトの中でいちばんよくできている面。** 直すところは少ない。
問題は `/board` に着くまでで、島からは2タップ、
「貼ったものが企画になり、伝説になる」という一周が、`/board` の中でしか見えていない。

## 3. 広い目線 — 骨格の問題

### 3.1 島が、サイトでいちばん遅い入口になっている

建物を押す → あやとが歩く → 札が開く → 札を押す → やっと入る。
札は閉じているとき 34×34px で、しかも `tabIndex={-1}`。
**キーボードだけで島から出ることはできない。**
読み上げでは閉じた札が「!あと1日これからこれから何をするかはいる」と1本につながって読まれる。

`.spot-hit` の `aria-label` は「配信やぐらへ行く」。
だが行かない。歩くだけ。**言っていることとやっていることが違う。**

### 3.2 同じ場所を指す名前が、画面ごとに違う

| 島の札 | ヘッダー | パンくず | h1 | 揃っているか |
| --- | --- | --- | --- | --- |
| たき火広場 | たき火広場 | あやと島について | あやと島について | × |
| 配信やぐら | 配信やぐら | 配信やぐら | どんな配信をしてるか | △ |
| アプリ工房 | アプリ工房 | アプリ工房 | アプリ工房 | ○ |
| これから | これから | これから | これから | ○ |
| 企画掲示板 | 企画掲示板 | 企画掲示板 | 企画掲示板 | ○ |
| 旅の桟橋 | 旅の桟橋 | 旅の桟橋 | これまでに歩いた17カ国 | △ |
| （なし） | — | …› いまのポスト | いま何してる | × |
| （なし） | — | …› 愉快な仲間達 | 愉快な仲間達 | × |
| （なし） | 配信やぐら | …› キッチン小屋 | クッキング・スタンプ帳 | × |

10ページのうち、名前が最後まで揃っているのは3ページ。
`/about` を開くと、ヘッダーで光っているのは「たき火広場」なのに、
見出しは「あやと島について」。**どこに居るのか、画面が2つの答えを出している。**

さらに悪いのは、**「たき火広場」が2つある**こと。
島の札とヘッダーでは `/about`、`/about` の中のタイル
（「たき火広場へ／島に住んでいる人たち、全員」）では `/friends`。
同じ名前で違うところへ行く。

名前そのものにも問題がある。

- **旅の桟橋**（`/map`）は、これまで歩いた国の記録。
  桟橋は「これから出ていく」ものなので、比喩が逆を向いている。
  しかも島に立っている絵は桟橋ではなく道しるべ（`icon: "signpost"`）。
  **名前と絵と中身が三者三様。**
- **たき火広場**（`/about`）は、火のまわりに人が集まっている絵。
  だが中身はあやと1人の紹介。人が集まっているのは `/friends` のほう。
  **比喩が隣のページに付いている。**

比喩が邪魔なのではない。**比喩が中身とずれているのが邪魔。**

### 3.3 「今日のこと」が建物の中に隠れている

島の建物は「そこに行くと何かがある場所」。
だが常連が知りたい「今夜ある?」「いまどこ?」は、行く場所ではなく**いつも出ていてほしいもの**。
建物にすると、押して、歩いて、入って、やっと分かる。

いま `/now` は建物があるのに押せず、`/about` の下にぶら下がっている。
`島 › あやと島について › いまのポスト` という並びは、
「いまどこにいるか」が「あやとの自己紹介」の一部だと言っている。違う。

### 3.4 トップページが、5ページぶんの1画面目のコピーになっている

島の下の4章に並んでいるのは、

- 配信の型5つ → `/streams` の主役
- 最近のごはん12品 → `/kitchen` の主役
- 国旗18 → `/map` の主役
- いちばん近い企画 → `/next` の主役
- YouTubeと外部リンク → `/about` にもある

**行き先のページを開く前に、そのページの1画面目を読ませている。**
だから 6.3画面ぶんになる。しかも同じ6つの行き先が、
島の札・下のバー・章のカード、と**3通りの速さで3回**出てくる。

### 3.5 押せない建物が3つある

キッチン小屋・伝説の丘・いまのポストは、他の建物とまったく同じ描き方で建っていて、
違いは「札が立っているかどうか」だけ。**押せるかどうかを、覚えてもらう前提になっている。**

そしてこの3つのうち2つ（キッチン小屋＝料理32品、伝説の丘＝伝説8つ）は、
このサイトでいちばん見て面白いものが入っている場所。それが島から3タップ。

### 3.6 島の外に出ると、島が消える

`/streams` を開いた瞬間、島は無くなって、木の看板のヘッダーだけになる。
時間帯で変わる空も、あやとも、住人も、そこには居ない。
**島は「トップページの飾り」であって、「このサイトの世界」にはなっていない。**

どうぶつの森は、メニューを開いても島は後ろに見えている。
だから道具箱を開いても「島にいる」感じが切れない。

## 4. 提案する骨格

### 4.1 二層をやめて、三層にする

いまは「島」と「島の外」の二層。ここに**時間の層**を足して三層にする。

```
第0層  いつも出ている（どのページにも、いちばん上に1本）
        今夜22時まで あと2時間14分   ／ 配信中です
        いま ジョージア・トビリシ
        つぎ 北欧ヒッチハイク あと6日
        ── 押すと /now

第1層  島（トップ）
        ステージ … 建物を1タップで入る。歩く時間がそのまま切り替わりの間になる
        島の下は1画面だけ

第2層  場所（10。全部、島に建っていて、全部押せる）
```

**なぜ第0層を足すか。** 常連が来る理由（今夜ある?・いまどこ?・次いつ?）は、
どこかへ行って調べるものではない。**時計と同じで、いつも視界の端にあるべきもの。**
これを1本足すと、`/now` は「奥にある特別なページ」ではなく
「いつも見えている帯の、詳しいほう」になる。

**なぜ島の建物を全部押せるようにするか。**
入口を6つに絞ることで、いま得ているものが無い。
島の上で開いている札はどのみち1つだけ（いちばん近い1つ）なので、
建物が6でも10でも、**画面に出ている文字の量は同じ**。
違うのは、押せない建物が3つあることと、
いちばん見て面白い中身（料理32品・伝説8つ）が3タップ奥にあることだけ。

いま建っているのは9つ。「あやとの家」を1つ足して10にして、全部押せるようにする
（4.3 で、たき火広場が `/about` から `/friends` へ移るぶんの1つ）。

これは `island-design.md` の6章「島の入口は6つ。増やさない」を書き換えることになる。
書き換えるなら、置き換わる決まりはこう:

> **島に建っているものは、全部押せる。押せないものは建物にしない**（木・岩・たき火にする）。
> 増やしたくなったら建物を増やすのではなく、**その建物の中に入れる**。

### 4.2 図

```
どこにいても（第0層）
  ┌────────────────────────────────────────┐
  │ 今夜22時まで あと2:14 ／ いま トビリシ ／ つぎ あと6日 │ → /now
  └────────────────────────────────────────┘

/  島
  ├ ステージ（建物10・全部1タップで入れる）
  │    右上に丸ボタン1つ  … 島をながめる（カメラ。行き先ではない）
  │    下辺に横長ボタン1つ … ここには何がある?（押すと10か所の一覧が下から上がる）
  └ 島の下（1〜1.5画面。これだけ）
      ├ はじめまして（顔・3行・今夜の1本）        ← はじめて来た人のため
      ├ 今夜と、いちばん近い企画                  ← 常連のため
      └ 島に何があるかの一覧（10行）             ← 歩きたくない人のため

島に建っているもの
  あやとの家     /about     あやとって、どんな人
  たき火広場     /friends   島の住人と、キャラクターの作り方
  配信やぐら     /streams   配信は5つの型
      └ /streams/[型] ×5
  キッチン小屋   /kitchen   作った料理のスタンプ帳
      └ /kitchen/[品] ×32
  伝説の丘       /legends   語り継がれてる企画
      └ /legends/[企画] ×8
  アプリ工房     /apps      なに食べよ／なにこれ
      └ /apps/[アプリ] ×2
  いまのポスト   /now       いまどこ・今週やること
  これから       /next      次にやること
      └ 大きい企画は専用ページ /nordic → /nordic/[国], /nordic/guide
  企画掲示板     /board     自分も企画を出せる
  たびの道しるべ /map       これまでに歩いた17カ国
      └ /map/[国] ×18
```

**なぜこの形なのか。** 2章の3人に、それぞれ別の層が答えるようにしてある。

| 来る人 | 最初に見るもの | どの層か |
| --- | --- | --- |
| はじめて来た人 | 島の上の名刺（4.5）→ 島の下の「はじめまして」 | 第1層の1画面目 |
| 常連 | 帯（今夜・いまどこ・つぎ） | 第0層。**どこを開いても、開いた瞬間** |
| 口を出したい人 | 企画掲示板の建物（島から1タップ） | 第2層 |

いまは3人とも同じもの（島の絵と、その下の6.3画面）を見せられていて、
**3人とも、自分の知りたいことが載っている場所を自分で探させられている。**

ページの数は減らさない。**12の面は多くない。** どれも中身がある。
減らすべきなのはページではなく、**トップページに置いてある「行き先ページの予告編」**のほう。

ただし1つだけ、位置を変える。**`/now` の親を `/about` から島の直下へ移す。**
`/friends` も `/about` の下から島の直下へ移す（たき火広場になるので）。

### 4.3 名前

決まりを1つだけにする。

> **1つの場所には1つの名前。島の札・ヘッダー・パンくず・h1 が、同じ文字列になる。**
> 説明は h1 の**すぐ下の1行**に置く。
> `<title>`（検索とタブに出るもの）だけは説明的でよい。

| 場所 | 画面に出す名前 | すぐ下の1行 | `<title>` |
| --- | --- | --- | --- |
| /about | あやとの家 | あやとって、どんな人 | あやとについて｜あやと島 |
| /friends | たき火広場 | 島に住んでいる人たち | 愉快な仲間達｜あやと島 |
| /streams | 配信やぐら | 配信は5つの型でできてる | どんな配信をしてるか｜あやと島 |
| /kitchen | キッチン小屋 | 作ってきた料理のスタンプ帳 | クッキング・スタンプ帳｜あやと島 |
| /legends | 伝説の丘 | いまも話に出てくる企画 | 伝説の丘｜あやと島 |
| /apps | アプリ工房 | 旅先で作っているアプリ | アプリ工房｜あやと島 |
| /now | いまのポスト | いまどこにいて、今週なにをするか | いま何してる｜あやと島 |
| /next | これから | 次に行くところ、次にやること | これから｜あやと島 |
| /board | 企画掲示板 | こういうことやってほしい、を貼る | 企画掲示板｜あやと島 |
| /map | たびの道しるべ | これまでに歩いた17カ国 | 歩いた17カ国の地図｜あやと島 |

**この2つは、検討したうえで「変えない」と決めた。**（判断: プロジェクトリーダー）

- **`/map` は「旅の桟橋」のまま。** 島には実際に桟橋が描いてあり（`IslandScene.tsx`）、
  ページの顔も桟橋の杭とロープ（`atlas.css` / `art.tsx` の `PierArt`）。
  小さい印が道しるべなのは、**桟橋のたもとに道しるべが立っている**ので矛盾しない。
  むしろ 24〜48px では、桟橋より道しるべのほうが形が読める。
  この名前は住人のセリフを含めて20か所に入っていて、変える利より手間が大きい。
- **`/about` は「たき火広場」のまま。** 「あやとの家」にすると建物の絵を描き替え、
  たき火を `/friends` へ移すことになるが、`/friends` にはすでに「仲間のテント」がある。
  火を囲んでこの人の話を聞く、で筋は通っている。

**名前と絵が食い違っているものは直す。食い違っていないものは、より良い名前を思いついても変えない。**
名前は住人のセリフ・パンくず・見出し・島の札に散っているので、
変えるたびに「どこかだけ古い」を作る危険のほうが大きい。

### 4.4 トップページ

いまの4章（5,309px）を、こうする。

```
島のステージ
──────────────
はじめまして
  顔 ／ 「毎晩22時、世界のどこかから生配信。旅しながらグルメアプリを作っています」
  ／ 今夜の1本（YouTube のサムネ1枚）      ← はじめて来た人はここで足りる
──────────────
今夜と、いちばん近い企画
  今夜22時まで あと2:14 ／ 北欧ヒッチハイク あと6日（NextUp をそのまま）
──────────────
島に何があるか
  10行の一覧。名前 ＋ すぐ下の1行 ＋ 数字（32品 / 17カ国 / 8つの伝説…）
  歩きたくない人・読み上げの人・PCの人のための、正直な目次
──────────────
```

**消すもの**（行き先のページに帰す）:
配信の型5つのカード列 → `/streams` へ。最近のごはん12品 → `/kitchen` へ。
国旗18 → `/map` へ。外部リンクの列 → フッターと `/about` へ。

1.5〜2画面になる。**6.3画面が2画面になって、失われる情報は無い。**
どれも行き先のページの1画面目に、もっと良い形で置いてある。

### 4.5 島の上に、最初の1回だけ名刺を出す

いまの到着演出（カモメについて空から降りる・3秒）は、
きれいだが**何も言っていない**。切り抜きから来た人はここで3秒待たされて、
そのあと島の絵だけを見る。

同じ3秒で名刺を出す。

```
   ┌──────────────────────┐
   │  （顔）  あやと                       │
   │  毎晩22時、世界のどこかから生配信。   │
   │  旅しながらグルメアプリを作っています。│
   │                                        │
   │  [ 今夜の配信を見る ]  [ 島に降りる ]  │
   └──────────────────────┘
```

- 画面を塞がない。島の下から3分の1に置く
- どこを押しても、どちらかを押しても消える
- 一度消したら二度と出ない（`localStorage`）
- 消えるときは、そのまま第0層の帯に吸い込まれる。
  **「さっき見たものが、上の帯になった」**と分かる形にする

### 4.6 島を、島の外でも消さない

3.6 の答え。島を全ページの背景に置くのがいちばん正しいが、
`IslandStage` はスプライト 160枚を毎フレーム動かすので、
**全ページに置くと全ページが重くなる。** それはやらない。

代わりに、島の**痕跡を3つ**だけ残す。どれも安い。

1. **空の色を、全ページで共有する。**
   いま `IslandTheme` が `<html data-time>` に朝・昼・夕・夜を入れていて、
   島の空だけがそれを見ている。**ページの地の色もこれを見るようにする。**
   夜に開いたら、島の外のページも夜の色。「同じ島の中にいる」がこれで半分は出る。
2. **第0層の帯を、木の看板ではなく「島の空」の上に置く**（4.1）。
   ヘッダーが海と空の続きに見える。
3. **フッターに、島の砂浜の帯を1本。**
   ページの終わりが「島に戻ってきたところ」になる。
   いまの「島にもどる」ボタンが、そこに立っている看板になる。

## 5. 狭い目線 — 1画面ずつ潰すもの

### 5.1 島（トップの1画面目）

- **下のバーの名前が読めない。** 390px で6つ並べると
  「これ…」「たき火…」「配信や…」「アプリ…」「企画掲…」「旅の桟橋」。
  6つのうち5つが切れている。**行き先の名前が読めないナビゲーションは、無いのと同じ。**
- **バーの中でいちばん目立つのが「島をながめる」。** 唯一の青いボタンで、
  他の6つより大きい。だがこれは行き先ではなくカメラの操作。
  **一等地を、行き先でないものが取っている。**
- そもそも、建物が1タップで入れるようになれば（7章の1）、
  **バーは島の複製でしかない。** 6つを2回出す必要はない。
  → バーをやめて、こうする。

  ```
  島の右上   ◎ 島をながめる            （丸ボタン1つ。カメラの操作はここだけ）
  島の下辺   ここには何がある?（10か所）  （押すと一覧が下から上がる）
  ```

  一覧のシートには、10か所を **名前 ＋ 何があるかの1行 ＋ 数字**（32品 / 17カ国 /
  8つの伝説）で並べる。押すと直接そのページへ。名前は切れない。
  これは 4.4 でトップの下に置く「島に何があるか」と**同じ部品を使い回す**。
  歩きたくない人・読み上げの人・PCの人は、島の絵を通らずにここから行ける。
- **押しどころが 48px を割っている。** `.spot-mark` 34×34、`.bar-spot` 90×32。
  `island-design.md` が決めた最小を、島そのものが守っていない。
- **「押したところまで歩いていくよ」が画面の真ん中に出る。**
  最初に読ませたいのは「建物を押すと中に入れる」のほう。
  歩けることは、押したときに歩き出せば分かる。
- **スマホでは、島の下に続きがあることを知らせるものが1つも無い。**
  `.stage` は `height: 100svh`（`app/css/tokens.css`）で画面いっぱい。
  下のバーが 98px（`--bar-h`）を占めて、そのすぐ下がページの折り返し。
  そして `.scroll-cue`（「島の外も見てみる」）は `display: none` で、
  `min-width: 640px` でしか出ない（`app/css/pages.css:856`）。
  **スマホで来た人にとって、このサイトは「島の絵1枚」で終わっている。**
  トップページの 5,309px のうち、下の 4,400px あまりが、存在を知らされていない。
  → 4.4 でトップを2画面に削ったうえで、島の下辺から次の面が
  20〜30px だけ覗いている状態にする。「めくれている紙の角」が、
  文字の案内より確実に効く。

### 5.2 どのページにも共通（`PageShell` / `PageHead`）

- **見出しの前置きが3段ある。** 絵（96px）→ h1 → lead → カモメのひとこと。
  `/about` では最初の中身が出るまでに 470px、スマホの1画面の 56% を使う。
  カモメは「ここでどう遊ぶか」だけを言う決まりだが、
  `/about` の「あやとが何者なのかは、この面でひととおり分かるよ」は
  lead の言い直しになっている。
  → **絵・h1・1行**の3つまで。カモメは、その面に**遊び方がある面だけ**に出す
  （`/board` `/next` `/kitchen` `/map`）。読むだけの面には要らない。
- **ヘッダーの6つのうち3つが画面の外。** `.ih-nav` は横スクロールで、
  端をぼかしてあるだけ。390px では「これから／たき火広場」までしか見えない。
  高さも 40px で 48px を割る。
  行き先が10になったら、この形はもっと破綻する。
  → スマホのヘッダーは**3つだけ**にする。

  ```
  [ 島にもどる ]   いま：キッチン小屋   [ ほかの場所 ]
  ```

  「ほかの場所」を押すと、5.1 と同じ**10か所の一覧のシート**が下から上がる。
  一覧の部品は1つ作って、**島の下辺・トップページ・ヘッダーの3か所で使い回す。**
  行き先が増えても減っても、直すのは1か所。
- **戻る導線が「島にもどる」1つだけ**（フッター）。
  6.5画面ぶんスクロールした先にある。
  → 上のヘッダーの左端に、常に「島にもどる」を置く。
- **押せるものと押せないものが、同じ形をしている。**
  `.chip`（押せない・数や状態の札）と `.chip.link`（押せる・行き先）は
  ほぼ同じ見た目で並ぶ（`/apps` の「開発中」「2 の節目」と、
  `/board` の「イランまで12日間歩いた」）。
  `ac-reference.md` の決まりは「厚みを付けるのは押せるものだけ」。
  → 押せるチップにだけ下の厚みと矢印を付け、押せないチップは完全に平らにする。
  **この2つが同じ画面に並ぶことは多いので、違いは遠目に分かる大きさで付ける。**

- 5,522px（6.5画面）。パネルが6枚、全部同じ形・同じ間隔で縦に積んである。

## 6. 操作感 — 音のかわりに何を返すか

どうぶつの森は「押した音」で成り立っている。音が出せないので、**動きで返す。**
決まりは1つ。

> **押したものは、押した瞬間（0秒）に形が変わる。
> そのあと何が起きるかは、100〜300ms のあいだに見せる。**

### 6.1 いま返せていないもの

| 押すもの | いま | どうする |
| --- | --- | --- |
| 島の建物（`.spot-hit`） | **何も返らない**。数百ms後にあやとが歩き出すだけ | 押した瞬間に建物が沈む（`scale(1.06, .94)`）。足元に輪が1つ広がる |
| 下のバー（`.bar-spot`） | 沈む（`:active`）が、そのあと歩くだけ | 沈む → そのまま入る |
| 住人（`.who-hit`） | 何も返らない。歩いていって、着いたら吹き出し | 押した瞬間に相手が「!」で跳ねる。歩き出したことが分かる |
| ページの切り替わり | 白く消えて、次が出る | 島の空の色で1枚かぶせて渡す（`View Transitions`。効かない端末では何もしない） |
| 折りたたみ（`Fold`） | 開閉が瞬間。高さが飛ぶ | `interpolate-size: allow-keywords` ＋ `::details-content` の高さを 180ms で送る |

### 6.2 歩く時間を、切り替わりの時間にする

建物を1タップで入れるようにする、と書いた。ただし**歩くのをやめない。**

```
押す → その瞬間に建物が沈む
     → あやとが走り出す（遠いところは速く走る。どこでも 800ms 以内で着く）
     → 走っているあいだに、次のページを読み込んでおく（next/link の prefetch）
     → 着く → 扉が開く（建物が一瞬だけ大きくなる）→ ページに入る
```

これで、

- タップは1回になる
- 歩く楽しさは残る
- **待ち時間が消える。** 走っている 800ms が、そのまま読み込みの時間になる
- 途中でどこかを押せば止まる（気が変わったときに逃げられる）

### 6.3 帰ってきたとき、出ていった場所に立っている

いま `/streams` から島に戻ると、あやとは初期位置（`AYATO_HOME`）に瞬間移動している。

→ 入るときに、どの建物から入ったかを `sessionStorage` に覚えておく。
戻ってきたら**その建物の前に、外を向いて立っている**。札は開いた状態。
カメラもそこに合っている。

これ1つで「島の外に行っていた」が「建物に入って出てきた」になる。
**世界が続いている感じは、ほとんどこれで作れる。**

### 6.4 注目させるのは一度に1つ、を守る

いま島の上で同時に動いているもの: 札の跳ね（`spotHop` 2.8秒ループ）×6、
開いた札の揺れ（`signSway`）、日数バッジの揺れ、建物の弾み（`spotBob`）、
住人の呼びかけ（`is-calling`）、木の揺れ。

**6つの札が全部いつまでも跳ねているのは、合図ではなく背景になっている。**
→ 跳ねるのは**いちばん近い1つだけ**。他の5つは静かな丸のまま。
「動いているものが押すところ」という読み方が、そこで初めて成り立つ。

### 6.5 スクロールの引っかかり

- 島（`.hero`）の上で縦に指を動かすと、ページが動く。これは正しい。
  ただし島は「歩く場所」でもあるので、**縦に払ったのか、地面を押したのかの区別**が要る。
  いまは `onClick` なので、払っても歩かない。正しい。**このまま変えない。**
- `.ih` は sticky。`.island-bar` は島の下辺に固定。
  島から下へ抜けるとき、バーが消えてヘッダーが出る、という交代が起きる。
  第0層の帯を入れると、**この交代をやめられる**（帯はずっと同じ位置に居る）。

### 6.6 「ゲーム性」を足すとき、足していいものと、足してはいけないもの

ここは留守番の場所。**来た人に宿題を出さない。**
点数・レベル・連続ログイン・「あと3つで達成」は付けない。
それを付けた瞬間、島は「毎日来ないと損する場所」になる。配信の空気と正反対になる。

足していいのは、**来るたびに違うものが見える**という一点だけ。

- **時間で変わるものを、もっと見えるようにする。**
  いま空の色だけが時間で変わる（`IslandTheme` の `data-time`）。
  夜だけ灯る窓、朝だけ出る鳥、雨の日の水たまり。
  「別の時間に来ると、別のものが見える」は、宿題を出さずに「また来る理由」になる。
- **住人に、今日という日を持たせる。**
  いま住人のセリフは 9秒ごとに入れ替わるだけ。
  1日ひとり「今日よく喋る住人」を決めて（日付から決める。乱数にしない）、
  その人だけ長めに話す。**毎日同じでも、毎日違ってもいけない。**
- **見た数を、押しつけずに数える。**
  `/kitchen` は32品ある。どうぶつの森のいきもの図鑑と同じで、

## 12. キーボードと、読み上げ

3.1 で「キーボードだけで島から出られない」と書いた。その先。

| 何 | いま | どうする |
| --- | --- | --- |
| 島の札 | `tabIndex={-1}`。**タブが当たらない** | `.spot-hit` を `<Link>` にすれば自然に当たる |
| 閉じた札の読み上げ | 「!あと1日これからこれから何をするかはいる」と1本につながる | 札の中の飾り（`!`・日数）に `aria-hidden` |

| 行き先の一覧 | 島の絵の中にしか無い | 5.1 の「ここには何がある?」のシートが、そのまま読み上げの目次になる |
| フォーカスの輪 | `3px solid var(--accent-2)` | **これは正しい。** 生成りの地でも見える |
| 見出しの段 | h1 → h3 に飛ぶ面がある（`.sub` が h3） | h2 を挟む |

**5.1 の「10か所の一覧のシート」は、見た目のためだけの提案ではない。**
島の絵を通らずに全部の行き先へ行ける道が1本あることが、

1つの部品で4人ぶん直る。**これが、この文書でいちばん割のいい提案。**
