# あやと島カード

**これは仕様である。** その日に投げ銭してくれた人へ、その日の写真が1枚ずつ渡る。
[`nordic-photos.md`](./nordic-photos.md) の写真の上に成り立っているので、そちらも読む。

**#202 で組み立ての元が変わった。** 北欧の名前（`nordicPhotos` /
`nordicDays`）から切り離して、企画に寄せてある。データの形は
[`island-db.md`](./island-db.md) に書いた。

---

## 1. 何をするものか

**その日の配信で投げ銭してくれた人が、その日の写真をもらう。**
あやとの言葉:「焼き込みをしようがしまいがあやと島カードはゲットした扱いになります。」

写真の上に、その人のキャラクターが1体立っている。それだけ。
順位でも点数でも称号でもなく、**その日そこにいたという事実だけ**が残る
（`nordic-photos.md` 2章と同じ考え方）。

もらったカードは、じぶんのこと（`/me`）に**勝手に増えていく**。
「もらう」を押す場所はどこにも無い。

## 2. カードは、企画・画像・台帳の3つから作られる

**ここがこの機能の芯。**

```
カード = その企画のカード画像（islandStreamEventImage の role: "card"）
       × その企画に当たる投げ銭（islandTips）
```

### なぜ台帳に変えたか

前は**引くたびに組み立てていた**。写真（`nordicPhotos`）とその日の名簿
（`nordicDays.people`）を掛け合わせて、その場で作っていた。**名簿が
BigQuery から翌朝にしか入らなかった**ので、「写真を貼ったら、その日の人ぶん
カードを作って置く」にすると、貼った夜のぶんが永久に0枚になったから。

台帳（`islandTips`）にして、その理由が消えた。**投げ銭は投げられた
その日に台帳へ入る。** だから貼った時点でもう相手がいる。

置いてあると、`orderBy("earnedAt")` と `where("channelId","==",…)` で
引ける。**どちらも単一フィールドなので索引が要らない**（#168）。

### 2か所から作る。どちらが先でも同じ結果

| いつ | 誰が |
| --- | --- |
| 画像を貼ったとき | `functions/src/streamEvents.ts` の `mintForImage` |
| 毎日 | `python/island_cards.py` |

片方だけだと、「画像が先で投げ銭が後」の日か「貼った夜」のどちらかが
空になる。**置き方（`x/y/rot/scale`）には触らない。**
触ると本人が動かしたカードが元に戻る。

| 何 | どこから |
| --- | --- |
| カードのID | `<画像のID>__<チャンネルID>`。決め打ちなので、2か所から作っても同じ書類になる |
| 置き方の既定値 | IDから決まる（`defaultPlace`）。毎回同じ場所に立つ。**式は TypeScript と Python で同じ**（片方だけ変えると、貼った日と翌朝で置き方が変わる） |

置き方は `x` `y` `rot` `scale`（あやとの「理想はXY軸、回転、拡大などを
もってほしい」）。`x` `y` は画像に対する 0〜1 の割合で、`y` は**足元**の
高さ。焼いた絵は置き場に持たない。同じ画像に何人も乗るので、焼くと
同じ画像を人数ぶん置くことになる。

既定値の芯は**見本の右下**（`nordic-photos.md` 5章）。そこから ID で
少しだけ散らす。同じ画像に何人も乗るとき、全員が寸分たがわず同じ場所に
立つと、並べたときに「同じ絵が人数ぶん」に見えるため。

### 企画と配信は N:N

**1本の配信に企画が何本も乗る。** 9月11日の配信は「北欧旅の出発日」
「海外出発二周年」「ジョージアバイバイ」の3本を兼ねている
（あやと・2026-09-07）。

だから「`videoId` → その配信の企画」を**1本に決めない。**
当たった企画すべてについて、その企画のカード画像ぶんカードを作る。
9/11 に投げてくれた人は、**3企画それぞれのカード写真ぶん**もらう。
カードIDは画像のIDを含むのでぶつからない。

当たり方は2つあって、**両方を足す**（片方で打ち切らない）。

1. その企画が `videoIds` でこの配信を名乗っている
2. 企画の日付と、投げ銭の日（**日本時間**）が同じ

**1で当たったら2を見ない、にしない。** あやとが `videoIds` を足すのは
たいてい1本だけなので、そこで打ち切ると残りのカードが黙って消える。
消えたことは画面に出ないので、誰も気づけない。

### 配信日の境目は日本時間の0時

旧来は9時間引いていた（＝日本時間の18時が境目）。旅で時差が9回変わると
そのたびに1日が2つに割れる（#201）。境目は
`DATE(donated_at, "Asia/Tokyo")` に固定して、**またいだぶんは人が決める。**
0時をまたいで配信が2本に割れたら、後半の動画IDを
`islandStreamEvent.videoIds` に足す（`/me` から打てる）。

## 3. 誰のカードか

台帳は YouTube のチャンネルIDを持つ。ログインしている人とは
`islandUsers/{uid}.channelId` で結び付く。**自分のカードとは、自分のチャンネルIDのカード。**

**チャンネルIDの無い投げ銭には、カードを作らない**（#202）。Doneru は
`viewer_pk`（どねID）しか持っていないので、`islandDonors` の対応表を
通してチャンネルIDに直す。紐付いていない人は台帳には残るがカードは
渡らない。**勝手に誰かのものにしない。**

紐付けは `/me` の「投げ銭を、YouTube につなぐ」から打てる（#190）。
打った翌日の日次ジョブでカードができる。

（前は「絵（`icon`）だけ持っていて持ち主の分からないカード」があった。
名簿に手で足された人のぶん。台帳に移して、その形は無くなった。）

キャラクターの絵をチャンネルに結び付けるのは `site/content/residents.ts` だけ。
**サーバーは絵を知らない**（絵の割り当てが2か所に散らないようにするため。
`python/build_residents.py` の頭に同じ話がある）。絵に結びつかない人のカードは、
画面に出ない。「あなたのキャラクターがありません」とは言わない。

## 4. どこに出るか

| どこ | 何を |
| --- | --- |
| `/cards` | 配られたカードぜんぶ。新しい順。面の名前は「あやと島カード」 |
| `/about` の「住んでる人」の下 | 最近の2枚と、`/cards` への札 |
| `/friends` | 図鑑の1枚の中に、その人のもらったカード |
| `/me` | 自分のカードが勝手に増えていく |

**URL は `/cards`。** 日本語の URL は貼ると `%E3%81%82…` に化けるので、
「あやと島カード」は面の名前としてだけ出す。

カード1枚には**その日の企画**も出す（あやとの「フードワインフェスの企画に紐つけて欲しい」）。

> **#202 でここは変わった。** カードは `streamEventId` を持つ。
> 日付から引いてもよいが、**1日に企画は何本でも立つ**ので
> `PLAN_BY_DAY` は配列を返す。以下は日付だけで引いていたころの説明。
`content/plans.ts` の `date` が写真の `day` と同じ形なので、そのまま引ける
（`PLAN_BY_DAY`）。長い企画（`until` を持つもの）は始まった日にしか付かない。
旅の写真ぜんぶに同じ名前が並ぶと、何も言っていないのと同じになるため。

## 5. 動かす

置き方を動かせるのは**本人だけ**（`POST /cards/{cardId}`）。あやとは全部動かせる。
自分のカードかどうかは、送られてきた値ではなく `islandUsers/{uid}.channelId` で決める。

**動かす画面はまだ無い。** 口と持ち方だけが先にある。
