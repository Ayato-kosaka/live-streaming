# あやと島カード

**これは仕様である。** その日に投げ銭してくれた人へ、その日の写真が1枚ずつ渡る。
[`nordic-photos.md`](./nordic-photos.md) の写真の上に成り立っているので、そちらも読む。

**#202 で組み立ての元が変わった。** 北欧の名前（`nordicPhotos` /
`nordicDays`）から切り離して、企画に寄せてある。データの形は
[`island-db.md`](./island-db.md) に書いた。

---

## 1. 何をするものか

**その日の配信で投げ銭してくれた人が、その日の写真をもらう。**
あやとの言葉:「焼き込みをしようがしまいがあやと島カードはゲットした扱いになります。」

写真の上に、その人のキャラクターが1体立っている。それだけ。
順位でも点数でも称号でもなく、**その日そこにいたという事実だけ**が残る
（`nordic-photos.md` 2章と同じ考え方）。

もらったカードは、じぶんのこと（`/me`）に**勝手に増えていく**。
「もらう」を押す場所はどこにも無い。

## 2. カードは、企画・画像・台帳の3つから作られる

**ここがこの機能の芯。**

```
カード = その企画のカード画像（islandStreamEventImage の role: "card"）
       × その企画に当たる投げ銭（islandTips）
```

### なぜ台帳に変えたか

前は**引くたびに組み立てていた**。写真（`nordicPhotos`）とその日の名簿
（`nordicDays.people`）を掛け合わせて、その場で作っていた。**名簿が
BigQuery から翌朝にしか入らなかった**ので、「写真を貼ったら、その日の人ぶん
カードを作って置く」にすると、貼った夜のぶんが永久に0枚になったから。

台帳（`islandTips`）にして、その理由が消えた。**投げ銭は投げられた
その日に台帳へ入る。** だから貼った時点でもう相手がいる。

置いてあると、`orderBy("earnedAt")` と `where("channelId","==",…)` で
引ける。**どちらも単一フィールドなので索引が要らない**（#168）。

### 2か所から作る。どちらが先でも同じ結果

| いつ | 誰が |
| --- | --- |
| 画像を貼ったとき | `functions/src/streamEvents.ts` の `mintForImage` |
| 毎日 | `python/island_cards.py` |

片方だけだと、「画像が先で投げ銭が後」の日か「貼った夜」のどちらかが
空になる。**置き方（`x/y/rot/scale`）には触らない。**
触ると本人が動かしたカードが元に戻る。

| 何 | どこから |
| --- | --- |
| カードのID | `<画像のID>__<チャンネルID>`。決め打ちなので、2か所から作っても同じ書類になる |
| 置き方の既定値 | IDから決まる（`defaultPlace`）。毎回同じ場所に立つ。**式は TypeScript と Python で同じ**（片方だけ変えると、貼った日と翌朝で置き方が変わる） |

置き方は `x` `y` `rot` `scale`（あやとの「理想はXY軸、回転、拡大などを
もってほしい」）。`x` `y` は画像に対する 0〜1 の割合で、`y` は**足元**の
高さ。焼いた絵は置き場に持たない。同じ画像に何人も乗るので、焼くと
同じ画像を人数ぶん置くことになる。

既定値の芯は**見本の右下**（`nordic-photos.md` 5章）。そこから ID で
少しだけ散らす。同じ画像に何人も乗るとき、全員が寸分たがわず同じ場所に
立つと、並べたときに「同じ絵が人数ぶん」に見えるため。

### 企画と配信は N:N

**1本の配信に企画が何本も乗る。** 9月11日の配信は「北欧旅の出発日」
「海外出発二周年」「ジョージアバイバイ」の3本を兼ねている
（あやと・2026-09-07）。

だから「`videoId` → その配信の企画」を**1本に決めない。**
当たった企画すべてについて、その企画のカード画像ぶんカードを作る。
9/11 に投げてくれた人は、**3企画それぞれのカード写真ぶん**もらう。
カードIDは画像のIDを含むのでぶつからない。

当たり方は2つあって、**両方を足す**（片方で打ち切らない）。

1. その企画が `videoIds` でこの配信を名乗っている
2. 企画の日付と、投げ銭の日（**日本時間**）が同じ

**1で当たったら2を見ない、にしない。** あやとが `videoIds` を足すのは
たいてい1本だけなので、そこで打ち切ると残りのカードが黙って消える。
消えたことは画面に出ないので、誰も気づけない。

### 配信日の境目は日本時間の0時

旧来は9時間引いていた（＝日本時間の18時が境目）。旅で時差が9回変わると
そのたびに1日が2つに割れる（#201）。境目は
`DATE(donated_at, "Asia/Tokyo")` に固定して、**またいだぶんは人が決める。**
0時をまたいで配信が2本に割れたら、後半の動画IDを
`islandStreamEvent.videoIds` に足す。

足すのは `/me` の**旅の道具 → その日の配信**（`components/me/PlanVideos.tsx`）。
**YouTube の URL をそのまま貼れる**（スマホで11文字を打たせない）。口
（`POST /nextplans/{id}/videos`）は**送った一覧でまるごと置き換える**ので、
画面はいま入っているものを先に出してから送る。

## 3. 誰のカードか

台帳は YouTube のチャンネルIDを持つ。ログインしている人とは
`islandUsers/{uid}.channelId` で結び付く。**自分のカードとは、自分のチャンネルIDのカード。**

**チャンネルIDの無い投げ銭には、カードを作らない**（#202）。Doneru は
`viewer_pk`（どねID）しか持っていないので、`islandDonors` の対応表を
通してチャンネルIDに直す。紐付いていない人は台帳には残るがカードは
渡らない。**勝手に誰かのものにしない。**

紐付けは `/me` の「投げ銭を、YouTube につなぐ」から打てる（#190）。
打った翌日の日次ジョブでカードができる。

（前は「絵（`icon`）だけ持っていて持ち主の分からないカード」があった。
名簿に手で足された人のぶん。台帳に移して、その形は無くなった。）

キャラクターの絵をチャンネルに結び付けるのは `site/content/residents.ts` だけ。
**サーバーは絵を知らない**（絵の割り当てが2か所に散らないようにするため。
`python/build_residents.py` の頭に同じ話がある）。絵に結びつかない人のカードは、
画面に出ない。「あなたのキャラクターがありません」とは言わない。

### アイコンは2つある。混ぜない

| | 何 | どこが正 | どこに出る |
| --- | --- | --- | --- |
| キャラクター | ハリネズミなどの絵 | あやとのスプレッドシート（`site/content/residents.ts` に焼く） | **カードの上**、`/friends`、`/me` の「島にいる、じぶん」 |
| プロフィール写真 | YouTube のアイコン | `islandChannels.photo`（`python/island_channel_photos.py` が日次で入れ直す） | `/me` の見出しの隣の顔 |

**キャラクターは YouTube を更新しても変わらないのが正しい。**
あやとが割り当てたものなので。プロフィール写真は逆に、
**替えたら替わらないと困る**（古くならないように日次で入れ直している）。

画面（`components/me/MyPage.tsx`）は顔を `me.channelPhoto` から引く。
無いあいだは `me.photo`（ログインした日のまま止まる）へ落ちる。
**顔が消えるよりは、少し古い顔が出ているほうがいい。**

> **`POST /me` はまだ `channelPhoto` を返していない。** 置き場
> （`islandChannels.photo`）には入っているが、そこを読む口がどこにも無い
> （`firestore.rules` でこのコレクションは閉じてある。2,200人の名簿になるため）。
> 口が付いた日に画面はそのまま新しいほうへ切り替わる。

## 4. どこに出るか

| どこ | 何を |
| --- | --- |
| `/cards` | **写真ぜんぶ。日ごとに1枚の紙。並ぶのは素の写真。** 面の名前は「あやと島カード」 |
| `/about` の「住んでる人」の下 | 最近の写真2枚と、`/cards` への札 |
| `/friends` | 図鑑の1枚の中に、その人のもらったカード |
| `/me` | 自分のカードが勝手に増えていく |

**URL は `/cards`。** 日本語の URL は貼ると `%E3%81%82…` に化けるので、
「あやと島カード」は面の名前としてだけ出す。

### 旅の写真（`/nordic/photos`）は、ここへ寄せた（2026-09-10）

あやとの言葉:

> https://.../nordic/photos のルーティングがおかしい。（略）
> そもそもこの画面入らなくて cards に統合すべきでは？
> /nordic/photos のUXの方がわかりやすいから統合して欲しい

**同じ写真の同じ人を、2つの面が別々の言い方で出していた。**
`/nordic/photos` は「写真を見て、誰かを入れて持って帰る」、`/cards` は
「配られた枚数を眺める」。やることは1つなのに、入口が2つあった。

**寄せ先を `/cards` にしたのは、写真が旅より長く残るから。**
`/nordic/photos` は「これから › 北欧ヒッチハイク › 旅の写真」の下にいて、
旅が終わると入口ごと過去の話になる。カードは島の常設で、`/about`・
`/friends`・`/me` の3か所から来る。

**手ざわりは写真の側に寄せた**（あやとの「UXの方がわかりやすい」）。
日ごとの紙・素の写真のマス・押すと大きく出て入れる人を選ぶ、まで同じ。

| もとの `/nordic/photos` | いまの `/cards` |
| --- | --- |
| 日ごとに1枚の紙、素の写真のマス | そのまま |
| 押すと大きく出て、入れる人を選ぶ | そのまま（`CardSheet`） |
| 「入れない」も同じ並びの1マス | そのまま |
| 「ほぞんする」で持って帰る | そのまま。**入れても入れなくても同じ1つ** |
| あやとだけ、写真を貼れる | そのまま（面のいちばん上） |
| その日の企画への札が無かった | **足した**（紙の見出しと、開いた先の底） |

`/nordic/photos` は**面ごと消さない。** `output: "export"` なので消すと
`dist` からファイルが消え、Firebase の受け皿（`"source": "**"`）が
**島の玄関を 200 で返す。** 404 にすらならないので、貼られた URL を踏んだ人は
なぜ違う面が出たのか分からない。301 で `/cards` へ送る
（`firebase.json` の `redirects` と、控えの `app/nordic/photos/page.tsx`）。

### 一覧に並ぶのは、カードではなく写真

**カードは「写真 × その日に投げてくれた人」で増える。** 写真が3枚あって10人が
投げれば30枚になり、同じ写真が10枚ずつ、同じ日付と同じ企画の札を連れて並ぶ。
あやとの言葉（2026-09-09）:「埋め込みキャラクターごと全部表示するのではなく、
カード画像を列挙してタップしたらキャラクター埋め込み版が見れるようにしないと、
カード一覧画面が散らかる気がする」。

だから一覧は**写真1枚につき1マス**にする。

**マスに代表の1人を埋めない**（あやと・2026-09-10「代表でキャラクターを
埋めるのはやめて欲しい」）。マスは素の写真で、**開いた先もはじめは素の写真。**
4人ぶんあるカードの1人目を出すと、その人がその写真の代表のように見える。

### 写真の口とカードの口の、両方を読む

一覧の土台は**写真の一覧**（`GET /nordic/photos`）で、そこへカードを重ねる
（`components/cards/cards.ts` の `useCardWall`）。カードだけを見ていると
**まだ誰も投げていない写真が1枚も出ない。** あやとが貼った直後がちょうど
それで、貼った本人が「入らなかった」と思う。
片方が読めなくても、もう片方のぶんは出る。

### 持って帰る

開いた先に出ているのは、**合成したあとの canvas そのもの**なので、
見えているものと保存されるものが必ず同じになる。
「入れない」を選べば素の写真がそのまま落ちる（あやとの「もちろん、
キャラ埋めなしでも」）。保存は3段構え（`docs/nordic-photos.md` 6章）。

### 日付と企画は、紙の見出しが1回だけ言う

カード1枚ずつには持たせない（`CardOne` の `showWhen`）。同じ写真から出た
カードは日付も企画も同じなので、1枚ずつに付けると人数ぶん同じ字が並ぶ。

**1日に企画は何本でも立つので、札も何枚でも出す。** 9月11日はそれが4本で、
ジョージアバイバイ・海外出発二周年記念日・ヒッチハイクで北欧へ・北欧旅の出発。
1本に絞ると、残りは黙って消える。

**開いた先では、札は紙のいちばん下に置く。** 上に置くと、4本立つ日は写真より
先に青い字が4行ならんで、そちらに目が行く（`docs/island-design.md` 3章の4）。

札の行き先は `/next#<企画のID>` のことが多い。**`#` で送るだけでは着かない**
（面が出てから伸びるので、ブラウザが `#` を探す時点ではまだその段が今の高さに
無い。実測で目当ての段が 3,055px にあるのに 238px で止まっていた）。
`components/ui/HashJump.tsx` が追いかけて送る。あやとの言葉（2026-09-10）:
「あお文字おしても food wine fest が見れない」。

引くのは**日付から**（`content/planDays.ts` の `PLAN_BY_DAY`。配列で返る）。
カードは `streamEventId` も持っているが、**そちらは札にしない。**
1枚の写真は1つの企画にしか付かないので、それで引くと同じ日のほかの企画が消える。

### 面で、仕組みの説明をしない

前はここに「どうやったら、もらえるんだろう」という紙があって、すぐ上の
リード文と同じことを言っていた。一覧の下には「写真12枚に、いま45枚。押すと…
名前が出ているのは、島に名前を出してよいと言ってくれた人です」という注記が
あった。あやとの言葉（2026-09-10）:

> このページすごくUX が悪い。
> 「どうやったら、もらえるんだろう」の説明が最上部の説明と被ってて要らない。

**書くのは、その人がこれから何をするかだけ**（`docs/island-misses.md` 7）。
いまの面の字は、リード「その日の写真に、キャラクターを1人だけ入れて持って
帰れます。」と、開いた先の「だれを入れますか」「ほぞんする」だけ。

## 5. 動かす

置き方を動かせるのは**本人だけ**（`POST /cards/{cardId}`）。あやとは全部動かせる。
自分のカードかどうかは、送られてきた値ではなく `islandUsers/{uid}.channelId` で決める。

**動かす画面はまだ無い。** 口と持ち方だけが先にある。

### 動かしていないカードは、既定の値では置かない

台帳が持っている `x/y/rot/scale` は、**`moved` が立っているときだけ**使う。
既定値（`defaultPlace` が ID から散らしたもの）は使わない。あやとの言葉
（2026-09-10）:

> たいpi のキャラクターが見切れてる。あと大きさも不揃い。

本番の4枚は `x` が 0.768〜0.864、`scale` が 0.959〜1.046。縦の写真では
キャラクターの横幅が写真の 34%×scale なので、`x = 0.864` は右端を **4%
はみ出す**（絵が切れる）。`scale` の幅はそのまま1人ずつ違う大きさになる。

散らしていたのは、**一覧に同じ写真のカードが人数ぶん並んでいたころ**、
全員が寸分たがわず同じ場所に立つと「同じ絵が人数ぶん」に見えたから。
一覧が写真1枚につき1マスになり、立つ人は開いた先で1人ずつ入れ替える
形になったので、**散らす理由が消えた。** 残っていたのは害だけ。

置くのは `docs/nordic-photos.md` 5章の右下ひとところ。
画面（`components/cards/cards.ts` の `cardPlace`）と焼く1枚
（`components/nordic/stamp.ts` の `stampBox`）が**同じ値**を使う。
動かしたぶんも、枠から出さないように両側で丸める。

**サーバーの `defaultPlace` は変えていない。** 変えると、
すでに置いてある台帳と、これから作るぶんで置き方が食い違う。
使わないと決めるのは画面の側。
