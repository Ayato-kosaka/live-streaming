# 0005 道は種類と名前だけで作り、入口の9つは案内の層とする

- 日付: 2026-11-22
- 状態: 採用
- 決めた人: あやと（仕様: 入口の9つ）／運営（設計: 道の作りかた）
- 仕様の条: `docs/spec/routes.md` R-1〜R-5 R-20〜R-25

## 状況
あやと（2026-11-18）:「興味ある部分は、あやとのこと・配信・伝説の企画・歩いた国・アプリ・作った料理・住んでる人・あやとグッズ・やってほしいこと、の9個」
あやと（2026-11-22）:「ルーティングが大事。あやと島の中はこういうルーティングになっていて、そこには何を入れるか、をディレクトリ階層のように責任分離して、将来的にバグらない形に」

数えた。
- 建物は11軒。索引（`/all`）は13棚が5つの切り口で並ぶ。どの建物にも属さない面が在る（`/island/**` の23面・`/cards`・`/updates`）
- 道は 2026-11-13〜14 に引っ越したばかり（#1201。`/map` `/nordic` `/atlas` ほか → `/travel` `/island`）

## 決定
- 道は「種類の接頭辞＋名前」だけで作る。あとで変わること（どの旅に属するか・状態・どの入口の下か）を道に入れない
- 入口は9つ。入口は道にかぶせる案内の層で、並べ替えても道は動かさない
- 下のボタン・島の建物・索引の棚・パンくずの2段目は、入口の表1つから引く
- 旅の島（`/island/**`）は、どの旅も「歩いた国」の入口の下とする
- `site/app` の道の型は、仕様の表に載っていなければ書き出せない（見張りで止める）

## 理由
- 道に入口の名前を入れると（例 `/travel/trips/<旅>`）、入口の分け方を変えるたびに道が動く。道は検索と貼られたリンクに残るので、動かす値段が高い
- 道を種類で分けておけば、「この道には何を入れるか」が種類の定義で決まる

## 捨てた案
- **道を入口の階層に合わせる**（`/streams/months/<月>`・`/travel/trips/<旅>`・`/goods/cards`）。直下が9つになって見た目は揃うが、入口を変えると道が動く。#1201 の 301 の上に、もう1段 301 を重ねることにもなる
- **旅の下に場所を入れる**（`/island/<旅>/<国>/<街>`）。#1201 で捨てたのと同じ理由（国がいくつもの旅に出る）

## 影響
