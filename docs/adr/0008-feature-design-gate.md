# 0008 面・道・表・大きい機能を足す前に、設計の関所を通す

- 日付: 2026-11-22
- 状態: 採用
- 決めた人: あやと（仕様）／運営（設計）
- 仕様の条: `docs/spec/routes.md` R-5／`docs/spec/model.md` M-2／`docs/README.md` D-2

## 状況
あやと（2026-11-22）:「ふと思いついたこと、例えばインドを回る旅をやりたい、来年の1月からこんなの予定してますから意見ください、みたいなページを作るかもしれない。そうなったときに毎回継ぎ足しにならないように、大型機能ができるときは、ちゃんとイケてる形になる仕組みを作ってほしい」

これまで、機能を1つ足すたびに、建物1軒・表1枚・机の道具1つを足してきた。足した時点では正しく、あとから「同じことを言う別の箱」が残った（#1274）。

## 決定
- 新しい面・道の型・表・机の道具・口を足す前に、スキル `/feature-design` を通す
- 関所は3つの問い（主語は何か・主語は1つか・ほかとは鍵で結ぶか）で、足すものの種類と置き場を決める
- **既に在る種類で足りるなら、表に行を足すだけにする。** 新しい面の型・道・建物・表を作らない
- 既に在る種類に入らないときだけ、決定の記録を1枚書き、仕様を直してから作る
- 機械で止める: 仕様の表に無い道の型は書き出せない（`python/route_spec_selftest.py`）。台帳に無い文書は置けない（`python/docs_index_selftest.py`）

## 理由
- 継ぎ足しは「いま頼まれたものを、いちばん近い所に足す」から起きる。足す前に、どの種類かを先に言わせれば、既に在る箱に入ることが多い
- 手順だけでは守られない日が来る。道の型と文書は数えられるので、機械で止める

## 捨てた案
- **設計のレビューを人に頼む。** あやとは承認者ではない。可否を預けない（`CLAUDE.md`）
- **PR の雛形にチェック欄を足すだけ。** 欄は埋まるが、止まらない

## 影響
- 新設: `.claude/skills/feature-design/`・`python/route_spec_selftest.py`・`python/docs_index_selftest.py`。`CLAUDE.md` に関所の1節
