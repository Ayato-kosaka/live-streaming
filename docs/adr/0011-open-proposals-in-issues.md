# 0011 まだ決めていない案は issue に置き、記録には決めた経緯だけを置く

- 日付: 2026-11-22
- 状態: 採用
- 決めた人: 運営（設計）
- 仕様の条: `docs/README.md` 1章（記録の行）・D-10

## 状況
`docs/README.md` の中で2か所が食い違っていた。
- 1章の種別の表は、記録を「そのとき起きたこと・調べたこと・**検討したこと**」としていた
- D-10 は「『これから増やすとしたら』のような**検討中の案**は `docs/` に置かず、GitHub issue を立てる」としていた

「検討したこと」を記録に書いてよいなら、検討中の案も記録として `docs/` に置けてしまい、D-10 が効かない。
前の担当（#1359）が申し送りとして残した。

## 決定
- D-10 を採る。まだ決めていない案（検討中のもの・やるかどうかが開いているもの）は issue に置く
- 記録が持つのは、終わったことだけとする: 起きたこと・調べたこと・検討して決めた経緯（何を比べて、なぜ捨てたか）。日付を付け、直さない
- 1章の記録の行と D-10 の字を、この読みかたに合わせて直す

## 理由
- 開いている案は状態を持つ（決まる・捨てる・形を変える）。状態を持つものは issue に置く、と D-10 が既に決めている
- 決めた経緯は、決まったあとも読む意味がある（なぜこの形かを引ける）。こちらは記録に置いてよい
- 既に在る記録（`island-card-rfc.md`・`island-play.md` ほか）は、書いた日の時点の検討として読める。置き場は動かさない（D-5）

## 捨てた案
- **記録の行を正にし、D-10 から「検討中の案」を消す。** `docs/` に開いた案が増え、どれが決まったのかが文書の種別から分からなくなる。0001 で直そうとしたことそのもの
- **「検討」という種別を足す。** 種別を増やすと、決まったことと決まっていないことの境目がまた1つ増える

## 影響
- `docs/README.md` 1章の記録の行と D-10 を直した
- 新しく「決める前の資料」を書くときは、issue の本文に置き、決まったら仕様と決定の記録へ移す（D-3）
