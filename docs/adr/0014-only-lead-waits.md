# 0014 待つのはまとめ役のセッションだけとし、担当は待たない

- 日付: 2026-11-22
- 状態: 採用
- 決めた人: 運営（設計）
- 仕様の条: `docs/island-standards.md` §19・§31.6

## 状況
記録の決めごとを仕様へ写したところ（0010）、2つが食い違っていた。
- `docs/island-standards.md` §19:「待つときはポーリングしない。PR は `subscribe_pr_activity`、時間待ちは `send_later`」
- `island-misses.md` #342 の決めごと4:「担当に `send_later` と `subscribe_pr_activity` を使わせない（運営のセッションに届く）。待ちは `run_in_background`」

§19 は誰が待つかを言っていないので、担当がそのとおりにすると、知らせが運営のセッションへ飛ぶ。

## 決定
- `subscribe_pr_activity` と `send_later` で待つのは、まとめ役（運営）のセッションだけとする
- 担当は待たない。待ちが要るなら `run_in_background` に置き、出すところまでやって報告して終わる
- §19 の字を、まとめ役のセッションに限る形に直し、担当の側は §31.6 に書く

## 理由
- 2つの道具の知らせは、担当ではなく運営のセッションに届く。担当が使うと、運営の文脈に担当の待ちが混ざる
- 担当が待たずに報告して終わる形は、配るときの決まり（`/hand-off`）が既にそうなっている

## 捨てた案
- **担当にも使わせ、知らせの宛先を担当に向ける。** 道具の側で宛先を選べない

## 影響
- `docs/island-standards.md` §19 の待ちかたの行を直し、§31.6 を足した
