# 0010 記録の決めごとを仕様に写し、作る前に読むのは仕様だけとする

- 日付: 2026-11-22
- 状態: 採用
- 決めた人: あやと（仕様）／運営（設計）
- 仕様の条: `docs/island-standards.md` §22〜§35／`docs/README.md` D-4

## 状況
あやと（2026-11-22）:「island-misses みたいな、検討資料・メモ資料みたいなのが結構散らばってる。もっと決まったことをガチッと書くべき」

数えた（master `8e1ca74`）。
- `docs/island-misses.md` は 19,101行・342節（`#1`〜`#343`。`#37` は欠番）。記録（いつ、何を指摘され、なぜ外したか）と決めごとが、同じ節の中に混ざっている
- `CLAUDE.md` は「作る前に必ず読む」と言っていた。読める長さではない
- 決めごとの書きかたが時期で5通りある（頭の `決めごと（先に読む）`・`**対策**` の段落・`### 決めごと` の塊・`### これからどうするか`・塊の外の `**決めごと。…**`）。抜くと1,221本
- `docs/island-standards.md` は §1〜§21 を持つが、どの節の決めごとがどの章に入っているかの対応が無かった
- 記録は732か所から節番号つきで名指しされている

## 決定
- 決めごとを抜く道具（`python/misses_rules.py`）を置き、抜いた1本ずつに行き先を1つ決めて、対応表 `docs/island-misses-map.md` に1行ずつ置く
- 行き先は3つのどれか: 既に在る仕様の条（§1〜§21・出す前のチェック・`docs/README.md` の D・`docs/guide-*.md`・`docs/island-money.md`）／仕様に足した条（`docs/island-standards.md` §22〜§35）／`この節かぎり`
- `この節かぎり` は、その節の1件の直しそのもの（道具の名指し・その面だけの寸法や置き場）か、道具や面がもう無いもの。仕様には写さない
- 同じ意味の決めごとは、1つの条にまとめる。1つの決めごとは仕様の1か所にだけ置く
- ショートの原稿・編集の決めごとは、`viral-shorts-creator` の帳面と様式が既に F 番号つきで持っているので、そこを正とする条（§35.5）だけを置き、中身を standards へ写さない
- 記録は記録として残す。節の中身と番号は変えず、頭に3行だけ「これは記録。決めごとは仕様へ写してある。作る前に読むのは仕様」と書く
- 新しい指摘を受けたら、記録に1節足し、決めごとが出たら同じ PR で仕様に条を足し、対応表に1行足す（§22）。抜けは `python/misses_rules_selftest.py` が止める
- `CLAUDE.md`・スキルで記録を「作る前に読む」と指していたところは、仕様を指す形に直す

## 理由
- 読まれない決まりは守られない。1万9千行を作る前に読むことはできず、実際には読まれていなかった
- 対応表を節番号の単位で持つと、記録の名指し（`#193 の決めごと4`）から仕様の条へ1行で引ける。記録を動かさずに済む
- 抜いた数と表の行の数を機械で突き合わせれば、写し忘れが人の記憶に頼らずに止まる
- 1本ずつ条を立てると standards が1,000条を超え、また読めなくなる。同じ形の外しかたは1つの条にまとめるほうが、次に同じ形で外しかけたときに止まれる

## 捨てた案
- **記録を章ごとの文書に割る。** 732か所の名指しが切れる
- **記録の節に「仕様の条」の欄を足して回る。** 節の中身を変えないと決めているので取れない。343節を書き換えると、並行する枝と衝突する
- **決めごとを1本ずつ条にする。** 上の理由で取らない
- **ショートの決めごとも standards へ写す。** 帳面（F 番号）が既に1か所で持っていて、写すと2か所になる

## 影響
- 新設: `python/misses_rules.py`・`python/misses_rules_selftest.py`・`docs/island-misses-map.md`
- `docs/island-standards.md` に §22〜§35 を足した。§19 の待ちかたを、まとめ役のセッションに限った（0014）
- 食い違っていた決めごとを3つ、別の1枚ずつで決めた（0012・0013・0014）
