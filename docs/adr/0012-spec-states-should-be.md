# 0012 仕様には「こう在るべき」を書き、まだそうなっていない所は「現状との差」に置く

- 日付: 2026-11-22
- 状態: 採用
- 決めた人: 運営（設計）
- 仕様の条: `docs/README.md` D-6

## 状況
記録の決めごとを仕様へ写したところ（0010）、2つが食い違っていた。
- `island-misses.md` #57（2026-09-11、データ設計の文書を3つに割ったとき）:「仕様に書いてよいのは『いま、どうなっているか』だけ。なぜそう決めたかは notes 側へ」
- `docs/README.md` D-6（2026-11-22）:「仕様は『こう在るべき』を書く。まだそうなっていない所は、同じ文書の末尾の『現状との差』に、条と issue を並べる」

#57 のとおりに書くと、仕様は現状の写しになり、直すべきところが仕様から見えない。

## 決定
- D-6 を採る。仕様は「こう在るべき」を書き、現状がまだ届いていない所は末尾の「現状との差」に置く
- #57 のうち「なぜそう決めたか・何に躓いたかを仕様に書かない」は、そのまま生きる（経緯は決定の記録と記録へ。D-2・0001）
- 対応表では #57 の決めごとを D-6 に向ける

## 理由
- 仕様が現状の写しだと、実装が間違っていても仕様が同じ間違いを書く。どちらが正か決まらない
- #57 が避けたかったのは仕様に経緯が混ざることで、こちらは D-6 でも変わらない

## 捨てた案
- **#57 を採り、仕様を現状の説明にする。** `docs/spec/` の「現状との差」が置けなくなり、直す作業の行き先が issue にしか残らない

## 影響
- 書き換えた文書は無い（D-6 は既にこの形）。対応表の #57 の行の行き先を D-6 にした
