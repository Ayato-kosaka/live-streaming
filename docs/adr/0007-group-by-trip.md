# 0007 国を束ねる語彙は「旅」1つとし、歩いた国を旅で束ねる

- 日付: 2026-11-22
- 状態: 採用
- 決めた人: あやと（仕様）／運営（設計）
- 仕様の条: `docs/spec/model.md` M-5 M-10 M-11 M-12 M-17

## 状況
あやと（2026-11-22）:「回った国に北欧周遊がない。粒度・切り口が違う」

数えた（本番）。
- `/travel` の畳みは ヨーロッパ15・中東5・コーカサス3＋国境・バルカン諸国周遊4。上の3つは地域（`Country.region`）、最後の1つは旅（章の名前）
- 北欧周遊の6か国は「ヨーロッパ」に入る。「行った順に」と言いながら、2026年の北欧が2025年の中東より上
- 束ねる語彙が3つ: `Country.region`（3値）／地図の `route.json` の章（3つ）／`CHAPTERS`（6つ）
- `iran-border` は国ではないのに国の表に居て、滞在がアルメニアと重なる（配信6本が両方の国に数えられる）

## 決定
- 国を束ねる語彙は「旅」だけとする。地域と、地図のボタン用の章をやめる
- 歩いた国の一覧と、地図の寄せるボタンは、旅で束ねる。行った順に ヨーロッパ周遊9・中東周遊5・コーカサス周遊3（枝の旅: イランまで歩く）・北欧周遊6・バルカン諸国周遊4
- 本線の旅は時間を隙間なく割る。枝の旅は親の期間の中に入る。滞在は重ならない
- 国の一覧には国だけを置く。イラン国境は、アルメニアの中の地点にする

## 理由
- 地域と旅は別の切り口で、同じ一覧に並べると粒度が揃わない。これまで名前がたまたま近かった（ヨーロッパ周遊とヨーロッパ）ので気づかなかった
- 島は旅ごとに1つ在る。束ねる単位を旅にすれば、一覧・地図・島・数字が同じ単位で揃う

## 捨てた案
- **地域だけで束ねる**（バルカンと北欧を地域として足す）。「行った順」にならない。島（旅）と単位が揃わない
