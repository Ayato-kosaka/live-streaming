# 0021 月末配信の授賞式の決まりを、仕様1枚（`docs/spec/monthly-review.md`）に寄せる

- 日付: 2026-11-27
- 状態: 採用
- 決めた人: あやと（仕様: 画面の形・コーナー・中身の選びかた）／運営（設計: 決まりの置き場）
- 仕様の条: `docs/spec/monthly-review.md` MR-1〜MR-30

## 状況

11月の授賞式を出したところ、あやとから10月に言った指摘が入っていないと言われた（2026-11-27）:

> 前回の指摘が全く入ってない気がする。ちょっと一回ちゃんと調べてください。

調べると、10月の配信のあとに組み直した版（`public/202610_monthly_review_v2.html`）に、あやと島カードの写真・付箋大賞・中身で問うクイズ・1件ずつ1面に出す組み方が入っていた。ところがそれは別の PR に紛れて master に入っており、手引き（`.claude/skills/monthly-review/SKILL.md`）にも仕様にも1行も書かれていなかった。11月は1つ目の10月版を土台にしたので、その指摘が全部抜けた。

手引きは328行あり、決まりと「いつ誰に何と言われたか」が段落の中で混ざっていた。あやと（2026-11-27）:

> プロンプトとかって、業界標準になるようにしてほしいです。検討状況とかは入れないで。決まったことを入れる形にしてほしい。

## 決定

- 月末配信の授賞式の決まりは `docs/spec/monthly-review.md` に、番号つきの条（MR-n）として置く。経緯は書かない。
- 手引き（SKILL.md）は手順だけを持ち、決まりは条を指す。
- 2026-11-27 の指摘（正方形・1件ずつ大写し・出席は −3 日まで・私生活の引用を外す・中身で問うクイズ・カードの写真・付箋大賞・エンディングは投げ銭の人）を、同じ PR で条にした。

## 理由

- 決まりが手引きの物語の中に埋まっていると、作る人は物語を読み飛ばし、決まりも一緒に落ちる。条にすれば1つずつ当てられる。
- 「作ったもの（v2）」に入った指摘は、次に作る人には見えない。決まりの置き場が1つなら、指摘はそこに入るまで終わらない。

## 捨てた案

- 手引きに追記を足し続ける: 10月まで続けた形で、328行のうち決まりは散らばっていた。今回の抜けはこの形から起きた。
- v2 を次の月の土台に指定するだけ: 作ったものは月ごとに変わる。土台を指しても、なぜそうなっているかは伝わらない。

## 影響

- `.claude/skills/monthly-review/SKILL.md` を手順だけに書き直す。
- `docs/README.md` の台帳に仕様1行を足す。
- 授賞式の道具（`tools/monthly_review/`）の検査（`check.mjs`）を、6章の線で測る形に直す。
