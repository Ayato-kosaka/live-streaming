# 北欧旅を、みんなで連れていく

投げ銭を「支援」ではなく「参加」にするための設計。
`/nordic`（[`island-plan-drafts.md`](./island-plan-drafts.md) でいう大きい企画の専用ページ）に
何を足すか、お金をどう扱うか、誰の名前をどこに残すかを決める。

**先に読む**: [`island-design.md`](./island-design.md)（拘束力あり）/ [`island-db.md`](./island-db.md)

---

## 1. 企画の芯

> 会いたい人がいるので、スウェーデンまでヒッチハイクで行きます。

**これが企画の全部で、投げ銭の設計もここにぶら下がる。**

「ヒッチハイクで北欧を回る」は行為でしかない。見ている人は結末を想像できないし、
どこで終わるのかも分からない。「会いたい人がいる」は目的なので、次の4つが同時に立つ。

1. **終わりがある。** 着いたら終わり。見ている人が結末を想像できる
2. **距離が意味を持つ。** 1,541km が、そのまま「会えるまでの遠さ」になる
3. **投げ銭の意味が変わる。** 「助ける」ではなく「**連れていく**」になる
4. **一点に向かう。** 区間も、意見も、到達も、記念も、全部この1本の線にぶら下がる

### 会いたい人の扱い（先に決めておくこと）

**その人は、この企画に応募していない。** 目標にされることに同意していない実在の人なので、
設計はこの3つを絶対に守る。

- **名前・顔・SNS を出さない。** あやとが本人の同意を取ったと確認できるまでは、
  ページ上はずっと「会いたい人」のまま。伏せたままでも設計が成立するようにしてある
- **ページの達成条件を、人に紐づけない。**
  サイト上のゴールは **ストックホルムに着くこと**。会えたかどうかは、そのあとの配信の話。
  相手の都合で会えないことは普通にあるし、そのとき相手が「約束を破った人」に見えるのは最悪
- **投げ銭の文言に相手を使わない。**
  「◯◯さんに会わせてあげよう」は、相手を人質にして金を集めている。書かない

伏せたまま出すなら、地図のストックホルムのピンに名前ではなく席を置く。

```
      ★ ストックホルム
        ここに、会いたい人がいる
```

名前を出していいと分かったら、この一行を差し替えるだけで済む。**構造は変えない。**

## 2. いま分かっていること

### 2.1 お金を出す人は、来ている人の 3% しかいない

BigQuery `youtube_chat.chat_messages` の実数（2026-09-05 時点）。

| | 直近1年 | 全期間 |
| --- | --- | --- |
| コメントした人 | 1,821人 | — |
| **スパチャを出したことがある人** | **55人** | 60人 |
| スパチャの件数 | 322件 | 377件 |
| スパチャの合計 | 187,536円 | 218,456円 |
| 1件の中央値 | — | **320円** |

**投げ銭だけを参加の形にすると、97% を締め出す。** これは設計の前提であって、
「お金を出さない人の道も一応作る」という話ではない。
出さない人の道が本線で、お金はそこに乗るもう1つの道、という順で組む。

もうひとつ。**中央値が320円**であることは、見せ方に直接効く。
10万円のバーに320円を入れても、目盛りは動かない。動かないものに人は2回目を入れない。
**320円で目に見えて何かが変わる単位に割る**（→ 4章 提案1）。

### 2.2 金額は、自動で取れる（いちばん大きい発見）

**あやとに毎日入力してもらう必要はない。もう仕組みがある。**

`functions/src/doneruAmount.ts` が既に本番にいる。
`https://api.doneru.jp/widget/goal/data?key=<goalKey>` を叩いて `{ amount }` を返すだけの
プロキシで、`cors: true` が付いている。
OBS の豚の貯金箱（`app/alertbox/components/PiggyGauge/`）は、これで動いている。

貯金箱の合計の作りかたも `app/alertbox/index.tsx` にそのまま書いてある。

```
currentAmount = startAmount + superChatAmount + doneruAmount
```

`startAmount` `superChatAmount` `targetAmount` `label` `doneruGoalKey` は
GAS の `Goals` テーブル（id は `2025-10-24` で固定）から来る。

**サイトが真似してはいけないところが1つある。**
OBS はスパチャを `SUPERCHAT_CONVERSION_RATE = 0.5`（半額）で足している。
これは配信の演出上の都合。**サイトで半額にすると、出した人が自分の額を見つけられない。**
サイトは満額で数える。

### 2.3 スパチャは BigQuery に入っている

`chat_messages` の `event_type = 'PAID'` に 377件。`purchase_amount_text` が `¥1,000` の形。
外貨が2件だけ混ざっている（`CA$2.79` / `₪6.00`）ので、`¥` の行だけ拾えばいい。

`python/island_daily_stats.py` が毎日 BigQuery → Firestore を回しているので、
**そこに1本足せば、スパチャの合計は毎日ひとりでに更新される。**

### 2.4 いまの `/nordic` に足りていないもの

出発6日前に見た状態（他の担当が同時に建て直している最中）。

- 地図は完成していて、この企画でいちばん強い。**触らない。上に乗せる**
- 区間カード（`RouteLegs`）は、区間ごとに違う絵（`Marks.tsx`）が付いていて、
  すでに「10本の短い話」の器になっている。**ここが投げ銭の置き場所**
- 意見欄（`CountryIdeas`）は**ページのいちばん下**にあり、**0件**。
  「この旅、どうなってほしい？」は漠然としすぎていて、書ける人がいない。
  スクロールで最下部まで来た人にしか見えないのも効いている

## 3. 設計の芯（この3つを外すと、ただの募金バーに戻る）

### (1) お金は「進む」に効く。言葉は「どう進むか」に効く。混ぜない

- **お金** → 距離が進む。区間が埋まる
- **言葉** → 行き先・やること・寄り道が決まる

**投げ銭を票にしない。** 55人が1,821人ぶんの行き先を決めることになり、
「みんなで連れていく」の逆になる。投票は1人1票のまま（`islandVotes` が既にそう）。

この一行は、あとから「投げ銭した人だけ投票権」みたいな案が出たときに戻ってくる場所。

### (2) 単位はバーではなく区間。10本の短い話

10万円のバーは、320円を入れても動かない。1,541km のバーも同じ。
**旅を、値段の付いた10個の区間に割る。**

- タリン→ヘルシンキのフェリーは €10.50（約1,800円）。**320円が5枚で埋まる**
- リガの一泊は、宿1つぶん。**具体的な物**なので、出す側が何を出したか分かる

埋まった区間が増える、という進み方にすると、
「合計いくら集まったか」を見なくても、**絵で進捗が分かる**。

#### ヒッチハイクだから、区間ごとに足代の有無が分かれる

**乗せてもらうこと自体には値段が付かない。** これが、この企画で二席の形がはっきりする理由。

- **足代の要る区間** … 飛行機・フェリー・その日泊まる街の一泊。物と値段が1対1で言える
- **足代の要らない区間** … 寄り道（行って戻ってくるので泊まらない）。
  ここは道しるべ1つで**つながる**

区間ごとに「お金の話がある / ない」が分かれているので、
**足代の席が無い区間**を見た人は、その区間が半分になっているとは思わない。
道しるべしか無い区間があること自体が、「言葉の席は添え物ではない」の証明になる。

実装では `Leg.fare` を任意にしてある（`site/content/nordic.ts`）。
`fare` が無い区間は足代の席そのものを出さず、道しるべ1つで「つながった」に変わる
（`components/nordic/Carry.tsx` の `fareDone`）。

### (3) 未達が、失敗にならない形にする

**この旅は、集まっても集まらなくても行く。** ヒッチハイクは元々ただだし、
飛行機はもう取ってある。だから「目標に届かないと行けません」とは書けない。嘘になる。

では何のバーなのか。

> **区間が埋まる = その一泊・その船賃を、誰かが代わりに出した。**
> 埋まらなければ、あやとが自分で出して越える。旅は止まらない。

これが、この企画で募金バーを健全に使える唯一の形。旅の可否を人質に取っていないので、
**達成しなくても誰も責められない。**

その代わり、出す側の見返りをはっきりさせる。

> **お金は旅を可能にするのではない。旅に名前を刻む。**
> あやとが配信で「リガの夜は、この人たちが出してくれた」と言える。
> ページにもずっと残る。

この2つはセットで書く。片方だけだと、前者は「じゃあ出さなくていいのか」になり、
後者は「金で名前を買っている」になる。

#### 失敗を晒さないための、具体的な決まり

- **「あと ◯◯円 足りません」を書かない。** 要求の言葉。島の言葉ではない
- **締切を作らない。** 「出発までに集まらないと」は嘘。区間は旅のあとでも埋まる
- **埋まっていない区間を灰色にしない。** 灰色は失敗の色。
  同じ明るさのまま、名前の欄が空いているだけにする。言葉は「まだ」ではなく「これから」
- **目標に届いたらバーを消す。** 満タンのバーを出し続けると、
  「もう要らないのに集めている」に見える
- **金額の順位表は出さない。** 理由は4章の「やらないことにした案」に書いた

### 提案1 連れていく区間ボード ── 出発までに1つだけ作るなら、これ

**重さ: 中** / 触るファイル:
`site/content/nordic.ts` `site/components/nordic/RouteLegs.tsx`
`site/components/nordic/Carry.tsx`（新規） `site/app/nordic/page.tsx` `site/app/globals.css`

**新しいセクションを作らない。** `/nordic` の「その道で、何が起きるのか」＝
既にある区間カード（`RouteLegs`）を、そのまま連れていくボードに育てる。
区間ごとの絵（`Marks.tsx`）も畳み（`Fold`）もできているので、器は完成している。

区間カードは、開くとこうなる。

```
┌─────────────────────────────────────────────┐
│ [絵] リガ → タリン                           │  ← いまもある
│      ヒッチハイク 307km / 1日      エストニアへ│
├─────────────────────────────────────────────┤
│ バルト海沿いの Via Baltica。9月のバルトは     │  ← いまもある
│ 3日に1日は雨が降る。濡れながら立つ日がある。   │
├─────────────────────────────────────────────┤
│ ● 足代 ── リガの一泊                          │  ← 足す（お金）
│   ●●●●●●●●●●●●●○○○○○  4,000円のうち 2,880円  │
│   7人が出した                                 │
│                              [ここを出す]     │
├─────────────────────────────────────────────┤
│ ● 道しるべ ── この区間で、何をしてほしい      │  ← 足す（言葉）
│   ・雨の日にどうやって立つのか撮ってほしい     │
│     たくやさん                    いいね 12   │
│   ・パルヌの海で足だけ入って                   │
│     名無しさん                    いいね 4    │
│                              [はりだす]       │
└─────────────────────────────────────────────┘
```

**この区間カードには席が2つある。足代と、道しるべ。**
片方だけの区間は、まだ半分。**両方あって、はじめてその区間は「つながった」ことにする。**

これが「お金を出さない人が締め出されない」の答え。
親切として言葉の欄を用意するのではなく、**言葉がないと区間が完成しない**構造にする。
道しるべが1つも無い区間は、あやとがそこを走るだけの区間になる。

区間の値段は、**その区間を越えるのに本当に要るもの1つ**に紐づける。
抽象的な「1kmあたり◯円」にしない。何に使うか分からない金は出しづらい。

| 区間 | 足代 | 出どころ |
| --- | --- | --- |
| クタイシ→カトヴィツェ | 飛行機 219ラリ（約13,000円） | `content/nordic.ts` に既にある |
| タリン→ヘルシンキ | フェリー €10.50 | `content/nordic/index.json` の `guide.move` |
| ヘルシンキ→ストックホルム | 夜行フェリー €43＋船室 €75.50 | 同上 |
| その他の陸路6区間 | 泊まる街の一泊 | **あやとに埋めてもらう**（→ 8章） |

**合計をここで丸めない。** 積み上げた額がそのまま目標額になる。
「なんとなく10万円」にすると、「何にいくら要るのか」が答えられなくなる。

集まった額の流し込みかたは単純にする。**合計を、通る順に上から注ぐ。**
どの区間が埋まったかを手で管理しない。累積額と区間の値段だけで決まる。

```
合計 32,000円 → 飛行機13,000(満) → クラクフ3,000(満) → ワルシャワ3,500(満)
              → ビャウィストク3,000(満) → ヴィリニュス3,500(満)
              → リガ4,000(満) → タリン4,500(満) → フェリー1,800(残1,700で満)
```

金額を出すのは**区間の値段と、その区間に入った額だけ**。
誰がいくら出したかは、どこにも出さない。

**値段の分からない区間で、注ぎを止める。** 宿代がまだ決まっていない区間（GitHub #107）を
飛ばして先に注ぐと、上流の区間が空のまま下流のフェリーが満ちる、という絵になる。
「上から順に埋まる」がそこで嘘になるので、`FARE_POUR`（`site/content/nordic.ts`）は
値段の無い区間に当たった時点で `reach: false` に落として、そこから下には注がない
（実測: 宿代6つが空のいまは、合計いくらでも飛行機の1区間しか満ちない）。
宿代が入れば、コードを触らずに下流まで流れ出す。

### 提案3 地図を連動させる

**重さ: 小** / 触るファイル:
`site/components/nordic/RouteMapSvg.tsx` `site/app/globals.css`

地図は既に `here` を受け取って、通った区間に `is-done` を付ける仕組みを持っている。
同じやりかたで `is-carried`（連れていってもらった区間）を足す。

地図の中に金額を書かない。地図はもう情報量が多い。金額は区間カードが持つ。

### 提案5 合計額を、サイトが読めるところに置く

**重さ: 中** / 触るファイル:
`functions/src/islandApi.ts` `site/lib/api.ts` `python/island_daily_stats.py`

`doneruAmount` は `cors: true` なのでブラウザから直接叩ける。**が、叩かない。**
静的書き出しのページに Doneru の goal key を焼き込むことになる。

`islandApi` に `GET /fund` を足す。キーは Functions 側に置いたままにする。

```
GET /island-api/fund
{
  total: 32450,        Doneru + スパチャ + startAmount
  people: 18,          出した人の数（延べではなく人数）
  updatedAt: 1757000000
}
```

- Doneru ぶん … `doneruAmount` と同じ URL を Functions の中から叩く
- スパチャぶん … `island_daily_stats.py` が毎日 Firestore `island/state.fund` に書く
- 読みは数分キャッシュする（`islandApi` は既に「読みは CDN にキャッシュさせる」方針）

画面側は `LiveNumber` と同じ形にする。**静的書き出しなので、画面が出てから取り直す。**
焼き込みの値をまず出して、読めたら差し替える（`site/lib/liveStats.tsx` がそのまま手本）。

**`GET /fund` が落ちたら、区間カードは足代の行ごと消す。**
0円と表示するのがいちばん悪い。誰も出していないように見える。

だからサーバ側も、**1円も分からないときは 200 で 0 を返さない。**
`503` を `Cache-Control: no-store` で返す。200 で 0 を返すと、その 0 が CDN に
5分ぶん焼き付いて、鍵を入れた直後も 0 のままになる。goal key がまだ無いあいだ
（GitHub #110）は毎回ここに来るので、これが**既定の状態**になる。
画面は 200 以外を「読めなかった」として黙って数字を消すので、エラーは表に出ない。

### やらないことにした案（理由つき）

| 案 | やらない理由 |
| --- | --- |
| **投げ銭を票にする** | 55人が1,821人ぶんの行き先を決めることになる。「みんなで連れていく」の逆 |

| **1kmあたり◯円** | 何に使うか分からない金は出しづらい。値段は「その一泊」「その船賃」に紐づける |

## 5. データをどう持つか

**手で入れるのは、金額ではない。「どこまで来たか」と「何が起きたか」。**

| 何を | どこに | 誰が / どうやって | 頻度 |
| --- | --- | --- | --- |
| 区間の値段と、何に要るか | `site/content/nordic.ts` の `Leg` | Git（手書き、レビューあり） | 最初に1回 |
| 集まった合計 | Firestore `island/state.fund` | **自動**。Doneru API ＋ BigQuery | 毎日 |
| どの区間まで埋まったか | どこにも持たない | 合計を区間の値段に上から流して**計算する** | — |
| いまどこに着いたか | Firestore `island/state.current` | `island_update.yml` で手動 | 街に着くたび（10回） |
| 区間で起きたこと | `site/content/nordicLog.ts` | Git（手書き） | 区間ごと（10回） |
| 道しるべ（意見） | Firestore `islandIdeas`（`【区間:xxx】`） | 視聴者さん | 随時 |

### Firestore に足すもの

`island/state` に `fund` を1つ。**新しいコレクションを作らない。**

```
island/state
  fund: {
    total: number       Doneru + スパチャ + startAmount の合計（円）
    people: number      出したことがある人の数
    superchat: number   うちスパチャぶん（BigQuery 由来）
    updatedAt: number
  }
```

### 匿名の扱い

**既定は匿名。名前を出すのは、本人が出すと決めたときだけ。**
`islandUsers.showName` と同じ思想（`island-db.md` 参照）。

問題が1つある。**Doneru の表示名と、島にログインした人を突き合わせる手段がない。**
自動で名前を出そうとすると、必ずどこかで人違いが起きる。人違いは、お金の話では致命的。

だから出発までの最小形では、こうする。

- **お金 … 人数だけ出す。名前は出さない。** 突き合わせをしないので、人違いが起きない
- **言葉 … 名乗った人の名前を出す。** 既存の `islandIdeas.name` がそのまま使える

「出した名前を残したい人」への道は、旅が始まって運用が回ってから足す。
やるなら、Doneru のメッセージに区間名を書いてもらって、あやとが手で拾って
`nordicLog.ts` に書く形（1区間1回）。**自動照合は作らない。**

この順にする理由はもう1つある。**いきなり金額と名前を結ぶと、金が名前を買う構図になる。**
先に「言葉を置いた人の名前が並ぶ」状態を作っておけば、あとから金の名前が入っても、
同じ列に並ぶだけで済む。
