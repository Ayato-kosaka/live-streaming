# お金の出しかた

**視聴者さんに見せる額と、管理側で見る額は別のもの。**
ここはその線引きと、式がどこにあるかを1か所に書いたもの。

あやとの言葉（2026-09-26）:

> 実額はアドミンから見れて良いですが、**視聴者から見えるものは全て
> 豚の貯金箱と同じ仕様にするべきです。ここ大事。**
> ランキングの仕様 = 豚の貯金箱の仕様 = **いくら配信の企画や私の夢への
> 応援に貢献してくれたか。** 実額は視聴者には一切見せない仕様整理です。

**額つきの順位を誰でも見られる面に置いてよいのは、月ごとのふりかえり
（`/months`）だけ。** あやとが 2026-10-13（#809）に理由つきで1か所だけ
外した。**ほかの面には1円も出さない。** → [2.1](#21-額つきの順位を出してよいのは月ごとのふりかえりだけ例外)

## 1. 式は1本

```
貢献額（視聴者さんに見せる額） = スパチャ ÷ 2 + Doneru
貯金箱                        = 貢献額 − 支出
```

**置いてあるのは `python/fund_box.py` のここだけ。**

| 関数 | 何を返すか | 誰が使うか |
| --- | --- | --- |
| `viewer_yen(superchat_yen, doneru_yen)` | 貢献額 | **視聴者さんに見せる額ぜんぶ** |
| `box(superchat_yen, doneru, spend_yen)` | 貯金箱 | 島の面・`/island-api/fund` |

`box()` は `viewer_yen()` を呼ぶ。**割り算は `viewer_yen()` の中の1行しかない。**
どこかで `// 2` や `* 0.5` を書いたら、それは割れている。

### なぜ「いくら出したか」ではないのか

**スパチャは YouTube が半分持っていく。** 出してくれた額と、夢に届いた額が違う。
1,000円のスパチャと 500円の Doneru は、旅には同じだけ効いている。
表彰するのは届いたほう。

これは演出ではなく仕様。**額が変わるだけでなく、並びが変わる**
（スパチャだけの人は半分になり、Doneru だけの人はそのまま残る）。
2026-09 は実額で出して、1位が入れ替わっていた（`island-misses.md` #191）。

### 端数

**切り捨て**（`//`）。`box()` と同じ丸め方にしてある。
片方だけ変えると、ランキングの合計と貯金箱の増えかたがずれる。

### 足してから半分にする

1人ぶんの**合計**を渡す。1件ずつ半分にすると、奇数円のスパチャの数だけ
ずれる（GAS の `=SUM(...)/2` がそうなっている）。

### 円以外の投げ銭は、**その日のレートで円に直してから足す**（#951）

あやとの言葉（2026-10-18。#951）:

> レートの取得は無料でできるの？ としたら、firestore に入れるときに、
> レート取得して日本の金額を入れるイメージ？
> **無料だったらそれでいいよ。** その金額に÷2すれば、整合性取れるんじゃない？

**直すのは取り込みのとき1回きり。** 足すたびに引き直すと、同じ投げ銭が
焼いた日によって別の額になって、図鑑と月末で順位が割れる。

| どこで | 何をするか |
| --- | --- |
| 引く | `python/fx_rate.py`。`https://api.frankfurter.dev/v1/<日付>?base=<通貨>&symbols=JPY`（ECB。**鍵なし・無料・過去の日付が引ける**） |
| 直す | `python/island_tips.py` の `yen_of`。台帳（`islandTips`）に入れるときに1回 |
| 持つ | `amountJpy`（円）・`fxRate`（使ったレート）・`fxDate`（**レートの日**）・`fxWhy`（直せなかった理由） |
| 足す | `python/fx_rate.py` の `row_yen()`。**図鑑も月末もこの1本を通す** |
| 埋め直す | `python/admin/fx_backfill.py`（`script: fx_backfill`。`{}` で下見、`{"apply": true}` で書く） |

**元の表記（`amount` / `currency`）は消さない。** 直した値だけ持つと、
あとでレートを引き直して検算できない。

**`÷2` は、円に直したあとの額にかける。** 式は `viewer_yen()` 1本のままで、
1件ずつ半分にはしない（上の「足してから半分にする」）。

#### **頼んだ日ではなく、返ってきた日**を持つ

ECB は営業日しかレートを出さない。土曜の日付で頼むと、返ってくるのは
**直前の営業日**の値（2026-10-18（土）に USD を頼むと `date` は 2026-10-16）。
`fxDate` に入れるのは**返ってきたほう**。頼んだ日を入れると、あとで検算
したときに「その日のレートなんて無い」になって合わない。

#### 直せないことがある。**そのときは足さない。0 にもしない**

| 何が | 直るか |
| --- | --- |
| 台湾ドル（TWD / NT$） | **この口が持っていない。** いつ引いても直らない |
| 口が落ちている晩 | 翌晩の取り込みで直る |
| 返事の形が違う | 同上 |
| 換算を入れる前に入った行 | `python/admin/fx_backfill.py` で直る |

**0 を入れない**（`docs/island-standards.md` 10）。足さないということは、
その人の貢献額がそのぶん足りないということなので、**残っているあいだは
人の見えるところに出す。**

| いつ | 何が起きるか |
| --- | --- |
| 台帳に直せない行が残っているあいだ | `fx-tips` の issue が1本開く（`python/fx_tips_watch.py`。直れば自分で閉じる。**窓で切らない**） |
| 月末に集計するとき | 直っていないスパチャを**1件ずつ名指し**（`python/monthly_tips.py` の `fx_stuck()`。日付・通貨・指紋・理由・その人が円でも出しているか） |

**どちらも額は出さない。** 公開の場に出るのは件数・通貨・日付・理由・
指紋まで（元の表記は実額なので、2章の表のとおり出さない。`python/logsafe.py`）。

本番の実測（2026-10-18。全期間のスパチャ547件・67人）では **ILS 1件・CAD 1件**で、
**2人とも、その1回がその人の唯一の投げ銭だった**（#951 を入れるまで、
2人とも貢献額が丸ごと 0円 の人として島に立っていた。`island-misses.md` #290）。
Doneru の1,068件はすべて通貨が空＝円。

## 2. 誰が何を見てよいか

| | 実額（生の円） | 貢献額 |
| --- | --- | --- |
| 島の面・授賞式・OBS | **出さない** | 出す |
| **月ごとのふりかえり（`/months`）** | **出さない** | **出す。順位・呼び名つきで並べてよい（例外。2.1）** |
| `/island-api/fund`（誰でも叩ける） | 出さない | 出す |
| `/island-api/fund/desk`（オーナーの口） | 出す | 出す |
| 公開の Actions ログ | **出さない** | 画面に出るものと同じなら出してよい |
| Firestore `islandTips.amount` | 持つ。**クライアントから読めない** | — |

### 2.1 額つきの順位を出してよいのは、月ごとのふりかえりだけ（例外）

**`/months` と `/months/<年-月>` でだけ、誰がいくら貢献したかを順位つきで並べてよい。**
あやとが理由つきで1か所だけ外した（2026-10-13、#809）:

> 例外で良い。配信で見せた内容は公開されてるので、同じものをあやと島から見れても問題ないという整理。

**外したのは「出してよい面」だけで、式も、中身も、何ひとつ外していない。**

| | |
| --- | --- |
| 出してよい額 | **貢献額だけ**（スパチャ ÷ 2 + Doneru）。`viewer_yen()` を通したもの |
| 実額 | **出さない。例外の対象ではない。** 月ごとの面でも1円も出さない |
| 出してよい面 | `/months`・`/months/<年-月>`・月末配信の授賞式（`public/*_monthly_review.html`） |
| **出してはいけない面** | **それ以外の全部。** 表紙・`/now`・`/friends` の図鑑・島の札・`/cards`・`/board`・`/all`・OG の絵 |
| 出してよい中身 | 順位・呼び名・貢献額・その月の合計 |
| 出してはいけない中身 | チャンネルID・どねID・`lookupKeys`・Doneru の名乗り（寄った人のぶん）・個人別のコメント数 |

#### 「配信で見せた」の線は、**確かめようのあるほう**で引く

理由が「配信で見せたものだから」なので、**何を配信で見せたのかを、あとから
誰でも確かめられないと、この例外はいくらでも広がる。** 「いつか配信で言った
かもしれない額」を根拠にすると、貯金箱の途中経過でも、1件ずつのスパチャでも、
同じ理屈で島に出せてしまう。だから線はこう引く。

**例外の中（出してよい）**

**月末配信の授賞式が画面に出す決まりの3つ——順位・呼び名・貢献額——を、
`python/admin/monthly_tips_run.py` が同じ期間・同じ式で出し直したもの。**

この形だけが確かめられる。出どころが1本（`viewer_yen()`）で、期間の決め方も
1本（5章）なので、**同じ期間でもう一度流せば同じ数が出る。**
8月・9月は授賞式の HTML が `public/` に残っているので、画面と突き合わせることもできる。

**例外の外（出してはいけない）**

- **実額**。授賞式でも出していない
- **その場で口に出した額**（配信中に言った合計、貯金箱の途中経過）。
  録画の中にしか無く、突き合わせようがない
- **1件ずつの投げ銭**（誰がいつ、いくら）。授賞式が出すのは1人ぶんの合計だけ
- **月ごとのふりかえり以外の面**。授賞式でその面を映したわけではないので、
  「配信で見せた」が成り立たない

#### 2026年1月〜7月は、授賞式の HTML が残っていない

**残っていないことは書いておく。** 1月〜7月の月末配信は実際にあったが、
OBS のページを1枚ずつ作り始めたのは8月からで、その7ヶ月ぶんは
**「画面に出した」ことを紙で確かめられない。**

それでも `/months` に出しているのは、**出している中身が8月・9月とまったく同じ3つ**で、
期間も式も同じ1本から出し直したものだから。あやとが #809 で求めたのも
**2026年1月からの面**で、月を選べとは言っていない。
**中身の形が例外の中にあることが根拠で、紙が残っていることは根拠ではない。**

**「どこでも出してよい」と読まない。** 島の表紙に「今月の1位 ◯◯さん 15,900円」を
置くのは、この例外の外側。
**「決めを破っている面がある」とも読まない。** `/months` に額が並んでいるのは
決め忘れではなく、ここに書いた例外。

焼き込みは `site/content/months.ts`（`python/build_monthly.py` が焼く）。
**そこから先へ運ばない**——あのファイルを別の面から読んだ時点で、例外が広がる。

これは気をつけて守るものではないので、数で見ている。
**`python/months_safe_selftest.py`**（毎 PR）が、

- `content/months.ts` を読んでいるのが `app/months/` と `components/months/` と
  `content/directory.ts` だけであること
- 出席が持っている欄が「来た日数」だけで、**個人別のコメント数が増えていない**こと

を数えて、1件でもあれば落とす。

公開の Actions ログに「誰がいくら」を並べない、は `python/logsafe.py` が
1か所で持っている。**授賞式のランキングだけは例外で、そこに出る順位・呼び名・
貢献額は、同じ日に公開の面へ出るもの**なので `monthly_tips_run` が出す。
**実額と、呼び名の一覧（`lookupKeys`）と、チャンネルID・どねIDは出さない。**

## 3. 名寄せは図鑑ひとつ

**誰と誰が同じ人か**を決めるのは `islandCharacter`。ほかに作らない。

| 出どころ | 引く鍵 | 当てる欄 |
| --- | --- | --- |
| スパチャ | `author_channel_id` | `channelId` |
| Doneru | 名乗り（`normKey` 済み） | `lookupKeys` |

Doneru 側が `lookupKeys` なのは、**配信中のカードとアラートボックスが
同じ欄で引いているから**（`functions/src/cards.ts` の `iconsOf`、
`functions/src/islandCharacter.ts` の `findBy`）。別の当て方をどこかに作ると、
**画面に出ている絵と、ランキングの並びが食い違う。**

**ちょうど1人に当たったときだけ寄せる。** 0人でも2人以上でも寄せない。
呼び名は誰でも同じにできるので、当てずっぽうで1人選ぶと**別人が公開の面で
表彰される。** 寄らなかった人は消さず、その人ひとりで1行として残す。

## 5. 期間の決め方（月末配信）

**前回の月末配信の日 〜 今回の月末配信の前日**（あやと 2026-09-26）。
9月版なら 8/29〜9/25。**「月初〜月末」ではない。**

出席の分母も、投げ銭も、はじめましての人数も、**全部この同じ期間**で数える。
0時をまたいだ続き枠（開始が 6:00 JST より前）は前日に寄せる。

## 6. 直す前に見るところ

- 額を出す面を足す → **`viewer_yen()` を呼ぶ。** 自分で割らない。
- 台帳から額を足す → **`fx_rate.row_yen()` を通す。** `amount` を直に足さない
  （円以外が素通りするか、直っていない行が 0円 になる）。
  **そもそも足してよいかは 2.1 を見る**（額つきの順位を出してよいのは月ごとのふりかえりだけ）
- 人を結ぶ → **図鑑の `channelId` / `lookupKeys`。** 名前の似ている度合いで当てない
- 本番の数字を作る → **`python/` に道具を置く。** `/tmp` の書き捨てで作らない
- 出す前 → `python3 python/monthly_tips_selftest.py` と、前の月の版との機械差分
