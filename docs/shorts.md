# ショート動画の仕組み（viral-shorts-creator）

配信アーカイブ1本から、初見の人が止まって最後まで見るショートを作り、あやとに見せて出し、
数字を取って次の企画に返す。**この文書は「どう回っているか」と「なぜそう決めたか」だけを書く。**
やることの一覧と進み具合は issue（親 #907）にある。手順はスキル `viral-shorts-creator`。

## 1. 形

```
           ┌──────────────── このセッション（指揮・判断） ────────────────┐
           │ 見どころの判断 / 企画3案 / 原稿・絵コンテ / 品質の判断 / 分析   │
           └──┬───────────────┬──────────────┬───────────────┬────────────┘
   依頼ファイルを push   復号して読む     issue に提出       SSM
              ▼               ▲              ▼                ▼
   ┌─ GitHub Actions ──────────┴─┐   ┌─ GitHub Issues ──┐  ┌─ EC2 の Chrome ─┐
   │ shorts_ingest: YouTube 取得  │   │ 企画を見せる     │  │ 投稿（YT・TikTok）│
   │  字幕・whisper・コマ・音量   │   │ 完成動画を見せる │  │ 数字（Studio 等）│
   │ （結果は暗号化して作業枝へ） │   │ あやとの返事を   │  │ 声（Fish Audio） │
   │ 書き出し・品質チェック       │   │ そのまま読む     │  └─────────────────┘
   └──────────────────────────────┘   └──────────────────┘
              BigQuery: 配信チャット（読む）／ 公開後の数字（書く・非公開）
```

| 置き場 | なぜそこか |
| --- | --- |
| **Actions** で YouTube を落とす・重い処理 | この箱からは YouTube に届かない（プロキシが 403）。Cookie なしの YouTube はボット確認で全滅、`YOUTUBE_COOKIES`（yt-dlp 専用アカウント）を読むだけで通る。4 vCPU・無料（公開リポジトリ） |
| 途中の結果は**暗号化して作業枝**に置く | artifact の実体（blob.core.windows.net）はこの箱から取れない。リポジトリが公開なので、フレームや文字起こしを平文で置くと公開になる。鍵はセッションごとに作り、依頼ファイルで公開鍵だけを渡す（秘密鍵はセッションの外に出ない） |
| 書き出しの本番は **Actions に並べる**（本数 × 本体・双子） | 作業箱の4コアで3本を順に回すと1周 約42分。素材は GCS の非公開バケット（#938）に中身の sha256 の名前で置いて受け渡し、毎周 数百MB を git に積まない（`tools/shorts/render/remote.py`。1周 9分）。中身を直している間は下書き（`render.py --draft`）で回す |
| 下見は **Firebase Hosting のプレビューチャンネル**（7日で消える） | あやとがスマホで開く。この箱から Hosting には届かないので、動画は Actions がその場で作った鍵で包んで git で渡し、Actions が配って確かめる（`tools/shorts/preview/`。3本96MB で85秒）。前の EC2 経由のドライブは35分。GCS（非公開バケットの署名付き URL）も #938 で使えるようになった（`put.py up --place gcs`。作業箱から直に上げて3本37秒）が、1本ずつの mp4 で並べたページが無いので、既定は Hosting のまま |
| **issue** で見せる | スマホから1行で返せる。何を見せて、あやとが何と言ったかが残る（チャットで決まったときは、こちらが書き置く） |
| **EC2 の Chrome** | 投稿（YouTube・TikTok）・数字取り（Studio・TikTok の分析）・ナレーションの生成（Fish Audio の画面）。あやとの依頼で、あやとのアカウントを操作する。運用実績のある道（`youtube-studio` など）なので、規約の文言のグレーを理由に API に寄せない（#911、`docs/island-misses.md` #273） |
| **BigQuery** に数字 | 公開後の数字は非公開の置き場に置く。リポジトリ（公開）には集計した学びだけ |

## 2. 段と、どこまで終わったかの見分け

| 段 | 入力 → 出力 | 終わった印 |
| --- | --- | --- |
| 取り込み | 配信 URL → 材料（字幕・whisper・コマ・音量・場面） | `shorts/.work/<id>/archive/manifest.json` が ok |
| 見どころ | 材料＋チャット → 候補（時刻・文脈・根拠・採点） | 制作 issue に候補の表 |
| 企画 | 候補 → 3案（原稿・絵コンテ・採点・推薦） | 制作 issue に出した版（p1, p2…）と、作る案を言ったあやとの返事 |
| ナレーション | 原稿 → 文ごとの音声と長さ・読みの食い違い | 長さの表 |
| 書き出し | 指示書 JSON → mp4 ＋ 編集データ | mp4 の sha256 |
| 品質チェック | mp4 ＋ work → 19項目の表（`tools/shorts/qa/check.py`。線と理由は同じ置き場の README）と、人の目の検査の帯（`strips.py`） | 終了コード 0。3（needs-human）は人が見てから |
| 完成を見せる | mp4・タイトル・説明文 → 出す案 | 出す案を言ったあやとの返事 |
| 投稿 | あやとが出してと言った案 → 媒体の URL | 投稿の記録（sha256 → URL）。重複は止まる |
| 数字 | 投稿 → 24h/72h/7日/14日 | BigQuery の行 |
| 改善 | 数字＋仮説 → 判定・次の方針 | 仮説の台帳 |

各段は**入力が揃っていなければ止まる**。落ちた段だけを、同じ入力でやり直せる。

## 3. 見せて、出す

- あやとに見せるのは2回——企画（3案）と完成動画。どちらも制作 issue（札 `shorts`）に出し、`call_ayato.yml` で知らせる
- **あやとが「出して」と言った案を、そのまま作る・出す。** 言葉は issue の返事でもチャットでもよい。書きかたは決めない（`A`・`全部`・`Aは今出して`）。書き直しを頼まない。読みかたに迷ったときだけ1回確かめる
- 投稿の担当は、出す前にあやと本人の言葉（issue のあやとのコメントか、チャットの書き置き）を読んで、出す案を確かめる。こちらが書いたコメントを、あやとの返事として数えない
- 機械の関所は置かない。2026-10-15〜17 は、返事の書式を読み分けて記録が無ければ投稿を止める関所があった。書式の読み違いと、書き足したコメントを数えない守りで、あやとに何度も書き直しを頼むことになり、オーナーが「要らない」と言ったので消した（`docs/island-misses.md` #283）

## 4. 決めたこと（なぜ）

| 決めたこと | なぜ |
| --- | --- |
| 書き出しは ffmpeg 直（`tools/shorts/render/`） | PoC で必須要件を全部通し、30秒を約40秒・3回書いてバイト一致。OpenChatCut は編集画面が localhost 専用・スマホで崩れる・テロップの地や縁取りが無い・書き出しが一致しない。比べた表はスキルの参照ファイル |
| 人の微修正は自前のページ（Remotion Player）＋差分をコメントに貼る | 無料の既成ツールに「URL を開くと今回の編集が入った状態でスマホで直せる」ものが無かった。ページに GitHub の鍵を持たせないため、差分は人が貼る |
| 書体 M PLUS Rounded 1c（OFL） | 参考スクショの丸い太い字に最も近かった（12書体を描いて比べた） |
| 字は安全領域（上360・下672・左120・右は下半分192）に置く | YouTube と TikTok の画面の部品に重ならない（広告の型紙と、あやとのスマホのスクショで実測） |
| 配信の右下の「PRISM Live」は消す | 配信ソフトの透かしがアーカイブに焼き込まれている。投稿に透かしを残さない |
| BGM は YouTube・TikTok とも、あやとが選んだ曲を**動画に入れて**同じ1本を出す。説明文・キャプションにクレジット | あやとの決定（#909）。媒体の音源を投稿のときに付ける道は、YouTube は web から付けられず（Studio のエディタが「音声トラックを追加できません。」）、TikTok は付けられたが「商用利用の権利あり」の印が無かった。曲を動画に入れれば、あやとに見せたものと出るものが同じになる |
| **曲は 2026-10-21 からポケットサウンドの「クシコス・ポスト」**（https://pocket-se.info/archives/1223/ 。ネッケの曲のポケットサウンド流のオーケストラ編曲、141.5秒）。クレジットは **YouTube の説明欄・TikTok のキャプションとも `BGM：ポケットサウンド – https://pocket-se.info/`**、TikTok はハッシュタグの行に **`#ポケットサウンド`** も足す。前の **OtoLogic「クシコス・ポスト」（CC BY 4.0、`BGM: OtoLogic（CC BY 4.0）`）は、北マケドニアの回から城塞の回 #977 まで**。**前の回の `post_*.json` を写すと OtoLogic の行が残る**ので、写したらクレジットの行を書き換える | あやとの決定（2026-10-21、#907 の書き置き「今回からBGMを https://pocket-se.info/archives/1223/ に変えて欲しい」。帳面 F-038）。規約（https://pocket-se.info/rules/ 「2023/05/31 版」、2026-10-21 に読んだ）は無料で「商用利用：OK」「音素材の加工：OK」「動画での音素材利用：OK」「YouTube収益化：OK」、条件は「作品でのクレジット表記、またはポケットサウンドへのリンク」。書き方は規約の例「効果音：ポケットサウンド – https://pocket-se.info/」の「効果音」を「BGM」にしたもの（名前とリンクの両方が入る）。TikTok は規約が「ハッシュタグを付けてください」と書いている。規約の YouTube 用の例 `@UCkcmg8yBpJk5I1fwu0sabJg` はハンドルとしては 404（チャンネル ID で、ハンドルは `@pocketse`）なので使わない。禁止は「BGM素材のみをそのまま動画にして」上げること・「音素材そのものの二次配布」・「クレジット表記の未記載」なので、**mp3 はリポジトリにも公開のバケットにも置かない**（あやとから受け取ったものを作業箱で使う）。クラシックなので YouTube の申し立てが付くことがある（規約「異議申し立てを行うと30日以内に解除されます」）。付いたら曲は消さず、規約の FAQ の例文で異議を申し立てる |
| 声は Fish Audio の Holiday Twist。画面（EC2 の Chrome）から1文ずつ作る | あやとの決定（#908）。API の鍵は使わない。1回の生成は UTF-8 で500バイト（日本語で約166字）までなので、原稿は1文ずつ作る。無料プランは料金ページで「個人利用（非商用目的）のみ」。2026-10-28 に無料枠（月 8,000、約7本ぶん）を使い切り、**Plus（月払い・月 250,000・商用利用可能）にした**（#1044） |
| 声を速める倍率は 1.4 まで（`tools/shorts/render/style.json` の `narration.max_tempo`）。道具は Rubber Band の R3。上限で尺に入らない原稿は字を減らす | 1本目は「毎秒9字」に合わせて atempo で 1.73〜1.79倍にし、あやとに「早送りで違和感」と言われた。測ると毎秒10.6拍（参考の目安 9拍より2割速い）で、atempo は継ぎ目の乱れも増えていた。Fish の画面の「速度」は声に効かない。下見の4案と数は `docs/island-misses.md` #285 |
| 比べる相手は2026年の自分のショート33本 | 2024年の動画は数え方が古いまま。継続率も 58.6% と 34.5% で別物 |
| チャットの時刻は 20〜30秒引いて使う | 北マケドニアの回で、字幕の「295レックあります」（0:45:25）にチャット「295レカ」（0:45:53）。見ている側の遅れと打つ時間 |
