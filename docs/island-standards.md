# あやと島に求められている水準

種別: 仕様

**作る前と、出す前に読む。** 個別の指摘の一覧ではなく、**そこから一般化した基準**。
個別の経緯は記録（`docs/island-misses.md`）に在り、記録から出た決めごとは全部この文書か
ほかの仕様に写してある（どの節がどの条かは `docs/island-misses-map.md`）。**作る前に読むのは、記録ではなくこちら。**

あやとの言葉（2026-09-10）:

> 私が求めてるもの（例えば、どう森レベルの品質とか、今まで指摘したこと）を
> 汎用化して（個別の指摘は要らない）反省して永続化する仕組みは作ってね。
> 何度もいうが「何回も同じことを言わすな」

---

## 1. 品質の水準は「任天堂のどう森レベル」


**「前より良い」は基準ではない。** 基準は、**見た人がワクワクするか。**

- 出す前に**自分の目で見る**（撮る）。数字が通ったことは、良いことの証明ではない
- 見て「弱い」と思ったら、それは弱い。**出さない**
- 足りないと分かっているものを出して、あとで下ろすのは**判断していないのと同じ**
- **品質の責任もこちらにある。** 「基準に届いているか」を決めるのはこちらで、
  届いていないものを出したら、それはこちらの判断ミス
- **あやとが見てワクワクするか**が基準（`docs/island-design.md`、および「任天堂のどう森レベル」）

判断に迷ったら「これを配信で画面に出して、視聴者さんに見せられるか」で決める。

## 2. 運営者は我々。**判断も設計も責務**


あやとは承認者ではなく、**意見を言う一人のオーナーユーザー**。

- 「出していいですか」「どちらにしますか」と**可否を預けない**。決めて、やって、報告する
- 面の構成・導線・文言を設計するのはこちらの仕事。
  **「この画面要る？」「統合すべきでは？」を言わせた時点で負け**。
  似た面が2つあれば寄せる。重複した説明は消す。使いにくい導線は言われる前に直す
- あやとに現場監督をさせない
- 意見はもらう。もらった意見をどう反映するかを決めるのも、こちらの仕事

承認を取らずにやること:

- ブランチを切って実装し、コミットする
- PR を作って、自分でマージする
- master にマージしたあと、本番へデプロイする
- 作業の粒度・順番・設計の判断をする
- **出す / 出さない / 下ろす の判断**

**やったことは必ず報告する。** 壊れうる変更（既存の配信用ページ、Firestore のルール、
GitHub Actions の秘密情報まわり）は、やる前に一言添えてから進める。
**一言添えるのは知らせるためで、許可をもらうためではない。**

## 3. ただし、**仕様が曖昧なら聞く**


「判断してよい」は「解釈で埋めてよい」ではない。**両者は矛盾しない。**

- 決められること（作り方・設計・出す出さない）は**決める**
- 決められないこと（何が欲しいのか・どちらが正解か）は**聞く**
- 見分け方: **こちらの調査で答えが出るなら決める。あやたの頭の中にしか
  答えが無いなら聞く。** 調べずに聞くのも、聞かずに推測するのも、どちらも駄目

**「決めて、やって、報告する」のは、やり方・順番・品質の話。
ユーザーが何を求めているか（仕様そのもの）は、こちらが決めるものではない。**
分からないまま自分の読み方で埋めると、出したあとに全部やり直しになる。

指示に幅があるとき——何を作るのか、どこまでが対象か、出来上がりが何に見えるか——は、
**作る前に1行で言って合わせる。** 自分に都合のいい読み方で進めると、
出したあとに全部やり直しになる（`docs/island-misses.md` の #3 #4 が実際にそれ）。

### 聞きかた（仕様の認識が合わないと分かったら、チケットで聞く）

- **チャットで聞かない。GitHub issue を立てる。** 会話に埋もれるし、
  セッションが変わると消える。あとから「何を聞いて、何と答えたか」を引けるように残す
- **聞く前に、いま動いているものを数える。** 「どうしますか」だけを投げない。
  **いまの実装が何をしていて、実測でどうなっているか**を先に出す
  （#568 がその形。「11人中4.2人が3ヶ月来ていない人」まで測ってから聞いた）
- **選択肢と、選んだ場合の数字を並べる。** 決める人が計算しなくていいようにする
- **答えを待つあいだは止まらない。** 他の作業を進める。
  1件の回答待ちで全部を止めると、こちらの手が空くだけで誰も得をしない

通知が実際に飛ぶ形で呼ぶ手順は `/ask-ayato`。

### **島の約束**に触るものは、調べて答えが出ても決めない

上の見分け方には穴がある。「投げ銭していない人も候補に出す」は、
コードを読めば**技術的には**答えが出る。出るので決めてしまった
（`docs/island-incident-2026-09-14-cards.md`）。

**技術的に答えが出ることと、決めてよいことは別。**
次の3つは、調べて答えが出ても**作る前に1行**。

| | 例 |
| --- | --- |
| **誰が何をもらえるか** | 投げ銭の特典、カード、称号、順位、並び順の優遇 |
| **誰が何を見られるか** | 公開する範囲、名前の出し方、過去ぶんの見せ方 |
| **誰が何を押せるか** | 書ける人、消せる人、1日の上限 |

見分けの言い方をひとつに:
**「これは視聴者さんとの約束か、作り方か。」約束なら、聞く。**

そして、**約束を「中のデータの形」で言い換えない。**
「`islandCards` の書類は増えないから特典は変わっていない」は、
実際にやった言い換えで、**受け取る人の手元には同じ画像が残っていた。**
数えるのは**受け取る人の手元に何が残るか**であって、書類の件数ではない。

## 4. 直したと言う前に、**本番で確かめる**


- 差し込み（テスト用の値）は**本番と同じものにする**。違う値で確かめると、
  直っていないものが直って見える（`docs/island-misses.md` #1 が実際にそれ）
- 合否は、見た目の印象ではなく**通信・データ・画素**で決める
- **判定の向きが、目的を変えたあとも合っているかを見る**
  （「消えたら合格」の判定を、出すように変えたあとも使うと、正しいものが落ちる）

### 配り終わりを待つ合図は、**その変更でしか現れない字**にする（2026-09-17）

デプロイを待つのに「本番にこの字が出たら」で見張る。ここで**前から在る字**を選ぶと、
1回目の問い合わせで当たって、**配る前の古い版を「配り終わった」と読む。**

2026-09-17 に2回やった。

| 待った合図 | なぜ嘘になったか |
| --- | --- |
| `/map` に「いま歩いている旅もふくむ」 | **その字は前から `/map` に在った**。待ちの上限で抜けただけなのに、一致したように読めた |
| `/kitchen/french-toast` に「No.13」 | 面そのものは前から在る。**変わったのは焼き込みの1行だけで、画面には1画素も出ない** |

選びかたは2つ。

1. **その変更でしか現れない字**を選ぶ（消えるほうでもよい。
   「`/map/iran-border` から**カ国目が消えたら**」で待って、正しく待てた）
2. **画面に出ない変更なら、画面で待たない。** 焼き込みのデータだけが変わったときは、
   出たかどうかを画面で確かめようがない。**その変更が効く先**——見張りの終了コード、
   配ったファイルのバイト列——で見る

**「合図が前から在る」は、対照が通らないのと同じ形。** 何を測っても通るものは、
何も測っていない（15章）。

### 本番で確かめる道具（`tools/sprites/prod.mjs`）

**この箱のブラウザは本番に届かない**（proxy が `ERR_CONNECTION_RESET` を返す）。
それで「ローカルの書き出しで確かめた」で済ませていた。出したものと違う。

curl では取れるので、ブラウザの要求を横取りして curl の結果を返す。
`viaCurl(ctx)` を `apply(ctx)` より**先に**呼ぶ（あとから登録した route が先に効く）。

```bash
node tools/sprites/prod.mjs        # 出したものを開いて、顔が出ているかを見る
```

**通すのは本番と顔の置き場（yt3 / lh3）だけ。外を止めたまま撮ると顔が「落ちた」と出て、
直っているものを直っていないと読む。**

## 5. 1件直したら、**横に展開する**


指摘は「見つかった1件」であって「直すべき全部」ではない（`docs/island-misses.md` #5 #6）。
**1件直したら、同じ理由で壊れているところを探しに行く。**

- データを直したら、それを読む画面・ルーティング・文言・導線まで見る
- 同じ形の間違いが他の面にもないか探す

## 6. 画面で、**システムの仕様を説明しない**


書いてよいのは、**その人がこれから何をするか／何が起きるか**だけ。

- 条件の説明（「〜な人には出ます」）、内部の決めごとは書かない
- 重複した説明は消す
- 「どういう条件でこう出しているか」は中の話で、読む人には要らない。迷ったら消す
- **説明が要る画面は、画面のほうが間違っている**（`docs/island-misses.md` #7）

## 7. 溜まるものは、**溜まっても背が変わらない形**にする


あやとの言葉（2026-09-10）:

> マイページの貼った付箋も縦長すぎる。溜まってきたので、
> **こういう、データが溜まった時の設計が甘いので水平展開すること。**

データは必ず増える。付箋も企画もカードも配信も、来てくれるほど増える。
**「いまは3件だから大丈夫」で作った面は、半年後に必ず壊れる。**

- 増えるものを縦に積まない。**畳む**（`components/ui/Longer.tsx`）
- 増えるものが**2つ以上ある面**は、畳むだけでは足りない。畳んだものが縦に並ぶ。
  札で切り替えて、**同時に1つしか出さない**
- 用事の違うものを1つの面に積まない。**面ごと分ける**
- 出す数は、**1件の背**で決める。1件が4段ある道具は4件、1行のものは6件
- 上限で切らない。押せば最後まで出る。**畳むことと、読ませないことは違う**

**作る前に「これが200件になったら」を1度考える。** 0件・数件・数十件・数百件で
撮って、どれも同じ背で収まることを確かめる。

### 背が変わるのは、溜まるときだけではない。**出るときにも変わる**

静的書き出しなので、画面が出てから入る値がある（いまの距離・いる場所・
今日が何日目か）。**焼いた HTML と、値が入ったあとで背が違うと、
読み始めたところで画面が飛ぶ。** `/nordic` のいちばん大きい札が 84px 飛んでいた
（`island-misses.md` #145）。

- **置き換わる札**（前も後ろも1つ出る）は、**出るまえに場所を取る。**
  取る大きさは**中身の字数ではなく字の大きさ**から決める（#530 / #145）。
  いちばん確かなのは、**出たあとと同じ形の写しを字を出さずに置く**こと
- **増える一覧**（掲示板・写真・額）は長さが先に決められない。
  こちらは「中身の形をした薄い板」で受ける（`island-design.md` 4章）
- 確かめは **JS を切った回と入れた回の引き算**。
  **切れている印（`self.__next_f`）を毎回1つ出す**——切れていなければ
  差はいつも 0 になり、何を測っても「直っている」と出る。
  道具は `tools/sprites/jsjump.mjs`

## 8. 名簿・一覧を**手で作らない**


街・国・企画などの一覧は、元のデータから導出する。手で書くと、元が変わったとき
**片方だけ古くなる。**

### 足し算で作った一覧は、**足して届かない範囲を数える**（2026-09-19）

出どころを2つ足して一覧を作ると、「A に無いものは B が持っている」と書きたくなる。
**書いた時点では確かめていない。** `prodsweep.mjs` の面の一覧がそれで、
sitemap と `site/app` の静的な道を足していた。**どちらも動く段（`[chapter]`）の
中身を知らない**ので、`/island/<章>/streams` の4面——いちばん大きいもので
949,893B——が、**在るのに誰も見ていない面**として残った（`island-misses.md` #174）。

- **2つ足したら、2つとも知らない面が在るかを1度数える**
- 同じものを数える一覧が**2つ以上あるなら、食い違いそのものを判定にする。**
  揃わなくてよいものは在るので、そこは**理由を機械の読める場所に**置く
  （12文字以上・日付つき。`prodsweep.mjs` の `ABSENCES`、`python/watch_excuses.py`）

### 導出していても、**何を数えているか**は別に確かめる

`/all` の「島にある紙、122枚」は `SHELVES` から導出してあった。それでも嘘で、
並んでいた紙は 121 枚だった——**行を数えていて、行き先を数えていなかった**
（いまいる島の行は `/` へ送るので、同じ紙を2回数えていた）。
**画面が名乗る数は、画面に並んでいるものを数え直して突き合わせる。**

## 9. 細かいのは、**エージェントに配る**


こちらの責務は**マネジメント**であって、目の前の1ファイルを直すことではない。
1ファイルの中で閉じる作業は、指摘が来た時点で渡す。渡すときは
**合格の条件・確かめかた・触ってよい範囲**の3つを必ず添える。

自分で書き始めると、視野がその1ファイルに落ちる。**もぐら叩きはそこから始まる。**
自分の手を動かすのは、配る前の判断と、出したあとの確認まで。
1ファイルの中で閉じる作業は、画面1枚の作り直し、文言の書き換え、道具の追加、データの焼き直しのこと。

配るときに必ず渡すもの:

- **合格の条件**（何が見えていれば通るか。「前より良い」は条件ではない）
- **確かめかた**（どの道具をどう回すか。無ければ作るところまでが仕事）
- **触ってよい範囲**（他の担当と同じファイルを踏ませない。worktree を分ける）

こちらに残る仕事:

- どの指摘が同じ根っこかを見て、**まとめて1人に渡す**
- 上がってきたものを**本番と同じ条件で確かめてから**出す
- 誰も見ていない面（指摘の来ていない面）を**先に見に行く**

**「自分でやったほうが速い」で抱え込まない。** 速くても、視野が1ファイルに落ちる。
依頼文の型は `/hand-off`。

## 10. **読めていないことを、値0と同じ絵にしない**


外から取ってくるものは落ちる。旅の最中は電波の弱いところを通る。
**「読めなかった」と「0だった」は別のもの。** 同じ見た目にすると、
届かなかっただけの日に「0でした」と言い切ることになる。

- 字で「読めなかったら出さない」にしているなら、**絵も同じにそろえる。**
  同じ面の中で、字と絵が違うことを言ってはいけない
- 読めていないときの姿は、**0のときと見分けがつくこと。**
  作り方は `docs/island-design.md` 4章（場所だけ先に取って、中身の形を薄く置く）
- 確かめかたは、**API を落とした状態で撮って、0のときと並べて見比べる。**
  見分けがつかなければ直っていない。面ぜんぶを機械で洗うのは
  `tools/sprites/zeroclaim.mjs`（落として1回・通して1回開いて、
  **どちらでも同じ「0◯」が出る場所**を並べる）
- **言い切りは数だけではない。** 「今日は出ていません」は 0 を1つも含まないので
  `zeroclaim.mjs` では永久に捕まらない（#116）。**言葉のほう**を洗うのは
  `tools/sprites/negclaim.mjs`（折りたたみ・札・「あと◯件だす」・帳面の送りを
  開いてから読み、**通したときだけ出る否定**を別枠で並べる）。
  どれが嘘かは機械に決められないので、**候補を並べるところまでが道具の仕事**
- **面の単位で分けても、その面が読む口が2値ならそこだけ2値に戻る**（#115）。
  読みものを1つ足したら `Read`（wait / ok / down）も一緒に足す。
  `Record` や配列だけ返す口は、落ちたときに空と見分けがつかない
- **`||` と `??` で 0 を畳まない。** `0 || fallback` は 0 を落として、
  いちばん言ってはいけない値を通す。「数が無い」は `undefined` のまま持って、
  出すか出さないかを画面で決める
- **口が「上位N件」を返すなら、載っていないことを 0 と読まない。**
  `limit` の付いた口の答えは3種類ある（値／載っていない／読めなかった）

## 11. **同じものの段階を並べるときは、完成形から引き算で作る**


段階（建設中→完成、下書き→清書）を並べて見せるとき、**各段階を独立に組むと
寸法が揃わない。** いちばん出来上がったものを基準にして、そこから引く。

- 合っているかを**目で見ない。測る。** 幅・高さ・上端を数で突き合わせる
- **並べた絵は、出す前に自分で開いて見る。** 作って満足して終わらない

## 12. **数式や定数を、別の画面へそのまま持っていかない**


その値が**何のために決められたか**を見る。小さく並べる一覧のために決めた
下駄は、全画面で1つを主役に出す画面のために決めた値ではない。
式が正しくても、当てる先を間違えれば絵は壊れる。

## 13. **当座の判定は、まずその判定を疑う**

不具合を見つけたと思ったら、**サイトを直す前に、自分の判定が正しいかを確かめる。**
2026-09-10 の1日で、その場で書いた判定が**3回**「不具合だ」と言って、
**3回とも判定のほうが間違っていた。**

| 判定が言ったこと | 本当は |
| --- | --- |
| `/nordic` に横あふれ20件 | SVG の中の `<path>`。ページは横に動かない（`scrollWidth == clientWidth`） |
| 旅の全面で React の水あわせエラー | 差し込んだ偽の時計が原因。本番は0件 |
| `/cards` に落ちた画像1件 | 自分の横取りが `firebasestorage` を止めていた。本番は 200 |

共通しているのは、**測るために作った仕掛けが、測る対象を変えてしまっている**こと。
横取り・偽の時計・要素の数え方は、どれも本番には無いものです。

**確かめかた:**

- **本番そのものを開いて、同じ判定が出るか見る**（`tools/sprites/prod.mjs`）。出なければ判定のせい
- 数える前に**何を数えているのかを1件だけ目で見る**（クラス名・URL・要素）
- 止めた通信・差し替えた値を**一覧に出す**。止めたものが原因の「落ちた」は毎回起きる
- **既にある判定と食い違ったら、新しいほうを疑う**（巡回は「横あふれ0」と言っていて、そちらが正しかった）

**間違った報告をしないために、これは効きます。** 3回とも、報告する寸前で止まりました。

## 14. 「あとで」を自分で決めない


重い・危ないと思ったら、後回しにするのではなく**そう言って判断を仰ぐ。**

## 15. **「0件」は、何件見たかを出させてから読む**

2026-09-15 に、この章の下のチェックに**名指しで載っている道具3本**が、
404 のページを測って「合格」と言っていたことが分かった。

書き出したものを静的に配ると、開けるのは `/about.html` であって `/about` ではない。

### 島の面ぜんぶに当てる（2026-09-17 / 分母を直したのは 2026-10-07）

上の表の道具は、**面を手で渡す。** 渡さなければ回らないので、
`hitbox` は長いこと **2面・札は `.crumbs a` だけ**、`inkpx` は **3面**しか
見ていなかった。「押しどころ 48px 以上・字の濃さ 4.5 割れ 0」という
下のチェックは、**26面のうち2面と3面のことだった**（`island-misses.md` #130）。

**そのとき置いた「26面」も、島の全部ではなかった。** 書き出すと島は
**26面よりずっと多い**（2026-10-07 に数えて 138面、2026-10-13 に 141面。
**数は増え続けるので、ここにも書き写さない**——下の `counts.py` が出す）。
一覧を手で並べていたので、面が増えても増えなかった——
**112面が「数えないまま 48px 割れ 0」に数えられていた**
（`island-misses.md` #221）。いまは `tools/sprites/islepages.mjs` が
**書き出したものを歩いて**面を出す。

**ここに書いた 138 が、6日で嘘になった**（料理33→39・伝説9→8・面138→141）。
数えかたは正しいのに数だけが古くなる、いちばんよくある壊れかたで、
直すたびに同じことが起きる。だから**数を書くのをやめて、数えかたを名指しする。**

```bash
python3 python/counts.py     # 焼き込み・章・歩いた国・図鑑・料理・伝説・面…を、その場で数える
```

**0 を答えとして出さない**（置き場が動いたら 2 で落ちる。対照は
`python/counts_selftest.py`）。面だけは書き出してからでないと数えられないので、
**先に `tools/build.sh <ポート>`。**

面ぜんぶを一度に回すのは `tools/sprites/tapink.mjs`。

```bash
tools/build.sh 3150
python3 -m http.server 4150 --directory site/.next-3150 &
PORT=4150 node tools/sprites/tapink.mjs     # 0＝通った / 1＝見つかった / 2＝数えるものが無い
PORT=4150 ONLY=hit node tools/sprites/tapink.mjs    # 1本ずつ（hit / shots / px / band / ink）
```

自分では1行も測らず、`hitbox` `shotstable` `inkpx` `inkband` を子として起こして
**終了コードだけを読む。**（138面 × 4とおりで、ひと回り1時間45分かかる。
時間で切られる所から回すときは `ONLY=` で1本ずつ。**4本ぜんぶの終了コードを
見るまで「島を測った」とは言えない**）走らせ役にも対照があり、
**わざと落ちる子を1本ずつ起こして 2 が返ることを見てから**本物の面を測る。
一覧が `sitemap.xml` より少なければ、**数字を出さずに落ちる。**

**その日の実測は、この手引きに書かない。** 2026-10-08〜09 に初めて全面へ当てた
2日で、面の数は **138 → 140 → 141** と動いた（北マケドニア・グッズの面が入った）。
押しどころの数も、カードが押せるようになった日に増えている。
**数を書いた瞬間から古くなる**ので、そのときの実測は日付つきの記録のほうに置く
（`island-misses.md` #216）。ここに書くのは**読み方**だけ:

- **「割れ 0」は、見た面の数と一緒に読む。** 「0件」ではなく「141面 / 6,778個中 0件」
- **測れなかったものを 0 に混ぜない。** 押しどころなら「当たりが測れず N 個」、
  濃さなら「拾った / 測れた」の2つ。測れた割合が 0.9 を切る面があれば、
  道具は 1 ではなく **2**（数えられなかった）で落ちる
- **1回で全部は回らない。** `ONLY=` で1本ずつ回すと、途中で切られても
  そこまでの終了コードが残る。**4本ぜんぶの 0 を見るまで「測った」と言わない**
- **測っているあいだに master が動く。** 動いたら面が増えるので、
  **出す直前にもう一度回す。** 一覧は書き出しから作るので、面を足した人が
  何もしなくても増える——**増えたことに気づくのは回した回だけ**

出た件の読み方は、1回目の2日ぶんを下に残す。

**押しどころで出た6件は、5件が本物・1件が測りかただった。**
本物は `/island/<章>/streams` の帰り道（見た目 49px・当たり **35px**）。
`--tap-inline: 15px` という値の根拠が**章の島1面で測ったもの**で、
同じ札が出る配信の面では真上が畳みの箱で1px も空いていなかった。
残り1件は `min-height: 48px` の押しどころで、**箱はちょうど 48.00px あった**——
1pxずつ伸ばす測りかたの目が粗く、同じ札が面によって 47 と 49 に振れていた
（§13。道具のほうを直した。いまは境目を 1/16px まで詰めて、**合否は 1px の目**で出す）。

**濃さは、面ぜんぶを1枚に撮る側だけでは足りない。** `content-visibility: auto` の段は
その撮りかたでは描かれないので、26面の回では 284か所が「測れなかった」に落ちた
（`/` は 120か所中 58か所）。画面のぶんずつ送って撮り直すと測れて、
そこで `/nordic/finland` の札4件（4.10〜4.50）が出た。**「割れ 0」は、
測れた数と一緒に読む**（`inkrate.mjs` が、測れた割合が足りない面を 2 で落とす）。

**字の濃さは dpr2 で測る。** dpr3 で背の高い面を撮ると、何も変えていない2枚が
食い違って（`/nordic/guide` で 540万画素）、**足りている字が大量に割れる。**
だから `tapink` は濃さの前に `shotstable.mjs` を通す。
**その関門は、関門をかける相手と同じ条件で測る**（2026-10-07 まで、公開面だけ
島を止めずに撮っていた。止めた側で測る濃さの関門が、動いた側で落ちていた）。

**測る前に、測る道具の手元を数える。** 住人の絵（`chars.py`）とサムネイル
（`avatars.py`）は、落としていないと既定の絵に倒れる——**絵は出る。**
`route.mjs` が「本物で返した枚数」を印字するので、**`0/N` が出ている回の絵は
読まない**（`plain-256` を落としていなかったあいだ、料理の面の10人は全員
同じ顔で、配信58本のサムネイルは58枚とも同じ写真だった）。
- **0件で黙って終わらせない。** 数えるものが1つも見つからなかったら、
  終了コードを分けて（0=通った / 1=落ちた / **2=数えるものが無い**）、
  何が見つからなかったかを並べる。手本は `tools/sprites/cardshot.mjs`
- **口と画面を突き合わせる。** 「この写真には12人立てる」と口が言っているのに
  顔が12でなければ落とす。片側だけ見ていると、両方0のときに気づけない
- **旗を回す人に預けない。** `STATIC=1` のような立て忘れで壊れる作りは、
  注意書きであって守りではない（#96）。開くところで止める（`tools/sprites/served.mjs`）
- **対照は、足の数だけ用意する。** 「壊し方を4通り当てた」は、その4通りが
  同じ足を折っているなら1通り。**判定の足を1本ずつ抜いて（`BREAK=`）、
  そのたびに対照が落ちること**まで見る（`island-misses.md` #128 の決めごと1）
- **診断を足したら、壊した写しで落ちることまで見る**（`island-misses.md` #99）。
  **その前に「壊していない写しが通ること」を先に見る。**
  写しを作る途中で壊れても終了コードは同じなので、そこを見ないと対照にならない

## 16. **入口の札に、0件になりうる時制を入れない**

あやと（2026-10-01、何度目かの指摘）:

> ルーティングが下手すぎ。根本的に再発しないように徹底的にみなおして。
> すべて。（例、北欧旅は「これから」ではない。）

数えた（本番・2026-10-01）。**時制を名乗る札 24件のうち、嘘が4件。
4件とも行き先は `/next` ひとつ**だった。

- ナビの札も、パンくずも、h1 も「これから」
- 中身は 9/6 のフード＆ワイン祭りと 9/11 のジョージアバイバイで、**ぜんぶ過去**
- **同じ画面が、自分で「いま 0 つ立っています」と正しく数えている**

**数は合っていて、札だけが嘘だった。** そして半月、誰も赤くならなかった。

### なぜ戻るのか

**札を固定の字で持ち、中身を日付で数え直しているから。** 両者は必ずいつか
食い違う。1件ずつ直しても、次に日が進めばまた食い違う。
直しかたの問題ではなく、**食い違いが起きたときに赤くなる場所が無い**のが問題。

### 決めごと

1. **常設の入口の札に、0件になりうる時制を入れない。**
   「いまどこ」はよい——`/now` は**いつでも「いま」がある**。
   「これから」は駄目——これから分が 0 件になる日がある。
   **時制は中身の側が言う。入口の札は時制を名乗らない。**
2. **時制を名乗るなら、中身から字を作る。** 固定の字にしない
3. **同じ行き先に、短い札を2種類付けない。** 人は別の部屋だと思う
4. **`tools/sprites/navtruth.mjs` が、これを毎回数える**（`重い見張り` に入れてある。
   master と毎晩。2026-10-16 まで `Selftests` の毎 PR だった。#281）。
   面を足しても札を足しても、名簿を直さずに勝手に見に行く

### 件数も時制のうち。そして**「0件の日に言い方を変える」では足りない**（2026-10-12 / #770）

決めごと1を守ったつもりで、**0件の日だけ別の字を出す**作りにしていた。
`/board` の札は「これから／いま 1 つ立っています」と「企画／やってきたことの記録」を
数で切り替えていて、数え直しは `useEffect` のあと。**開いている人の目には合っている。**

合っていないのは**焼いた HTML のほう**。`output: "export"` なので、出した日の字が
そのまま配られ続ける。10-12 に焼いた「いま 1 つ立っています」は、その企画が
終わった翌日からも本番に出たままだった。**画面では直っているので、
ブラウザで見ても分からない。**

- **言い方を変えられるのは画面が出てからで、焼いた字は動かない。**
  入口の札には、**時制も件数も**置かない
- **「終わったもの」も時制**（`tenseOf` は過去の札として読む）。札が言うのは
  **行き先が何の置き場か**だけ
- **`navtruth` は焼きたてしか見ていない。** CI は build → 判定の順なので、
  焼いた日はいつも合っている。**時計を進めて数えるのは
  `tools/sprites/nextempty.mjs`**（`重い見張り` の browserwatch に入れてある。
  2026-10-16 まで `Selftests` に在った。#281）。
  札の字が日で1文字も変わらないことと、0件の日に黙っていないことを見る

  ```bash
  tools/build.sh 3150
  python3 -m http.server 4150 --directory site/.next-3150 &
  SPORT=4150 OUT=/tmp/nextempty node tools/sprites/nextempty.mjs
  ```

### 「今夜は◯◯の日」は、**日付を持っているものから引く。無ければ黙る**（2026-10-12）

`/streams` は**その月の最終日**を月末配信の日として名乗っていた。実測では
9/26・8/29・7/26・6/28・5/31 で、**最終日だったのは1回だけ。** 2026年11月は
最終日が月曜なので、そのままだと 11/30 に嘘になる。曜日に賭け直しても当たらない
（土3回・日2回）。

**暦から当てにいく字は、当たらない日が必ず来る。** 日付を持っているもの
（`content/plans.ts`）にその回が立っていればその日だけ言い、立っていなければ
**何も言わない。** 日付の計算が1つも残らなければ、日が進んでも古くならない。

### 字を替えたら、**行の折れ方**まで読む（2026-10-12）

0件の見出しは、撮った絵の中で 390px でこう折れていた——
「日にちの決まった企画／**は、**いまはありません」。**撮ったのに読んでいなかった。**
`text-wrap: balance` は行の長さを均すだけで、どこで切るかは選ばない。

- **折ってよい場所を減らす**のがいちばん確か（`components/ui/Phrase.tsx`。
  塊ごとに `white-space: nowrap`）。`word-break: auto-phrase` は Chromium にしか無い
- **幅を振って、行の頭を数える**（`nextempty.mjs`。行頭に来てはいけない字で
  始まる行と、1〜2文字しか乗っていない行）。目で1つの幅を見るだけでは出ない

- **22.2** 節から決めごとが出たら、同じ PR で仕様に条を足すか、既に在る条を指す。対応は `docs/island-misses-map.md` に1行足す（`この節かぎり` も1行）。1つの決めごとは仕様の1か所にだけ置く。抜けは `python3 python/misses_rules_selftest.py` が止める
- **22.3** 足す条が既に在る条と食い違ったら、どちらを採るかを決定の記録（`docs/adr/`）に1枚書いてから、仕様を直す

## 23. **測る**

- **23.1** 前と後・A と B は、同じ道具・同じ条件・同じ送り方で測って見比べる。数が動いたら、まず前の道具をもう一度回す。絵を変えない直しは前後を画素で、焼き直しは1バイトも変わらないことで見る
- **23.2** 原因・前提・人から渡された数は、見え方・記憶・話から決めない。データを引いて決める。「直っていない」と言われたら、まず現況を対照つきで測る。傍証を測定の代わりにしない
- **23.3** 別の問いは別々に数える（焼けているか／出ているか、古い／足りない、拾った／測れた、取り込めた／見られる、戻る／戻らない、誰が取り消したか）。1つの数で読まない
- **23.4** 割合は、分子と分母を別々に、同じ単位で数え直す。全体の数・全部の合計を分母や上限にしない。丸めてから比べない。1つの測定から出た数どうしは、足し合わせて矛盾しないかを見てから出す
- **23.5** 画面に在る・無いは、書き出しの字や grep の生ヒットで決めない。面を開き、下まで送り、畳みを開き、描かれたもの（`innerText`・`textContent`・画素）で数える。画面で数え直されるものは、落ち着くまで待ってから読む
- **23.6** 読む絵・数・記録は、いつ作られたか（いつ時点か）を見てから読む
- **23.7** 「在る」ではなく「効いている」で判定する。リンク切れ0は行き先が合っていることではなく、式が合っていることは出口まで数えてから言う。測る前に変わるはずのものを1つ決め、それが変わったかを見る。道が複数あるものは、いちばん狭い道で確かめる
- **23.8** 合っているかを目で見て決めない。測る。数が揃ったこと・型が通ったこと・数字が正しいことを、中身が良いことの証拠にしない。絵でおかしいと思ったら、字（コードの並び）で裏を取る
- **23.9** 確かめる相手は、自分の計算の外から取る。写して作った道具は写していない実装と、モデルで数える見張りは実物と、同じものを数える別の口とは答えを突き合わせる
- **23.10** 当たりを付けた直しは、手元で1回動かしてから本番へ持っていく。走らせずに分かることは、走らせる前に出す。「直せる」「N件を直す」は、当てて・下見して N を数えてから言う
- **23.11** 測る道具が、測るものを変えない（面を開き直さない・押すと閉じる面・貼り付いた頭・動き終わり・揺れ）。道具の目の粗さを面の不具合として出さない。旗や段で道が分かれる道具は、本番と同じ値で回す
- **23.12** 「取れた」は、何バイト・`size`・`sha` まで見て言う。抜き取りの標本は毎回ずらし、抜き取りの数を全体の数として書かない

## 24. **撮る**

- **24.1** 撮った絵は、出す前に自分で開いて見る。撮れているか・用が足りるかで見て、きれいかで見ない。1枚直したら並べた全部を、一覧ではなく詳細の面まで見る。道具が緑でも本番の面を見る
- **24.2** 入力（人・日付・件数・状態）で変わる面は、それを替えて撮って並べる。日付で変わるものは、その日を過ぎた形でも撮る。「出るはず」の形・増えたあと・入れ替えたあとの形を撮る
- **24.3** 差し込み・差し替え（偽データ・`route`）は、本物の形と寸法から作り、本番と同じ値を置く。差し替えた数は撮る道具が自分で出し、1枚に潰さない。偽の宛先は、その道具が通す先か道具自身にする。差し替えた宛先の絵は、生死を判定しない。注に「あの道具が差し替えてくれる」と書かない

## 25. **見張りと道具**

見張りの対照（壊して赤くなるか）は §15。ここは、見張りが何を覆い、いつ鳴るか。

- **25.1** 見張りは、守るものを全部覆う。拾い方は「全部拾って、外すものだけ名前で断る」とし、断った名前が在るかを見て、消えたら赤くする。見ていない側・見ないと決めた側も同じ表に理由つきで並べる。道具の名前・手順書の curl・「いま壊れていない」を、覆っている範囲の代わりにしない
- **25.2** 繋いだ見張り・ワークフローは、走ったこと・発火したこと・定時の回が1度まわったことを数えるまで「繋がった」と言わない。冗長にしたら、1本ずつの生き死にを数える見張りを同時に置く
- **25.3** 毎晩ひとりでに回るものは、量だけでなく、中身が埋まっているか・入るべきものが入ったか・減っていないかを見る。人が書いた表から来る数は、1つでも減ったら止める。ひとりでに書く道を増やしたら、受ける側の見張りも足す
- **25.4** 誤検知・満たしようのない見張り・毎回出る赤は、見張りが無いより悪い。不具合でないものを赤にしない。しきい値と番兵を、いまの実測値の写しで決めない。機械で判定できるぶんだけを道具にし、できないぶん（語の表で落とすしかないもの）は決まりに書く
- **25.5** 見張りが測るものは、見張りの説明文と同じものであること。字面ではなく中身で見る。道具が通ったことを、決まりを守った証明にしない。同じ穴を見る道具が複数あるなら、関門と対照は1か所から呼ぶ。判定は、リポジトリの中の道具に置く
- **25.6** 赤が出たら、まず見張りが正しいかを見る。赤を消すために、見られている側を直さない・見張りを緩めない。緩めたら緩めたぶんを書く。いつも赤い見張り・鳴っているのに直らない見張り・仮の値で黙らせた見張りを、そのまま置いておかない
- **25.7** 時間の軸で見張る。猶予は「直しが動き出してから」の時計で測り、「まだ来ていない」の境目に猶予を置く。1日で合格にしない
- **25.8** くり返す数え方・確かめ方は、書き置きにせず、回せる道具にして git に入れる。名指しする手引きの側が回す。人が目で見つけた穴は、その場で機械に移す。道具の中に、リポジトリの場所・画面の名前を直に書かない。長く回る道具は、かかる時間を書き、途中経過を出し、落ちたところから先を捨てない。足す前に、その名前が空いているかを見る
- **25.9** 道具は、外れたものの名前（どれが・どこが）まで出す。渡したものと測ったものの数が合っているかを、道具に言わせる。ログを切るなら頭を切り、終わりを残す

## 26. **落ちたとき**

読めていないことを0と同じ絵にしない、は §10。ここは、落ちたときに何を出し、何を開けておくか。

- **26.1** 落ちたときの面は、少なくとも2通りの落とし方（`abort`・`503`・返さない）で確かめる
- **26.2** 読めていない相手に、書ける口を開かない。上書きになる口は、読めるまで押させない。書くときは、送られてきた欄だけを書き替える
- **26.3** 配信に映る面は、落ちても字を出さない。印を重ねる（面を差し替えない）。何も出さないなら、地の色まで消し、消えたことを alpha を持つ形で撮って数える
- **26.4** 黙らせる・隠す・落とすなら、黙ったことに誰がどう気づくかを1行で言う。片づけの操作が、片づいていないことを消していないかを見る
- **26.5** エラーの字・警報・札は、原因ごとに分ける。人が直せる話と、こちらが直す話を同じ字で返さない。横取りの道具は、本番の状態番号と型をそのまま返す。出せない理由は、機械が読める形で返す
- **26.6** 一部が落ちても、乗っている塊・入口を道連れにしない。控えに「落ちた」を書くなら、捨てる道を同じ場所に置き、「押したら直る」は押して確かめる

## 27. **データの正**

- **27.1** 1つの値・判断・数は、1か所に置く。同じものを入れる口・同じ問いに答える式・同じ仕事をする入口を2つ作らない（重なったら共通化ではなく統合する）。2つになっていたら、本番に届いた回数で残すほうを決め、入口だけ捨てて中身は移す。複数が読む値は、どちらでもない置き場に置き、書き写すなら出どころを名指す
- **27.2** 一次情報（本人の言葉・会話・字幕・実績）を正にする。一次情報を人が打つ欄に置かない。導出したもの・コメントから推したものを、事実と同じ強さで言わない。「◯◯から焼く」と書くなら、本当に◯◯を引く
- **27.3** 突き合わせの鍵は、両側から1件ずつ持ってきて確かめてから使う。名前が似ている・値が一致しているだけで同じものにしない。配信について数えるときは `video_id` で切る。鍵（slug・突き合わせの字）を、表示の都合で切ったり変えたりしない
- **27.4** 移す・消す・置き換えるときは、元でできていたこと・外部依存・移行前の値を数えてから移す
- **27.5** 本番の表を書き換える道具は、落とす相手を入力で受け取らない。巻き込んではいけないものには守りを2枚かけ、二度流したら 2 で止まる形にする。口が画面から呼べるなら、道具を書かない
- **27.6** 状態は、終わりのある形で持つ。移すとき、理由を空で潰さない。印は真偽ではなく「何について」を一緒に持つ
- **27.7** 1つの式・欄・並び・つまみ・部品に、2つの問いを兼ねさせない（見本と最新・絵の並びとたどる列・固定の字と行き先ごとの字）
- **27.8** 入口で、空のまま生まれない形にする。作れないなら、空のまま残らない形にし、毎晩の掃除は「その晩の出来事」ではなく、いま在るもの全部を見る
- **27.9** 投げ銭してくれた人を数えるときは、出どころを2つ書き出して突き合わせる。BigQuery を当日ぶんに使わない

## 28. **時と焼き込み**

入口の札の時制は §16。

- **28.1** 人が書く欄・焼く事実には、いつ時点か・いつまで本当かを持たせる。直したら、直した値と測った日を書く。前にやった日は、やった先そのものに埋める。人が手で打つ欄を、打った日のまま出さない
- **28.2** 日付の切り方・期間の判定・物差しの「きょう」は1か所に置き、新しく作らない（日は JST で切る）。時刻は呼ぶ側から渡し、既定の `new Date()` に黙って落とさない。空でありうる日付をそのまま割らない。「毎週」「毎月」を今日の曜日で決めない。日付を2つ使うなら、確かめる側も2つ持つ
- **28.3** 日付で答えの変わる数・地名・状態を焼かない。今日から数える数は、画面が出てから数える（終わったものの数は焼いてよい）。先の日付を焼かない。焼いた答えと呼んでよいのは、環境変数から来た値だけ

## 29. **守り**

- **29.1** 守りは、呼ぶ側が何を書いても破れない場所に、守りの持ち主に置く。知っている人・注意書き・手引き・「気をつける」に預けず、数で止める。「いま実害0」「いまは繋がっていない」は、守りを置かない理由にならない
- **29.2** 守る境目は、本番かどうかではなく、公開の場に出るかどうか。公開の口は誰でも読めてキャッシュに載る。口の鍵を、その画面が既に見せているものより細かくしない。消すのは明細だけにして、操作できなくしない
- **29.3** 外から来る字・番号で、置き場の名前や問い合わせを組み立てない。受け取った番号は確かめ、受け取らないと決めたものは受け取ったときに断る
- **29.4** Firestore のルールは、`read` を `get` と `list` に割る。ルールに書いた想定は実測を添えるまで信じず、閉じたら外から実測する。守りの条件が守りたいものを指し続けているかを、データで見る
- **29.5** 同意の範囲を、こちらで広げない。伏せ字は、形で分かるものだけでは足りない
- **29.6** 窓を閉じたら、口も閉じる。許す表ではなく、断る表を持つ。締めるのは「新しく書く」ことだけ。締め切りを、人によって意味の変わる形にしない
- **29.7** 外が断ったら迂回しない（別の名乗り・別の箱から取り直さない）。外から取った参考を、公開の枝に入れない

## 30. **作りかた**

- **30.1** 共通の部品・仕組みを作ったら、同じことを自前でやっているところと、当てるべき場所を、同じ回で全部置き換える。新しく作る前に、既に在るもの（重み・recipe・計算）を探して借りる。直しを、その1件（街・人・名前・片方の島）だけに効く形にしない
- **30.2** 自動生成ファイルは、見出しで生成物かを確かめ、元を直して作り直す。焼くものの並び順は焼くほうで決め、2回焼いて1バイトも違わないことを見る（`dict` の走査順・`glob`・`os.listdir` も）。スクリプトが書き換えるファイルは、1つ残らず commit の対象にする
- **30.3** 条件・しきい値・近道（早期 `return`）を足したら、境目をどちらへ倒すかを書き、「終わっていないもの」や先の処理が落ちていないかを見る。判定の数字は両側から挟んで決める。段を重ねるなら、あとの段が前の段をひっくり返せない形にする
- **30.4** 渡し忘れると静かに壊れるものは、渡させない。`!` で型を黙らせない。例外は1か所に書き、書き忘れたら赤くする
- **30.5** 正規表現ひと息で入れ子を取らない。繋がりを数える道具は、行頭のコメントも落とす。`set -euo pipefail` の下で `grep … | head` を `$( )` に入れない
- **30.6** `requestAnimationFrame` で回したものは rAF で、`setTimeout` で回したものは `setTimeout` で止める。たまにしか出ない時間切れ・1コマを、待ちや撮るコマを増やして追わず、構造で直す。長く開く面は増え続けないかを数で見て、要素を手放すときは要素を持つ箱からの参照も切る
- **30.7** 足す操作・状態を付ける仕組みを出すなら、減らす・外す仕組みを同じ回で出す。`lib/api.ts` に関数を足したら、呼ぶところまで書く
- **30.8** HTML は `no-cache`。名前に内容ハッシュが付いているものは1年の `immutable`。ハッシュの付いていないものに `immutable` を付けない

## 31. **ジョブと繋ぎ**

- **31.1** ジョブ A の書いたものを B が読むなら、順番を繋ぎで保証する。両方緑は、順番が合っていた証拠にならない。繋ぐ前に、その引き金に既にぶら下がっているものと依存の向きを数える。下流は上流と同じ回の中に置く。機械が押した run の完了を、繋ぎの起点にしない。間引きの関所を `run:` に置かない
- **31.2** 窓・枠の幅は実測で決める。窓を外さず、窓の外に細い枠をあける。絞りや上限のある仕組みで「動いていない」と言う前に、枠を見る。人の手が要る窓のあるものは、窓が開いた瞬間に抜ける道具にする
- **31.3** 1つが落ちても、ほかを道連れにしない。`continue-on-error` を付けた step は、落ちた理由を持つ。`::error::` を、exit に効かないところへ出さない。重い見張りを、空いている job に相乗りさせない。焼き直しの中で回すものは、その依存が無くても動く
- **31.4** 撮り直し・回し直しを選ぶなら、2回目が安全かと、同じ入力で2回の結果を先に実測する
- **31.5** 長い job の最後で外へ書き込む step は、始めたときに在ったものが今も在るかを見る。2本が同時に「無い」と見て作りに来たら、遅いほうは引く
- **31.6** 待つのはまとめ役のセッションだけ（`subscribe_pr_activity`・`send_later`）。担当は待たず、待ちは `run_in_background` に置く。時刻の約束をしたら、その場で知らせを2つ置く。後ろで走らせた知らせを、時間の決まった伝言に使わない。待ち時間を秒で書かない

## 32. **報告と段取り**

- **32.1** 「した・動いた・緑・0件・読んだ・確かめた」と言う前に、何を見てそう言うかを言う（ワークフローは step と `::warning::`、本番は本番）。見ていない結論を書かない。数を伝える turn では、ほかの仕事を挟まない
- **32.2** 報告が外れていたら、向きにかかわらず直す。できていないこと・分かっているが直していないこと・弱いもの・締め出したものを、名指しで書く。「〜には無い」で止めず、どこになら在るかまで書く
- **32.3** 言い切る前に、それを知る手立てがあるかを確かめる。分からない値を、手持ちの値（最小値・0・推定）で代用しない。「できない」「使えない」と決める前に別の道を数え、規約に「当たりうる」だけでは止めない
- **32.4** 機械では直せないと分かったら、その場で誰が直すかを決め、issue にして、待つ先を書く。`todo` に「待てば入る」だけを書かない
- **32.5** 数える・報告する前に、手元が master に追いついているか・同じ場所の開いている issue・走っている担当の一覧を見る
- **32.6** 日をまたいだ PR は、マージの前に紐づく issue を開き直し、`predeploy` と同じ順で回す。担当が触っているファイルを、担当が終わる前にビルドしない。マージしたら、run の色を見る。配りの赤（`ship-down`）は、立った時点でこちらの仕事にする
- **32.7** あやとへの知らせは、書いたかではなく飛ぶかで見る。`待ち-あやと` は機械が鳴らす。メンションを全部に入れない。頼むときは中の仕組みを説明せず、返事はあやとがふだん返す形で受け、承認はあやとの言葉をそのまま読む（書き直しを頼まない）
- **32.8** セッションの頭（要約からの再開も）で、`待ち-システム` の issue を開いて確かめる。要約に書いてある「〜待ち」は、issue を開くまで信じない
- **32.9** 理由つきで書いた決めごと・コメント・前提は、その理由が変わった日に見直す。取り消した決めごとを根拠として残さない。仕様とコードのコメントが食い違ったら、仕様が正。「載せない」「繋がない」と決めたものは、理由を機械が読める形で残す
- **32.10** 「例外はない」と書いた決まりには、理由を思いついても例外を作らない
- **32.11** 作業箱では、始める前に置き場の空きを見て、足りなければ始めない。掃くのは書き出しだけで、走っているビルドの書き出し先は触らない。この箱でできないことを手順の前提にしない。EC2 の操作の記録は消さず、動画や秘密は SSM のコマンドに載せない

## 33. **面と言葉**

- **33.1** 同じ意味の字は、1か所の部品から出す（同じことを2通りに・2つ言わない）。期間で変わる言い方は、対（いつもの／その期間の）で1か所に置く。押した回に返す字と、次に開いた人に見える字は分けて書く。リンクの字は行き先ごとに変える
- **33.2** 数は、持っている面だけが言う。言えない数は欄ごと出さない。読むたびに判定が変わるものを、画面で約束しない。数と札・数と一覧を同じ面で食い違わせない（一覧を数える）。上限を書くなら、何の上限かを書く
- **33.3** 字・札・絵は、出うるいちばん長い言い方・いちばん狭い幅・増えたあとの形で収まるかを撮って決める。揃えるより、はみ出さないほうが先。置く前に、そこに先に何が居るかを見る
- **33.4** 画面が出てから入る値は、出るまでのあいだの字と背も読む。出たあとと同じ形の写しを置く
- **33.5** 見出しの下には、見出しの言葉に当てはまるものだけを置く。問いを見出しにしたら、その場で字で答える。欄の主語と押しどころの主語をそろえる。行き先の無い札・中身の無い口を出さない
- **33.6** 足すものは、その面で既に使われている形に合わせる。机の道具は、在るものを全部出してから「足す」を出す
- **33.7** 人に字を打たせない。打たせるなら、1字ずれても当たり、打ったあと島がどう受け取ったかを返す。完全一致で引くところは、打つ人が何を打つかから決める
- **33.8** 読ませたい字を絵に焼かない。絵の中の言葉は画面が既に出しているものを撮り、画面を直したら絵も直す。絵に重ねる字は「読める」と「主役に勝たない」の両方で通し、絵の中の字は元の大きさで1文字ずつ数える
- **33.9** 字の色と飾りの色はトークンを分けて1か所に置き、色はそれが乗る地と一緒に決める。組み合わせる前にトークンの注を読み、色を変えたらその色で全部を見直す。色を比べる絵は昼で撮る
- **33.10** 島の上に置いてよいのは閉じた札1枚。島の板は字を持たない。島の上の札の避ける相手に、あやとを入れる。主人公を画面のどこに置くかは1か所に書く。島の上に固定した帯は、いつか入口の上に来る
- **33.11** 押しどころの合格は、大きさと「自分が最前か」の両方で見る。歩いているあいだ、押しどころを動かさない。送りは下へ行くときだけにし、人が触ったらやめる

## 34. **絵と見せ物**

- **34.1** 絵は名前で選ばず、開いて見る。描かせた絵は、出す条件を1枚ずつ自分で見る。1枚直したら、残り全部を1枚の紙に並べて見る。人のキャラは、設定画と同じ品質の絵にする
- **34.2** 機械で選んだ上位は、貼る前に1人ずつ読む。軸を足すとき前の軸を弱めず、指示の言葉をそのまま軸の名前にしない。「◯◯を落とす」は重みではなく門で書き、語の表（禁止ワード）で消さない
- **34.3** 見せ物を作るときは、先に比べる相手を調べて並べて見比べ、合格の条件に「見た人がどう感じるか」を入れる。段を上げるとき、同じものを増やさない。配信に出るものは配信と同じ画面の形で録り、オーナーには動画で見せる。誰の顔も隠していないかを見る

## 35. **配信と、島の外の面**

- **35.1** 投げ銭アラートは、試し見と本物で道を分けず、本物の通知の道を配信の条件で CI に回す。見せるのは「見せてよい」の合図のどれか早いもので、配信の頭で要るものを控えに頼らない。演出の判断を毎回ログに残し、構造の見張りで守る（目で見ない）
- **35.2** 月末の授賞式の面は、1行 46px 以上・1画面 16行まで。出す前に横 900px に縮めて見る。おもしろコメント大賞は1行読んで笑えるものだけ、調べもの大賞は1ページで豆知識を入れない
- **35.3** 書体の字の範囲は、表の中の字そのものから取る（定数の名前で書かない）。面の字を足したら、言い換えで逃げずに測り直す。字の多い面は `SOLO` にし、字形の無い字は範囲に入れない
- **35.4** 検索の手を選ぶ前に、狙う語の上位を実物で読む。点は `python/seo_score.py` の100点で言う。題・説明・h1 は、サジェストで引いた語の形で、面の中身を言う。画像検索に出す絵は、上位の絵と並べて見てから出す
- **35.5** ショートの原稿・編集の決まりは、`viral-shorts-creator` の帳面（`references/ayato_feedback.md` の F 番号）と様式（`references/script_writing.md`・`planning.md`・`production.md`）が持つ。決まりをそこ以外に書かない。あやとの返事を受けたら、直すより先に帳面に足す
