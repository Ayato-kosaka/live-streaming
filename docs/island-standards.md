# あやと島に求められている水準

**作る前と、出す前に読む。** 個別の指摘の一覧ではなく、**そこから一般化した基準**。
個別の経緯は `docs/island-misses.md`。

あやとの言葉（2026-09-10）:

> 私が求めてるもの（例えば、どう森レベルの品質とか、今まで指摘したこと）を
> 汎用化して（個別の指摘は要らない）反省して永続化する仕組みは作ってね。
> 何度もいうが「何回も同じことを言わすな」

---

## 1. 品質の水準は「任天堂のどう森レベル」


**「前より良い」は基準ではない。** 基準は、**見た人がワクワクするか。**

- 出す前に**自分の目で見る**（撮る）。数字が通ったことは、良いことの証明ではない
- 見て「弱い」と思ったら、それは弱い。**出さない**
- 足りないと分かっているものを出して、あとで下ろすのは**判断していないのと同じ**

判断に迷ったら「これを配信で画面に出して、視聴者さんに見せられるか」で決める。

## 2. 運営者は我々。**判断も設計も責務**


あやとは承認者ではなく、**意見を言う一人のオーナーユーザー**。

- 「出していいですか」「どちらにしますか」と**可否を預けない**。決めて、やって、報告する
- 面の構成・導線・文言を設計するのはこちらの仕事。
  **「この画面要る？」「統合すべきでは？」を言わせた時点で負け**
- あやとに現場監督をさせない

## 3. ただし、**仕様が曖昧なら聞く**


「判断してよい」は「解釈で埋めてよい」ではない。**両者は矛盾しない。**

- 決められること（作り方・設計・出す出さない）は**決める**
- 決められないこと（何が欲しいのか・どちらが正解か）は**聞く**
- 見分け方: **こちらの調査で答えが出るなら決める。あやたの頭の中にしか
  答えが無いなら聞く。** 調べずに聞くのも、聞かずに推測するのも、どちらも駄目

### **島の約束**に触るものは、調べて答えが出ても決めない

上の見分け方には穴がある。「投げ銭していない人も候補に出す」は、
コードを読めば**技術的には**答えが出る。出るので決めてしまった
（`docs/island-incident-2026-09-14-cards.md`）。

**技術的に答えが出ることと、決めてよいことは別。**
次の3つは、調べて答えが出ても**作る前に1行**。

| | 例 |
| --- | --- |
| **誰が何をもらえるか** | 投げ銭の特典、カード、称号、順位、並び順の優遇 |
| **誰が何を見られるか** | 公開する範囲、名前の出し方、過去ぶんの見せ方 |
| **誰が何を押せるか** | 書ける人、消せる人、1日の上限 |

見分けの言い方をひとつに:
**「これは視聴者さんとの約束か、作り方か。」約束なら、聞く。**

そして、**約束を「中のデータの形」で言い換えない。**
「`islandCards` の書類は増えないから特典は変わっていない」は、
実際にやった言い換えで、**受け取る人の手元には同じ画像が残っていた。**
数えるのは**受け取る人の手元に何が残るか**であって、書類の件数ではない。

## 4. 直したと言う前に、**本番で確かめる**


- 差し込み（テスト用の値）は**本番と同じものにする**。違う値で確かめると、
  直っていないものが直って見える
- 合否は、見た目の印象ではなく**通信・データ・画素**で決める
- **判定の向きが、目的を変えたあとも合っているかを見る**
  （「消えたら合格」の判定を、出すように変えたあとも使うと、正しいものが落ちる）

### 配り終わりを待つ合図は、**その変更でしか現れない字**にする（2026-09-17）

デプロイを待つのに「本番にこの字が出たら」で見張る。ここで**前から在る字**を選ぶと、
1回目の問い合わせで当たって、**配る前の古い版を「配り終わった」と読む。**

2026-09-17 に2回やった。

| 待った合図 | なぜ嘘になったか |
| --- | --- |
| `/map` に「いま歩いている旅もふくむ」 | **その字は前から `/map` に在った**。待ちの上限で抜けただけなのに、一致したように読めた |
| `/kitchen/french-toast` に「No.13」 | 面そのものは前から在る。**変わったのは焼き込みの1行だけで、画面には1画素も出ない** |

選びかたは2つ。

1. **その変更でしか現れない字**を選ぶ（消えるほうでもよい。
   「`/map/iran-border` から**カ国目が消えたら**」で待って、正しく待てた）
2. **画面に出ない変更なら、画面で待たない。** 焼き込みのデータだけが変わったときは、
   出たかどうかを画面で確かめようがない。**その変更が効く先**——見張りの終了コード、
   配ったファイルのバイト列——で見る

**「合図が前から在る」は、対照が通らないのと同じ形。** 何を測っても通るものは、
何も測っていない（15章）。

### 本番で確かめる道具（`tools/sprites/prod.mjs`）

**この箱のブラウザは本番に届かない**（proxy が `ERR_CONNECTION_RESET` を返す）。
それで「ローカルの書き出しで確かめた」で済ませていた。出したものと違う。

curl では取れるので、ブラウザの要求を横取りして curl の結果を返す。
`viaCurl(ctx)` を `apply(ctx)` より**先に**呼ぶ（あとから登録した route が先に効く）。

```bash
node tools/sprites/prod.mjs        # 出したものを開いて、顔が出ているかを見る
```

**通すのは本番と顔の置き場（yt3 / lh3）だけ。外を止めたまま撮ると顔が「落ちた」と出て、
直っているものを直っていないと読む。**

## 5. 1件直したら、**横に展開する**


指摘は「見つかった1件」であって「直すべき全部」ではない。

- データを直したら、それを読む画面・ルーティング・文言・導線まで見る
- 同じ形の間違いが他の面にもないか探す

## 6. 画面で、**システムの仕様を説明しない**


書いてよいのは、**その人がこれから何をするか／何が起きるか**だけ。

- 条件の説明（「〜な人には出ます」）、内部の決めごとは書かない
- 重複した説明は消す
- **説明が要る画面は、画面のほうが間違っている**

## 7. 溜まるものは、**溜まっても背が変わらない形**にする


あやとの言葉（2026-09-10）:

> マイページの貼った付箋も縦長すぎる。溜まってきたので、
> **こういう、データが溜まった時の設計が甘いので水平展開すること。**

データは必ず増える。付箋も企画もカードも配信も、来てくれるほど増える。
**「いまは3件だから大丈夫」で作った面は、半年後に必ず壊れる。**

- 増えるものを縦に積まない。**畳む**（`components/ui/Longer.tsx`）
- 増えるものが**2つ以上ある面**は、畳むだけでは足りない。畳んだものが縦に並ぶ。
  札で切り替えて、**同時に1つしか出さない**
- 用事の違うものを1つの面に積まない。**面ごと分ける**
- 出す数は、**1件の背**で決める。1件が4段ある道具は4件、1行のものは6件
- 上限で切らない。押せば最後まで出る。**畳むことと、読ませないことは違う**

**作る前に「これが200件になったら」を1度考える。** 0件・数件・数十件・数百件で
撮って、どれも同じ背で収まることを確かめる。

## 8. 名簿・一覧を**手で作らない**


街・国・企画などの一覧は、元のデータから導出する。手で書くと、元が変わったとき
**片方だけ古くなる。**

## 9. 細かいのは、**エージェントに配る**


こちらの責務は**マネジメント**であって、目の前の1ファイルを直すことではない。
1ファイルの中で閉じる作業は、指摘が来た時点で渡す。渡すときは
**合格の条件・確かめかた・触ってよい範囲**の3つを必ず添える。

自分で書き始めると、視野がその1ファイルに落ちる。**もぐら叩きはそこから始まる。**
自分の手を動かすのは、配る前の判断と、出したあとの確認まで。

## 10. **読めていないことを、値0と同じ絵にしない**


外から取ってくるものは落ちる。旅の最中は電波の弱いところを通る。
**「読めなかった」と「0だった」は別のもの。** 同じ見た目にすると、
届かなかっただけの日に「0でした」と言い切ることになる。

- 字で「読めなかったら出さない」にしているなら、**絵も同じにそろえる。**
  同じ面の中で、字と絵が違うことを言ってはいけない
- 読めていないときの姿は、**0のときと見分けがつくこと。**
  作り方は `docs/island-design.md` 4章（場所だけ先に取って、中身の形を薄く置く）
- 確かめかたは、**API を落とした状態で撮って、0のときと並べて見比べる。**
  見分けがつかなければ直っていない。面ぜんぶを機械で洗うのは
  `tools/sprites/zeroclaim.mjs`（落として1回・通して1回開いて、
  **どちらでも同じ「0◯」が出る場所**を並べる）
- **言い切りは数だけではない。** 「今日は出ていません」は 0 を1つも含まないので
  `zeroclaim.mjs` では永久に捕まらない（#116）。**言葉のほう**を洗うのは
  `tools/sprites/negclaim.mjs`（折りたたみ・札・「あと◯件だす」・帳面の送りを
  開いてから読み、**通したときだけ出る否定**を別枠で並べる）。
  どれが嘘かは機械に決められないので、**候補を並べるところまでが道具の仕事**
- **面の単位で分けても、その面が読む口が2値ならそこだけ2値に戻る**（#115）。
  読みものを1つ足したら `Read`（wait / ok / down）も一緒に足す。
  `Record` や配列だけ返す口は、落ちたときに空と見分けがつかない
- **`||` と `??` で 0 を畳まない。** `0 || fallback` は 0 を落として、
  いちばん言ってはいけない値を通す。「数が無い」は `undefined` のまま持って、
  出すか出さないかを画面で決める
- **口が「上位N件」を返すなら、載っていないことを 0 と読まない。**
  `limit` の付いた口の答えは3種類ある（値／載っていない／読めなかった）

## 11. **同じものの段階を並べるときは、完成形から引き算で作る**


段階（建設中→完成、下書き→清書）を並べて見せるとき、**各段階を独立に組むと
寸法が揃わない。** いちばん出来上がったものを基準にして、そこから引く。

- 合っているかを**目で見ない。測る。** 幅・高さ・上端を数で突き合わせる
- **並べた絵は、出す前に自分で開いて見る。** 作って満足して終わらない

## 12. **数式や定数を、別の画面へそのまま持っていかない**


その値が**何のために決められたか**を見る。小さく並べる一覧のために決めた
下駄は、全画面で1つを主役に出す画面のために決めた値ではない。
式が正しくても、当てる先を間違えれば絵は壊れる。

## 13. **当座の判定は、まずその判定を疑う**

不具合を見つけたと思ったら、**サイトを直す前に、自分の判定が正しいかを確かめる。**
2026-09-10 の1日で、その場で書いた判定が**3回**「不具合だ」と言って、
**3回とも判定のほうが間違っていた。**

| 判定が言ったこと | 本当は |
| --- | --- |
| `/nordic` に横あふれ20件 | SVG の中の `<path>`。ページは横に動かない（`scrollWidth == clientWidth`） |
| 旅の全面で React の水あわせエラー | 差し込んだ偽の時計が原因。本番は0件 |
| `/cards` に落ちた画像1件 | 自分の横取りが `firebasestorage` を止めていた。本番は 200 |

共通しているのは、**測るために作った仕掛けが、測る対象を変えてしまっている**こと。
横取り・偽の時計・要素の数え方は、どれも本番には無いものです。

**確かめかた:**

- **本番そのものを開いて、同じ判定が出るか見る**（`tools/sprites/prod.mjs`）。出なければ判定のせい
- 数える前に**何を数えているのかを1件だけ目で見る**（クラス名・URL・要素）
- 止めた通信・差し替えた値を**一覧に出す**。止めたものが原因の「落ちた」は毎回起きる
- **既にある判定と食い違ったら、新しいほうを疑う**（巡回は「横あふれ0」と言っていて、そちらが正しかった）

**間違った報告をしないために、これは効きます。** 3回とも、報告する寸前で止まりました。

## 14. 「あとで」を自分で決めない


重い・危ないと思ったら、後回しにするのではなく**そう言って判断を仰ぐ。**

## 15. **「0件」は、何件見たかを出させてから読む**

2026-09-15 に、この章の下のチェックに**名指しで載っている道具3本**が、
404 のページを測って「合格」と言っていたことが分かった。

書き出したものを静的に配ると、開けるのは `/about.html` であって `/about` ではない。
**`goto` は 404 でも成功する。** そこから数えると要素が0件になり、それが
「違反 0件」に見える。

| 道具 | そのとき | 直して測り直したら |
| --- | --- | --- |
| `popcheck`（押せないのに厚み） | 26面ぜんぶ0件 →「違反 0」 | **827件**を見て 違反 0 |
| `hitbox`（押しどころ 48px） | 「押しどころ 0個・48px割れ 0」 | 押しどころ **3個**・48px割れ 0 |
| `inkpx`（字の濃さ） | `/map` で 37か所（**ディレクトリ一覧の字**） | `/map` で **108か所** |

**面そのものは3本とも合格だった。** 嘘だったのは合格の根拠のほうで、
**測っていないことを「違反なし」と読んでいた。**

### 撮る道具は、終了コードで読む（2026-09-17）

上の3本を含む5本は、**数字を印字するだけで何も止めていなかった**
（`island-misses.md` #128）。いまは5本とも**終了コードと対照を持っている。**
決めは全リポジトリ共通で **0＝通った / 1＝見つかった / 2＝数えるものが無い**。

| 道具 | 見るもの | 対照 | 分母として出るもの |
| --- | --- | --- | --- |
| `tools/sprites/popcheck.mjs` | 押せないのに厚み | `popcheckfix/` 20件 | 見た面 / 見た要素 / 厚みのある要素 |
| `tools/sprites/hitbox.mjs` | 押しどころ 48px | 仕込み（`PROBE_JS`）8件 ＋ 台に1件 | 見た面 / 押しどころ / 測れず / 数えなかった内訳 |
| `tools/sprites/inkpx.mjs` | 字の濃さ 4.5 | `inkpxfix/` 14件 | 見た面 / 拾った字 / 測れた字 / 落とした内訳 |
| `tools/sprites/facecheck.mjs` | 看板と顔が同じ人か | 生きた面を壊す 8件 | 見た組み合わせ 2 |
| `tools/sprites/iconcheck.mjs` | 絵がほんとうに描けたか | 生きた面を壊す 7件 | 見た組み合わせ 2 / 見た絵 |
| `tools/sprites/shotstable.mjs` | 同じ2枚が揃って撮れたか | 揃う1件＋揃わない1件 | 見た面 / 揃わない面 / いちばん高い絵 |
| `tools/sprites/inkband.mjs` | 字の濃さ（送りながら） | `inkbandfix/` 20件 | 見た面 / 拾った字 / 測れた字 |

**対照が1件でも外れたら、本物の面の数字を1つも出さずに 2 で落ちる。**
`BREAK=` を渡すと、直す前の測りかたを再現できる（当てると対照が落ちる）。
どの道具も `| tail` を挟まない——**終了コードが消える。**

### 26面に当てる（2026-09-17）

上の表の道具は、**面を手で渡す。** 渡さなければ回らないので、
`hitbox` は長いこと **2面・札は `.crumbs a` だけ**、`inkpx` は **3面**しか
見ていなかった。「押しどころ 48px 以上・字の濃さ 4.5 割れ 0」という
下のチェックは、**26面のうち2面と3面のことだった**（`island-misses.md` #130）。

26面ぜんぶを一度に回すのは `tools/sprites/tapink.mjs`。

```bash
tools/build.sh 3150
python3 -m http.server 4150 --directory site/.next-3150 &
PORT=4150 node tools/sprites/tapink.mjs     # 0＝通った / 1＝見つかった / 2＝数えるものが無い
```

自分では1行も測らず、`hitbox` `shotstable` `inkpx` `inkband` を子として起こして
**終了コードだけを読む。**（26面 × 4とおりで、ひと回り40〜60分かかる） 走らせ役にも対照があり、**わざと落ちる子を3本起こして
2 が返ることを見てから**本物の面を測る。面の一覧は `tools/sprites/islepages.mjs`
（`popcheck.mjs` の一覧と食い違ったら、数字を出さずに落ちる）。

2026-09-17 に初めて26面へ当てた実測:

| 見たもの | 分母 | 出たもの |
| --- | --- | --- |
| 押しどころ（390px） | 26面 / 1,143個 | 48px 割れ **0**・当たりが測れず 2（横に流す棚。指では届く） |
| 押しどころ（1000px） | 24面 / 1,244個 | 48px 割れ **0** |
| 字の濃さ（390px / dpr2） | 26面 / 拾った 3,595・測れた 3,311 | 4.5 割れ **297**（296 は `/design` の絵の名前＝`opacity: 0.6`、1 は数え方のほう） |

**濃さは、面ぜんぶを1枚に撮る側だけでは足りない。** `content-visibility: auto` の段は
その撮りかたでは描かれないので、24面で 284か所が「測れなかった」に落ちる
（`/` は 120か所中 58か所）。画面のぶんずつ送って撮り直すと測れて、
そこで `/nordic/finland` の札4件（4.10〜4.50）が出た。**「割れ 0」は、
測れた数と一緒に読む。**

**字の濃さは dpr2 で測る。** dpr3 で背の高い面を撮ると、何も変えていない2枚が
食い違って（`/nordic/guide` で 540万画素）、**足りている字が大量に割れる。**
だから `tapink` は濃さの前に `shotstable.mjs` を通す。

### 決めごと

- **分母を出させる。** 「違反 0」だけの道具は信じない。
  「**何面/何件を見て、そのうち0件**」が出るまで直す
- **0件で黙って終わらせない。** 数えるものが1つも見つからなかったら、
  終了コードを分けて（0=通った / 1=落ちた / **2=数えるものが無い**）、
  何が見つからなかったかを並べる。手本は `tools/sprites/cardshot.mjs`
- **口と画面を突き合わせる。** 「この写真には12人立てる」と口が言っているのに
  顔が12でなければ落とす。片側だけ見ていると、両方0のときに気づけない
- **旗を回す人に預けない。** `STATIC=1` のような立て忘れで壊れる作りは、
  注意書きであって守りではない（#96）。開くところで止める（`tools/sprites/served.mjs`）
- **対照は、足の数だけ用意する。** 「壊し方を4通り当てた」は、その4通りが
  同じ足を折っているなら1通り。**判定の足を1本ずつ抜いて（`BREAK=`）、
  そのたびに対照が落ちること**まで見る（`island-misses.md` #128 の決めごと1）
- **診断を足したら、壊した写しで落ちることまで見る**（`island-misses.md` #99）。
  **その前に「壊していない写しが通ること」を先に見る。**
  写しを作る途中で壊れても終了コードは同じなので、そこを見ないと対照にならない
