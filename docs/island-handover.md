# 誰も見ていない日の、あやと島

**この紙は「セッションが動いていない日」のために書いてある。**
毎晩ひとりでに何が起きるか、壊れたらどこに出るか、人しかできないことは何か。

作りの話は別の紙にある（`island-fresh.md` 何が機械で新しくなるか／`island-db.md` データ／
`island-api.md` 口／`island-standards.md` 水準／`island-misses.md` 外した記録）。
**ここに書くのは、運転の話だけ。**

---

## 1. 毎晩ひとりでに起きること

**cron で起きるのは2本だけ。** あとは全部、その2本の**完了に繋いで**走る。
どちらも GitHub の定時で**何時間も遅れる**。**遅れているのは異常ではない。**

**遅れの数はここに書かない。** 書くと古くなる（前は「1時間49分〜3時間32分」と
書いてあって、半年で桁が変わった）。**疑う前に、道具を回して今の数を見る:**

```bash
python3 python/cron_lag.py            # 回数・中央値・いちばん遅い・何時間待つか
python3 python/cron_lag.py --by-month # 悪化しているか
```

### 繋ぎの図（`.github/workflows/*.yml` の `on:` から組み直したもの。2026-10-14）

```
   cron 20:00 UTC                              cron 20:30 UTC
         │                                           │
  ┌──────┴──────────────┐                 ┌──────────┴──────────┐
  │ Fetch YouTube Chat  │                 │ Fetch Doneru        │
  │ Data                │                 │ Donations           │
  └──────┬──────────────┘                 └──────────┬──────────┘
         │                                           │
         ├────────────────── 両方から ───────────────┤
         │   退避 / 島の数字を焼き直す / 取り込みが落ちている /       │
         │   配りが赤い / Ticket Stock / 待ち札を裏返す /            │
         │   **重い見張り**（PR から外したブラウザの見張り2本）        │
         │                                           │
         ├─ SUZURI API                               ├─ 投げ銭の台帳を入れ直す
         ├─ 紐付け待ち                                ├─ 図鑑の呼び名を追いつかせる
         ├─ 外貨を issue に映す                       └─ 公開に戻った配信を返す
         ├─ 焼き直しが止まっている（受け皿）                      │
         └─ 人の手入れ待ち（受け皿）                              ▼
                                              紐付け待ち（台帳の完了からも）
                                              外貨を issue に映す（同上）
         ┌──────────────────────┐
         │ 島の数字を焼き直す     │──┬─→ 焼き直しが止まっている
         │ （↑の2本から起きる）  │  └─→ 人の手入れ待ち
         └──────────┬───────────┘
                    │ 中から `gh workflow run` で
                    ▼
         ┌──────────────────────┐
         │ Firebase Hosting     │──→ 配りが赤い
         │ Deploy               │    （**配りの中から名指しで押す**。
         │                      │      配った面を一周して確かめるのも、この中）
         └──────────────────────┘
```

**起点は2つだが、親は4つ。** `島の数字を焼き直す`・`投げ銭の台帳を入れ直す`・
`Firebase Hosting Deploy` も、自分の完了で次を起こしている（**2段目の繋ぎ**）。
2026-10-13 に run の時刻で突き合わせたところ、**2段目は実際に発火していた**——
焼き直し→焼き直しが止まっている 63回 / 焼き直し→人の手入れ待ち 37回 /
台帳→紐付け待ち 53回 / 配り→配りが赤い 47回。**帰属不明 0件。**

> **「配り→配りが赤い」だけは `workflow_run` ではない**（2026-10-15。#865）。
> 毎晩の配りは焼き直しの中から `GITHUB_TOKEN` で押しているので、**GitHub の
> 再帰よけで、その完了がさらに次を起こさない。** run を1本ずつ寄せて数えたら
> （`ship_down.yml` が在った期間・3分窓・1対1・帰属不明0件）、
> **人が押した配りは 90/90 で起こし、bot が押した配りは 0/72** だった。
> 上の「47回」は、人が押したぶんを数えていた。
>
> いまは**配りの最後の job（`wake_ship_down`）が、下流を名指しで押す。**
> `workflow_dispatch` は再帰よけの外（2026-10-15 に、bot が押した配りから
> 下流が起きるところまで実際に見た）。**押したあと run が増えたかまで見て、
> 増えなければ配りが赤くなる**ので、ここは静かには止まらない。
> `workflow_run` の3本は受け皿として残してある。

**繋ぎはワークフローの `name:` で解決される。** あちらの `name:` を書き換えると、
**黙って切れる。赤くならない。走らなくなるだけ。**
ぜんぶ解決するかは `python/workflow_link_selftest.py` が毎 PR で当てている
（**本数はここに書かない。** 道具が「繋ぎ N本」と出すので、そちらを読む。
前は「21本」と書いてあって、`wait_flip.yml` が入った**翌日に**23本になった）。

### 名前が合っていても、繋ぎは死ぬ

名前の見張りが止められるのは**1通りだけ**——繋ぎ先の `name:` を書き換えた場合。
残りの3通りは、名前がぜんぶ合ったまま静かに死ぬ。

| 切れかた | 名前の見張り | どこで止まるか |
| --- | --- | --- |
| 繋ぎ先の `name:` を書き換えた | ○ | 毎 PR |
| 繋ぎ先が**走らなくなった**（止めた・消した・鍵が切れた） | ✕ | 毎 PR（**実績を数える**） |
| 繋ぎは在るのに、こちらが**一度も繋ぎで起きていない** | ✕ | 毎 PR（同上） |
| `conclusion` で絞ってしまい、**赤い晩だけ落ちる** | ✕ | 毎 PR（`if:` を読む） |
| **受け皿が起きるので、1本目の繋ぎが死んでも生きて見える** | ✕ | 毎 PR（**繋ぎ1本ずつ**） |

下の4つを `python/chain_alive_watch.py` が当てている（`Selftests` の中。
GitHub の run を読むので、**この1本だけネットに出る**）。

**いちばん下が #865 で見つかった穴。** [4] までは「このファイルが**何かの**
繋ぎで起きたか」しか見ていないので、受け皿を持つものは1本目が死んでいても
緑になる。`ship_down` がまさにそれで、`Firebase Hosting Deploy` からの繋ぎは
**毎晩の配りに対して 0/12** なのに、チャットとどねるの受け皿から起きるので
ワークフロー単位では生きて見えていた。

[5] は**どの上流の完了と時刻がそろったか**を寄せる。見るのは**無人で終わった
上流だけ**——手で押した回を混ぜると、死んでいる繋ぎが「半分は生きている」に
化ける（人 90/90・bot 0/72）。窓は**うしろ3分**で、これも実測で決めてある
（10分に広げると、受け皿の起こした下流がたまたま入って 4/12 に見える）。

```bash
python3 python/chain_alive_watch.py             # 5つぜんぶ
python3 python/chain_alive_watch.py --offline   # ネットに出ない2つだけ
```

**「走っていない」と言うまでは3日。** 実測で、繋ぎ先5本の連続する run の間隔は
いちばん空いて 1.22日、繋ぎで起きた回の間隔は 1.10日（2026-10-14）。
**1晩落ちても赤くならず、2晩つづけて落ちたら赤くなる。**
短くすると、定時の遅れ（最長 8.0時間）と区別がつかなくなる。

**4つ目がいちばん見つからない。** `Fetch YouTube Chat Data` は
「表に無い どねID が投げ銭してきた」晩だけ最後の step が `exit 1` で終わる。
**あれは失敗ではなく呼び出しで、数字は BigQuery に入っている。**
`conclusion == 'success'` で絞ると、**呼び出しの出た晩だけ焼かれない**
——月に何度かしか起きないので、気づくのは数字が古いと言われたとき。

### 保険の cron は、書いてある時刻には動かない

繋ぎが切れたときのために、**繋ぎを持つものは、1本の例外もなく保険の
cron も持っている**（01:00〜05:41 UTC に散らしてある。**本数はここに書かない**
——前は「13本」と書いてあって、2026-10-16 に数えたら15本だった。数えるなら
`python3 python/chain_alive_watch.py` が出す繋ぎの一覧と、各ファイルの
`schedule:` を突き合わせる）。**実測では一度の例外もなく3時間以上遅れ、
中央値で4〜7時間後**に動く（2026-10-14。`python3 python/cron_lag.py`）。

| 書いてある時刻 | 実際に火が付く（中央値。2026-10-13 時点） |
| --- | --- |
| 01:00 UTC（島の数字を焼き直す） | **06:00 UTC ＝ 日本時間 15時** |
| 04:00 UTC（焼き直しが止まっている） | **10:18 UTC ＝ 日本時間 19時** |
| 04:30 UTC（配りが赤い） | **10:42 UTC ＝ 日本時間 19時** |

つまり **「02:00 の保険」を信じて 02:30 に Actions を見に行くと、まだ何も
起きていない。** いまは繋ぎが毎晩効いているので実害は出ていないが、
**繋ぎが切れた日に保険が動くのは5〜7時間後**だと思っておく。
（この表の数も古くなる。`python3 python/cron_lag.py` が今の数を出す）

### 豚の貯金箱の控えを写す仕組みは、**もう無い**（2026-09-24。#639）

`goal_backup_nightly.yml` / `python/admin/goal_backup.py` /
`python/admin/goal_migrate.py` は、GAS の `Goals` 表を
`islandGoal/2025-10-24` へ写すためだけのものだった。**写す先を誰も読まなく
なったので、ファイルごと畳んだ。**（額は #305 で台帳へ、Doneru の鍵は
#639 で `islandFundConfig/doneru` へ移った）

**いま Doneru の鍵を触る道は1本だけ**——Actions の「管理スクリプトを実行」で
`doneru_key` を押す。既定は下見で、`{"apply": true}` のときだけ書く。
**鍵を ARGS に書かないこと**（ARGS は公開のログに出る。取り替えるときは
環境変数 `DONERU_GOAL_KEY_NEW`）。

**鍵を失うと、豚の貯金箱から Doneru のぶん（194,820円）が消える。**
消えたときは島の足代も配信の豚も 503 になって**数字が出なくなる**（0円とは
出ない）。戻すには Doneru の管理画面に入れる人が要る——**機械では戻せない。**

### GitHub の外にも1本ある（リポジトリからは見えない）

**claude.ai の Routine が、毎日 21:00 UTC に1本動いている**
（「Doneru セッションの寿命を日次で見る」）。毎回まっさらなセッションで起きて、
上の cookie が切れていないかを見て、切れていたらあやとにメールする。
**これはこのリポジトリのどこにも書かれていないので、`.github/workflows` を
いくら読んでも出てこない。** 止めたい・中身を見たいときは claude.ai の Routines から。

### 繋ぎが生きているかを確かめる（副作用がある。読んでから押す）

`Fetch Doneru Donations` を `probe: true` で押すと確かめられる。
ただし**「1バイトも書かない」のは、押したその枠だけ。**

**押すと、繋いだ先がぜんぶ起きる。** 2026-09-19 に実際にこうなった:

```
probe: true で押す → 焼き直しが走る → 5c811ba を commit する → Hosting を配る
```

**本番に配りが1回出る。** これは繋ぎが生きている何よりの証拠だが、
**配信の直前や、master に出したくないものが載っているときに押すものではない。**
押す前に master を見る。

### 配りの側だけなら、何も起こさずに試せる（2026-10-15。#865）

`Firebase Hosting Deploy` を **`wake_only: true`** で押す。書き出しも配りも
丸ごと skip して、**「配り → 配りが赤い」の繋ぎだけ**を試す。
**本番に1バイトも出ないし、issue も1文字も動かない**（起こされた側は
`apply: false` で走る）。1分で終わる。

上の Doneru の `probe` と違って**何も起きない**ので、押す前に master を
見る必要もない。`ship_down` が起きたかは Actions の一覧に出る。

## 2. 壊れたら、どこに出るか

**全部 GitHub の issue に出る。** 機械が立てて、直れば機械が閉じる。

| 出るもの | ラベル | 何が起きたか | あやとを呼ぶか |
| --- | --- | --- | --- |
| 焼き直しが止まっている | `bake-down` | 夜の焼き直しが赤い。**本文に、落ちた step の名前が出る** | 呼ばない（こちらで直せる） |
| ↑のうち **ショートの棚**だけ | 同じ `bake-down` | 赤の注記に**理由の1行がそのまま出る**（#289 まで「上の『焼く』を見てください」としか出ず、run を開くまで何が駄目か分からなかった）。筋道は2つ——**手元の id が YouTube の一覧から消えた**（`python/data/shorts.json` の `_gone` に理由を添えて足す）か、**焼くほうが落ちた**（直す） | 呼ばない |
| **配りが赤い** | `ship-down` | **本文の1行目で「もう本番に出ている／出る前に止まった」を言い分ける** | **出ているときだけ呼ぶ** |
| 取り込みが落ちている | `ingest-down` | チャットが入っていない | cookie 切れのときだけ呼ぶ |
| 紐付け待ち | `donor-calls` | 投げ銭した人が YouTube に繋がっていない＝**カードが渡らない** | 呼ぶ |
| **円に直せなかった投げ銭** | `fx-tips` | 円以外はその日のレートで直して足すが、**直せないことがある**（台湾ドル・口が落ちた晩）。直せなかったぶんは足さないので、**その人の貢献額がそのぶん足りない。** 台帳に1件でも残っているあいだ開く（窓で切らない）。直すのは `python/admin/fx_backfill.py` | 呼ばない（こちらで直せる） |
| **重い見張りが赤い** | `watch-down` | **PR の通り道から外した2本**（`browserwatch` / `reachwatch`）が master で赤い。本文に、落ちた job と何を見ている job かが出る（#281） | 呼ばない（こちらで直せる） |
| **開いたままの issue** | `ticket-stock` | **週1の棚卸し（#583 を上書き）。30日動いていないものを名指し。** 「週1」は曜日ではなく**前に書いてから7日たったか**で決める（#264。曜日で見ていたあいだ、繋ぎで来た 57回のうち 55回が落ちていた）。**10日あくと赤くなる** | あやと待ちが在る週だけ |
| **繋ぎが切れた**（`workflow_run`） | — **issue にならない。PR が赤くなる** | 名前を変えると**黙って切れる**（赤くならず、走らなくなるだけ）ので、変えた PR のその場で止める（`python/workflow_link_selftest.py`。毎 PR・繋ぎぜんぶ。**本数は道具が出す**） | 呼ばない |
| **繋ぎが黙って死んだ** | — **issue にならない。PR が赤くなる** | 名前は合っているのに、繋ぎ先が走っていない／こちらが繋ぎで起きていない／`conclusion` で絞ってしまった／**受け皿に隠れて1本目だけ死んでいる**（`python/chain_alive_watch.py`。毎 PR・境目は3日） | 呼ばない |

**待ちの相手はラベルで分かる**（`待ち-あやと` / `待ち-システム` / `旅のあと`）。
**PR に `Closes #NNN` が在れば、マージでひとりでに閉じる。**

**赤くても「落ちた」とはかぎらない。** 焼き直しには、配ったうしろで赤くする見張りが2本ある
（セリフの届いていない人／焼き込みが古い）。**あれは「書き足してほしい」というお願い**で、
数字は入って本番にも出ている。issue の本文がそう書いてある。

## 3. 人（あやと）しかできないこと

`island-fresh.md` の②に一覧がある。**要するに、配信を見ないと決まらないもの。**

- 料理のスタンプ（何を作ったか）
- 他己紹介の引用（どれを採るか）
- 歩いた国と滞在期間
- 図鑑のハンドル（誰が誰か）
- **Doneru の cookie**（下に別立て）

### Doneru の cookie は、いつか必ず死ぬ。替えられるのはあやとだけ

投げ銭の取り込みは cookie（`_dt`）1本で通している。**Doneru はこれを配り直さない**
（応答に `Set-Cookie` が無いことを確認済み。台帳の `renewed_dt` は23回とも `false`）。

**実測（`youtube_chat.doneru_ingest_runs` の23回、2026-09-06〜09-19）:**

| | |
| --- | --- |
| 通った | 19回 |
| **切れた** | **2回（2026-09-13 と 09-14）** |
| 別の失敗 | 2回 |
| 1本目の寿命 | **7日以上**（台帳を取り始める前から生きていたので、下限） |
| いま入っているもの | 2026-09-15 に入れ直し。**4日目、生きている** |

**あやとの当初の見立ては「3日くらいで切れるかも」だったが、実測の下限は7日以上。**

切れると取り込みが終了コード2で落ちて、`ingest-down` の issue が立つ。
**入れ直しはあやとにしかできない**（ログインが Google OAuth なので機械にはできない）:

1. https://doneru.jp にログイン
2. DevTools → Application → Cookies の `_dt` をコピー
3. `gh secret set DONERU_COOKIE --repo Ayato-kosaka/live-streaming`
   （**対話で貼る。引数で渡さない**——引数は公開ログに出る）
4. Actions で `Fetch Doneru Donations` を流し直す

**切れているあいだ、島は壊れない。** 投げ銭の数字が止まるだけで、面は出る。

**これを焼くにはセッションが要る**（`/island-fresh` の手順で回す）。
**焼かなくても島は壊れない。** その欄が古くなるだけ。
**古くなったら、`bake-down` の issue が「人しか新しくできない焼き込みが置いていかれています」
という本文で出る**（焼き直しが落ちたときとは、本文の頭が違う）。どれがどれだけ古いかは、
`島の数字を焼き直す` のいちばん新しい run の「焼き込みが古くなっていないか」の表に出る。

  上げるとブラウザの置き場が `chromium-1194` から別の番号になり、`tools/sprites/*.mjs` の
  **213本**が持っている `executablePath` の直書きが黙って外れる（2026-09-19 の実測。
  うち 206本は `executablePath:` に直に書いてある）。**無人で走るぶん**——配りの後ろの
  `cardgo.mjs`——だけは `tools/sprites/chrome.mjs` 経由で番号を見ないので生き残るが、
  **手で回す道具は全部死ぬ。** 上げるなら、直書きを `chrome.mjs` に寄せてから

## 5. 島が止まったときの、いちばん短い直しかた

1. **GitHub の Actions を見る。** 赤いものがあるか
2. **赤が `Fetch YouTube Chat Data` なら、Cookie が切れている**ことが多い
3. **赤が無いのに数字が古いなら、繋ぎが切れている。**
   `Fetch Doneru Donations` を `probe: true` で押して、後ろが起きるかを見る。
   **1章のとおり、これは本番への配りを1回起こす**ので、押す前に master を見る。
   配りの側だけでよければ `Firebase Hosting Deploy` を `wake_only: true` で
   押す（**こちらは何も起こさない**）。
   **「まだ来ていないだけ」と「来ない」を取り違えない**——どれだけ待てばよいかは
   `python3 python/cron_lag.py` が「もう来ないはず、と判断するまで待つ時間」として
   ワークフローごとに出す
4. **島の面そのものが壊れたら**、`Firebase Hosting Deploy` を手で押せば master から配り直せる
