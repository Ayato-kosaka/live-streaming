# 言われたことと、外した理由

**あやとに指摘されたことを、ここに残す。** 直したかどうかではなく、
**なぜ外したか**と、**次に同じ形で外さないための決めごと**を書く。

あやとの言葉（2026-09-09）:

> 君なんかいも指摘してるけど、私と認識あわないまま進めすぎよ。
> それで、毎回もぐら叩きになってることに気付け。
> まずは、自分が指摘されたら、原因と対策を自分で記憶する仕組みが必要。

もぐら叩きになるのは、**1件ずつ直して、外し方を残していない**から。
セッションが変わると、同じ外し方をもう一度する。ここはそのための場所。

**直したら消す、ではない。** 直したあとも残す。理由は「同じ形で外しかけた
とき、ここを読めば止まれる」ため。

## 決めごと（先に読む）

### 1. 作る前に、何を作るかを1行で言って合わせる

指示に幅があるとき、**自分に都合のいい読み方で埋めない。** 作る対象・範囲・
出来上がりの形を1行で言って、違ったら言ってもらう。1行を惜しんで作り直す
ほうがずっと高くつく。

「地図を貼って」で国の地図を切り取って出したのがこれ（下の #3）。

### 2. 直したと言う前に、**本番の値**で確かめる

差し込み（`tools/sprites/asme.mjs`）に本番と違う値を置くと、直っていない
ものが直って見える。**差し込みの値は本番から取ってくる。**
合否は、見た目ではなく**通信やデータ**で決める。

### 3. 名簿を手で作らない。**もうある導出を使う**

街・国・企画の一覧は、旅程から導出されている（`VISIT_CITIES`,
`MAYBE_CITIES`, `visitCitiesOf`）。手で書くと、旅程が変わったときに
**片方だけ古くなる。**

### 4. 可否を預けない。**決めて、やって、報告する**

あやとの言葉（2026-09-09）:

> デプロイの可否は自分で判断してね。（略）あなたがあやと島運営者です。
> つまり、システムの判断は全てあなたの責務。
> 私はいち、オーナーユーザーとして、意見を言ってるだけ。

「出していいですか」「どちらにしますか」と聞くのは、**判断を投げていること。**
意見はもらう。それをどう反映するかを決めるのは、こちらの仕事。

**品質の可否もこちらが決める。** 出す前に自分で見て、届いていなければ出さない。
出してから言われて下ろすのは、判断をしていないのと同じ（#6）。

### 5. **言われたところだけ直さない。横に展開する**

あやとの言葉（2026-09-10）:

> Firestore 見直したはず。データ直したら、同じ反省点としてルーティングも
> 直すのが常識の仕事の進め方ですよ。（略）
> 言われたことだけ直してる感が半端ないんですよあなた。

1件直したら、**同じ理由で壊れているところを探しに行く。**
データを直したら、それを読む画面・ルーティング・文言・導線まで見る。
指摘は「見つかった1件」であって、「直すべき全部」ではない。

### 6. **面の構成は、こちらが設計する**

> そもそもこの画面入らなくて cards に統合すべきでは？
> ちゃんと、システム管理者として広い目で設計してる？
> 私に現場監督をさせるな。

「この画面要る？」「統合すべきでは？」を**あやとに言わせた時点で負け。**
似た面が2つあれば、どちらが良いかを決めて寄せる。重複した説明があれば消す。
使いにくい導線は、言われる前に直す。

**あやとは意見を言う人であって、現場監督ではない。**

### 7. **画面で、システムの仕様を説明しない**

> システムの仕様の説明をするのはやめて欲しい。
> 例えば、「名前が出ているのは、島に名前を出してよいと言ってくれた人です。
> 出していない人も、絵はそのまま立っています。」
> この文章そもそもすごくわかりにくいし、仕様の説明はしないで欲しい。

書いてよいのは、**その人がこれから何をするか／何が起きるか**だけ。
「どういう条件でこう出しているか」は中の話で、読む人には要らない。
迷ったら消す。**説明が要る画面は、画面のほうが間違っている。**

### 8. 「あとで」を自分で決めない

あやとは「旅が終わってからの作業に後回しをするつもりはない」と言っている。
重い・危ないと思ったら、**後回しにするのではなく、そう言って判断を仰ぐ。**

### 9. 外から取ってくるものは、**3つの答えで持つ**（`wait` / `ok` / `down`）

2026-09-10 の1日で、**同じ形を4回にわたって踏んだ**（#34 → #36 → #43 →
最後の4件）。1件ずつ直しても終わらないのは、**その1行だけ見れば正しく
見える**から。`catch` の中の `setX([])` は、その行の外に出ないと嘘だと分からない。

**新しく読みものを足すときは、書く前にこの6つを通す。**

1. **`catch` で空にしない。** `setX([])` / `setX(null)` / `return null` と
   書いた時点で、落ちた日の絵が「0件の絵」と同じになる。
   持つのは `Read`（`lib/auth.tsx` の `wait` / `ok` / `down`）
2. **「無い」と言ってよいのは、口が**ぜんぶ**読めた上での0件だけ。**
   口が2つある面は落ち方が3通り。**片方だけ落ちるのがいちばん多い**
3. **灰色に上限を置く。** `fetch` は自分では諦めないので `withRead`（12秒）を
   通す。**`abort` だけで試すと、この穴は見つからない**（即座に catch に入る）
4. **押されるまで待たない。** 落ちたら間隔を倍にしながら黙って読み直し、
   `online`・画面に戻ってきたでも読み直す。**画面を開き直させない**
5. **骨に戻すのは、押されたときだけ。** ひとりでに読み直すたびに戻すと、
   灰色と文言が数秒おきに入れ替わる
6. **読めていない相手に、書ける口を開かない。** 区画は残して、押しどころだけ
   出さない。**上書きになる口（`POST /nordic/log`・`/me`・`/current`）は特に。**
   消える書き込みは、出ない書き込みより悪い

顔と言い回しは**部品ひとつ**から出す（`components/me/ReadAgain.tsx`。
「いま、〜を読みに行けなかった」「少し待ってから、もう一度。」
「もう一度よみこむ」）。**同じ意味を2通りに書かない。**
とくに「**開き直してください**」と書かない。開き直させないために4がある。

確かめかたは `tools/sprites/readbase.mjs` の上に立っている3本
（`readshot.mjs` / `forkshot.mjs` / `lieshot.mjs`）。落とし方3通り
（`abort` / `503` / **45秒返さない**）× オーナー／視聴者さん ×
**口を1つだけ落とす回**、それに**戻したとき（押す／押さない）**。

### #12 「言われたところ」しか直さず、その裏の道を直さなかった（2026-09-10）

**言われたこと**「Firestore 見直したはず。データ直したら、同じ反省点として
ルーティングも直すのが常識の仕事の進め方ですよ。」

**原因** 写真のデータを直したとき、**それを読む面・その面への入口・その面の
URL** まで見にいっていない。実際に壊れていたのはこの3つ。

1. `/nordic/photos/`（うしろにスラッシュ1本）が**島の玄関を 200 で返していた。**
   Firebase の受け皿（`"source": "**"` → `/index.html`）に落ちるため。
   404 にすらならないので、踏んだ人には何が起きたのか分からない。
   **`/nordic/photos` だけの話ではなく、島じゅうの URL がそうだった**
   （`/nordic/day/1/` も同じ）。`"trailingSlash": false` を足して直した
2. `/nordic` からの入口は、写真が貼られるまで出ない1行だけ。
   旅程表の 7画面ぶんの下にあって、**入れないに等しかった**
3. カードの企画の札（`/next#food-wine-fest`）を押しても、その段まで**送られない。**
   目当ての段が 3,055px にあるのに、止まったのは 238px。面が出てから伸びるので、
   ブラウザが `#` を探す時点ではまだその高さに無い。**島の面はどこも中身を
   取りにいくので、この面だけの話ではない**（`components/ui/HashJump.tsx`）

**対策** 決めごと5。データを直したら、それを読む画面・その面への入口・
URL・文言まで、**同じ理由で壊れているところを探しに行く。**
そして **curl の 200 を「入れる」と読まない。** curl は
`/nordic/photos` しか叩いていないし、スラッシュ1本違いも、押したあと
どこへ着くかも見ていない。**ログインして、実際に押して確かめる。**

### #13 「代表の1人」を勝手に立てた（2026-09-10）

**言われたこと**「代表でキャラクターを埋めるのはやめて欲しい。」
「たいpi のキャラクターが見切れてる。あと大きさも不揃い。」

**原因** 1枚の写真に4人ぶんカードがあるのに、開いた先が**1人目を入れた絵**で

`/about` の帯も同じことをしていた。

散らしたのは「一覧に同じ写真のカードが人数ぶん並ぶ」ころの都合で、
**一覧が写真1枚につき1マスになった時点で、理由が消えていた。**
消えた理由の名残を、消さずに残していた。

**対策** 決めごと4と6。**まとめ方を変えたら、その前提で入れた工夫を
見直す。** 出す前に、本番と同じ値で撮って自分の目で見る
（本番の4人ぶんで撮っていれば、はみ出しはその場で見えた）。

**式そのものは正しい。当てる先を間違えた。**

出そうとした**（水準の1に反する）。

**対策** 数式や定数を別の画面へ持っていくときは、**それが何のために決められた

### #22 章の名前を "use client" のファイルから持ち出して、表紙を丸ごと入れ替えていた（2026-09-10）

### #29 「今日」を UTC で切っている場所が1つだけ残っていた（2026-09-11）

**何が起きたか** 島の日付はほとんど日本時間で切っている（`lib/nightly.ts` の
`jstNow`、`lib/stay.ts`）のに、`content/plans.ts` の `daysUntil()` だけが
`getUTCFullYear` / `getUTCMonth` / `getUTCDate` だった。UTC は9時間遅れなので、
**毎日 00:00〜09:00 JST のあいだ「今日」が前の日を指す。**

北欧への出発は 04:30 JST。**出発の瞬間から、まるごとその窓に入る。**
出発の夜の4時間半、表紙の「いま、いちばん近い企画」がいちばん大きい札で
**過ぎた「ジョージアバイバイ」を「今日」と出し、旅そのものが表紙から消えていた**
（`NextUp.tsx` の一覧が、北欧を `daysLeft = -1` として落とすため）。
`/next` の先頭も `/now` の「次の企画まで 今日」も同じ。

**なぜ気づけなかったか** 日付の切り方が2つあることが、どこにも書いていなかった。
`daysUntil` は1行で読めば正しく見える（UTC どうしで引き算していて、時差の
バグには見えない）。**ずれるのは1日のうち9時間だけ**なので、昼に撮っている
かぎり一生出てこない。出発の時刻が朝4時半だったのは、たまたま。

**対策**

- **日付の切り方は1か所に寄せる。** 島の「今日」は `lib/nightly.ts` の
  `jstNow` ひとつ。日付を扱う関数を書いたら、そこを見ているか確かめる
- **日付で変わるものは、その日を過ぎた形で撮る**（#23 と同じ）。
  ただし**時計を差し込むときは、時差も一緒に差し込む**
  （`timezoneId: "Asia/Tokyo"`）。`Date` だけ差し替えて時差を UTC のままに
  すると、**JST と UTC の食い違いそのものが消えて、直っていないものが
  直って見える**。道具は `tools/sprites/jstday.mjs`
- 撮る時刻は**昼だけにしない。** 00:00〜09:00 JST の窓を必ず1本入れる

### #30 ブラウザで読み直される「焼いた答え」を、焼いた答えとして使っていた（2026-09-11）

**何が起きたか** `/atlas` が `Minified React error #418`（水あわせの失敗）を
出していた。原因は2つあって、どちらも**「焼いた HTML」と「ブラウザの最初の
描画」が別の答えを出す**形だった。

1. `chapterDays(cur, today ?? undefined)`。`today` が `null` の最初の描画で
   `undefined` を渡すので、既定引数の `new Date()` が走る。焼いた HTML は
   焼いた日で「440日」、開いた日は「441日」。**焼いた翌日から毎日ずれる。**
   同じ形が `NextUp.tsx` の `planDaysLeft(p, today ?? undefined)` にもあった
2. `NOW_CHAPTER`（`content/chapters.ts` のいちばん外で `chapterNow()` を
   呼んだ値）。**あれは「焼いた答え」ではない。** モジュールのいちばん外の
   式は、ブラウザでも読み込んだ瞬間の時計で数え直される。焼いた HTML は
   「コーカサス周遊・440日」なのに、出発の時刻を過ぎたブラウザでは最初の
   描画から「北欧周遊・1日」になる。**出発の 19:30Z を境に、1分刻みで確認した**

**対策**

- **`?? undefined` で既定引数の `new Date()` に落とさない。** 最初の描画は
  必ず**焼いた時刻**（`lib/nightly.ts` の `BUILT_AT`）で数える。本物の今日で
  数え直すのは `useEffect` が動いてから。この形は
  `components/live/NextPlans.tsx` と `PlanCard.tsx` が先にやっていた
- **「焼いた答え」は、環境変数から来た値だけ。** `NEXT_PUBLIC_BUILT_AT` は
  サーバ側とブラウザ側に**同じ文字**で埋まるのでずれない。
  関数を呼んで作った定数は、ブラウザでは呼び直される
- 確かめかたは、**焼いた翌日を装って、差し込みなしの本物の時計で開く**
  （`NEXT_PUBLIC_BUILT_AT` を1日前にしてビルドする）。時計を差し込んで
  確かめると、差し込みそのものが原因の水あわせ失敗と見分けがつかない
  （`docs/island-standards.md` 13）

### #34 「読めなかった」を「無い」に倒して、旅先で島を動かせなくしていた（2026-09-10）

**言われたこと**「電波が細いと、あやとが島を動かせなくなる。今日いちばん重い1件。」
出発は翌日。**車の中・国境・山のなかからスマホ1台**で島を動かす旅で、
**電波が細いのは異常ではなく、ふつうの状態。**

**何が起きていたか** `POST /island-api/me` が**1回でも返らないと**、こうなった。
`abort` だけでなく **503 でも「45秒返さない」でも同じ**なので、
横取りの作りかたのせいではない（判定#13の裏取り済み）。

| 面 | 出ていたもの |
| --- | --- |
| `/me/desk` | 高さ 934px、「ここは、あやとの机」。**道具の札 0枚** |
| `/me` | 「島の手入れ」のカードごと消滅。**画面上に `/me/desk` へ行く道が1本も無い** |
| `/nordic/day/N` | 書く欄 1→0、書き出しの札 5→0、「入れる」消滅 |
| `/me` の数 | 付箋 20 / 企画 10 / カード 12 → **0 / 0 /（空）**＋「まだ1枚も貼っていません」 |
| `/me/remote` `/me/roulette` | **灰色の骨2本、998px。何分待っても変わらない** |

**しかも二度と読み直さなかった。** `lib/auth.tsx` の `token` は
`useCallback(…, [])` で参照が変わらず、読みにいく効果の依存が `[user, token]`
だったので、**画面を開き直すまで直らない。**

**原因** 3つとも根は1つで、**読めなかったことを「無い」と同じ絵にしていた**
（`docs/island-standards.md` 10）。

1. `amIOwner()` / `loadMe()` の `catch` が **`false` を返していた。**
   「読めなかった」は「あやとではない」ではない。しかも同じことを
   4か所（机・日誌・板・カード）がそれぞれ聞いていたので、
   **落ちたぶんの面だけが「あやとではない人」の顔に化けた**
2. 付箋・企画は `catch` で **`setStickies([])`** としていた。空の配列は
   「読めた上での0枚」のことばで、届かなかった日に言ってよい嘘ではない
3. 遠隔操作とルーレットは、`if (!ses) return <骨>` が**エラーの文言より上**に
   あった。文言（「開けませんでした。電波の届くところで、もう一度。」）は
   もう書いてあったのに、**構造上ぜったいに到達しなかった。**
   骨は「もうすぐ出る」の意味で、出ないものの上に置いてはいけない

**対策**

- **答えは3つ持つ。** `owner` は `"yes" / "no" / "unknown"`、読みものは
  `wait / ok / down`。**`unknown` は「オーナーである」でも「オーナーでない」
  でもない**ので、道具も出さないし、他人の顔にもしない
- **前に口が返した答えを、端末に覚えておく**（`ayato-island-owner`）。
  覚えているのは *口が返した答え* で、こちらで決めた答えではない。uid ごとに
  持ち、ログアウトで消える。実際に書けるかどうかは書く先の口
  （`functions/src/islandApi.ts` の `ownerUid`）がもう一度見ているので、
  ここを書き換えても道具は使えない
- **返事が来ないのも「読めなかった」**（`withRead`、12秒）。細い電波では
  断られるより固まるほうが多い。`fetch` は自分では諦めない
- **押されるまで待たない。** 落ちたら間隔を倍にしながら黙って読み直し、
  `online` と「画面に戻ってきた」でも読み直す。**画面を開き直させない**
- **島でひとつの答えを見る。** `POST /me` は `AuthProvider` が1回だけ引いて
  配る。面ごとに聞くと、落ちたぶんだけ答えが割れる

**確かめかた**（`tools/sprites/readbase.mjs` / `readshot.mjs`）。
落とし方3通り（`abort` / `503` / 45秒返さない）× 端末2通り（前に読めたことが
ある / まっさら）× **視聴者さんでも同じ3通り**を撮る。
**7番目の条件がいちばん大事で、「読めなかったら見せる」に倒すと、
他人にオーナーの道具が見える。**

直らない**（#34 の `token` と同じ形）。

**いちばん効いたのは、文言がもう書いてあったこと。** `Fork.tsx` には
「いま数えられませんでした。少し待ってから、もう一度どうぞ。」が書いてあるのに、
**押したあとにしか出ない**位置にいた。#34 の遠隔操作・ルーレットで
「エラーの文言より上に骨がある」と書いたのと同じで、**書いてあるのに

**原因** 「分からないときは席を消す」が、#15（足代）で一度否定されたあとも

**対策**

- **否定した決めごとを、根拠として書き残さない。** 直したときは、それを引いて
  いるコメントも一緒に直す。**根拠として残っていると、次の担当がそれに従う**
- 「読めなかった」の顔は**部品ひとつ**（`components/me/ReadAgain.tsx`）から出す。
  同じ意味を4通りに書かない。今回、写真の口の「企画の一覧が読めませんでした。
  このまま貼れます。日付から結びます。」が**4つめの言い回し**になっていた

  押しどころは出さない、の2つは別

**確かめかた**（`tools/sprites/forkshot.mjs`）。落とし方3通り ×
オーナー／視聴者さん、それに**通信を戻して、画面を開き直さずに読み直せるか**。

### #43 同じ「読めなかったら消す」が、あと4か所に残っていた（2026-09-10。#277）

**言われたこと**「#34 と同じ根っこの4件目です。洗い出しで残り12件、そのうち
**嘘をつくもの4件**」。#34（じぶんのこと・机）、#36（旅の日のページ・写真の口）と
同じ日の、3度目の申し送り。

**何が残っていたか** 4つとも `catch` の中で空にしていた。

| どこ | 出ていたもの |
| --- | --- |
| `/cards` | **片方の口だけ落ちると「まだ1枚もありません」** |
| `/next/new?id=…` | 企画が読めないまま、**空の書く欄が「書きたす」付きで**出る |
| `/nordic` の写真の入口 | 入口の1行ごと消える（貼った本人が「入らなかった」と思う） |
| `/nordic` の旅程表・`/nordic/day/N` | 印が9日ぶんまとめて消え、「まだ書いていません。」 |

**いちばん重かったのは、片方だけ落ちる回**（`/cards`）。ここは口が2つ
（写真とカード）あって、`off` が **`bad >= 2`**——**2つとも落ちたときだけ**
「いまつながりません」だった。細い電波でいちばん多いのは**片方だけ落ちる**ことなので、

**書ける口まで開いていた。** `POST /nordic/log` は同じ日に書くと上書きなので、
読めないまま出る空の欄に打って押すと、**前に書いたものが消える。**
企画の「書きたす」も同じで、空の欄がそのまま送られる。#36 で
「読めていない相手に、書ける口を開かない」と書いた翌日に、2か所で開いていた。

**原因** 1件ずつ直していて、**同じ形を機械で洗い出していない**（#35 と同じ）。
`catch` の中で `setX([])` / `return null` / `setX(null)` と書くところは、
**その1行だけ見れば正しく見える**。落ちたときの絵が「0件の絵」と同じになることは、
その行の外に出ないと見えない。

`log.ts` には**否定された決めごとが根拠として書き残してあった**（#36 と同じ）。
「読めなくても何も出さない。『読めませんでした』の箱が旅程表に9個並ぶほうが悪い」。
**箱を9個並べない**ところは正しい。正しくないのは、そのために
**読めなかったことまで黙った**こと。箱は9個ではなく、旅程表にひとつでいい。

**対策**

- **口が2つある面は、落ち方が3通りある。**「両方落ちたら」で判定を書かない。
  **「無い」と言ってよいのは、口が**ぜんぶ**読めた上での0件だけ。**
  片方が読めていれば、読めたぶんは出す
- **数を言うところは、読めたときだけ言う。** 入口の札は消さずに、数だけ落とす
  （`TripPhotos`）。**行き先は落ちていないので、道まで閉じない**
- 「箱が並ぶから黙る」は答えではない。**箱の数を減らす**（区画ひとつに1枚、
  同じ面の2枚めは `quiet`）。黙ると、読めなかった日が「無い」になる
- **上書きになる口の前では、読めるまで書かせない。** 消える書き込みは、
  出ない書き込みより悪い

**確かめかた**（`tools/sprites/lieshot.mjs`）。落とし方3通り × オーナー／視聴者さん、
それに**口を1つだけ落とす回**（写真だけ／カードだけ）。通信を戻して、
押す回と押さない回の両方で、画面を開き直さずに直ることまで見る。

**道具が git に入っていなかった。** `_read.mjs` が `.gitignore` の
`tools/sprites/_*`（使い捨ての測定スクリプト）に当たっていて、
`readshot.mjs`・`forkshot.mjs` は誰も `git add` していなかった。
**同じ根っこを1日に4回踏んでいるのに、次のセッションには確かめかたが無い。**
土台は `readbase.mjs` に改名して3本とも入れた。
**持ち回る道具に `_` を付けない。**

本番で時計を旅の2日目（2026-09-13）に進めて `/` を開いた実測。待ち時間を
500 / 1500 / 2200 / 4000ms と変えて**4回とも同じ**。一時的な表示ではない。

**同じ根っこを、その日に4回踏んでいる。**

| | 直した面 | 何を足したか |
| --- | --- | --- |
| #265 | `/now` の1画面目 | `lib/stay.ts` の `placeOutdated` / `tripAsPlace` |
| #273 | `/nordic` の地図と旅程表 | `components/nordic/where.ts` の `planStop` |
| #276 | `/nordic/day/N` の越えた日の問い | 章が終われば問いも閉じる |
| **#44** | **表紙の名刺** | ——（判定を1つも通していなかった） |

**原因** 2つある。どちらも「置いた」で終わっていた。

1. **判定は1か所にあったが、その答えを字にするところが面ごとに書いてあった。**
   `/now` の1画面目だけが `` `${trip.name}のとちゅう` `` と書いていて、名刺は

   足しても直らない。** 直すたびに「その面の言い方」を新しく書いていたので、
   次の面が抜けても誰も気づかない
2. **名刺は便りを読みにすら行っていなかった。** サーバ側で焼いた字のまま。
   だから「あやとが旅先で書き替えれば人の字が勝つ」も、表紙だけ効いていなかった。
   **判定の有無より前に、そもそも古いデータしか持っていない面がある**

`docs/island-misses.md` #24 の対策に「閉じ方を1か所に置いただけでは足りない。
置いたら、**同じことを自前でやっているところを名前で探す**」と書いてある。
`.to` については探した。**`current.place` については、3回とも探していない。**

**対策**

- **判定だけでなく、言い方も1か所に置く**（`lib/stay.ts` の `placeWord`）。
  判定を呼んだ面が、答えを字にするところで独自の言い回しを書けないようにする
- **判定を足したら、その元データを読んでいるところを名前で全部洗う。**
  `NOW_FALLBACK.place` と `current.place` を `site/` から機械的に grep して
  一覧にする。**1件直したときの副産物ではなく、直しの一部としてやる**
- **面が「読みに行っているか」も一緒に見る。** 焼いた字だけの面は、判定を
  通しても配り直すまで古い。焼いた答え（配った日のもの）と、画面が出てからの
  引き直しの**両方**を見る
- **確かめかたは `tools/sprites/meishishot.mjs`。** 時計を進めて、表紙の名刺と
  `/now` の1画面目から**同じ字**を読んで突き合わせ、**並べて1枚**にする。
  別々に撮ると、食い違っていても2枚を見比べるまで気づかない。
  差し込みの既定は本番のまま（「ジョージア・トビリシ」・`updatedAt` 2026-09-04）
- **`innerText` で数えるところは、送る前と送ったあとの両方で読む。**
  表紙の章は `content-visibility: auto`（`.hchap-mat`）なので、送らないと
  本文に出てこない。両方で同じ答えになるまで見る（水準13）
- **並べた絵は、出す前に自分で開く。** `setContent` の中身は about:blank なので
  `file://` の絵は黙って壊れる。**空の枠が2つ並んだ絵を、一度そのまま出しかけた**
  （水準11「作って満足して終わらない」）

### #46 「配信はのこっていない」が、拾えていないだけだった（2026-09-10。ジョージアの7街）

あやとの言葉:

> `/map/georgia` の「行った街」。クタイシ・ズグディディ・メスティア・ボルジョミ・
> バトゥミが「配信はのこっていない」になってる。**残ってるはず**

BigQuery で数えたら、全部残っていた。題名にその街の名前が入っているものだけで
ボルジョミ10・バトゥミ9・ズグディディ5・メスティア4・クタイシ4。
画面に出ていたのは**トビリシ3・カズベキ3の2街だけ**だった。

**なぜ外したか**

同じ日の朝、`cityStreams.ts` が古いのを見つけていた。そのとき
**「焼き直すと別物になる（並びごと変わる）」から触らない**と決めて、
`rebake.yml` の allowlist からも外している。

**「古いだけ」だと思っていたのが間違い。** 中身は最初から足りていなかった。
`python/build_city_streams.py` の `read_stays()` が `countries.ts` を
正規表現ひと息で読んでいて、2ヶ所で**例外を出さずに**落ちていた。

1. 滞在が**複数行**で書いてある国（イギリス・ジョージア）は、内側の式が1行の
   `{ from: ..., to: ..., cities: [...] }` しか探さないので**まるごと落ちる**。
   ジョージアの9ヶ月とイギリスの2ヶ月が消えた
2. `stays` と `summary` の間に注釈がある国は、外側の式が**次の国の stays まで飲む**

結果、**イギリスは8街ぜんぶが「配信はのこっていない」**、ジョージアは7街中5街。
36街89本しか入っていなかった（焼き直したら49街322本）。

そのうえ、committed の `cityStreams.ts` の見出し行はスクリプトが書くものと
**文言が違う**。あのファイルは**一度もこのスクリプトで焼かれていない**。手で書いたものだった。

**横に展開して、もう1本見つかった**

同じ `countries.ts` を読んでいる python を名前で洗ったら、**`build_on_this_day.py` にも
同じ形の式が残っていた**（`stays: \[...\],\n    summary`）。こちらは注釈のある国で
`continue` して**その国がまるごと落ちる**。いま落ちるのは**ジョージア**で、
`onThisDay.ts` の618件のうち**378件**がジョージアの日。

**まだ本番は無事だった**（配ってある `onThisDay.ts` は注釈が入る前に焼かれている）。
ただし `build_on_this_day` は**毎晩ひとりでに回る**ので、次に焼いた晩に378件から
場所が消えて、緑のまま master に入るところだった。**今日直した。**

しかも `build_on_this_day.py` の docstring には
「`build_city_streams.py` の正規表現は…イギリスとジョージアを取りこぼす」と
**書いてあった**。気づいていて、自分のところだけ避けて、元は直していない。

**対策**

- **「古い」と「足りない」を分けて確かめる。** 焼き込みを疑ったら、日付を見て
  終わりにせず、**元（BigQuery）と件数を突き合わせる。**
  今回は「街の数」を数えるだけで気づけた（36街しか無いのに国は18ある）
- **読み落としを、件数で落とす止め金を置く**（`read_stays()`）。
  `countries.ts` の `cities:` の数と、読めた滞在の数が合わなければ例外にする。
  黙って減るものは、減ったことに誰も気づかない
- **正規表現ひと息で入れ子を取らない。** 括弧を数えて切る。
  `(?:.|\n)*?` は、途中に注釈が1つ入っただけで隣の要素まで飲む
- **自動生成ファイルは、生成物かどうかを見出しで確かめる。** スクリプトが書く
  見出しと1文字でも違えば、それは手で書かれたもの（水準8「名簿を手で作らない」）
- **「あっちが壊れている」と書いたら、あっちを直す。** 避けて通ると、避けた本人が
  いなくなったあとも壊れたまま残る。今回は半年残った
- **触らない判断をしたら、その理由を1回は裏取りする。**
  「別物になるから触らない」は、**別物になった先が正しいかを見ずに**決めていた。
  見ていれば、その日のうちに気づけた

### #49 毎晩ひとりでに走るものに、止め金が1つしか無かった（2026-09-10）

**言われたこと**「17日間手が出せない。そのあいだ `rebake.yml` が毎晩ひとりでに走って
master に push する。誰も見ていない。**次に同じことが起きたとき、止まる仕掛けを作れ。**」

`onThisDay.ts` の618件のうち378件がジョージアなので、**61%の日から場所の字が消えたもの**が

**原因** 止め金が `residents.ts` の `ACTIVE_FRIENDS` の増減比**1つだけ**だった。
それを付けたのは 61 → 174 が実際に起きたからで、**起きたところにしか置いていない。**
ほかの焼き込み4本には何も無かった。**「見つかった1件」を直して、同じ理由で

### #54 配るたびに、直前1時間に島を見ていた人が全員落ちていた（2026-09-11。本番の白画面）

あやとの言葉（2026-09-11）:

> 本番が `Application error: a client-side exception has occurred while
> loading live-streaming-d3cac.web.app (see the browser console for more
> information).` となってる。

**コードのバグではなかった。配り方の設定が抜けていた。**

**何が起きていたか**

1. Firebase Hosting は HTML を既定の `Cache-Control: max-age=3600` で配る。
   **端末は1時間、古い HTML を持ち続ける**
2. 焼き直して配ると、束のファイル名（内容ハッシュ）が変わり、**前の名前の
   ファイルは消える**
3. `firebase.json` の rewrites のいちばん最後に総取りの
   `{"source": "**", "destination": "/index.html"}` がある。**消えた束を
   取りにいくと 404 ではなく 200 + `index.html`（372KB）が返る**
4. ブラウザはそれを JavaScript として構文解析して
   `SyntaxError: Unexpected token '<'` を投げる → 面が丸ごと落ちる

**`webpack-….js` と `app/layout-….js` はどの面でも読まれる。** だから面を
問わず落ちる。あやとの字の「while loading live-streaming-d3cac.web.app」に
面の名前が無いのは、そういう落ち方だから。

**1時間で自然に直る。だから、こちらで開き直すと再現しない。** ログアウトでも、
ログインしていても、どの面でも例外0だった。**新しく開いたブラウザは新しい
HTML を取り直すので、そもそも消えた束を知らない。**

**なぜ急いだか。** 旅のあいだは毎晩 01:00 UTC に焼き直しがひとりでに出る
（`.github/workflows/rebake.yml`）。**そのたびに、直前1時間に島を見ていた人が
——視聴者さんを含めて——開くと落ちる。** あやとは旅先にいて直せない。

**原因**

**「配ったら古いものは消える」を、配り方の設定で受けていなかった。**
HTML を溜めさせるなら、束は消してはいけない。束が消えるなら、HTML を
溜めさせてはいけない。どちらも決めていなかったので、既定の1時間が
そのまま**毎晩1時間の落下時間**になっていた。

**対策**（`firebase.json` に `headers` を足した）

- **HTML は `no-cache`。** 持っていてよいが、使う前に必ず聞き直す。
  変わっていなければ 304 なので往復は軽い。`max-age=0, must-revalidate`
  でも同じことができるが、`must-revalidate` は間に入る箱によって読みが
  分かれる。**どこでも同じに読まれるほう**を選んだ
- **名前に内容ハッシュが付いているものは、逆に1年（`immutable`）。**
  `/_next/static/**` と `/_expo/static/**`。中身が変われば名前が変わるので
  古いものを掴む心配が無い。**HTML を毎回聞き直すぶんの往復を、ここで取り返す**
- **ハッシュの付いていないものに `immutable` を付けない。**
  `/sprites/**` `/characters/**` `/og.png` `/favicon.ico` は名前が変わらない。
  1年置かせると、差し替えても誰にも届かなくなる
- **並び順は、外しても落ちないほうに倒す。** 同じ道に2つ当たったとき
  Hosting が先勝ちか後勝ちかは公式に書かれていない。総取りの `no-cache` を
  **先頭**に置いたので、後勝ちなら下の2つが効いて速くなり、先勝ちなら
  全部 `no-cache` で遅いだけ。**どちらでも、直したかった落ち方は起きない**

**消えた束が、島の HTML で返るのもやめた**

総取りの rewrite より**前**に、`/_next/static/**` と `/_expo/static/**` を
実在しない道（`/__gone__`）へ流す2本を置いた。**あるファイルはこれより先の
「そのままの静的ファイル」で配られる**ので、ここに落ちてくるのは消えたものだけ。
Hosting の emulator で確かめた:

| 道 | 前 | 後 |
| --- | --- | --- |
| ある束 | 200 `application/javascript` | 200 `application/javascript`（変わらない） |
| 消えた束 | **200 `text/html` 372KB** | **404** |

`SyntaxError: Unexpected token '<'` で面ごと落ちるかわりに、束1本が
取れなかったという顔になる。**原因も、次に何が起きたかも読める。**

**残っている穴**（小さいが、書いておく）

`immutable` は**外れた道にも付く。** 404 を1年ぶん端末に置くので、
`git revert` で前と同じ名前の束が戻ってきた日に、その端末だけ取りに来なくなる。
消える前は 200 + HTML を1年ぶん抱えていた（もっと悪い）ので後退ではないが、
**戻す形のデプロイをしたら、束の名前が前と同じになっていないかを見る。**

---

**測りかたを2つ外した。両方とも「道具のほうが間違っていた」（決めごと13）**

**(1) 生きているかを、状態番号で測った。**
「本番の HTML が指す束に 404 は1本も無い」と報告した。**この本番は
存在しないパスにも 200 を返す**ので、状態番号では何も分からない。

```bash
# 駄目な測り方（全部 200 と出る）
curl -s -o /dev/null -w "%{http_code}" "$ORIGIN/_next/static/chunks/nope.js"   # → 200

# 正しい測り方（中身を見る）
curl -s "$ORIGIN/_next/static/chunks/nope.js" | head -c 20                     # → <!DOCTYPE html
```

**総取りの rewrite がある置き場では、資源の生死は中身で測る。**

**(2) 横取りの道具が、状態番号を握りつぶして偽の落下を作った。**
本物の返事で落ちるところを探すために、`/island-api/...` を差し替えずに
curl で本番へ通す道具（`tools/sprites/_errraw.mjs`）を作った。その1版目が
**curl の結果を何でも `status: 200` で返していた。** 本番の
`401 {"error":"no token"}` が「読めた返事」として画面に届き、
`MyPage.tsx` の `{st:"ok", list:undefined}` を作って `/me` が落ちた。

```
TypeError: Cannot read properties of undefined (reading 'length')
  at m (app/me/page-….js:1:4189)      // "ok"===e.st ? String(e.list.length) : ""
```

**本物の口は 401 を返して `req` が投げるので、本番では起きない。**
報告する寸前で止まった。番号と型をそのまま返すように直してある。

**決めごと13に足す:** 横取りの道具は、**本番が返した状態番号と
content-type をそのまま渡す。** 200 に丸めると、画面から見て
「読めた」と「断られた」の区別が消える。**エラーの道が全部消えるので、
落ちるはずのないところが落ちる。**

### #74 1つの式に2つの問いを兼ねさせて、寝かせる理由を確かめずに書いた（2026-09-12）

旅程表の「いま、ここ」の札が、**今日ではない日の行**に付いていた。
9/12（旅の1日目）に本番を見ると「2日目 9月13日(日) **いま、ここ**」と、
**今日ではない日付の横に「いま」**が並んでいた。

原因は `nowRow` の式が、**別の2つの問いを兼ねていた**こと。

```ts
const nowRow = sure
  ? (dayOf[mainLegs[at]] ?? null)   // 居どころから「そこを発つ区間の行」
  : (today && dayByDate[today]) || null;
```

- **「旅程表のどの行が今日か」** は暦の問い。行は1行=1日で日付を持っている
- **「地図のどの街に居るか」** は居どころの問い。別の `useEffect` が答えている

居どころで行を決めると、リガに 9/16 に着いて 9/18 に発つあいだの2日間、
札は 9/18 の行に出る。**終点には発つ区間が無いので、ストックホルムの
8日間は札が1つも出ていなかった。**

**決めごと。1つの式に2つの問いを兼ねさせない。**
行は日付で引く。場所は居どころで引く。混ぜると、どちらかが必ずずれる。

**決めごと。理由の書いてあるコメントは、その理由が片方の枝にしか
当たっていないことを疑う。** ここには
「区間から引くと、動かない日が翌日の行を指す」と**正しい注記**があった。
正しいのに、`!sure` の枝にしか当てていなかった。**同じ理由が、もう片方の
枝にもそのまま効いていた。**

## #79 下見が出した「0人」を、事実の0だと読んだ

投げ銭の対応表を Firestore に入れる道具（`python/admin/donors_import.py`）を、

if cur and cur.get("editedAt") and not force:

**決めごと。下見は、本番と同じところを読んでから数える。**
書かないことと、読まないことは別。**読まない下見は、下見ではなく気休め。**

#### 追記（#79 を直す側で、今度は #78 を踏んだ）

上の穴を直す担当に渡すとき、**コードを読んで決めた原因をそのまま症状として書いた。**

> `_veil` は `list` を `_PLAIN` で素通りさせている。`query.get()` は list を返す

| 素通りしていた器 |
| --- |
| `query.get()` / `collection.get()` / `select().get()` / `list_documents()` / `collections()` / `get_all()` |

**決めごと。原因を1つ見つけたら、それが「全部」か「1つ目」かを分ける。**

直す前に、同じ種類の入口を**並べて全部叩く**。1本ずつ直すと、直した数だけ安心が増えて、

## #88 issue の読み替えを読まずに、同じ仕事をする入口をもう1本マージした（2026-09-14。切り抜きの mp4）

**何が起きたか** 配信から mp4 を切り出す入口が、**2本になっていた。**

| | 中身 | 実績 |
| --- | --- | --- |
| `clip_fetch.yml` → `tools/clip/fetch.py`（PR #377） | 口を9つ当たり直す。PO Token を自分で立てる | **本番で81回叩いてある**（3ランナー × 9つの口 × 3周） |
| `clip_make.yml` → `tools/clip/make.sh`（PR #384） | 1発で切る。時間帯の見張り付き | **YouTube に一度も届いていない** |

issue #322 には「以前この issue に書いた `clip_make.yml` は結局作っていません。
読み替えてください」と書いてあり、**前の担当は `clip_fetch.yml` に一本化する

マージした（PR #384）。**判断はもう出ていて、それを知らずに巻き戻した。**

**原因** 古い PR を、**その PR の中身だけを見てマージした。**
PR は「作った時点の判断」で止まっている。あとから issue のほうで判断が
変わっていても、PR の差分にはそれが出ない。**変わったかどうかは、
PR ではなく issue に書いてある。**

そして issue を開いていれば、いちばん上に読み替えが書いてあった。
**開かなかったのは、差分が読めて、CI が緑で、自分が出した issue だったから。**
自分が書いたものは覚えているつもりでいた。セッションは変わっている。

**しかもこれは、こちら（管理側）の外し方。** 実装を配った先の話ではない。
「どの入口を正にするか」は設計の判断で、配れない仕事のほうに入る。

**対策**

- **日をまたいだ PR は、マージする前に紐づく issue を開き直す。**
  差分と CI は「作った時点で正しいか」しか言わない。
  **「いまも要るか」は issue にしか書いていない**
- **同じ仕事をするものが2つになっていないかは、マージのあとに1回数える。**
  入口（ワークフロー）の一覧を見て、名前で読み替えて重なりを探す
  （`ls .github/workflows/`）。増えた直後なら、まだ寄せられる
- **どちらを残すかは、本番に届いた回数で決める。** 出来のよさでも、
  新しさでもない。**一度も本番を通っていないものを正にしない**
- **捨てるのは入口だけ。中身は移す。** 落としたほうにしか無い確かめかた
  （切り出した頭をフレームのハッシュで突き合わせる・頼んだ長さの半分に

対照（当たるはずのものが当たるか）まで要る。

### 確かめは、道具の隣に置いた

`python/admin/characters_freeze_selftest.py`。偽の Firestore で3つの仕分けを
実際に数え、**対照が本当に火を噴くところまで**見る。壊した写しは2つ:

- 引き当て方を壊した写し（`@` を落とさない）
- **辞書が1件も返らない写し**（本番で2回起きた形そのもの）

どちらも終了コード 2 で止まり、**数字を1つも出さない**ことを確かめる。
壊していない写しが通るのを**先に**見る（`#99` の決めごと）。

### 同じ日に、同じ形をもう1回やった —— **中身が空のままマージした**

上の #100 を記録する PR（#428）が、**変更ファイル 0 件のままマージされた。**
`git push origin <ブランチ名>` は「いま HEAD にあるもの」ではなく
**そのブランチが指している先**を押す。`master` の上でコミットしてから
古いままのブランチ名を押したので、**新しいコミットが1つも載っていなかった。**

PR は緑で、マージも通り、あやとには「足しました（#428）」と報告した。**嘘だった。**

## #101 配った担当が落ちたのに気づかず、2時間「調査中」と言い続けた（2026-09-15。歩くキャラの調査）

あやとに「歩くキャラの仕様がバグってそう」と言われて担当に配り、
そのあと**2時間、聞かれるたびに「調査中です」と答えていた。**

あやとが「歩くキャラ調査はどうなった？」と聞いてきたので走っている一覧を見たら、
**その担当は一覧に居なかった。** 落ちていて、報告も来ていなかった。
自分で調べたら**15分で答えが出た**（見ているのはコメントだけで、投げ銭は
1件も条件に入っていない）。

### なぜ気づかなかったか

**「配った」を「走っている」の証拠として使っていた。**

配ったときに手元に残るのは「配った」という記憶だけで、いま生きているかは
どこにも出ていない。**完了の知らせは来たものしか見えないので、
「来ていない」は「まだ終わっていない」と見分けがつかない。**

| 知らせが来ない理由 | 見分けかた |
| --- | --- |
| まだ働いている | **走っているものの一覧に居る** |
| 落ちた | 一覧に居ない |

`#99` とまったく同じ形。**緑になる道が2本あって、どちらなのかが書いていない。**

### 決めごと。**「担当が作業中」と言う前に、一覧を見る**

- 状況を報告するとき、**走っていると書く担当は、その場で一覧に居ることを見る**
- **記憶から書かない。** 「さっき配ったから走っているはず」は、走っている証拠ではない
- 一覧に居なければ**落ちている。** 配り直すか、自分でやる。**黙って待たない**
- 長く音沙汰のないものは、**聞かれる前にこちらから見る**

### 待つ相手が2種類あることを、混ぜない

- **仕掛けた仕事**（ワークフロー・デプロイ）… 終わったかを**問い合わせて**確かめられる
- **配った担当** … 知らせが来るのを待つ形なので、**来ないことが何も意味しない**

前者は今日ずっと問い合わせて確かめていたのに、後者は待っているだけだった。
**待ちかたが違うものを、同じ「待ち」で扱っていた。**

## #102 「隣がいまどれだけ太いか」を数字で書き写していた（2026-09-16。島の隅の道具・札・カメラ）

あやとの言葉（2026-09-15、スクショ2枚つき）:

> あやと島、3日ぶりに触ったら、全体的に歩きづらくなってる。画像①下部押しても
> マップが下にいかないので下に進めない。広げると、島に降りると島の地図が被ってる。
> 代表6件のボタン無くなってる（**この仕様毎回消すのそろそろやめろや**）

3つとも過去に直した。3つとも同じ理由でまた壊れた。

### 同じ根っこ：**いまの値を書き写して、変わったことに気づけない形にした**

| どこ | 何を書き写したか | 変わったときに何が起きたか |
| --- | --- | --- |
| `chain.css` `.isle-atlas` | 隣（`.isle-view`）の幅 48px を `left: 68px` として | 引きで字が戻って隣が 105px に太り、**49px 重なった** |
| `chain.css` 640px 以上 | 上に積む札の高さを `bottom: 72px`（16+48+8）と手で足して | 同上の形。片方の背が変われば黙ってずれる |
| `plates.ts` | 建物の当たりを「在るもの」として | 引きでは当たりを止めてあるのに、**札が止まった当たりを避けて**引っ込んだ |
| `IsleStage.tsx` `camWant` | 引き戻しの量を「建物が1画面に入るか」だけで決めて | あやとが枠の **94%** に貼りつき、下に残る 61px は板が占めていた＝**押す地面が無い** |

どれも書いた時点では正しい。**正しいまま、隣が変わると嘘になる。**
しかも**赤くならない。** 見た目が少しずつ悪くなるだけなので、
次に誰かが目で見るまで誰も気づかない。あやとが3日ぶりに触るまで誰も気づかなかった。

### 決めごと

- **隣の寸法を数字で書き写さない。** 並べたいなら入れ物に並べさせる（`.isle-tools`）。
  太っても崩れない形にする。**「いま 48px だから 68px」は、次の変更で嘘になる。**
- **「在るか」ではなく「効いているか」で判定する。** 止めてある当たりは、
  避ける相手ではない。当たりどうしの取り合いには `takesTap` として同じ直しが
  入っていたのに、**札の側に入れていなかった。1か所直したら、同じ形を全部探す**（#5 #6）。
- **主人公が枠のどこに立つかを、決めごとにする。** カメラの値を
  「何が画面に入るか」だけで決めると、主人公の足元は成り行きになる。
  押して歩く島では、**足元の下に地面が残っているかが仕様**（`FOOT_LOW` / `FOOT_HIGH`）。

### なぜ3回目まで来たか

**目で見て気づくしかない形でしか確かめていなかった。**
島は幅と寄り引きで組み替わる。1つの幅を1回見ても、隣の幅が壊れたことは出ない。
実際、こちらが手で測ったときは 390px で「札が5枚」までしか分からず、
**1280px では4枚しか出ていなかった**ことは、道具にして初めて出た。

`tools/sprites/islenav.mjs` を git に入れた。3幅 × 寄り／引きで、
(A) 隅の道具と看板ロゴが重なっていないか (B) 引きに代表の札が6枚あるか
(C) 下半分の地面を押して南へ歩けるか を数で落とす。
**道具は、いまの本番に対して7件で落ちることを見てから使った。**
落ちない道具は、壊れていないことを証明しない。
