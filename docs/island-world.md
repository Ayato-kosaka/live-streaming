# あやと島 — 世界の設定と、部品の割りあて

同時に何人かで別々の場所を綺麗にすると、**それぞれ違う方向に綺麗になる。**
この文書はそれを止めるためだけにある。決めるのは「どちらに揃えるか」の一点で、
絵の作りかたは [`island-design.md`](./island-design.md)、
どうぶつの森との差は [`ac-reference.md`](./ac-reference.md)、
どこに何があるかは [`island-ux.md`](./island-ux.md)。

**使いかた。** 何かを作る前に 2章（型の割りあて）と 4章（部品）を引く。
表に無い部品を新しく作らない。作りたくなったら、表に1行足してから作る。

**優先順位。** `island-design.md` のほうが拘束力を持つ。
ここの決めごととぶつかるところは「**`island-design.md` を直す**」と書いてある。
先にあちらを直してから実装する。

2026年9月5日に、全21面をスマホ幅 390px で撮って並べて決めた。
撮り直す道具は `tools/sprites/wsheet.mjs`。

```bash
cd /home/user/live-streaming/site && NEXT_DIST_DIR=.next-dev3030 npx next dev -p 3030 &
cd ../tools/sprites && PORT=3030 node wsheet.mjs /tmp/wsheet 390 1400
# → /tmp/wsheet/_sheet.png に21面が1枚に並ぶ
```

**1枚に並べないと不統一は見つからない。** 1ページずつ見ているあいだは、
どのページもそれぞれ良く見える。並べて初めて「地の色が2種類ある」が見える。

**撮るときの注意。** 21面を1本撮るのに、開発サーバーが空いていて5分、
何人かが同時に動いていると 20分以上かかる。
2回目を撮ろうとしたとき、開発サーバーが8本・Chromium が47本立っていて
ロードアベレージが 260 まで上がり、1枚も撮れずに止めた。
**撮る前に `uptime` を見る。** 100 を超えていたら、撮らずに待つか、
CSS を読んで確かめる（そのほうが速いことも多い）。

**揃ってきたかの確かめは、撮り直しでなくてもよい。**
7章の7つは、2回目を撮れないまま `git log` と CSS で確かめた。
「`.chip` が平らなオリーブ1種類になっているか」を目で探すより、
`sed -n '/^\.chip {/,/^}/p' app/css/pages.css` を1回叩くほうが速くて確実だった。
**撮るのは「知らない不統一を見つける」ため。
「直ったかを確かめる」なら、コードを読むほうがいい。**

## 1. 世界の設定

ここから先の全部が、この1文から出ている。

> **あやと島は、あやとが旅で拾ってきたものが置いてある島。
> 島そのものは板でできていて、置いてあるものは紙でできている。**

### 1.1 島は「もう1つの場所」ではなく「このサイトそのもの」

いまは島がトップページの絵で、その外に11の面がある。
**この形は取らない。** ページは島の外ではなく、島の中にある物にする。

| 誤 | 正 |
| --- | --- |
| トップに島があって、その下にページのリンクがある | 島に建物があって、押すと中に入る |
| ページは「島とは別のウェブサイト」 | ページは「島で手に取った紙」 |
| 島の絵はトップだけの飾り | 島の**時刻**はどのページにも効いている |

### 1.2 時間 — ある。日本時間と同じものが流れている

すでに `IslandTheme` が `<html data-time>` に4つのうち1つを入れている。
これが島の唯一の時計。**乱数を持たない。** 日付と時刻から決める。

| `data-time` | いつ | 島がどうなるか |
| --- | --- | --- |
| `morning` | 5:00–10:00 | 海が明るい青緑。金色の光がひとさじ |
| `day` | 10:00–16:00 | 何もかけない。これが基準 |
| `evening` | 16:00–19:00 | 海がすみれに寄って、橙を乗算 |
| `night` | 19:00–5:00 | 海が沈み、`--lamp: 1` で窓に灯りが入る |

**時間で動かしてよいもの**

- 島の海・空・地面（`--sea-*` `--sky-*` `--tint` `--glow`）
- 板の型の地（`--ground-board`）
- 建物の窓の灯り（`--lamp`）
- 島にいる住人の数、鳥、星

**時間で動かしてはいけないもの**

- **紙**。`--ground-paper` も `--paper-mottle-*` も、夜に暗くしない。
  暗くすると、時間帯によって字が読めたり読めなかったりする面ができる
- 文字の色。全部
- 「押せる」の合図（枠の金色・厚み）

紙にも時刻を効かせたいときは、**紙の四隅に落ちる陰だけ**を動かす。
夜は `--shadow-2` を 0.34 → 0.40 に。それ以上はやらない。

### 1.3 季節 — 持たない。かわりに「いまいる場所」を持つ

あやとは移動している。**9月のジョージアと2月のスウェーデンが、同じ企画の中に同時にある。**
ここに日本の暦の季節を入れると、島が「日本にある島」になって、旅の意味が消える。

季節の代わりは `<html data-theme>`。いまは3つ。

| `data-theme` | いつ入るか | 何が変わるか |
| --- | --- | --- |
| （既定） | ふだん | ジョージアの昼の色 |
| `nordic` | 北欧旅のあいだ | 草が青みへ、砂が生成りへ。**彩度は落とさない** |
| `desert` | 中東・コーカサスの乾いた場所 | 草が黄へ、砂が濃く |

**決めごと。** 雪だるま・紅葉・こいのぼりのような**暦の飾りを足さない。**
足していいのは「いまいる国の気候」だけ。増やすときは `data-theme` を1つ増やす。

### 1.4 天気 — いまは持たない

島の状態は「4時間帯 × 3場所 = 12通り」。ここに天気を掛けると確かめる数が跳ねる。
**天気を足すのは、12通りを全部撮って揃ってからにする。**

### 1.5 ページは、島の中の何なのか

**この文書でいちばん効く決めごと。** 三段ある。混ぜると世界が壊れる。

| 段 | 何か | 型 | 地 | 例 |
| --- | --- | --- | --- | --- |
| 島 | 立っている土地 | **板** | 海。時間で動く | `/` の `.stage` |
| 手に取った紙 | 島で拾ったもの。図鑑・カタログ・番組表・しおり | **紙** | 生成り。時間で動かない | 島の外の面ぜんぶ |
| 紙の上の道具 | 押すもの・書くもの。紙の上に**載っている** | **板** | — | ボタン・入力欄・付箋 |

一文にすると:

> **島は板。島の外のページは、島で拾った紙。
> 紙の上で動くもの（押すもの・書くもの）だけが板。**

`main.page` を持つ面はぜんぶ紙、という切り替えが `tokens.css` に入った。
**この判断で正しい。** 理由は3つ。

1. 島の外の面を板にすると、厚みのある窓が延々と積まれる。
   `ac-reference.md` 7章が禁じているのがまさにこれ
2. 島の外の面はぜんぶ「拾った紙」で説明がつく。
   配信やぐらのページ＝やぐらに貼ってある番組表。企画掲示板＝掲示板に貼った紙。
   旅のしおり＝しおり。スタンプ帳＝帳面
3. 「紙の上の道具だけ板」にすると、**押せるものが自動的に浮いて見える**。
   押せる／押せないを、色でも光でもなく**型**で分けられる

**ただし1面だけ例外にする。** トップページ（`/`）は島そのものなので、
島の下も板の地（海）のままにする。
ここは一時期4色のパステルになっていて、板でも紙でもない第3の地だった（7.2）。

### 1.6 「島から出た」感じをなくす3つ

安い順。1だけでも半分は効く。

1. **紙の地を、島の空と同じ光で照らす。**
   `--ground-paper` の明るさは動かさないまま、**紙の外の粒と帯の色**だけを
   `--sea-mid` から取っている（`body .page::before` で置き換え済み）。
   ここに時刻をひとさじだけ入れる。夜は粒をわずかに濃く
2. **どのページにも1本、島の帯を置く**（`island-ux.md` 4.1 の第0層）。
   今夜の配信・いまいる場所・次の企画。**押すと `/now`**
3. **フッターを砂浜にする。** ページの終わりが「島に戻ってきたところ」になる。
   いまの「島にもどる」が、そこに立っている看板になる

**「紙＋板の道具」の意味。** 面は紙。その上に載っている**書く道具だけ**が板。
`.dform`（`ui.css`）がすでにこの作りになっている。`/board` の投稿欄も同じにする。

### 2.1 紙の面で、板の部品を出していいもの

これ以外は紙にする。

| 出していい板 | なぜ |
| --- | --- |
| 押すボタン（`.chip.link` `.rleg-go` `.hbig-go` `.dadd`） | 押せることは厚みで言う |
| 入力欄・選択欄（`.dform` の中） | 彫ってある溝で「書くところ」と言う |
| 行き先のカード（`.tile` `.scard`） | 押せるので |
| ヘッダーとフッター | 島の板が紙の面をはさんでいる、という形 |

出してはいけない板の例（いま出ている）:

- `/legends` の「いちばん語られている」の金のバッジ。**押せないのに板。** 平らな紙の札にする
- 紙の面の `.stat`（数字）。`.panel.paper` の中では影が消える決まりになっているが、
  `.panel.paper` を付けていない面（`/kitchen` `/legends` `/streams`）では板のまま残っている

## 3. 色 → 意味

### 3.1 決めごと

> **色で分けていいのは「配信の型」だけ。
> 章・パネル・ページ・国に色を割りあてない。**

いまサイトの中に、**意味のある色分けと意味のない色分けが同居している。**
意味のあるほう（配信の型5色）は残す。意味のないほう（トップの4章のパステル）は消す。
2種類が同居しているあいだ、見る人は色を手がかりにできない。

### 3.2 色の表

| 色 | トークン | 意味（1つだけ） | 出る場所 | 出してはいけない場所 |
| --- | --- | --- | --- | --- |
| こはく・金 | `--frame` `--frame-dark` `--frame-deep` | **押せる板のふち** | ボタン・ヘッダー・入口・カード | 紙の上の見出し、押せない札 |
| クリーム | `--paper` `--paper-2` | 板の面 | ボタンの面・吹き出し | 紙の面（そちらは `--paper-mottle-*`） |
| 生成り | `--paper-out` → `--ground-paper` | **紙の外**。紙より明るい | 島の外のページの地 | 紙そのもの |
| 図鑑の紙 | `--paper-mottle-a/b` | 紙の面 | 紙の型のパネル | 板の面 |
| 桃 | `--accent` | **いま／新しい** | 日数バッジ、NEW の丸 | ふつうのボタン |
| 濃い桃 | `--accent-deep` | 同じものの濃いほう | バッジの下側、日数の丸 | 単独で使わない |
| 水色 | `--accent-2` | **外へ出る** | 本文中のリンク、YouTube へ、フォーカスの輪 | 島の中の行き先（そちらは金） |
| オリーブ | `--chip` `--chip-ink` | **数えたもの。押せない** | 件数の札 | 押せるもの |
| 朱 | `--pick` | **いま選んでいる** | 絞り込みの枠、しおりの「やらない」 | 装飾、警告 |
| 蛍光 | `--marker` `--marker-ink` | **紙の見出し** | 紙の型の h3 | 板の上、本文 |
| 罫 | `--rule` | 紙の区切り | 紙の型の線 | 板の型（そちらは影と厚み） |
| 海 | `--sea-*` | 島の外の水 | ステージ、トップ | 紙の面の中 |

**この表に無い色を CSS に直接書かない。** `home.css` が
`#fff4d4` `#e8f8e0` `#ddf3fb` `#ffe6ea` を直値で持っていた。消えた（7.2）。

### 3.3 唯一許す色分け — 配信の型5つ

`content/streams.ts` の `color`。**この5色だけは「どの型か」を指している。**
使っていいのは3か所だけ。

1. `/streams` の型の札の帯
2. `/streams/[型]` の紙のわずかな染まり（`--zk-paper`。`color-mix` で 8〜11% まで）
3. 配信の一覧で、どの型かを示す点

**型の色を、その型に関係ないところへ持ち出さない。**
「クッキング配信が桃だから、料理のページも桃」はやらない。
料理のページは料理の紙であって、型の紙ではない。

### 3.4 押せる／押せないは、色ではなく型で分ける

`island-design.md` 3章に「押せるは1種類の合図で伝える」とある。その1種類をここで決める。

> **押せるものには、下に厚みがある（`--pop` 系）。押せないものは完全に平ら。**

光らせない。きらめかせない。色を変えない。**厚みだけ。**
遠目に分かる大きさで付ける。48px のボタンで 6px、30px の札で 4px。

## 4. 部品の一覧

**新しい部品を作る前に、ここを見る。** 同じ意味のものが2つあるなら、片方を消す。

| 部品 | 意味 | 型 | 見た目 | 最小の高さ | いまの class |
| --- | --- | --- | --- | --- | --- |
| 行き先のカード | 押すと別の面へ | 板 | 金のふち・厚み6px・右に矢印 | 56px | `.tile` `.scard` `.hcard` `.city` |
| 押せるチップ | 押すと絞り込む／開く | 板 | 丸・厚み4px | **48px**（いま30px） | `a.chip` `button.chip` `.kf-b` |
| 押せない札 | 数・状態を言うだけ | 紙 | 平ら・角丸8px・オリーブ | — | `.chip` `.fold-n` |
| 紙の見出し | 紙の上のまとまりの頭 | 紙 | 蛍光ペンの帯・字は `--marker-ink` | — | `.panel.paper h3` `.gh` |
| 板の見出し | 板の上のまとまりの頭 | 板 | 金のふちの丸札・スプライト1枚 | — | `.panel h3` |
| 区切り | 話題が変わる | 紙 | `--rule` 1px。**影で区切らない** | — | `.gtable` `.spost-list` |
| 折りたたみ | 長い話を畳む | 紙 | 罫で区切る・しるしは回る | 48px | `.fold` |
| 数字 | 数えた事実 | 紙 | 罫のます目。**板のカードにしない** | — | `.stat`（紙の面では） |
| 空っぽ | まだ何も無い | 紙 | 罫の枠1枚。次にすることを1つ書く | — | `.blank`（`ui.css`） |
| 読み込み中 | いま取りに行っている | 紙 | 出てくる物と同じ形の薄い板 | — | `.wait`（`ui.css`） |
| 書く欄 | 書き込むところ | 板 | 彫った溝（内側に影）・金のふち | 48px | `.dform input` |
| 入口（島） | 島の建物 | 板 | スプライト＋札 | **48px**（いま34px） | `.spot-hit` `.spot-mark` |

### 4.1 「空っぽ」と「読み込み中」を作る

サイトの中でいちばん抜けているのがここ。いま `/board` は
「読み込み中…」の**文字だけ**、`/next` は読む前に**「まだ1枚もありません」と嘘をつく**。

決めごとを1つ。

> **読み込み中は、出てくる物と同じ形・同じ大きさの灰色を置く。
> 空っぽは、灰色ではなく「ここに何が入るか」を言う紙を1枚置く。**

| 状態 | 出すもの | 出してはいけないもの |
| --- | --- | --- |
| 読み込み中 | 出てくる物と同じ形を灰色で3つ | 「読み込み中…」の文字だけ／何も出さない／「0件」 |
| 空っぽ | 「まだ誰も貼っていない。1枚目になる?」＋書く欄への矢印 | 「0件」「データがありません」 |
| 読めなかった | 「いまつながらない。あとでもう一度」＋もう一度押す板 | 何も言わずに空っぽのまま |

**部品はある。`ui.css` に3つとも入っている。**

- `.wait` … 中身の形をした薄い板を、出てくる数だけ並べる。
  高さは `.wait.is-row`（一覧の1行）/ `.wait.is-card`（カード1枚）か `--wait-h` で変える。
  1.4秒でゆっくり明滅する。`prefers-reduced-motion` では止まる
- `.blank` … 空っぽ。中に `<b>` で一言、`<p>` で説明、`.blank-go` で次の一手（48px の板）
- `.blank.is-off` … 取れなかったとき。形は同じで、色を落として静かにする

色は `--ink-3` を 26% で。動かすなら 1.4秒でゆっくり明滅させる。それより速いと落ち着かない。

### 4.2 部品を新しく作っていいとき

- 表の部品を組み合わせて作れないとき**だけ**
- 作ったら、この表に1行足す
- `/design`（デザインの見本）にも1つ置く。**置いていない部品は無いものとする**

### 4.3 良い例と、悪い例

いま画面に出ているもので言う。

**① 数字の並べかた**

| | |
| --- | --- |
| 良い | `/kitchen` の「ここまでに押したスタンプ」。1枚の紙を細い罫で4つに割って、`32品` だけ大きい。**紙の型のまま数字を出せている** |
| 悪い | `/about` の6つの数字。同じ大きさの板が6枚。**どれが大事か言っていない**。板の型なので、押せそうにも見える |

決まり: **数字は「1枚の面を罫で割る」。数字ごとにカードを作らない。
いちばん言いたい1つだけ大きくする。**

**② 「押せる」の言いかた**

| | |
| --- | --- |
| 良い | `/next` の「くわしく見る >」。クリームの板・厚み4px・右向きの印。**遠目に押せると分かる** |

## 5. 段（余白・角丸・影・字）

段が揃っていないと、並べたときだけ「なんとなく雑」に見える。
どれも `tokens.css` に段がある。**直に px を書かない。**

### 5.1 余白

| --- | --- | --- |

### 5.2 角丸

## 6. 絵。スプライトと SVG と写真が、同じ世界に見えるか

**いちばん揃っていないのがここ。** 島の上のスプライトは1つの世界にいるが、
ページの中の絵は3つの世界に分かれている。

### 6.1 いま3つある絵柄

| 絵柄 | どこ | 見え方 |
| --- | --- | --- |
| 焼いたスプライト | 島、見出しの丸、タイルの印 | どうぶつの森。輪郭線なし・強い環境光 |
| 自前の SVG | `Icon.tsx`、料理の絵、地図 | 平ら。線と面。**光が無い** |
| 写真 | あやとの顔、Wikimedia の景色 | 現実。**この2つと並ぶと浮く** |

そのうえ地図だけで3つの描き方がある。

| 地図 | どこ | 描き方 |
| --- | --- | --- |
| 世界地図 | `/map` | 実際の海岸線。ピンは橙の丸 |
| 国の地図 | `/map/[国]` | 実際の海岸線。緑と生成り |
| 北欧のルート | `/nordic` | 描き起こし。島と同じ柔らかい色 |

**北欧のルート図が正解。** ほかの2つをそちらへ寄せる。

### 6.2 決めごと

1. **輪郭線を引かない。** SVG も。`island-design.md` 2章はスプライトの話に見えるが、
   **アイコンと地図にも同じだけ効かせる**
2. **SVG にも光を1方向入れる。** 平らな塗り1色をやめて、
   上を明るく下を暗くする（同じ色相のまま 6〜10% だけ）。
   これだけでスプライトの隣に置いても浮かなくなる
3. **写真は、必ず紙に貼る。** 角丸 `--r-2`・生成りの縁 6px・わずかに傾ける。
   「写真そのもの」を置かない。島の中の物は全部「誰かが置いたもの」なので、
   貼られていない写真は世界の外にある
4. **アプリの画面のモックは、島の色域に入れる。**
   いま `/apps` の端末の絵が純度の高い橙・水色・桃で塗られていて、
   これだけ別のデザインシステムに見える。`--roof-*` の5色から選ぶ
5. **国旗だけは例外。** 実際の色を守る。旗は事実であって絵ではない

### 6.3 スプライトを見出しに使うときの決まり

- 大きさは 96px（`.phead-icon`）と 26px（ヘッダー）と 22px（タイル）の3つだけ
- 必ず `object-position: center bottom`。足元を揃えないと浮く
- 接地影は**1枚だけ**。`drop-shadow` を2回かけない
- **中身そのものを表す印（国旗・料理）と、場所を表すスプライトを混ぜない。**
  `PageHead` の `icon` と `mark` は別の引数になっている。守る
