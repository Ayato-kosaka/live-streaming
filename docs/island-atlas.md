# 島をひとつから、島の連なりへ

**これは仕様である。拘束力がある。** 島のかたちを変える作業は、まずここを読んでから始める。

`docs/island-design.md`（絵と触りごこちの決まり）と `docs/island-world.md`（板と紙の決まり）は
そのまま効く。ここはその上に載る「島が何個あるか」の話。

---

## 1. なぜ変えるか

いまは島が1つで、その中に「これから」「あやとのこと」「配信」「アプリ」「歩いた国」「企画」が
建っている。**旅そのものが、島の中の1つの建物（歩いた国）に押し込まれている。**

あやとがやっているのは、**2年かけて西から東へ移動し続けている旅**で、章がある。
ヨーロッパを回った時期、中東を回った時期、ジョージアに落ち着いた時期。
それぞれで配信の中身も、作っていたアプリも、来てくれていた人も違う。

**それを島1つの中の1ページに畳むと、旅が旅に見えない。**
章ごとに島を1つ立てて、島が連なっているようにする。

---

## 2. 章の切りかた

章は**配信の中身と滞在で切る**。`site/content/countries.ts` の滞在期間と、
BigQuery の `youtube_chat.videos`（配信のタイトルと日付）から決めた。

| # | 章 | 期間 | 日数 | 国 | 島の性格 |
| --- | --- | --- | --- | --- | --- |
| 1 | **ヨーロッパ周遊** | 2024-10-28 〜 2025-03-29 | 153 | 9 | 配信が始まった島。週3から毎日へ |
| 2 | **中東周遊** | 2025-03-30 〜 2025-06-28 | 91 | 5 | 祭りが生まれた島（GWエジプト祭） |
| 3 | **コーカサス周遊** | 2025-06-29 〜 いま | 続いている | 3 | **いまいる島。いちばん大きい。** アゼルバイジャンから入って、ジョージアに腰を据えて「なに食べよ」を作り、アルメニアへ出て、また戻った |
| — | ↳ **イランまで歩く**（枝） | 2026-04-29 〜 2026-05-08 | 10 | 1 | **先に進んだのではなく、逸れた。** 歩いて国境まで行って、戻ってきた |
| 4 | **北欧周遊** | これから | — | — | **次の島。まだ建っていない** |

**ジョージアを独立した島にしない。** アゼルバイジャン・ジョージア・アルメニアで
ひとつのコーカサス周遊。ジョージアの274日はその中でいちばん長い滞在だが、
章としては同じ島の中の出来事。

### 枝（逸れた島）を、進んだ島と同じに描かない

イランは、ジョージア／アルメニアから**歩いて国境まで行って、また戻ってきた**。
西から東への流れの中の1歩ではない。**本線から下へ枝分かれした小島**として描く。
船の道も、本線とは別の細い線にする。

### 章が増えたとき

`site/content/chapters.ts` に足す。**期間が重ならないこと**と、
**本線は日付順に一列**であることだけを守る。枝はいくつあってもよい。

**画面は1つも触らない。** 1行足すと、連なりに島が1つ増え、`/island/<章>/` に
**歩ける島**が1つ建つ。輪郭も草木も大きさも建物も、そこから勝手に決まる（3章・4章）。
`ISLAND_ART` に手で形を書いていない章は、`artOf()` が回った国の region から
かたち・草木・色を引く（`site/components/chain/shapes.ts`）。

### いまいる島は、日付で決まる

`chapterNow(new Date())`（`content/chapters.ts`）。**`to` の空欄では決めない。**
空欄で決めていたときは、北欧へ出発しても誰かが `chapters.ts` を書きかえるまで
島が入れ替わらなかった。旅は日付で進むので、判定も日付でやる。

まだ始まっていない章には `opensAt`（出発の日時）を持たせる。
北欧は `content/nordic.ts` の `DEPART` と同じ値。**片方を動かしたら両方動かす。**

**静的書き出しに焼かない。** `output: "export"` なので、ビルドしたときの答えが
HTML に入る（`CLAUDE.md`）。焼くのはいまの島1つだけにして、画面では必ず
`chapterNow(new Date())` を呼び直す。連なりの「いまここ」も、トップの表紙も、
これを見ている。

## 3. 島の見た目は、事実から決める

**手で「この島は大きめ」と決めない。** 全部データから引く。

| 何 | 何で決まるか |
| --- | --- |
| **大きさ** | 滞在した日数。コーカサス周遊（434日）はヨーロッパ周遊（153日）の 2.8倍の面積になる。**ただし下駄がある**（すぐ下） |
| **かたち** | その章で回った土地を、抽象的に思わせる輪郭。ヨーロッパならヨーロッパらしく |
| **草木・建物** | その土地のもの。中東なら乾いた土とナツメヤシ、北欧なら針葉樹と岩 |
| **住人** | **その章のあいだに来てくれていた人**。同じ人が複数の島に出てよい |
| **色** | 章の色ではなく、**土地の色**。`docs/island-design.md` の色の決まりに従う |

### 大きさには、日数と関係のない下駄がある

面積∝日数をそのまま守ると、10日のイランが半径 18 にしかならない。
その大きさでは浜も草木も 1px を切って、**島に見えない**（撮って確かめた）。
なので「**どの島にも、日数と関係のない浜のぶんの面積がある**」ことにして足す。

```
r = √(BASE² + K²・日数)      BASE = 26, K = 118/√434
```

コーカサス 118 → 121 とほとんど変わらず、小さい島だけ持ち上がる。
**大小の順は崩れない**（北欧 31 < イラン 32 < 中東 60 < ヨーロッパ 75 < コーカサス 121）。
`site/components/chain/shapes.ts` の `islandRadius`。
**「日数に比例していない」と思って外さないこと。**

### 住人

BigQuery から引く（`chat_messages` の `author_channel_id` と、章の期間の重なり）。
数え方は `.claude/skills/monthly-review/SKILL.md` 3章と同じにする
（日ごとに数える／配信日は UTC で切る／コメントの残っていない日は当時すでに来ていた人を出席扱い）。

**どの絵が誰かは、alertbox の Viewers 表が決める**（`python/residents_map.json`）。
本人に選ばせない。表に載っていない人は絵が無いので、**人数には入るが島には立たない。**

## 4. 島に建てるものは、章ごとに違う

**素材のあるだけ建つ。** 島に建っているものは全部押せる（`docs/island-design.md` 6章）。

### 「どの島も最大6つ」をやめた（2026-09-10）

前はここに **「どの島も最大6つ」** と書いてあった。あの決まりは、別の2つを
1つにまとめてしまっていた。

1. **引き（島ぜんぶ）で名前が出るのは6つまで**（`docs/island-design.md` 3-4）
2. 島に建てられる建物の数

**(2) は、もともと事実ではない。** いまの島は10軒建っていて、そのうち看板が6つ。
それでも「6つまで」と書いてあったせいで、章の島は `spec.ts` が5つ＋船着き場で
切っていた。結果、ヨーロッパの島からは石碑が落ち、**コーカサスの島は3軒しか
建たなかった**（あやと 2026-09-10「この島の画面の中身の本部の部分が一切なくて
（略）さすがにこれは、デザインレベルが低すぎてて」）。

**いま守るのは (1) だけ。** 建物は素材のあるだけ建てて、
**引きで名前を出す6つを `sign` で選ぶ**（`components/isle/spec.ts`）。
いまの島と同じ作りになった。

### 表紙の島（いまの島）

**常設の入口は、章が変わっても消えない。**

表紙は日付でその章の島に入れ替わる（`components/isle/Cover.tsx`）。
その入れ替えを `nordicSpec` でやっていたころ、**入れ替わった瞬間に表紙が
5軒だけの島になっていた。** あやとのこと・配信・アプリ・歩いた国・作った料理・
住んでる人への入口が、表紙から全部消える。

あやとの言葉（2026-09-10）:

> 例えば配信とか、歩いた国、あやとのこと、アプリ、企画を出す、これからとかって
> いうのは、**次の島でもデフォルトの島には常に引き継がないと、新しく入ってきた
> 人からすると困りますよね。**

だから表紙の島は **常設の入口10軒 ＋ その旅のこと ＋ 船着き場 = 12軒**で建てる
（`components/isle/cover.ts`）。章が増えても、ここは1文字も変わらない。

- **常設の入口は書き写さない。** 出どころは `components/island/layout.ts` の
  `PLACES` ひとつ。名前も絵も行き先も看板の6つも、あちらが決める
- **大きさは日数から出さない。** `isleRadius` は `/atlas` の連なりで島どうしを
  比べるために決めた式（3章）で、出発した日の北欧に当てると1日ぶんの島になり、
  10軒が重なって建つ。表紙の島は「何軒建つか」で広さを決める（`COVER_R`）。
  大きさの比べ合いは `/atlas` の航路の丸が持っている（4.5章）
- **建設中の区画は出さない。** その日からは、いま歩いている島（5章）

#### 入れ替えは、焼いた島とその日が食い違ったときだけ

表紙の島は**サーバ側で焼く**（`app/page.tsx`）。焼いたときの章が手で作った島の
章なら手で作った島を、進んでいれば `coverSpec` の島を HTML に入れる。
`Cover.tsx` が受け持つのは、**出発してから配り直すまでのあいだ**だけ。

理由は速さ。焼いた島は HTML に入っているのですぐ出るが、画面が出てから組むと
スマホ（CPU 4倍遅）で **LCP 1.8秒 → 3.4秒**になる。`nordic_depart.yml` は
押すと Hosting も配り直すので、この遅い状態は出発の夜の数時間だけ。
そのあいだも画面は白くならない（先に手で作った島が出ていて、そのあと入れ替わる）。

**入れ替えの判定を "use client" のファイルに置かない。** 章の名前のような
ただの文字列でも、クライアント側のモジュールからサーバ側へ持ち出すと
参照が渡ってきて、比較がいつも false になる。**表紙が丸ごと入れ替わっていたのに、
型でもビルドでも気づけなかった**（`components/isle/handmade.ts`）。

### 過去の島

**その章のときに何をしていたかで決める。** いまの6つを写さない。

**「作った料理」はジョージアに落ち着いてから始めたことなので、ヨーロッパの島には建てない。**
その章に無かったものを建てると、島が嘘をつく。

だから**章ごとに手で並べない。** `site/components/isle/spec.ts` が、
**その章に中身のあるものだけ**を建てる。歩いた国が0なら道しるべは立たないし、
伝説の企画が無い章に館は建たない。素材の足りない章は、建つものが自然に減る。

| 建つもの | 建つ条件 | 中に出るもの |
| --- | --- | --- |
| **この島で歩いた国**（道しるべ） | `countries` がある | 国旗と滞在した街 → `/map/<国>` |
| **この島で起きたこと**（やぐら） | その章の配信がある | 新しい3本 → `/island/<章>/streams` |
| **ショート動画**（板） | `content/shorts.ts` にその章のぶんがある | サムネイルの格子 → YouTube |
| **この島の代表的な企画**（館） | 期間に重なる `legends` がある | 企画と、その1つの数字 → `/legends/<企画>` |
| **この島で作っていたアプリ**（工房） | 期間に重なる `apps` の節目がある | アプリと、この島にいたあいだの節目 → `/apps/<アプリ>` |
| **はじめての配信**（たき火） | **いちばん古い配信を持っている島だけ** | 1本目の配信 |
| **この島のこと**（石碑） | `chapterStats` がある | 日数・本数・来た人数・国数 |
| **となりの島へ**（船着き場） | **いつでも** | ひとつ前の島／つぎの島／島の地図 |

船着き場だけは、あふれても削らない。島から出る道が消えると、島が袋小路になる。

### あふれるのは、名前のほう

建物は削らない。**引きで名前を出す6つ**を選ぶ。

| 名前を出す（`sign`） | 出さない |
| --- | --- |
| この島で歩いた国／この島で起きたこと／この島の代表的な企画／この島で作っていたアプリ／この島のこと／となりの島へ | ショート動画／はじめての配信 |

上の6つは、どの章でもこの並びから選ばれるので**6つを超えない**（作りとして超えられない）。
落としたのは、同じ島の他の札で言い換えのきくもの。ショート動画は板の中に
サムネイルが並ぶので、名前が無くても絵で分かる。

**船着き場には必ず名前を出す。** 島から出る道が引きで消えると、島が袋小路になる。

### 章の期間は、`to` の空欄で判定しない

伝説の企画もアプリも、`c.from && c.to` が両方入っている章だけ拾っていた。
`to` が空いている章——つまり**いま歩いている島**——では、
**何ひとつ拾えない。** コーカサスの島が石碑と道しるべと桟橋の3つだけだったのは、
素材が無かったからではなく、ここが取りこぼしていたから。

いまは `chapterSpan()`（`content/chapters.ts`）で期間を出す。
終わりが入っていない章は「次の章が始まった日」か「今日」で閉じる。

### ショート動画

**埋め込まない。** ヨーロッパだけで31本あるので、プレイヤーを並べると板を開いた
瞬間に外へ31本つなぎにいく。サムネイルを並べて、押したら YouTube へ出る。

**絵は縦。** YouTube の `hqdefault.jpg`（480×360）は、縦の絵を中心に置いて
まわりを同じ絵のぼかしで埋めたもの。縦の枠に `object-fit: cover` で入れると、
そのぼかしが左右に逃げて元の縦の絵だけが残る。1枚 15KB。

**看板は出さない**（`sign` を付けない）。島の上に常に出る名前は3枚のままにする
（`docs/island-design.md` 6章）。

出どころは `python/data/shorts.json` ひとつで、BigQuery には無い
（`videos` 表は配信だけ）。焼くのは `python python/build_shorts.py --build`。

### 配信を始める前の6週間は、島に建てない

もらった58本のうち15本（ロンドン6・バルセロナ5・ローマ3・ナポリ1）は、
公開日が 2024-09-17〜10-19 で、**ヨーロッパ周遊の章が始まる 2024-10-28 より全部前**。
章の外のものを島に建てると、島が嘘をつく。

出すのは `/map` の「その前に、配信していない6週間がある」の段。
あそこは「配信が無いので、下の一覧には出てきません」で終わっていて、
実際には動画が15本あるので、そのままだと嘘に近かった。

**スペインとイタリアの国の面は作らない。** `COUNTRIES` に足すと `order`
（「◯カ国目」）を全部振り直すことになり、世界地図の焼き込み
（`build_world_route.py`）と食い違う（`content/countries.ts` の `BEFORE_STREAM`）。
それに `/map/<国>` はチャットの集計を出す面なので、配信が1本も無いこの6週間は
本数0・人数0・コメント0の面になる。GitHub #122 への答えは、国の面ではなく
**この段に中身が入ること**。

### 建物の中身は、島から出ずに見る

あやとの言葉:「その中の**やぐらみたいな感じで**、この島で歩いた国とか、

## 5. 次の島は、集まったぶんだけ建つ

**豚の貯金箱（Doneru）の集まりぐあいで、次の島の建設が進む。** いまの目標は5万円。

| 集まり | 島の姿 |
| --- | --- |
| **読めていない** | 区画だけ取ってあって、**建つものが薄く見えている** |
| 0% | 更地。地面と杭だけ |
| 10% | 鉄筋が立つ |
| 50% | 壁と屋根がかかる |
| 100% | 完成。草木も住人も入る |

**いちばん上の行を落とさない。** 足代は外から読むので落ちる（旅の最中は
電波の弱いところを通る）。`useFund()` は読めないときも 0以下のときも `null` を
返すので、それを 0% として描くと、**届かなかっただけの日に「まだ1円も
集まっていない島」が出る。** 出してくれた人に対して嘘になる。
額のほうは「読めなかったら金額を出さない」なので、**絵もそろえる**
（`docs/island-standards.md` 9）。

読めていないときの姿は、島の決まりどおりの**読み込み中の作り方**
（`docs/island-design.md` 4章「場所だけ先に取る。中身の形をした薄い板を置く」）。
更地の縄張りとも、鉄筋の骨組みとも、木の色の箱とも、できあがった家とも
見分けがつくこと。**確かめるときは API を落として撮って、0円のときと並べる。**
道具は `tools/sprites/atlasfund.mjs`（5段まとめて撮る）。

なお **0円は絵に出ない。** `useFund()` が 0以下を `null` にするので
（0円と出すのがいちばん悪い、という決まり）、更地が出るのは 1〜4,999円のあいだ。

**これは進捗バーではない。** `docs/island-play.md` は進捗バーを「移植してはいけないもの」に
挙げているが、あれは**やらされている感を出す棒**のこと。ここは**島の絵そのものが変わる**。
数字を棒で見せるのではなく、行った先の景色が育つ。

**集まらなくても旅には行く**（`docs/nordic-fund.md`）。
建っていない島へ船で行けること自体は変えない。更地に立てる。

### 草木まで消さない

**育つのは建物のほうで、島そのものは最初からそこにある。**
0% は「まだ杭しか打っていない区画」が島のまん中にある姿。

歩ける島（`/island/nordic`）も、`/atlas` の模型も、これで描く。
一度、模型のほうだけ島ぜんぶを土色にしていた（連なりを 124px の行で並べて
いたころの決まりを引き継いだもの）。**主役として大きく出すと、島ではなく
茶色い塊に見える**（あやとの指摘 2026-09-10「大きな水色の皿の上に小さな
茶色い塊が乗っているだけで、島に見えません」）。土にするのは区画だけ。

区画は**ひし形**に置く。斜め見下ろしの絵で、地面の四角はひし形になる。
真四角に描くと地面ではなく「立っている枠」に見えて、杭4本が小屋に化ける。

### 建つものは、100% の家を測って、そこから引き算で作る

**鉄筋も壁と屋根も、完成品（`hut-home` のスプライト）に寸法を合わせる。**
50% を独立に組んだら、完成品より 19% 大きい家が建った。
**建設中のほうが完成品より大きいのは、単純におかしい**（あやとの指摘 2026-09-10）。

寸法は完成品の不透明画素を1行ずつ数えて出した（`hut-home.webp` 物体 258×263px）:

| 何 | 全高に対する割合 |
| --- | --- |
| 軒の高さ | 25.8% |
| いちばん高いところ | 71%（底面の中心から） |
| 見かけの半幅 | 48% |
| 底面の半奥行き | 29%（→ 奥行きの潰しは 0.603） |

**向きも合わせる。** あの絵は角をこちらに向けた見え方で、左右2面の壁と2枚の屋根が
見えている。別の向きで組むと、隣に並べたときに別の建物に見える。
（「棟を水平に見せる」は face-on の向きでしか作れないので、そちらは取らなかった。
100% と同じ家が育っていくことのほうを取っている。）

合っているかは目で見ない。**測る**（`tools/sprites/atlashouse.mjs`）。
50%: 幅 17.4 / 高さ 17.5 / 上端 -19.6 に対して、100%: 幅 17.1 / 高さ 17.5 / 上端 -19.5。

前に外したのは、寄棟にしたことではなく**頂点を奥の角の上に置いた**こと。
まん中の真上に戻すと、手前の角へ下りる稜線が出て屋根に見える。
それと、棟は奥へ上がっていくので、**棟の高さをそのまま 71% にすると背が高くなる。**
71% は「いちばん高いところ」なので、棟の高さはそこから奥行きぶんを引く。

**出発したら、この区画は消える。** その日からは「これから建つ島」ではなく、
いま歩いている島になる。判定は日付（2章）で、画面が出てから決める。

## 6. 島から島へは、船で行く

**押した瞬間に切り替えない。** 船が出て、水路をたどって、着く。かわいく、ゲームらしく。

- 動きを減らす設定の人には、船を出さずに切り替える
- 船に乗っているあいだも押せる（急ぐ人を待たせない）
- **島の連なり全体を見わたす画面**が要る（`/atlas`）

**舟は水の上を走らせる。** `/atlas` の模型は水ごと切り取った円盤なので、
円盤の外を舟が横切ると、浮いている模型のまわりを空飛ぶ舟が回ることになる。
手前の水ぎわから、島の浜へ。水面の見かけの高さは島ごとに違うので、
出ている島の値を CSS 変数で渡す（`components/chain/Isles.tsx` の `--atl-wy`）。

着いた先の島では、**浜に船着き場があって、舟がつないである。**
あやとはそこから歩きはじめるし、そこを押せばとなりの島へ渡れる。
連なりの画面のカヌーと、島の浜の舟は同じ絵（`canoe`）。

### `/atlas` は、模型を1つずつ出す

あやとの言葉:「島のマップを押すと、今の島が3Dモデル風に出てきて、
左右上矢印が出てきて、押すとその島が出てきて、その島を押すとその島に
移動できるUXがどう森っぽいと思うけどどうだろう？」

はじめは5つの島を縦に並べていた。一覧としては読めるが、**島が模型に見えない。**
いま出るのは1つだけで、まわりの島ははみ出して覗いている。

| 何 | どう |
| --- | --- |
| **出る島** | いまいる島（`chapterNow(new Date())`。焼き込まない） |
| **左右** | 本線のとなりの島。矢印・矢印キー・指ではらう、の3つで動く |
| **上** | **枝の島**（イラン）。親の島にいるときだけ出る。枝からは下で戻る |
| **押すと** | その島へ渡る。舟が水の上を渡ってから面が変わる（6章） |
| **航路** | 下に並ぶ丸。連なりぜんぶが1本で見える。押すとその島の模型が出る |

#### 模型の作りかた

海ごと**丸く切り取った円盤**に、島が乗っている（`components/chain/diorama.ts`）。
島だけを宙に浮かせると「船で渡る」と絵が食い違うので、水も同じ模型に入れた。

立体は**同じ輪郭を少し下にずらして2枚描く**だけで作る。側面の多角形は計算しない
（凹んだ形で破綻する）。カメラ（縦の潰し）は**どの島も同じ値**にする。
`art.squash` は島ごとに 0.56〜0.70 とばらついているが、あれはカメラの値であって
島の形ではない（形は `art.radii` が持っている）。ばらつかせると、同じ棚に
別の縮尺の模型が載っているように見える。

**建っているものは、渡った先と同じ。** 歩ける島（`components/isle/world.ts`）が
決めた並びを、島の半径で割った割合にして縮めてある（`components/chain/isles.ts`）。
配信240本や企画の表を読む計算なので、**ブラウザには絵と位置だけを渡す。**
いまいる島だけは渡る先がトップ（`/`）なので、あちらの10軒
（`components/island/layout.ts`）を使う。ここを章の島の作りで描くと、
**押した先に10軒建っているのに押す前は3軒**という嘘になる。

#### 主役は枠いっぱいに寄る。比べ合いは航路が持つ

**`islandRadius` の式（3章）は1文字も変えない。** 変えるのは、1つだけ主役として
出すときの**カメラの寄り**だけ。模型は水の皿ごと枠（100×84）に合わせて拡大する
（`components/chain/diorama.ts` の `fit`）。17日の北欧も 438日のコーカサスも、
同じくらい枠を埋める。

なぜ寄せるか。3章の下駄（`ISLE_BASE`）は「小さく並べたときに島に見えなくなる」のを
避けるために決めた値で、**全画面で1つを主役にする画面のために決めた値ではない。**
日数どおりの縮尺で17日の島を1枚に出すと、大きな水色の皿に小さな茶色い塊が
乗っているだけになる（あやとの判断 2026-09-10「主役の1島は、島ぜんぶを枠に
合わせて拡大する。大きさの比べ合いは下の航路が持つ」）。

**代わりに、航路の丸は直径が島の半径そのもの。** 面積が日数に比例する。
下駄も上限も足さない——足したら比べる意味が無くなる。丸の下に
「丸の大きさが、島の大きさ。模型はどれも枠いっぱいに寄せてあります。」と書く。
これを書かないと、北欧とコーカサスが同じ大きさの島に読める。

となりの島は 0.36倍。どの島も枠いっぱいなので、この1つの値でまん中より必ず小さくなる。
端の島（ヨーロッパ・北欧）は片側にとなりが無いので、そのぶん空いた側へ寄せて
釣り合わせる（`.atl-stage.is-end-r` / `is-end-l`。狭い画面はとなりが見えていないので寄せない）。

### 値段 — 島が5つでも、払うのは1つぶん

見えている島はいつも1つなので、原理的に1つぶんで済む。そのために、
いまの島で効いた3つをそのまま持ってきた。

1. **`viewBox` を書き換えない。** 書き換えると SVG の中身が全部塗り直される。
   画面より広く焼いておいて、ズレは CSS の `transform` で見せる
2. **同じ値を書かない。** 属性に書けば、値が同じでもその要素は塗り直される
3. **見えていないあいだは動かさない**（画面の外／別のタブ）

やらないこと: **SMIL を使わない**（中身を全部塗り直す）。
**島を囲む大きさの形を動かさない**（海のきらめきは静止。動かすと、海が画面の
1割しか写っていなくても10割ぶん払う）。

実測（390×844・dpr3・放置6秒・`Performance.ProcessTime`。交互に測って比を読む）:

| 面 | 1秒あたりの CPU |
| --- | --- |
| `/board`（島の無い面。下駄） | 55 ms |
| **`/`（いまの島）** | 267 ms |
| `/island/europe`（いちばん大きい章の島） | **192 ms** |
| `/island/middle-east` | 178 ms |
| `/island/nordic` | 115 ms |

歩かせると `/` が 532ms、`/island/europe` が 293ms（×0.55）。
PC（1440×900）で `/` が 165ms、`/island/europe` が 145ms（×0.88）。
**どの島も、いまの島より安い。**

ショート動画を足す前と後を、2つの書き出しを**交互に**測って比べた
（`tools/sprites/_abport.mjs`）。放置6秒・390×844・dpr3:

| 面 | 足す前 | 足したあと | 比 |
| --- | --- | --- | --- |
| `/island/europe` | 155 ms/秒 | 155 ms/秒 | **×1.00** |
| `/island/iran-walk` | 208 ms/秒 | 202 ms/秒 | ×0.97 |

**サムネイル58枚を足しても、島の値段は動かない。** 板を開くまで `<img>` が
1つも作られないから。板を開いたままの6秒も、同じ島の別の板と交互に測って
「歩いた国」168 ms/秒 に対して「ショート動画」162 ms/秒（`_sheetcpu.mjs`）。

`/island/europe` を**歩ける島にする前**（絵が出るだけだった紙の面）と
交互に測ると **×1.00**。エンジンを1本足して、1秒あたりの CPU は変わっていない。
