# 旅に出てから、旅が終わるまで

**これは仕様である。** 北欧ヒッチハイクの旅で、サイトが「出発前」から
「旅の最中」へ、そして「旅のあと」へ変わる仕組みを決める。

**先に読む**: [`nordic-fund.md`](./nordic-fund.md)（企画の芯）/
[`island-atlas.md`](./island-atlas.md)（章と島）

---

## 0. なぜこの面が要るのか

出発の6日前に時計を進めて点検したら、**出発の当日から9日間ずっと `/next` が
「もう行ってきた」「おわった」と出ていた。**

パンくずが「これから > 北欧ヒッチハイク」なので、旅を見に来た人は必ずここを通る。
毎晩の配信で「見てね」と言われる面へ入る手前が、旅のあいだじゅう
「終わった」と書いてあったことになる。

原因は、企画が**始まる日しか持っていなかった**こと。始まる日を過ぎたら
終わったことに倒れる作りだった。同じ形の穴がもう3つあった。

| どこ | 何が起きていたか |
| --- | --- |
| `/next` | 出発の当日から「もう行ってきた」 |
| `NORDIC_LOG` | 直すのに commit と Hosting の手動起動が要る。**道の上では回らない** |
| 出発の日の手順 | 4つの操作が、どこにも書かれていない |
| 旅の終わり | **「旅が終わった」という事実が、データのどこにも無い** |

---

## 1. 企画の3つの状態

**これから / いま行っている / 行ってきた。**
決めているのは `site/content/plans.ts` の `planPhase` 1か所だけ。

終わりの持ち方が3通りある。**どれも「決まっていないものを決まったことにしない」
ために要る。**

| 企画が持っているもの | いつ「行ってきた」になるか |
| --- | --- |
| `done`（実際に終わった日） | その日を過ぎたら。**事実なので、いちばん強い** |
| `until`（終わる予定の日） | その日を過ぎたら |
| `endsWhen`（終わりの合図だけ） | **日付では終わらない。`done` が入るまでずっと「いま」** |
| どれも無い | `date` のその日1日で終わる（お祭りはこれ） |

### 北欧は `endsWhen`

```ts
until: "2026-09-27",              // 発つ便の切符がある日
endsWhen: "ストックホルムを発ったら",
doneFromState: "nordic",          // 実際に発った日が届いたら、そちらが勝つ
reached: { when: "2026-09-20", ... },  // 着いた日。**ここでは終わらない**
```

**終わりを「着いたら」にしない**（2026-09-06 に直した）。着くのは9月20日で、
発つのは27日。「着いたら終わり」にしていたあいだ、**友だちの家での7泊が
まるごと「もう行ってきた」になっていた。**

**着く日のほうは、いまも焼き込まない。** ヒッチハイクなので、着く日は
乗せてもらえた車でずれる。着いた日は島から届く（`reached.fromState`）。
終わる日だけは切符があるので `until` で言い切れる。

### 状態は、必ず画面が出てから決める

静的書き出し（`output: "export"`）なので、ビルドした日の答えが HTML に焼かれる
（`CLAUDE.md`）。`planPhase` を素で呼んで焼くと、何日たっても同じ答えが出る。
画面の側は `usePhase`（`components/live/PlanCard.tsx`）を通す。
**出るまでは「これから」**にしておく。焼き込みの日付で「終わった」と言わない。

## 2. その日に起きたことを、道の上から書く

`site/content/nordic.ts` の `NORDIC_LOG` は Git にある。直すには
編集して commit して、Hosting のワークフローを手で起動する。
**あやとはヒッチハイクをしている。それは回らない。**

### 書くところは、その日のページの中

`/nordic` → 今日の行を押す → いちばん下に「この日、何が起きたか」。
あやとでログインしていると、そこに書く欄が出る
（`components/nordic/DayLog.tsx`）。

**旅の途中に来た人が最初に開くのも、書く本人が開くのも同じ面。**
覚えることを増やさないために、写真を貼るところ（`/nordic/photos`）と
同じ作りにしてある。

### 何を書くのか

**スマホの親指で打つ。長い文章は書けない。** 400字までに縛ってある。
配信で3時間しゃべった話をここに書き写すことはできないし、書けても誰も読まない。

押すと書き出しが入る札を並べてある。続きだけ打てばいい。

- 何台目で停まってくれた：
- 乗せてくれたのは：
- 泊まったのは：
- 食べたのは：
- いちばん驚いたのは：

**この旅で毎日起きることだけを並べている。** 順位でも点数でもない、
その日そこにあった事実。`docs/island-play.md` の「移植してはいけないもの」
（育成・連続ログイン・島内通貨）に触れていない。

### 日付も一緒に入る

旅程表の行は、切符のある2日しか日にちを持っていない（`Day.date`）。
**書いた日が、その行の日付になる。** よていの欄を先に埋めるのではなく、
起きたことのほうから埋まっていく。

### 鍵は「区間」ではなく「旅程表の行」

`nordicLog/{day-1}`。あやとがスマホから選ぶのは「何日目か」であって
「どの区間か」ではない。区間で持つと、1日に2区間ある日（出発の翌日と着く日）に
同じ話を2回書かせることになる。

### 書けないときの逃げ道

ログインが通らない・打ち間違いをあとから直したい、というときは
「管理スクリプトを実行」から `script: nordic_log`
（`python/admin/nordic_log.py`）。読むだけもできる。

### 旅が終わったら、Git に焼き戻す

読み返されるのは旅のあとのほうが長い。そのころには API に頼らないほうがいい。

```
run_admin_script.yml  →  script: nordic_log  args: {"op":"export"}
```

出てきた TypeScript を `content/nordic.ts` の `NORDIC_LOG` に貼って、
Hosting を配る。**両方あるときは届いたほうが勝つ**ので、写し忘れているあいだも
新しく書いたものが古い焼き付けに負けることはない。

## 3. 出発の日にやること

**ボタン1つ。** GitHub Actions の「北欧へ出発した」
（`.github/workflows/nordic_depart.yml`）を `workflow_dispatch` で走らせる。

入力は「いまどこ」だけ。既定で `ポーランド・カトヴィツェ` が入っている。

押すと、この4つが順に走る。

1. `site/content/chapters.ts` の `caucasus.to` に日付を入れる
2. `python/build_chapter_stats.py` を回す
3. master に押し戻して、Hosting のデプロイを起動する
4. 島の「いまどこ」を `place` に、景色を `nordic` にする

**何度押しても同じ。** 2回目は `nordic_depart.py` が
「すでに閉じてあります」と言って何もしない。

### なぜ手順書ではなくボタンにしたか

`CLAUDE.md` は「あやとにやってもらう操作」「期限や状態を持つもの」を
`docs/` に置かず issue に立てる、と決めている。出発の日の操作はまさにそれで、
手順書を `docs/` に置くのは決まりに反する。

かといって issue に4つ並べても、**読む・順に踏む・どこまでやったか覚えておく**
の3つが要る。押す本人はその日、深夜1時のカトヴィツェに降り立って、
そこからヒッチハイクを始める。

**そこで、手順そのものを消した。** ボタン1つにすれば、覚えることは
「押したかどうか」しか無い。しかも押したかどうかは**データが持っている**
（`caucasus.to` が空か、入っているか）ので、状態を別に持たなくてよい。
この面に残したのは「どういう仕組みで切り替わるか」だけで、期限も状態も持たない。

### `nordic.from` は入れない

**`site/content/countries.ts` に北欧の6カ国が無い。** ここに `from` を入れると
`build_chapter_stats.py` が北欧の章を数えはじめて、国0・配信0の島ができる。

北欧が「いまいる島」になるのは `opensAt`（出発の日時）が決めていて、
`from` は要らない。`nordic_depart.py` は `from` が入っていたら**止まる**。

### `caucasus.to` を入れると、4時間半だけ島がいなくなる

`to` を `2026-09-11` にすると、日本時間の 9/11 23:59:59 で
コーカサスが閉じ、北欧が開くのは 9/12 04:30（ジョージア時間 23:30）。
**そのあいだ、開いている章が1つも無い。**

前はそこで `chapterNow()` が `undefined` を返して、島の連なりも表紙も落ちた
（型は `Chapter` と言い切っているので、誰も気づかないまま落ちる）。
いまは**いちばん最後に始まった章**を返すので、その4時間半はコーカサスに見える。
一瞬だけ前の島に見えるのは、画面が落ちるよりずっとよい。

### 出発が延びたら

押さなければいい。ただし切り替わりは日付を見ているので、日をまたぐと
島だけ北欧に変わる。そのときは出発の日時を直す。**2か所ある。**

- `site/content/nordic.ts` の `DEPART`
- `site/content/chapters.ts` の `nordic.opensAt`

（`plans.ts` の `at` も同じ値だが、こちらは `DEPART` と揃える決まりが
すでにコメントに書いてある。**3か所と数えたほうが安全。**）

## 4. 着いた日と、旅の終わり ── **2つある**

あやとの言葉（2026-09-06）:

> ストックホルム出るまでが北欧旅です。なので、それが企画に盛り込まれてるか心配。

心配のとおりだった。長いあいだ、旅の終わりは「ストックホルムに着いたら」で、
**着くのは9月20日、発つのは27日。あいだの7泊がまるごと「もう行ってきた」に
なっていた。** 着いた日と終わった日は別の出来事なので、値も2つ持つ。

| Firestore | 何の事実か | 押すところ |
| --- | --- | --- |
| `island/state.nordic.arrivedOn` | ストックホルムに着いた日（9/20） | 旅程表の「着く」の行 |
| `island/state.nordic.endedOn` | 旅が終わった＝発った日（9/27） | 旅程表の「旅のおわり」の行 |

どちらも `current.place` では代わりにならない。**友だちの家に7泊する**ので、
そのあいだに街を離れることは普通にある。離れた瞬間に `/nordic` が
「ストックホルムまで（数えています）」に戻ってしまう。

### 押すところ

`/nordic` の旅程表のいちばん下、2行。あやとでログインしているとボタンが出る
（`components/nordic/GoalRow.tsx` の `ArrivedRow` と `EndRow`）。
**その出来事を言う場所と、押す場所を同じにしてある。**

「旅がおわった」は、**着いた日が入るまで押せない。** 順番が逆に入ると、
着いていないのに終わったことになる。

どちらも取り消せる。船が着く前に押してしまうことは普通に起きる。

逃げ道は「管理スクリプトを実行」の `script: nordic_arrived`
（`python/admin/nordic_arrived.py`）。`{"date": "..."}` が着いた日、
`{"ended": "..."}` が終わった日。日付をずらしたいときもこちら。

### 押すと、こうなる

**「着いた」を押したとき**（旅はまだ続いている）

| どこ | 押す前 | 押したあと |
| --- | --- | --- |
| `/nordic` の大きい数字 | ストックホルムまで ◯◯km | **着いた ストックホルム**（9月20日）／ここから7泊して27日に発ちます |
| 旅程表の「着く」の行 | 着く 9月20日(日) | **着いた**（9月20日）/ ポーランドから◯日 |
| `/next` の企画 | いま 行っている | **いま 行っている**のまま ＋「ストックホルムに着く」の節目が出る |

**「旅がおわった」を押したとき**

| どこ | 押す前 | 押したあと |
| --- | --- | --- |
| `/nordic` の大きい数字 | 着いた ストックホルム | **旅がおわった**（9月27日、ストックホルムを発ちました） |
| 旅程表のいちばん下 | 旅のおわり 9月27日(日) | **旅がおわった**（9月27日） |
| `/next` の企画 | いま 行っている | **おわった 9/11〜9/27** |
| トップの札 | 進行中 | **行ってきた** |

**押さなくても、9月27日を過ぎれば「おわった」になる。**
発つ便には切符があるので、`plans.ts` は `until: "2026-09-27"` を持っている。
押すのは、日がずれたときに事実で上書きするため。

### 「会えた」はゴールにしない

サイトの上のゴールは**ストックホルムに着くこと**で、会えたかどうかは
そのあとの配信の話（`nordic-fund.md` 1章）。相手の都合で会えないことは
普通にあるし、そのとき相手が「約束を破った人」に見えるのがいちばんまずい。

着いたあとの字にも、発ったあとの字にも、会えたかどうかは書かない。

### 章のほうの終わり

`chapters.ts` の `nordic.to` は**着いた日でも、発った日でもない**。あれは
「北欧の島にいた期間」なので、次の場所（ティラナ）の章が始まる日と合わせる。

## 5. 触るところの一覧

| 何をしたいか | どこ |
| --- | --- |
| 出発した | Actions「北欧へ出発した」を押す |
| いる街が変わった | Actions「あやと島の「いま」を更新」の `place` |
| その日に起きたことを書く | `/nordic` → その日の行 → いちばん下 |
| その日の写真を貼る | `/nordic/photos` |
| 着いた | `/nordic` → 旅程表のいちばん下「着く」の行 |
| 旅が終わった（発った） | `/nordic` → 旅程表のいちばん下「旅のおわり」の行 |
| 旅の日記を Git に焼き戻す | `run_admin_script` → `nordic_log` / `{"op":"export"}` |

**街の名前はそのまま入れる。**「ラトビア・リガ」でも「リガ」でも当たるように、
含んでいるかで見ている（`components/nordic/TripNow.tsx`）。
